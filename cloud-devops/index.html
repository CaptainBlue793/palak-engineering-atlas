One code style, all the way through

Five languages appear in this course (Bash, Dockerfile, Kubernetes YAML, Terraform and GitHub Actions), and all of them follow the same five rules, so every listing is also a small lesson in operating safely. This is the style, stated once and never broken.

  • Fail loudly. Every script starts with set -euo pipefail and quotes every variable. A step that fails stops the pipeline instead of carrying on with bad state.
  • Pin everything. Image digests, provider versions and actions by commit SHA. A tag can be moved under you; a digest cannot.
  • Desired state lives in Git. Changes go through terraform plan, kubectl diff or a pull request, never a hand edit in the console.
  • Least privilege by default. Non-root containers, scoped IAM roles, and an explicit permissions: block on every workflow.
  • Every resource says who owns it. Labels and tags for team, environment and service, so alerts, bills and blast radius can all be traced back to someone.
# Test every pull request. Least privilege, everything pinned.
name: ci
on: [pull_request]
permissions:
  contents: read                  # the token can read the repo, nothing more
jobs:
  test:
    runs-on: ubuntu-24.04         # a fixed runner image, not ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2
      - run: ./scripts/test.sh     # starts with set -euo pipefail

Twelve lines, and three of the rules are already in them. In March 2025 attackers moved the version tags of a popular action to a commit that printed CI secrets into build logs (Chapter 48). Workflows that had pinned it by commit SHA kept running the old, safe code.
