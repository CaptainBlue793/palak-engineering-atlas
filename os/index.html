One code style, all the way through

Every listing in this course is C against the real Linux interfaces, written the same way, so the shape of the code becomes a memory aid instead of noise. This is the style, stated once and never broken.

  • Check every return value. System calls fail for ordinary reasons; every call is followed by a check, and errors are reported with perror or strerror(errno).
  • Name the owner of every allocation. Whoever calls malloc or open is responsible for free or close, and the comment says so.
  • Handle short reads, short writes and EINTR. A read may return fewer bytes than asked; a signal may interrupt it. Loops, not hope.
  • Fixed-width, unsigned sizes. size_t for sizes, uint64_t for addresses and counters, const wherever nothing changes.
  • One lock order, written down. Every chapter with more than one lock says the order they are taken in.
/* Read exactly n bytes, or fail. read() may return fewer bytes than asked. */
ssize_t read_all(int fd, void *buf, size_t n) {
	size_t got = 0;
	while (got < n) {
		ssize_t r = read(fd, (char *)buf + got, n - got);
		if (r == 0) break;                     /* end of file */
		if (r < 0) {
			if (errno == EINTR) continue;      /* interrupted by a signal: retry */
			return -1;                       /* real error: the caller checks errno */
		}
		got += (size_t)r;
	}
	return (ssize_t)got;
}

Nine lines that handle end of file, signals and partial reads. Most "works on my machine" I/O bugs are one of those three.
