Bits, Hex & Binary Data

Operating systems pack meaning into individual bits. A page-table entry is a physical address with permission flags in its low bits; open() takes a set of flags OR-ed together; file permissions are three groups of three bits written in octal; a virtual address splits into a page number and an offset by shifting and masking. This chapter is the toolkit for reading all of that: binary and hex by hand, masks and shifts, what happens when integers overflow, byte order, and the powers of two the rest of the course uses constantly.

Binary and hex by hand

Computers store numbers in binary, base 2. Systems programmers write them in hexadecimal, base 16, because one hex digit is exactly four bits, so a 32-bit value is 8 hex digits and a 64-bit address is 16. Converting is mechanical: split the binary into groups of four from the right and replace each group with its digit.

Bits0000000100100011010001010110011110001001101010111100110111101111
Hex0123456789abcdef

So 1010 1111 is 0xaf, which is 10 × 16 + 15 = 175. Octal (base 8, three bits per digit, written with a leading 0 in C) survives in one place you'll use daily: file permissions. 0755 is 111 101 101: read-write-execute for the owner, read-execute for the group and for everyone else.

Masks, shifts and flags

The bitwise operators work on every bit position independently. & (AND) keeps bits set in both values, so it tests and clears. | (OR) sets. ^ (XOR) flips. ~ inverts all bits. x << n shifts left by n (multiplying by 2n) and x >> n shifts right (dividing by 2n for unsigned values). With those, one integer can carry a whole set of yes/no options, each in its own bit:

#include <fcntl.h>

/* Flags are single bits, combined with |. These values are Linux's, in octal. */
/* O_WRONLY = 01, O_CREAT = 0100, O_TRUNC = 01000, O_APPEND = 02000, O_NONBLOCK = 04000 */
int fd = open("server.log", O_WRONLY | O_CREAT | O_APPEND, 0644);   /* 0644: rw-r--r-- */
if (fd < 0) { perror("open"); return -1; }

int fl = fcntl(fd, F_GETFL);
if (fl & O_NONBLOCK) { /* test a bit */ }
fcntl(fd, F_SETFL, fl | O_NONBLOCK);      /* set a bit, keep the others */
fcntl(fd, F_SETFL, fl & ~O_NONBLOCK);     /* clear a bit, keep the others */

The same operations split addresses. With 4 KiB pages, the low 12 bits of an address are the offset inside the page (212 = 4096) and the rest is the page number. That one shift and one mask are the heart of address translation in Chapter 12:

#define PAGE_SHIFT 12
#define PAGE_SIZE  (1UL << PAGE_SHIFT)        /* 4096 */
#define PAGE_MASK  (~(PAGE_SIZE - 1))          /* ...fffff000: clears the low 12 bits */

uint64_t addr   = 0x00403a7c;
uint64_t page   = addr >> PAGE_SHIFT;          /* 0x403: which page */
uint64_t offset = addr & (PAGE_SIZE - 1);      /* 0xa7c: where inside it */
uint64_t base   = addr & PAGE_MASK;            /* 0x403000: start of the page */

Signed, unsigned and overflow

A 32-bit pattern means different numbers depending on its type. As unsigned, it ranges 0 to 4,294,967,295. As signed, the hardware uses two's complement: the top bit has weight −231, so the range is −2,147,483,648 to 2,147,483,647, and −1 is all ones (0xffffffff). Two's complement is used because the same adder circuit works for both types.

System calls mix the two on purpose. read() returns ssize_t, a signed size, so it can return −1 for errors and byte counts otherwise. Compare it with a size_t carelessly and −1 becomes 18 quintillion: this course always checks < 0 first, then casts.

✈️
Counters that run out: the 787, jiffies and 2038

In 2015 the US Federal Aviation Administration ordered Boeing 787 operators to power-cycle the aircraft periodically: a software counter in the generator control units, counting hundredths of a second in a signed 32-bit integer, would overflow after 231 ÷ 100 seconds, about 248 days, and the units could shut down. The Linux kernel guards against the same class of bug by deliberately starting its tick counter, jiffies, five minutes before it wraps, so wrap-around bugs show up within minutes of boot instead of after months of uptime, and by comparing ticks with macros like time_after() that work across a wrap. The next big one is 2038: a signed 32-bit time_t counting seconds since 1970 overflows on 19 January 2038, which is why Linux added 64-bit time system calls for 32-bit platforms (kernel 5.6, 2020) and distributions have been rebuilding their 32-bit software with a 64-bit time_t.

Endianness: which byte comes first

A 32-bit integer occupies four bytes, and machines disagree about their order in memory. Little-endian machines (x86 and, in practice, ARM) store the least significant byte at the lowest address, so 0x12345678 sits in memory as 78 56 34 12. Big-endian stores 12 34 56 78, the order you'd write it. Inside one machine you never notice. You notice when bytes cross a boundary: a file format, or the network, where protocol headers are defined as big-endian, called network byte order.

⚠️
Common mistakes
  • Testing a flag with ==. if (flags == O_NONBLOCK) fails as soon as any other bit is set; use flags & O_NONBLOCK.
  • Setting flags with = instead of |=. You silently clear every other option.
  • Writing permissions in decimal. chmod(path, 755) means octal 01363, nonsense; write 0755.
  • Shifting a plain 1 past bit 31. 1 << 40 overflows an int; write 1ULL << 40.
  • Relying on signed overflow wrapping. It's undefined; the optimiser may delete your overflow check.
  • Forgetting byte order when filling sockaddr_in or parsing a binary file format.

Interview drill

Explain it simply: Given the address 0x7f3a1c229d90 and 4 KiB pages, what is the page number and the offset?

How a strong answer sounds
A 4 KiB page is 212 bytes, so the low 12 bits, the last three hex digits, are the offset: 0xd90. The page number is the address shifted right by 12, which in hex just drops those three digits: 0x7f3a1c229. In C that's addr >> 12 and addr & 0xfff. Because 12 is a multiple of 4, hex makes this a matter of reading digits.

Deeper: How would you check whether a number is a power of two, and why does the kernel care?

How a strong answer sounds
x != 0 && (x & (x - 1)) == 0: subtracting 1 flips the lowest set bit and everything below it, so the AND is zero only if there was exactly one set bit. The kernel cares because sizes like pages, cache lines and ring buffers are powers of two precisely so that division and modulo become shifts and masks: i % size becomes i & (size - 1), and rounding an address down to its page is addr & ~(PAGE_SIZE - 1), one instruction instead of a slow division.

🧠 Key takeaways

  • One hex digit is four bits; one octal digit is three, which is why permissions are written in octal.
  • & tests and clears, | sets, ^ flips, ~ inverts; flags are bits combined with |.
  • With 4 KiB pages, addr >> 12 is the page number and addr & 0xfff the offset.
  • Unsigned overflow wraps; signed overflow is undefined in C; −1 is all ones in two's complement.
  • x86 and ARM are little-endian; the network is big-endian, so convert with htons/ntohl.
  • Powers of two turn division into shifts: 64-byte lines, 4 KiB pages, 2 MiB huge pages, 248-byte address spaces.

Check your understanding

What is 0xff in decimal?

15 × 16 + 15 = 255: eight bits, all set.

How do you turn on O_NONBLOCK in an existing flags value without changing the other flags?

OR sets the bit and leaves every other bit alone. Plain assignment wipes the other flags; AND would clear them.

With 4 KiB pages, what is the offset within the page of address 0x00403a7c?

4 KiB = 212, so the offset is the low 12 bits: the last three hex digits, 0xa7c. The page number is 0x403.

On an x86 machine, how is the 32-bit value 0x12345678 laid out in memory, lowest address first?

x86 is little-endian: the least significant byte, 0x78, comes first. Network byte order is the reverse, which is why htonl exists.

Why did the Boeing 787's generator controllers need a reboot at least every 248 days?

2,147,483,648 hundredths of a second is about 248.6 days. Integer width is a design decision with an expiry date.
