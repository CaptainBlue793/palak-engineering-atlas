Comparing Models Honestly

Model B scores 98.2% on the test set and model A 96.9%. B is better, surely? Not necessarily. A test score is an estimate from a finite sample of cases, and a different, equally valid test set would have given different numbers. With 450 test cases, a gap of 1.3 points is well within what chance alone produces. Ship B on that evidence and you may be swapping one model for an equally good one, or a slightly worse one, at real cost.

This chapter is about telling real improvements from noise: how much a score wobbles, how to put a confidence interval on a difference, why paired comparisons on the same test cases are far more sensitive than comparing two separate numbers, what goes wrong when you test many models and keep the best, and why the final word usually belongs to an online experiment.

  • Estimate the sampling noise in a test metric
  • Put a bootstrap confidence interval on a difference between models
  • Use paired comparisons and McNemar's test
  • Recognise and correct for multiple comparisons
  • Explain why offline wins need online confirmation

Noise in a score

An accuracy measured on n test cases is a proportion, and its standard error is about √(p(1 − p) / n). At 80% accuracy on 500 cases that is 1.8 points, so a 95% interval runs roughly ±3.5 points. Halving the noise needs four times the data. Other metrics are noisier still: AUC and precision at a high threshold depend on the few rare positives, and averages over heavy-tailed errors such as RMSE are pulled around by a handful of cases. Every reported score should come with its uncertainty, and every comparison should ask whether the difference is larger than that uncertainty.

Bootstrap confidence intervals

The bootstrap estimates that uncertainty without formulas: resample the test cases with replacement many times, recompute the metric on each resample, and take the 2.5th and 97.5th percentiles as a 95% interval. It works for any metric, including AUC, F1 and business costs. For a comparison, resample case indices and compute both models' metrics on the same resample, then take percentiles of the difference. On the digits test set above, the 1.3-point advantage of an SVM over logistic regression had a paired bootstrap interval from −0.4 to +3.3 points: plausibly better, possibly not.

import numpy as np

rng = np.random.default_rng(0)
idx = rng.integers(0, n, size=(10_000, n))                  # 10,000 resamples of the test cases
diff = correct_b[idx].mean(1) - correct_a[idx].mean(1)      # paired: same cases for both models
np.percentile(diff, [2.5, 97.5])                            # digits, SVC vs LR: [-0.0044, +0.0333]

Paired tests and McNemar

Two models evaluated on the same test cases are strongly correlated: most cases are easy for both, and some are hard for both. Only the cases where they disagree carry information about which is better. McNemar's test uses exactly those: let b be the number of cases A got right and B wrong, and c the reverse; if the models were equally good, each disagreement would be a coin flip, so c out of b + c follows a binomial distribution with p = 0.5. On the digits example, b = 6 and c = 12: B won twice as many disagreements, but with only 18 of them the exact p-value is 0.24. For metrics averaged over cross-validation folds, use a paired test on per-fold differences, with corrections for the overlap between training sets, or repeated cross-validation.

from scipy.stats import binomtest

b = int((correct_a & ~correct_b).sum())     # A right, B wrong: 6
c = int((~correct_a & correct_b).sum())     # A wrong, B right: 12
binomtest(c, b + c, 0.5).pvalue              # exact McNemar test: 0.238

Things to try.

  • Start with 450 test cases and a true advantage of 2 points for B. Across 400 test sets, B comes out ahead in 82% of them, and McNemar's test detects the advantage in only 12%: the observed difference has a standard deviation of 1.9 points, about as large as the effect. On this test set B leads by 2.0 points, with a paired interval of [−1.8, 5.8].
  • Compare the two intervals. The paired interval is about three quarters as wide as the unpaired one ([−3.2, 7.2] here), because only the 75 disagreements carry information; the other 375 cases drop out. Press Draw a new test set a few times and watch both intervals move.
  • Set the true advantage to zero. B still looks better in 44% of test sets. Any single test set can crown either model.
  • Raise the test set to 5,000 cases. The spread of the observed difference falls to 0.6 points; with a true 2-point advantage, B is ahead in every test set and McNemar's test detects it 94% of the time. Precision costs data: four times the cases for half the noise.
  • Open Many comparisons. Testing 10 candidates that are no better than the baseline produces at least one "significant" win in 11.6% of experiments, and 50 candidates in 28%; on average the best-looking one leads by 2.1 points, all of it luck. Switch to Bonferroni and the false-win rate stays at 3% or below for any number of candidates.

The multiple-comparisons trap

Each test at the 5% level has a 5% chance of a false alarm when there is no real difference. Run 20 such tests, against 20 model variants, feature sets or random seeds, and a false "significant improvement" becomes likely. This is the same effect as the winner's curse in Chapter 13: the best of many noisy scores is biased upwards. Defences: decide the comparison and metric in advance; correct the significance level, for example dividing it by the number of tests (Bonferroni), or controlling the false discovery rate; keep a final test set that is used once, after all choices are made; and treat a surprising win from a long search as a hypothesis to confirm on fresh data.

Offline versus online wins

Even a real offline improvement may not translate into the outcome the business cares about. Offline metrics are proxies: a recommender with better ranking accuracy may not raise watch time, a fraud model with higher AUC may not cut losses at the operating threshold, and any model that changes what users see also changes the data future models are trained on. The definitive comparison is usually an online controlled experiment, an A/B test in which users are randomly assigned to the old or new model and the outcome metric is compared with the same statistical care. Offline evaluation decides what is worth testing; online evaluation decides what ships.

Use case: most good ideas are not

Ronny Kohavi led online experimentation at Microsoft, where teams ran thousands of controlled experiments a year on products such as Bing. He and his colleagues reported a sobering pattern: only about a third of the ideas tested improved the metrics they were designed to improve; roughly a third had no detectable effect and a third made things worse, and at Bing, a mature and heavily optimised product, the success rate was lower still. These were ideas that engineers and product managers believed in enough to build. The surprises ran the other way too. One small change to how ad headlines were displayed, an idea that sat in a backlog for months because it seemed unimportant, increased revenue by 12% when it was finally tested, worth more than $100 million a year in the United States. The lesson for model comparison is humility: intuition, and offline metrics, are poor predictors of what will happen when real users meet a change, so the claims that matter should be tested the way medicine tests treatments, with randomisation, pre-agreed metrics and honest statistics.

⚠️
Common mistakes
  • Declaring a winner from two numbers without an interval or test.
  • Comparing overlapping unpaired intervals instead of the paired difference.
  • Testing many variants and reporting only the best as if it were the only one tried.
  • Reusing the test set for model selection, then reporting it as unbiased.
  • Treating "not significant" as "no difference", when the interval is simply wide.
  • Assuming an offline gain will appear online without an experiment.

Interview drill

Explain it simply: Model B scores 1 point higher than model A on the test set. How do you know it is really better?

How a strong answer sounds
A test score is measured on a limited sample of cases, so it has some random wobble; with a few hundred cases, one point can easily be noise. I would look at the cases where the two models disagree, since those are the only ones that tell them apart, and use a paired method: a bootstrap confidence interval for the difference, resampling the same test cases for both models, or McNemar's test on the disagreements. If the interval clearly excludes zero, B is very likely better on this kind of data; if not, I cannot tell them apart and would need more test data, or prefer the simpler or cheaper model.

Deeper: Your team tried 40 model variants over a month, and the best beats production by 0.8 AUC points with p = 0.03. Do you ship it?

How a strong answer sounds
Not on that evidence. With 40 variants compared, a p-value of 0.03 for the best one is roughly what chance alone would produce, and if the same validation data guided all the choices, the best score is biased upwards: the winner's curse. I would correct for the number of comparisons, for example Bonferroni would require p below about 0.001, or better, evaluate the chosen variant once on a fresh holdout that played no part in the search, with a paired bootstrap interval for the AUC difference. If it still holds, I would check that the improvement appears at the operating threshold and in key segments, weigh it against any added cost, and then run an online A/B test on the business metric before rolling it out fully.

🧠 Key takeaways

  • Every test score has sampling noise; report it, and compare differences against it.
  • Bootstrap the paired difference on the same test cases for a confidence interval.
  • McNemar's test uses only the cases where two classifiers disagree.
  • Many comparisons inflate false wins; correct for them and keep a final holdout.
  • Offline wins are hypotheses; online experiments confirm what helps the business.

Check your understanding

Accuracy is about 80% on 400 test cases. Roughly what is its standard error?

√(0.8 × 0.2 / 400) = 0.02, so a 95% interval is about ±4 points.

Why is a paired comparison of two models on the same test set more sensitive than comparing their separate intervals?

Most variation in each score comes from which cases happen to be in the test set, and that variation is common to both models.

In McNemar's test, which cases matter?

Cases both get right or both get wrong say nothing about which model is better.

You test 20 variants, none truly better, each at the 5% level. Roughly how likely is at least one false "significant" win if the tests were independent?

1 − 0.95²⁰ ≈ 0.64. Tests on one shared test set are correlated, which changes the exact figure, but the risk is large either way.

A bootstrap interval for B minus A runs from −0.5 to +2.5 points. What is the right conclusion?

"Not significant" is not "no difference". The interval says the true gap could be slightly negative or a few points positive.
