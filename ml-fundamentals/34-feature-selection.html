Feature Selection

More features are not always better. Irrelevant columns add noise for the model to fit, redundant ones split credit and confuse explanations, and every feature in production is a pipeline to maintain and a place for data to break. Feature selection keeps the columns that carry information about the target and drops the rest.

There are three families. Filters score each feature on its own and keep the best; wrappers search over subsets by training models; embedded methods, such as L1 regularisation, select while fitting. Each has a blind spot, and all of them must be run inside cross-validation, or they will select features that look good only on the data used to choose them. The simulator puts four methods on a problem where we know exactly which features matter.

  • Explain why mutual information catches non-linear relationships that correlation misses
  • Run recursive feature elimination
  • Use L1 regularisation for selection, and know its behaviour with correlated features
  • Keep selection inside cross-validation

Filter methods

Filters score each feature against the target independently of any model: the correlation or an F-test for a numeric target, a chi-squared or ANOVA test for classes, or mutual information. They are fast and model-agnostic, but they judge features one at a time, so they cannot see redundancy (two copies of the same signal both score high) or interactions (a feature useful only in combination with another). Correlation and F-tests also only see linear relationships: a feature whose effect is U-shaped can have a correlation of zero with the target.

Mutual information measures how much knowing a feature reduces uncertainty about the target, for any kind of relationship. It is zero only if the two are independent. It is harder to estimate than a correlation; scikit-learn uses a nearest-neighbour estimator. On a synthetic problem with a feature whose effect on the target was purely quadratic, its correlation with the target was 0.005 and the F-test ranked it 18th of 20; mutual information ranked it 3rd.

from sklearn.feature_selection import SelectKBest, f_regression, mutual_info_regression

sel_f = SelectKBest(f_regression, k=5)                 # linear relationships only
sel_mi = SelectKBest(mutual_info_regression, k=5)       # any dependence; noisier estimates

Wrapper methods: recursive elimination

Wrappers evaluate subsets by training a model on them. Recursive feature elimination (RFE) fits a model on all features, drops the least important one or few (by coefficient size or importance), refits, and repeats until the requested number is left; RFECV chooses that number by cross-validation. Forward and backward stepwise selection add or remove one feature at a time by score. Wrappers account for redundancy and for the model actually used, but they are expensive and, because they search many subsets, they can overfit the selection itself. RFE with a linear model also inherits the linear model's blindness: it dropped the quadratic feature and kept a redundant copy of another.

Embedded methods: L1 as selection

The lasso's L1 penalty drives some coefficients exactly to zero, so fitting it selects features; a stronger penalty keeps fewer. Tree ensembles also embed selection through their importances, and SelectFromModel keeps features above an importance threshold. L1 has two quirks. Among highly correlated features it tends to keep one somewhat arbitrarily, or to spread weight between them. And the penalty chosen for the best predictions by cross-validation usually keeps extra noise features: on the synthetic problem, LassoCV kept 12 of 20 features, including 6 pure noise columns, and split the weight of the duplicated signal between the original and its copy (1.46 and 1.54).

from sklearn.feature_selection import RFECV, SelectFromModel
from sklearn.linear_model import LinearRegression, LassoCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rfe = RFECV(LinearRegression(), step=1, cv=5)
lasso_sel = SelectFromModel(LassoCV(cv=5))
model = make_pipeline(StandardScaler(), lasso_sel, LinearRegression())   # selection refits inside every CV fold

  • Correlation, top 5. It keeps x₀, its copy x₅, and x₁ to x₃, and ranks the U-shaped x₄ 13th, since its correlation with y is 0.033. Validation R² is 0.592, against 0.853 with exactly the true five features: one missed non-linear feature costs a third of the explained variance.
  • Mutual information, top 6. x₄ now ranks 4th, and the top 6 contain all five true features plus the copy: R² 0.851. At top 5, the copy pushes out x₂ and R² is 0.763; a filter cannot tell that x₅ adds nothing to x₀.
  • RFE, top 5. Refitting after each removal lets RFE drop the copy, but its linear model gives x₄ no weight, ranking it 9th; the fifth slot goes to noise feature 17, and R² is 0.575. x₄ only enters at top 10.
  • Lasso, walk λ down from 1.5. 2, 3, then 5 features with no noise, all linear; x₄ first appears at λ = 0.2, together with four noise features (R² 0.852). Smaller penalties add more noise: 11 noise features at λ = 0.02. Here it always kept x₀ and dropped its copy.
  • Compare with all 20 features. R² 0.844, only a little below the true five. With 300 rows, carrying noise costs less than missing a real effect, which is why selection should be judged by validated performance, not by how short the list is.

Selection inside cross-validation

Any selection that looks at the target is part of the model and must be refitted inside every training fold; otherwise the validation rows help choose the features they are scored on, and the score is inflated, dramatically so when there are many features and few rows (Chapter 24). Put the selector in a pipeline, and if the number of features is tuned, use nested cross-validation to estimate the final performance. Check stability too: rerun the selection on bootstrap samples and see which features are chosen consistently. A feature picked in 3 runs out of 10 is not a finding.

Use case: the challenge that planted fake features

In 2003 Isabelle Guyon and colleagues ran a feature selection challenge alongside the NIPS conference, with five classification datasets drawn from cancer diagnosis, text, drug discovery and handwriting. Their twist was to add probes: thousands of artificial features with no relation to the labels, mixed in with the real ones, and the organisers knew which were which. One dataset, Madelon, was entirely synthetic: 500 features, of which only 20 were real, 5 informative and 15 combinations of them, arranged so that the classes formed an XOR-like pattern that no single feature revealed on its own. Univariate filters struggled with it, because each informative feature looked useless alone. Because the probes were known, the organisers could measure not just accuracy but how many fake features each entry had selected. The probe idea has outlived the competition: adding a few columns of random noise to your own data and checking where they land in your feature ranking is one of the cheapest sanity checks for any selection method. A feature that ranks below random noise has not earned its place.

⚠️
Common mistakes
  • Selecting features on all the data before cross-validating.
  • Using correlation alone, missing non-linear and interaction effects.
  • Reading the lasso's choice among correlated features as which one really matters.
  • Dropping features for interpretability without checking the cost in accuracy.
  • Trusting an unstable selection that changes with every resample.
  • Selecting by p-values from many tests without correcting for multiple comparisons.

Interview drill

Explain it simply: What are filter, wrapper and embedded feature selection methods?

How a strong answer sounds
Filter methods score each feature on its own against the target, for example by correlation or mutual information, and keep the top ones; they are fast but cannot see redundancy or features that only help in combination. Wrapper methods try subsets of features by actually training a model on them, such as recursive feature elimination; they account for redundancy and the real model, but are slow and can overfit the search. Embedded methods select while training, like the lasso, which pushes useless coefficients to exactly zero, or tree models, whose importances rank features as a side effect of fitting.

Deeper: You have 2,000 features and 400 rows. How do you select features and report performance honestly?

How a strong answer sounds
With five times more features than rows, chance correlations are guaranteed, so the main risk is selection bias. I would put every step that looks at the target, filtering, selection and the model, into one pipeline and evaluate it with nested cross-validation: the inner loop chooses the number of features and hyperparameters, the outer loop estimates performance. For the selector I would start with a regularised embedded method, such as an L1 or elastic net logistic regression, possibly after a mild filter, and compare against using all features with strong regularisation, which is often as good. I would add random probe features to check that the selection ranks them low, measure stability by repeating selection on bootstrap samples, and report the outer-loop score with its spread, plus a permutation test on shuffled labels to show what score pure noise achieves with the same procedure.

🧠 Key takeaways

  • Filters are fast but judge features one at a time; correlation misses non-linear effects, mutual information does not.
  • Wrappers such as RFE account for redundancy and the model, at a computational cost.
  • L1 selects while fitting, but chooses arbitrarily among correlated features and tends to keep some noise.
  • Selection is part of the model: refit it inside every cross-validation fold.
  • Check stability and compare against random probe features.

Check your understanding

A feature affects the target through a U-shape centred on its mean. What will its Pearson correlation with the target be?

The rising and falling halves cancel. Mutual information, which measures any dependence, will still be clearly positive.

What does recursive feature elimination do?

It is a wrapper: the model is refitted after each removal, so redundancy is taken into account.

Two features are near-copies of each other. What does the lasso tend to do?

The L1 penalty does not care which copy carries the signal. Elastic net, which adds an L2 term, spreads weight more evenly.

Why must feature selection run inside each cross-validation fold?

Selection that sees the target is training. Doing it on all rows leaks validation information into the model.

You add three columns of random noise, and one of them ranks 4th in your feature importance. What should you conclude?

Random probes give a floor. Anything ranking below them has no evidence of being useful.
