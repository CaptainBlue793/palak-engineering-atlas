Imbalanced Data

Fraudulent card payments, failing machine parts, rare diseases, customers about to leave: the cases worth predicting are often the rare ones. When 1 row in 100 is positive, a model that always says "no" is 99% accurate and completely useless, and a model trained to minimise errors on such data learns to say "no" almost every time.

This chapter covers the standard remedies: weighting the rare class, resampling the training data, generating synthetic examples with SMOTE, and the one that is often enough on its own, moving the decision threshold. It also covers the step that ties them together, deciding what each kind of mistake costs and measuring that rather than accuracy.

  • Explain why accuracy and a 0.5 threshold mislead on imbalanced data
  • Use class weights, under-sampling, over-sampling and SMOTE
  • Move the decision threshold to match the costs of errors
  • Evaluate with precision-recall curves and expected cost
  • Know which remedies change the ranking and which only change the threshold

Why accuracy lies

With a positive rate of 1%, predicting "negative" for every row scores 99% accuracy. Accuracy counts every error the same and is dominated by the majority class, so it says almost nothing about the rare one. The same goes for a model's default behaviour: logistic regression and most other classifiers minimise average loss, and the cheapest way to do that is to be confidently negative almost everywhere. On a synthetic problem with 1.1% positives, logistic regression reached 98.98% test accuracy, barely above the 98.87% of always saying "no", and at the default 0.5 threshold it caught just 11% of the positives.

The model was not useless; the threshold was. Its predicted probabilities ranked positives above negatives reasonably well (ROC AUC 0.79), but positives seldom reach a probability of 0.5 when they make up 1% of the data. Measure imbalanced problems with precision and recall for the rare class, the precision-recall curve and its summary, average precision, and, best of all, the expected cost of the decisions you will actually make.

Class weights and resampling

Class weights multiply each row's loss by a weight for its class. class_weight="balanced" uses n / (K·nₖ), so each class contributes equally to the loss in total, and errors on the rare class become expensive. Random under-sampling discards majority rows until the classes are balanced: fast, but it throws away data. Random over-sampling duplicates minority rows: no information is lost, but the model can memorise the duplicates. SMOTE (Synthetic Minority Over-sampling Technique, Nitesh Chawla and colleagues, 2002) creates new minority points on the line segments between a minority point and one of its k nearest minority neighbours, which spreads the minority region rather than stacking copies.

Resample only the training data, and only inside each cross-validation fold; the validation and test sets must keep the real class ratio, or your metrics describe a world that does not exist. A resampling step inside an imbalanced-learn pipeline does this automatically.

from sklearn.linear_model import LogisticRegression
from imblearn.pipeline import make_pipeline       # pip install imbalanced-learn
from imblearn.over_sampling import SMOTE

weighted = LogisticRegression(class_weight="balanced", max_iter=2000)
smote = make_pipeline(SMOTE(k_neighbors=5, random_state=0), LogisticRegression(max_iter=2000))
# resampling runs in fit() only, so cross-validation scores each fold on its real class ratio
# 1.1% positives: plain LR recall 0.110 at threshold 0.5; balanced weights recall 0.717, precision 0.034

Things to try.

  • Start as is, 1% positives, threshold 0.5, misses costing 20×. The model catches 9 of 214 positives. Its accuracy, 98.87%, is below the 98.93% of flagging nothing, and the cost is 206 per 1,000 payments.
  • Lower the threshold to 0.05, close to the theoretical 1/21 = 0.048. Recall rises to 0.57, precision is 0.15, accuracy falls to 96.2%, and the cost drops to 126. The green dot, the best threshold on the grid, is 0.032 at 121. Nothing was retrained.
  • Try Class weights at threshold 0.5. Recall jumps to 0.90 with precision 0.07, at a cost of 143. Its own best threshold (0.71) reaches 121: the same as the untouched model at its best. Over-sampling also reaches 121; under-sampling 128 and SMOTE 127.
  • Make misses cost 100×. At 0.5 the untouched model costs 1,026 per 1,000; at threshold 0.01 it costs 227, and the best on the grid is 0.0089, against the theoretical 1/101 = 0.0099.
  • Slide the positive rate from 0.5% to 20%. ROC AUC stays near 0.95 throughout, while average precision climbs from 0.09 to 0.80. ROC AUC does not show how hard rare positives are to find among many negatives; average precision does.

Threshold moving and cost

If a model's probabilities are calibrated and a missed positive costs c_FN while a false alarm costs c_FP, the decision that minimises expected cost is to flag a row when p > c_FP / (c_FP + c_FN). With a missed fraud 100 times as costly as a false alarm, that threshold is 1/101 ≈ 0.0099. scikit-learn's TunedThresholdClassifierCV finds the best threshold by cross-validation for any scoring function; on the synthetic problem above, with costs of 100 to 1, it chose 0.0101 and cut the cost from 1,008 to 583 per 1,000 rows, without retraining anything.

from sklearn.model_selection import TunedThresholdClassifierCV
from sklearn.metrics import make_scorer

def neg_cost(y, y_pred):                     # a missed positive costs 100, a false alarm 1
    return -(100 * ((y_pred == 0) & (y == 1)).sum() + ((y_pred == 1) & (y == 0)).sum())

tuned = TunedThresholdClassifierCV(LogisticRegression(max_iter=2000), scoring=make_scorer(neg_cost), cv=5)
tuned.fit(X_train, y_train).best_threshold_   # 0.0101; theory says 1 / 101 = 0.0099

Weights and resampling mostly do the same thing as moving the threshold: they shift the model's probabilities upwards for the rare class. They can also change the shape of the boundary, because the model now pays more attention to the minority region, and that sometimes helps the ranking and sometimes hurts it. In the same experiment, balanced weights raised ROC AUC from 0.790 to 0.813 but lowered average precision from 0.293 to 0.177. Their probabilities are also no longer calibrated to the real rate. The practical order is: get a model that ranks well (a gradient-boosted model reached average precision 0.558 here), then choose the threshold for your costs, and reach for resampling only if validation shows it helps.

Use case: spotting oil spills from orbit

In 1998 Miroslav Kubat, Robert Holte and Stan Matwin described a system for detecting oil spills in satellite radar images of the sea, built with the Canadian company Macdonald Dettwiler. Oil calms the surface and shows up as a dark patch, but so do many natural phenomena, the "look-alikes". Their data had 41 genuine spills against 896 look-alikes. A classifier could reach about 96% accuracy by calling everything a look-alike, which is exactly what several standard learners came close to doing. The authors argued that accuracy was the wrong measure for such problems, evaluated with the geometric mean of the accuracy on each class instead, and trimmed the majority class with "one-sided selection", removing redundant and borderline look-alikes before training. The paper became one of the standard references for learning from imbalanced classes, alongside the SMOTE paper four years later, and its framing still applies: decide what the rare class is worth, measure that, and do not let the majority class choose the model for you.

⚠️
Common mistakes
  • Reporting accuracy, or ROC AUC alone, when positives are very rare; show precision, recall and average precision.
  • Resampling before the train-test split, so duplicated or synthetic points leak into the test set.
  • Evaluating on a rebalanced test set, which inflates precision far above what production will see.
  • Keeping the 0.5 threshold after changing weights or the class ratio, or without considering costs.
  • Using probabilities from a weighted or resampled model as real risks without recalibrating.
  • Too few positives in validation for the estimates to mean anything; check the counts, not just the rates.

Interview drill

Explain it simply: Why is accuracy a bad metric for fraud detection?

How a strong answer sounds
Because fraud is rare. If one transaction in a thousand is fraudulent, a model that never flags anything is 99.9% accurate and catches no fraud at all. Accuracy treats a missed fraud and a false alarm as equally bad and is dominated by the huge number of normal transactions. Instead I would look at recall, the share of fraud we catch, precision, the share of flagged transactions that really are fraud, the precision-recall curve, and ideally the money: the cost of missed fraud against the cost of investigating false alarms.

Deeper: You have 0.5% positives. Walk me through how you would build and tune the classifier.

How a strong answer sounds
First I would agree the costs of a missed positive and a false alarm with the business, and check how many positives I actually have, since a few hundred limits how complex the model and validation can be. I would split with stratification, or by time if the data drifts, and keep validation and test at the real rate. I would train a model that ranks well, often gradient boosting, and select it by average precision rather than accuracy. Then I would choose the threshold that minimises expected cost on validation, which for calibrated probabilities is c_FP over c_FP plus c_FN, or tune it with TunedThresholdClassifierCV. Class weights or resampling are experiments I would keep only if they improve validation cost or average precision, with resampling inside the cross-validation folds only. Finally, if downstream users need probabilities, I would calibrate on data at the true rate, and I would monitor precision and recall in production, since the positive rate itself often changes.

🧠 Key takeaways

  • With rare positives, accuracy rewards ignoring them; measure precision, recall, average precision and cost.
  • A low recall at threshold 0.5 often means the threshold is wrong, not the model.
  • The cost-optimal threshold for calibrated probabilities is c_FP / (c_FP + c_FN).
  • Class weights and resampling mostly shift probabilities; keep them only if validation improves.
  • Resample training data only, inside each fold, and evaluate at the real class ratio.
  • Train for good ranking, then let costs choose the threshold.

Check your understanding

2% of rows are positive. What accuracy does a model that always predicts negative achieve?

It is right on every negative, 98% of rows, and wrong on every positive. That is the baseline any useful model must beat on the measures that matter.

A missed positive costs 9 times a false alarm, and the model's probabilities are calibrated. Which threshold minimises expected cost?

Flag when p > c_FP / (c_FP + c_FN) = 1 / (1 + 9) = 0.1.

When should resampling such as SMOTE be applied?

Resampling before splitting leaks copies or interpolations of test points into training, and balanced evaluation sets misstate real precision.

How does SMOTE create new minority examples?

Each synthetic point lies on the segment between a minority point and a randomly chosen one of its k nearest minority neighbours.

A model trained with class_weight="balanced" outputs 0.6 for a transaction. What can you conclude?

Weighting changes the effective class ratio, so the outputs are not calibrated to the real rate. Recalibrate if you need risks.
