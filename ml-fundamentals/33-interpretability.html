Model Interpretability

A gradient-boosted model with five hundred trees can be accurate and impossible to read. Yet people need to know why: a customer refused a loan is owed reasons, a doctor will not act on a risk score they cannot question, and a data scientist needs to know whether the model learned the problem or a quirk of the data. Interpretability methods probe a trained model from outside to answer two kinds of question: what drives the model overall, and why it made this particular prediction.

This chapter covers the standard tools, permutation importance, partial dependence and individual conditional expectation, and SHAP values, by computing them in the page for a house-price model whose true behaviour we know. It also shows the most important lesson about them: an explanation describes the model, not the world, and correlated features can make two equally accurate models tell completely different stories.

  • Distinguish global from local explanations
  • Compute and read permutation importance
  • Use partial dependence and ICE plots, and spot interactions
  • Explain a single prediction with Shapley values
  • Recognise when explanations mislead: correlated features, extrapolation and causal over-reading

Global and local

Global explanations describe the model as a whole: which features matter most, and how predictions change as a feature changes. Local explanations describe one prediction: why this house was valued at £410,000, why this applicant was declined. Some models are interpretable by construction, such as a short decision tree, a sparse linear model or a generalised additive model; the methods here are model-agnostic, treating any model as a black box that can be queried.

Permutation importance

Shuffle one feature's column in a held-out set, breaking its link with the target while keeping its distribution, and measure how much the model's score drops. A big drop means the model relies on that feature. It works for any model, measures importance for prediction on data the model has not seen, and avoids the bias of impurity-based importance. Its main weakness is correlated features: if two features carry the same information, shuffling one leaves the other to stand in, so both look less important than the information they share. On California housing, a random forest's permutation importance for median income was 1.319; after adding a near-copy of that column, it was 0.590 for the original and 0.159 for the copy, with the same accuracy.

from sklearn.inspection import permutation_importance, PartialDependenceDisplay

r = permutation_importance(model, X_test, y_test, n_repeats=10, random_state=0)
r.importances_mean                                    # drop in score when each column is shuffled
PartialDependenceDisplay.from_estimator(model, X_test, ["MedInc"], kind="both")   # PDP plus ICE lines

Partial dependence and ICE

A partial dependence plot (PDP; Jerome Friedman, 2001) shows how the average prediction changes as one feature is set to each value in turn for every row, with the other features left as they are. An ICE plot (individual conditional expectation) draws that curve separately for each row; the PDP is their average. When ICE lines are parallel, the feature acts the same way everywhere; when they fan out or cross, it interacts with other features, and the average can hide effects in opposite directions. Both rely on setting a feature to values that may never occur alongside the row's other features, such as a 40 m² flat with eight rooms, so with correlated features they can describe the model in regions it never saw.

SHAP values

Shapley values come from cooperative game theory (Lloyd Shapley, 1953): they divide a total payout fairly among players by averaging each player's marginal contribution over every order in which the players could join. SHAP (Scott Lundberg and Su-In Lee, 2017) applies this to predictions: the players are features, and the payout is the difference between this prediction and the average prediction. The values add up exactly: base value plus the contributions equals the prediction. Averaging their absolute values over many rows gives a global importance, and plotting them against feature values gives a dependence plot. Exact computation needs every subset of features, so libraries use model-specific shortcuts, such as TreeSHAP for tree ensembles, or sampling.

import shap                                       # pip install shap

explainer = shap.Explainer(model, X_background)    # TreeSHAP is chosen automatically for tree models
sv = explainer(X_test)
shap.plots.waterfall(sv[0])                        # one prediction, feature by feature
shap.plots.beeswarm(sv)                            # global view: every row's values for every feature

Simulator: explaining a house-price model

500 houses with four features: floor area, number of rooms (which tracks floor area closely), age and a location score. Floor area and rooms are two noisy measures of the same underlying size. Two models predict prices about equally well: model A uses floor area, model B uses the number of rooms instead. Everything here is computed in the page: permutation importance and exact Shapley values (all 16 subsets of the 4 features, against a background of 100 houses), PDP and ICE curves.

Use case: the model that said asthma was protective

In the 1990s a large research project on cost-effective health care trained several models to predict the risk of death for pneumonia patients, so that low-risk patients could be treated at home. One of the models was a set of rules, and Rich Caruana, who worked on a neural network for the same project, later described what the rules revealed: patients with asthma were predicted to have lower risk. The pattern was real in the data. Asthmatic patients with pneumonia were usually admitted straight away, often to intensive care, and the aggressive treatment made them less likely to die. A model that learned it would send exactly the most vulnerable patients home. The neural network was more accurate, but nobody could see whether it had learned the same thing, so the project used the simpler model. In 2015 Caruana and colleagues returned to the data with an accurate but intelligible model, a generalised additive model with pairwise interactions, and found the asthma effect and several others like it, such as a lower predicted risk for patients with chest pain or heart disease, who also received faster care. The lesson is the one this chapter keeps returning to: an explanation shows what the model learned from the data, which includes the consequences of how people were treated, and someone who knows the domain has to look.

⚠️
Common mistakes
  • Reading importance as causal effect, and promising that changing a feature will change the outcome.
  • Ignoring correlated features when ranking importances.
  • Using impurity importance instead of permutation importance or SHAP on held-out data.
  • Showing only a PDP when ICE curves would reveal interactions.
  • Explaining on training data, where an overfitted model's quirks look like signal.
  • Treating SHAP values as the truth about the world rather than about one model.

Interview drill

Explain it simply: What are SHAP values?

How a strong answer sounds
SHAP values explain a single prediction by splitting the difference between that prediction and the model's average prediction among the features. Each feature gets a number saying how much it pushed this prediction up or down, and the numbers add up exactly to the difference. The split is done fairly, using an idea from game theory: each feature's contribution is averaged over all the orders in which features could be added. So for a house valued well above average, you might see that its location added £60,000, its size added £40,000 and its age took off £10,000.

Deeper: Two models with the same accuracy give different top features. Which explanation is right?

How a strong answer sounds
Both can be right about their own model. Explanations describe how a particular model uses its inputs, not how the world works. When features are correlated, many different models fit the data equally well, one relying on floor area, another on the number of rooms, and their explanations will differ. I would check the correlations, group strongly related features and report importance per group, look at whether the models' predictions actually differ on realistic data, and avoid causal language. If the question is causal, what would happen if we changed something, I would need an experiment or a causal analysis, not a feature attribution. And if one explanation contradicts domain knowledge, that is a reason to investigate the data or the model, not to pick the explanation that sounds better.

🧠 Key takeaways

  • Global explanations describe the whole model; local ones explain a single prediction.
  • Permutation importance measures how much held-out performance depends on a feature.
  • PDPs show average effects; ICE curves reveal interactions the average hides.
  • SHAP splits a prediction into additive, fairly assigned feature contributions.
  • Correlated features make importance unstable: equally good models can disagree.
  • Explanations describe the model, not causation in the world.

Check your understanding

How is permutation importance computed?

Shuffling breaks the feature's link with the target while keeping its distribution; no retraining is needed.

A model uses two nearly identical features. What typically happens to their permutation importances?

When one copy is shuffled the model still has the other. Group correlated features to measure their joint importance.

ICE curves for a feature fan out in different directions, while the PDP is nearly flat. What does that suggest?

The PDP averages the ICE curves. Opposite effects in different rows average out to a flat line.

What property do SHAP values have for a single prediction?

Additivity, or local accuracy, is one of the defining properties of Shapley values.

A model predicts lower pneumonia mortality for asthma patients. What is the most likely explanation?

The model learned a real pattern in the data caused by treatment decisions. Deploying it to decide treatment would be dangerous.
