Feature Engineering for Numbers

A model can only learn from what its features let it see. A linear model given raw income cannot learn that the first £10,000 of extra income changes spending far more than the hundredth; given log income, it learns that in one weight. Feature engineering is the work of reshaping raw columns so that the patterns in them are within reach of the model you are using.

This chapter covers the transformations for numeric columns: scaling, logs and other power transforms, binning, ratios and interactions, and polynomial and spline expansions, with a clear answer to which models need which. The simulator fits the same linear model to one skewed feature after each transformation, then shows what each scaler does when a column contains a few huge outliers.

  • Choose between standard, min-max, robust and quantile scaling
  • Use log and power transforms on skewed features and targets
  • Bin a feature, and know what binning costs
  • Build ratio, interaction, polynomial and spline features
  • Say which models need scaling and which barely care

Scaling

Scaling changes a feature's units without changing its shape. It matters for any model that compares features by size: distances (k-NN, k-means, SVMs with RBF kernels), penalties (ridge, lasso, regularised logistic regression), and gradient descent. Trees split on one feature at a time by thresholds, so they are indifferent to scaling.

Transforms for shape

A transform changes a feature's shape. The log is the workhorse: incomes, prices, populations, counts and latencies usually vary by multiples, and their logs are closer to symmetric, with a relationship to the target that is closer to straight. Use np.log1p (log of 1 + x) when zeros occur. Power transforms (Box-Cox for positive data, Yeo-Johnson for any sign) search for the power that makes a column most normal-looking. And the same idea applies to the target: predicting log(price) and exponentiating back often fits better and makes errors proportional to price (Chapter 2).

from sklearn.preprocessing import FunctionTransformer, PowerTransformer, KBinsDiscretizer, PolynomialFeatures, SplineTransformer
from sklearn.compose import TransformedTargetRegressor

log_tf = FunctionTransformer(np.log1p)                       # log(1 + x): safe at zero
yeo = PowerTransformer(method="yeo-johnson")                   # learns the best power per column
bins = KBinsDiscretizer(n_bins=10, strategy="quantile", encode="onehot")
poly = PolynomialFeatures(degree=2, include_bias=False)          # squares and pairwise products
spline = SplineTransformer(n_knots=6, degree=3)                 # smooth, local curves

model = TransformedTargetRegressor(regressor=Ridge(), func=np.log1p, inverse_func=np.expm1)   # log the target

Binning, ratios and interactions

Binning cuts a feature into ranges and replaces it with "which range". It lets a linear model fit any shape as a staircase, and it is robust to outliers, at the cost of throwing away detail within each bin and adding a column per bin. Quantile bins, with equal numbers of rows each, are usually better than equal-width ones on skewed data.

Ratios and differences encode what domain knowledge says matters: price per square metre, debt over income, rooms per person, days between signup and first purchase. A linear model cannot divide one column by another on its own, and even trees, which can approximate a ratio, need many splits to do it. Interactions, products of features, let a linear model express "the effect of x depends on z". PolynomialFeatures builds all squares and products automatically, which grows quickly: degree 2 on 50 features is 1,325 columns.

Use case: the features that moved a valuation model

A property-valuation team starts with what the listings give them: floor area, plot size, number of rooms, year built, postcode, and the last sale price and date. A linear model on those columns does badly, and the reasons are all in this chapter. Prices vary by multiples, so they model log(price). Price scales with area, so they add price per square metre for the postcode from recent sales, a ratio built from other rows. The effect of age is not linear, with new builds at a premium, a dip for 1960s and 70s stock, and old period properties valued again, so year built goes in as a spline. And the last sale price is only useful once it is adjusted by how far the local market has moved since, a product of two columns. With those changes a regularised linear model gets close to a gradient-boosted model on the raw columns, and stays much easier to explain to a mortgage lender. Gradient boosting on the engineered features is better than either, because the ratios helped it too.

⚠️
Common mistakes
  • Fitting scalers or binners on the full dataset, leaking the validation rows' statistics into training.
  • Min-max scaling a column with outliers, which crushes every normal value into a tiny range.
  • Taking the log of zero or negative values; use log1p or Yeo-Johnson.
  • High-degree polynomials, which explode at the edges of the data (Chapter 11); prefer splines.
  • Scaling for tree models and expecting it to change anything.
  • Forgetting to transform new data the same way: the fitted transformer must ship with the model (Chapter 24).

Interview drill

Explain it simply: When do you need to scale features, and which scaler would you use?

How a strong answer sounds
Whenever the model compares features by magnitude: distance-based models like k-NN, k-means and RBF SVMs, regularised linear and logistic regression where the penalty acts on weights, and anything trained with gradient descent, including neural networks. Tree-based models split on one feature at a time and do not care. StandardScaler is the default; RobustScaler, which uses the median and interquartile range, is better when a column has outliers I want to keep; MinMaxScaler suits bounded features without outliers; QuantileTransformer suits very heavy tails. In every case the scaler is fitted on the training data only, inside a pipeline, so the same transformation is applied at prediction time.

Deeper: A linear model predicting delivery time does well on short routes and badly on long ones. What feature work would you try?

How a strong answer sounds
First I would look at residuals against distance and against the prediction. Errors that grow with route length suggest a multiplicative relationship, so I would try predicting log time, which also makes the errors roughly proportional. If the residuals curve against distance, I would give the model a spline on distance, or bins, so it can bend: very short routes have fixed overheads like loading and parking, long ones are dominated by speed. Then interactions that domain knowledge suggests: distance times a rush-hour flag, or distance divided by an average speed for that road type, which turns two weak features into one strong ratio. Number of stops matters more than distance for multi-drop routes, so stops per kilometre could help. I would add each change one at a time and check validation error by route-length band, and I would compare with gradient boosting on the raw features to see how much of the gap is the model's shape rather than missing information.

🧠 Key takeaways

  • Scaling changes units, not shape; it matters for distances, penalties and gradient descent, not for trees.
  • Min-max scaling is ruined by outliers; robust or quantile scaling copes.
  • Logs and power transforms straighten skewed features and targets that vary by multiples.
  • Bins, splines and polynomials let linear models bend; splines are the safest of the three.
  • Ratios and interactions encode domain knowledge that even flexible models find hard to build.
  • Fit every transform on training data inside a pipeline, and ship it with the model.

Check your understanding

A column has typical values between 10 and 90 and one value of 50,000. What does MinMaxScaler do to the typical values?

The range is set by the minimum and the outlier, so 10 to 90 maps to roughly 0 to 0.0016. Robust or quantile scaling avoids this.

Which model is least affected by whether features are scaled?

Trees split one feature at a time by thresholds, which depend only on the order of values, not their scale.

Spending rises steeply with income at first and then flattens. Which single feature lets plain linear regression fit it best?

A curve that rises fast and then flattens is close to a logarithm, so log(income) turns it into a straight-line relationship.

Why would you build "price per square metre" when the model already has price and floor area?

Linear models only add weighted features. A ratio encodes knowledge they cannot construct, and even trees need many splits to approximate it.

A feature contains zeros and positive values. Which transform is safe for reducing its skew?

log1p computes log(1 + x), which is defined at zero. Plain log and 1/x fail at zero, and min-max scaling does not change shape.
