NumPy Arrays & Vectorisation

Every dataset in this course ends up as a NumPy array: a feature matrix X with one row per example and one column per feature, and a target vector y. scikit-learn takes arrays in and gives arrays back, and pandas is built on top of them. Knowing how arrays are shaped, and how NumPy combines arrays of different shapes, is most of what makes ML code short, fast and correct.

The idea that ties it together is vectorisation: say what should happen to a whole array in one expression, and let compiled code do the looping. The simulator covers the rule that makes that possible for arrays of different shapes, broadcasting, including the quiet version of it that turns a five-element subtraction into a five-by-five matrix.

Why arrays, not lists

A Python list of a million numbers is a million separate Python objects scattered around memory, plus a list of a million pointers to them. A NumPy array of a million numbers is one block of eight million bytes, every element the same type, side by side. That layout is the whole story: compiled code can walk a contiguous block of identical values at full hardware speed, while a list must be walked one object at a time by the interpreter.

Creating arrays, and their dtype

import numpy as np

a = np.array([1, 2, 3])            # dtype int64 (on Linux and macOS; Windows NumPy 1.x used int32)
b = np.array([1, 2.5, 3])          # float64: one float makes them all floats
c = np.array([1, "a"])              # <U21: everything became text, silently

np.zeros((3, 4))                      # 3 rows, 4 columns of 0.0
np.arange(0, 10, 2)                    # [0 2 4 6 8]
np.linspace(0, 1, 5)                    # [0.   0.25 0.5  0.75 1.  ]
rng = np.random.default_rng(0)
X = rng.normal(size=(1000, 8))           # 1,000 examples, 8 features

X.dtype, X.shape, X.ndim, X.nbytes      # float64, (1000, 8), 2, 64000
counts = np.array(["3", "5"]).astype(int)   # convert explicitly with astype

The dtype is chosen once for the whole array, from the "widest" value given. One stray string in a column of numbers turns the entire array into text, and arithmetic on it then fails. When data comes from a file, always check .dtype before computing anything.

Shapes and axes

ML code has a convention you will see everywhere in scikit-learn: X has shape (n_samples, n_features), one row per example, and y has shape (n_samples,), a flat vector. Most aggregations take an axis argument, and it names the axis that is collapsed.

X.shape                      # (1000, 8)
X.mean(axis=0)                # shape (8,): one mean per feature, averaged down the rows
X.mean(axis=1)                # shape (1000,): one mean per example, across its features
X.mean()                      # a single number over everything

y = rng.integers(0, 2, size=1000)    # shape (1000,)
y.reshape(-1, 1).shape           # (1000, 1): -1 means "whatever fits"
X[:, 0].shape                  # (1000,): one column, as a flat vector
X[:, [0]].shape                # (1000, 1): one column, kept two-dimensional

The difference between (1000,) and (1000, 1) looks cosmetic. It is not. A flat vector has one axis; a column has two. Mixing them is the source of one of the most common silent bugs in ML code, which the simulator below reproduces.

Broadcasting

To standardise features, you subtract each column's mean and divide by its standard deviation. X is (1000, 8) and the means are (8,); NumPy still lets you write X - X.mean(axis=0). The rule that allows it is broadcasting, and it is short:

  1. Line the two shapes up from the right. If one has fewer dimensions, pad it on the left with 1s.
  2. Compare each pair of sizes. They are compatible if they are equal, or if one of them is 1.
  3. The result takes the larger size in each position. A size-1 axis is stretched to match, without copying any data.
  4. If any pair is unequal and neither is 1, NumPy raises ValueError: operands could not be broadcast together.
mu = X.mean(axis=0)            # (8,)
sd = X.std(axis=0)             # (8,)
Z = (X - mu) / sd               # (1000, 8) - (8,)  ->  (1000, 8): each column standardised

row_means = X.mean(axis=1)     # (1000,)
X - row_means                   # ValueError: (1000,8) and (1000,) do not line up from the right
X - row_means[:, None]          # (1000, 8) - (1000, 1): each row centred

Things to try.

  • (3, 4) and (4,). The row of four is stretched down three rows: this is X - X.mean(axis=0).
  • (3, 4) and (3,). It fails. Lined up from the right, 4 meets 3. Turning the vector into a column, (3, 1), fixes it.
  • (3, 1) and (1, 4). Both are stretched, and two small arrays produce a 3 × 4 table: an "outer" operation in one line.
  • The bug preset: (5,) and (5, 1). Predictions as a column minus labels as a flat vector. No error at all: the result is a 5 × 5 matrix of every prediction minus every label, and its mean is a meaningless number that looks like a plausible error.

Vectorisation: let NumPy do the loop

A vectorised expression describes an operation on whole arrays: (x * x).sum() instead of a for loop accumulating squares. The loop still happens, but in compiled code over contiguous memory, without the interpreter unpacking a Python object for every element.

x = rng.random(1_000_000)
xs = x.tolist()

def sum_sq_loop(values):
    s = 0.0
    for v in values:
        s += v * v
    return s

# in a notebook, %timeit measures each one properly
%timeit sum_sq_loop(xs)      # about 80 ms
%timeit (x * x).sum()          # about 3.5 ms: 23 times faster
%timeit np.dot(x, x)           # about 0.2 ms: 360 times faster (an optimised BLAS routine, no temporary array)

Those numbers were measured on the laptop this chapter was written on, with Python 3.11 and NumPy 2.4; yours will differ, but the ratios hold in their order of magnitude. Notice the gap between the last two lines: (x * x).sum() first builds a temporary array of a million squares, while np.dot computes the same sum in one pass. Vectorising removes the interpreter; choosing the right function also removes the extra memory traffic.

Conditionals vectorise too. Instead of an if inside a loop, use np.where(condition, a, b), or a boolean mask.

Boolean masks, and views versus copies

A comparison on an array produces an array of True and False, a mask, and indexing with a mask keeps the rows where it is True. Masks combine with &, | and ~, and each comparison needs its own parentheses because those operators bind more tightly than >.

positives = X[y == 1]                         # rows of the positive class
mask = (X[:, 0] > 0) & (X[:, 1] < 2)        # parentheses are required
X_clipped = np.where(X > 3, 3, X)             # cap values at 3, elementwise

a = np.arange(12).reshape(3, 4)
b = a[:, :2]          # slicing returns a VIEW: the same memory
b[0, 0] = 99
a[0, 0]               # 99 -- the original changed too

c = a[a > 5]          # masks and integer lists return a COPY
np.shares_memory(a, b), np.shares_memory(a, c)    # (True, False)
safe = a[:, :2].copy()                           # ask for a copy when you mean one

Views are why slicing a large array is instant: nothing is copied. They are also why editing a slice can quietly change the training data you thought you had left alone. The rule to remember: basic slicing (a[1:3], a[:, 0]) gives a view; masks and lists of indices give a copy.

Use case: a per-customer feature over ten million transactions

A fraud model wants, for every card transaction, how unusual its amount is for that customer: the amount minus the customer's average, divided by the customer's standard deviation. Written as a loop, that is a dictionary lookup and some arithmetic per row in the interpreter, ten million times. Written with arrays, it is three lines. Map each customer ID to an integer index once; compute the per-customer mean and standard deviation into two arrays of length "number of customers" (with np.bincount, or a pandas groupby from the next chapter); then z = (amount - mean[cust]) / std[cust]. The expression mean[cust] is integer-array indexing: it gathers one mean per transaction, a new array of ten million, in compiled code. The whole feature runs in well under a second, and it reads like the formula it implements, which is the other reason to vectorise.

⚠️
Common mistakes
  • Subtracting a (n,) vector and a (n, 1) column. The result is (n, n), not an error. Check shapes with .shape or an assert.
  • Using the wrong axis. axis=0 gives one value per column (per feature), axis=1 one per row.
  • One string in a numeric array, which makes the whole dtype text.
  • Editing a slice and changing the original array through the view.
  • Writing X[:, 0] > 0 & X[:, 1] < 2 without parentheses. & binds first and the expression is wrong or raises.
  • Using Python's and/or on arrays. They need a single truth value and raise "The truth value of an array is ambiguous".
  • Appending to an array in a loop with np.append. Each call copies the whole array; collect into a list and convert once.

Interview drill

Explain it simply: What is broadcasting in NumPy?

How a strong answer sounds
Broadcasting is how NumPy combines arrays of different shapes in an elementwise operation. It lines the shapes up from the right, and two sizes are compatible if they are equal or one of them is 1; a size-1 axis is then stretched to match the other without copying data, and missing leading dimensions count as 1. So a (1000, 8) feature matrix minus an (8,) vector of column means subtracts each mean from its column. If two sizes differ and neither is 1, it raises an error. The danger is the case that succeeds by accident: a (n,) vector minus an (n, 1) column broadcasts to an n by n matrix with no warning, so I check shapes whenever I mix vectors and columns.

Deeper: Why is vectorised NumPy so much faster than a Python loop, and when can you not vectorise?

How a strong answer sounds
Three reasons. A Python loop pays interpreter overhead on every element: fetch the next object, check its type, unbox the float, dispatch the multiplication, allocate a new float object for the result. A NumPy array stores raw values of a single type in one contiguous block, so the loop over it runs in compiled C with no type checks or allocations per element. And contiguous memory lets that C code use the CPU caches well and SIMD instructions that process several numbers per instruction; some operations, like a dot product or a matrix multiply, go further and call an optimised BLAS library. In practice that is tens to hundreds of times faster. You cannot vectorise directly when each step depends on the previous one, such as a running state machine, a recursive filter or a simulation with branching; then the options are restructuring the problem, using a built-in that already does it, like np.cumsum, or compiling the loop with Numba or Cython. And sometimes vectorising costs memory, because it builds large temporary arrays, so for very large data you process in chunks.

🧠 Key takeaways

  • An array is one contiguous block of one dtype; check .dtype and .shape before computing.
  • X is (n_samples, n_features); axis=0 collapses rows and gives one value per feature.
  • Broadcasting aligns shapes from the right; sizes must match or be 1, and size-1 axes stretch without copying.
  • A (n,) vector and a (n, 1) column broadcast to (n, n), silently.
  • Vectorised code is tens to hundreds of times faster than a Python loop, and shorter.
  • Slices are views that share memory; masks and index lists return copies.

Check your understanding

What is the shape of A + B when A is (3, 4) and B is (4,)?

B is padded to (1, 4) and stretched down the three rows. This is the shape of subtracting column means from a feature matrix.

pred has shape (5, 1) and y has shape (5,). What does pred - y produce?

Aligned from the right, (5, 1) and (1, 5) are both stretched to (5, 5). Every prediction is subtracted from every label, and nothing warns you.

X has shape (100, 8). What is the shape of X.mean(axis=0)?

The axis you name is the one collapsed. Averaging down the 100 rows leaves one mean per feature.

After b = a[:, :2] and b[0, 0] = 99, what happens to a[0, 0]?

Basic slicing returns a view onto the same memory. A boolean mask or a list of indices would have returned a copy.

What is the dtype of np.array([1, 2.5, 3])?

An array has one dtype, chosen to hold every value. One float makes the whole array float64.
