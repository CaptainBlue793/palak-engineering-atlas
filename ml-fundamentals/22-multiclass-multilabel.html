Multi-Class & Multi-Label Problems

Most of the classifiers so far answered a yes-or-no question. Real problems often have more answers: which of ten digits, which of forty product categories, which department should handle this ticket. And sometimes several answers are right at once: a film can be a comedy and a romance, and a comment can be both insulting and threatening.

This chapter covers the two ways of building a multi-class model out of binary ones, one-vs-rest and one-vs-one, the natively multi-class softmax regression, and the different problem of multi-label outputs. It also covers the decision that changes your headline number most: whether to average a metric over classes (macro), over individual predictions (micro), or by class size (weighted).

One-vs-rest and one-vs-one

One-vs-rest (OvR, also one-vs-all) trains one binary classifier per class: this class against all the others. With K classes that is K models; to predict, run them all and pick the class whose model is most confident. It is simple and scales well, but each model sees a lopsided problem, one class against everything else, and the models' scores were not trained to be compared with each other.

One-vs-one (OvO) trains a classifier for every pair of classes, K(K − 1)/2 of them: 45 for the ten digits. Each is trained only on the rows of its two classes, so it is small and balanced; to predict, every pair votes. OvO is what scikit-learn's SVC uses internally, because kernel SVMs train much faster on several small problems than one big one.

Softmax regression

Logistic regression extends naturally to K classes. Give each class its own weight vector and compute a score zₖ = wₖ·x + bₖ. The softmax function turns scores into probabilities that are positive and sum to 1: P(class k | x) = exp(zₖ) / Σⱼ exp(zⱼ). Training minimises cross-entropy, the multi-class log loss: −log of the probability given to the true class. With two classes it reduces exactly to the sigmoid and binary log loss. Because all classes are fitted together, the probabilities are consistent with each other, which OvR's separate models are not. Neural network classifiers end with this same softmax layer.

from sklearn.linear_model import LogisticRegression
from sklearn.multiclass import OneVsRestClassifier, OneVsOneClassifier

softmax = LogisticRegression(max_iter=5000)                       # multinomial by default for 3+ classes
ovr = OneVsRestClassifier(LogisticRegression(max_iter=5000))     # 10 models for 10 digits
ovo = OneVsOneClassifier(LogisticRegression(max_iter=5000))      # 45 models
# scaled digits, 30% test: softmax 0.972 (0.05 s), OvR 0.969 (0.16 s), OvO 0.985 (0.44 s)

Things to try.

  • Start with softmax and class C at 5%. Accuracy is 0.907 and weighted F1 0.905, but class C's recall is only 0.56, and macro F1, 0.814, is the number that shows it.
  • Make C rarer: 2%. Accuracy goes up, to 0.921, while C's F1 falls to 0.46 and macro F1 to 0.757. Ignoring a rare class is rewarded by accuracy.
  • Switch to one-vs-rest at 2%. The C-versus-rest model sees 2% positives and seldom claims anything: C's recall drops to 0.13 and macro F1 to 0.673, against 0.757 for softmax. About 5% of the plane is hatched, where no binary model is more than 50% sure.
  • Make the classes even: 33%. Micro and weighted F1 are 0.866 and macro is 0.851: when classes are balanced, the averages tell nearly the same story.
  • Compare one-vs-one with softmax. They land close at every setting, for example macro F1 0.744 and 0.757 at 2%: with a linear model and three classes, the strategy matters less than how you measure.

Macro, micro and weighted averages

Precision, recall and F1 are defined per class. To report one number you have to average them, and the choice matters:

AverageHowAnswersDominated by
MicroPool every prediction, then compute onceHow good is the model per prediction?Large classes
MacroCompute per class, then take the plain meanHow good is it on a typical class?Weak classes, including rare ones
WeightedPer-class mean weighted by class sizeLike micro, but from per-class scoresLarge classes

On a three-class problem with 85%, 12% and 3% of rows, a logistic regression reached 89% accuracy, micro F1 0.89 and weighted F1 0.873, all respectable. Its F1 on the rarest class was 0: it never predicted it correctly. Macro F1 was 0.52 and was the only one of the four numbers to reveal the problem. Report macro when every class matters, which is most of the time when classes are imbalanced, and always look at the per-class numbers (classification_report).

Multi-label problems

In multi-label classification each row can have any number of labels. The target becomes a 0/1 matrix with one column per label, built with MultiLabelBinarizer. The simplest model is binary relevance: one independent binary classifier per label (MultiOutputClassifier). It ignores how labels go together; a classifier chain feeds each label's prediction into the next model, so it can learn that "romance" makes "comedy" more likely. Many models, including trees, k-NN and neural networks with one sigmoid output per label, handle multi-label targets directly.

Evaluation needs its own metrics. Subset accuracy counts a row as right only if every label is right, which is strict. Hamming loss is the share of individual label decisions that are wrong. Micro, macro and samples-averaged F1 average over label decisions, labels and rows respectively. On a synthetic problem with 5 labels and about 1.9 labels per row, a chain raised subset accuracy from 0.354 to 0.419, while its Hamming loss was slightly worse (0.215 against 0.211): which model is better depends on which metric matches the use.

from sklearn.preprocessing import MultiLabelBinarizer
from sklearn.multioutput import MultiOutputClassifier, ClassifierChain
from sklearn.metrics import hamming_loss, f1_score

Y = MultiLabelBinarizer().fit_transform([{"comedy", "romance"}, {"drama"}, ...])   # rows × labels, 0/1
chain = ClassifierChain(LogisticRegression(max_iter=2000), order="random", random_state=0).fit(X_tr, Y_tr)
P = chain.predict(X_te)
hamming_loss(Y_te, P), f1_score(Y_te, P, average="samples")

Use case: labelling toxic comments

In 2018 Jigsaw, a unit of Google, ran a Kaggle competition to classify about 160,000 Wikipedia talk-page comments, each labelled by human raters for six kinds of toxicity: toxic, severe toxic, obscene, threat, insult and identity hate. It was a multi-label problem in every sense. A comment could carry several labels at once, and the labels were strongly related: most severely toxic comments were also obscene and insulting. They were also very unequal in frequency: about one comment in ten was toxic, while threats were around 0.3%. A model that never predicted "threat" would lose almost nothing on accuracy or micro-averaged scores. The competition was scored with the mean ROC AUC over the six labels, a macro average, so performance on threats counted as much as performance on the common toxic label. Winning teams trained models with six sigmoid outputs sharing one network, which lets the related labels share what they learn.

⚠️
Common mistakes
  • Reporting accuracy or micro F1 alone on imbalanced classes, hiding a class the model never gets right.
  • Using softmax for a multi-label problem, which forces labels to compete for one unit of probability.
  • Comparing OvR scores as if they were calibrated probabilities across classes.
  • Treating ordered classes (low, medium, high) as unrelated, when ordinal or regression approaches fit better.
  • Stratifying multi-label splits by one label only, leaving rare labels missing from some folds.
  • Thresholding every label at 0.5 when label frequencies and costs differ.

Interview drill

Explain it simply: What is the difference between multi-class and multi-label classification?

How a strong answer sounds
In multi-class classification each example belongs to exactly one of several classes, like a handwritten digit being one of 0 to 9; the model picks one, usually with a softmax over the classes so the probabilities sum to one. In multi-label classification each example can have any number of labels at the same time, like a film being both a comedy and a romance; the model makes a separate yes-or-no decision for each label, usually with one sigmoid per label, and the evaluation looks at each label decision or each row's set of labels.

Deeper: Your five-class model has 94% accuracy, but the product team says it is useless for one class. How do you investigate and report it?

How a strong answer sounds
Accuracy and micro-averaged metrics are dominated by the large classes, so a model can ignore a small class and still score highly. I would print the per-class precision, recall and F1 and the confusion matrix to see which classes the troubled one is confused with, and report macro-averaged F1 alongside accuracy so every class counts equally. Then I would look at fixes: class weights or resampling during training, per-class decision thresholds rather than a plain argmax, more labelled data for that class, or features that separate it from the class it is confused with. Finally I would agree with the team which metric reflects the cost of errors in that class, and use it for model selection.

🧠 Key takeaways

  • One-vs-rest trains K models; one-vs-one trains K(K − 1)/2 on pairs; softmax regression fits all classes jointly.
  • Softmax with cross-entropy is the natural multi-class extension of logistic regression and the output of most neural classifiers.
  • Multi-label problems need one decision per label, with sigmoid outputs, binary relevance or classifier chains.
  • Micro averages are dominated by big classes; macro averages give every class equal weight.
  • Always read the per-class report and the confusion matrix, not only the headline number.

Check your understanding

How many binary classifiers does one-vs-one train for 6 classes?

One per pair: 6 × 5 / 2 = 15. One-vs-rest would train 6.

What does the softmax function guarantee about a model's outputs?

Softmax exponentiates the scores and normalises them, giving a probability distribution over the classes. Calibration is a separate question.

A model scores micro F1 0.95 and macro F1 0.60. What is the most likely explanation?

Micro pools predictions, so big classes dominate it. Macro is a plain average over classes, so one badly handled small class pulls it down.

You need to tag news articles with any number of topics. Which output layer fits best?

Each topic is its own yes-or-no decision. A softmax would force the topics to compete for one unit of probability.

What does Hamming loss measure in multi-label classification?

It counts wrong label decisions across all rows and labels. Subset accuracy is the strict row-level measure.
