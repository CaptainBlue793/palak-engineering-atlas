Multi-Head Attention & Position

Chapter 4's attention head has two limits. It can only follow one pattern at a time, and it cannot tell "dog bites man" from "man bites dog", because nothing in it depends on order. Real models fix the first by running many smaller heads side by side, and the second by mixing position into the vectors, in one of three ways that the field has moved through: learned, sinusoidal and rotary.

This chapter builds both and checks them against real models: multi-head attention matched GPT-2's layer exactly, and rotary positions matched Qwen2.5's attention weights to within 0.000004. It also measures what position is worth. With its position vectors zeroed, GPT-2's perplexity on WikiText went from 37 to 3,659. And removing any one of 84 of its 144 heads changed its loss by less than 0.01.

Splitting into heads

One head produces one set of weights per position, so it can follow one pattern: the previous token, or the subject of the sentence, but not both. Multi-head attention runs several heads in parallel, each on its own slice of the vector. GPT-2 projects its 768-dimensional vectors to queries, keys and values as usual, then cuts each into 12 heads of 64, runs attention in each head separately, glues the 12 outputs back together and mixes them with one more linear layer.

def split_heads(x, n):                        # (B, T, n*d) -> (B, n, T, d)
    B, T, C = x.shape
    return x.view(B, T, n, C // n).transpose(1, 2)

def merge_heads(x):                          # (B, n, T, d) -> (B, T, n*d)
    B, n, T, d = x.shape
    return x.transpose(1, 2).reshape(B, T, n * d)

q, k, v = attn.c_attn(x).split(768, dim=2)        # GPT-2 computes Q, K, V with one 768 → 2,304 layer
out, _ = attention(split_heads(q, 12), split_heads(k, 12), split_heads(v, 12))   # Chapter 4's function
y = attn.c_proj(merge_heads(out))                  # one output projection mixes the heads

Fed the real input of GPT-2's fourth layer, captured during a normal forward pass, this gave the layer's real output with a largest difference of 0.0. Splitting costs nothing in parameters: the four 768 × 768 projections are the same size whether they feed 1 head or 48, 2.36 million parameters in all. Nor does it change the arithmetic of the scores, since 12 heads × 64 dimensions is the same work as 1 × 768. What it changes is the number of T × T weight tables: at 2,048 tokens, from-scratch attention took 0.27 ms with 1 head and 6.0 ms with 48, while the fused kernel stayed between 0.24 and 0.52 ms.

Why order is invisible to attention

Attention compares every query with every key and averages the values. None of that depends on where in the sequence a vector sits. Shuffle the input vectors and, without a mask, the outputs come out shuffled the same way and otherwise identical: measured, the largest difference was 1.8 × 10⁻⁷, rounding error. As far as attention alone is concerned, a sentence is a bag of words. The causal mask breaks this a little, since position 5 sees five tokens and position 50 sees fifty, but that is a weak signal.

So models add position information to the vectors. How much it matters shows clearly in GPT-2 on 20,480 tokens of WikiText-2 (40 blocks of 512):

Perplexity (P4) is roughly how many tokens the model is choosing between at each step. Without its positions GPT-2 did worse than when its positions were intact but the words were in random order. A model trained with positions depends on them completely.

Learned and sinusoidal positions

The original 2017 Transformer added a fixed sinusoidal vector to each token's embedding: each pair of dimensions is a sine and cosine at a different frequency, from fast ones that change every token to slow ones that take thousands of tokens to cycle, like the hands of a clock. GPT-2 instead learns a 1,024 × 768 table, one row per position, trained like the token embeddings. That gives a hard limit: there is no row 1,025, so GPT-2 cannot read past 1,024 tokens at all.

Both end up with similar structure, which the explorer below draws: nearby positions have similar vectors. In GPT-2's learned table, positions 1 apart have an average cosine similarity of 0.997 and positions 64 apart 0.73; the sinusoidal table gives 0.97 and 0.49. The learned table also treats position 0 specially: its vector has a length of 9.9, against 3.4 for a typical position, which fits the first-token sink of Chapter 4.

Rotary embeddings (RoPE)

Most current open models, Llama, Qwen, Mistral and others, use rotary position embeddings. Instead of adding a position vector to the input, RoPE rotates each query and key just before the dot product. The head's dimensions are taken in pairs, and each pair is rotated by an angle of position × frequency, with frequencies spread from fast to slow as in the sinusoidal scheme:

def rope(x, pos, base=1_000_000):                # Qwen2.5's base; the original paper used 10,000
    d = x.shape[-1]
    inv = base ** (-torch.arange(0, d, 2).float() / d)    # one frequency per pair of dimensions
    ang = pos[:, None] * inv[None]                       # (T, d/2) angles
    cos, sin = ang.cos(), ang.sin()
    x1, x2 = x[..., : d // 2], x[..., d // 2:]              # pair dimension i with dimension i + d/2
    return torch.cat([x1 * cos - x2 * sin, x1 * sin + x2 * cos], dim=-1)   # 2-D rotation of each pair

q, k = rope(q, positions), rope(k, positions)              # then Chapter 4's attention, unchanged

Used on Qwen2.5-0.5B's first-layer queries and keys, this reproduced the model's own attention weights with a largest difference of 3.4 × 10⁻⁶. (Qwen2.5 shares each key and value head between 7 query heads, 14 query heads to 2 key-value heads, to shrink its cache; Chapter 15 covers this grouped-query attention.)

The reason for rotating is that the dot product of two rotated vectors depends only on the difference of their angles. So a query at position m and a key at position n score according to m − n, how far apart they are, not where they are. Measured: a query and key at positions 10 and 3 scored −3.6865; moved to 1,010 and 1,003, −3.6865; at 30,010 and 30,003, −3.6854, the same up to float rounding. Relative distance is what language mostly cares about, and RoPE gets it with no parameters at all. In Qwen2.5 the fastest pair rotates once every 6.3 tokens and the slowest once every 4 million.

RoPE does not on its own let a model read further than it was trained on; rotations it never saw in training are as unfamiliar as missing rows (Chapter 18). Within its training length it uses the context well: Qwen2.5-0.5B's loss on WikiText fell from 5.15 in the first 16 tokens of a passage to 2.79 by tokens 64–256 and 2.42 by tokens 4,096–8,192, because more of the passage was there to use.

What different heads do, and which matter

Chapter 4 named a few of GPT-2's heads by their patterns. A blunter question is which ones the model needs. Removing each head in turn, by zeroing its slice before the output projection, and measuring the loss on 5,120 tokens of WikiText answers it. The baseline loss was 3.878.

  • Most heads barely matter on their own. Removing any one of 84 of the 144 heads changed the loss by less than 0.01.
  • A few matter a lot. Layer 0's heads 10 and 0 each added more than 2.0 to the loss, multiplying perplexity by about 8, from one head out of 144. Head 5.1, another induction-style head (third on Chapter 4's sentence), added 0.145.
  • Parts don't add up. Removing all twelve of layer 0's heads added 0.66, less than removing head 10 alone. Knocking parts out of a network shows what it now relies on, not what each part contributes, because the remaining parts expect each other.

Heads also differ in how far back they look: on WikiText, the average distance from a token to what it attends to ranged from 0.3 tokens for a head that attends to itself to over 120 for some heads in layers 5 to 8. Distance mixes two things, though: a head that parks its weight on the first token (Chapter 4) has a long average distance without using long-range information.

Use case: stretching a model's context with RoPE scaling

Because RoPE positions are just angles, a model trained on short sequences can be adapted to longer ones by changing the angles rather than adding rows. Position interpolation (Meta, 2023) divides positions so a longer sequence's angles fall inside the trained range; NTK-aware scaling and YaRN instead stretch the slow, long-wavelength pairs more than the fast ones, so nearby-token detail is kept. Raising the base does something similar, which is why Qwen2.5 uses 1,000,000 instead of the original 10,000. Qwen2.5's model cards describe enabling YaRN in the config to go beyond their native context. A learned table like GPT-2's offers nothing comparable: past row 1,024 there is simply no vector to use. Chapter 18 measures what these tricks buy.

⚠️
Common mistakes
  • Reshaping without transposing: view(B, n, T, d) straight from (B, T, n·d) mixes positions into heads; it must be view(B, T, n, d).transpose(1, 2).
  • Expecting more heads to cost more parameters; the projections are the same size whatever the split.
  • Applying RoPE to the values, or after the dot product; it rotates queries and keys only, before scoring.
  • Pairing the wrong dimensions: some code rotates neighbours (0,1), others halves (i, i + d/2), as Qwen does; weights trained one way give garbage the other way.
  • Feeding a learned-position model more tokens than it has rows; GPT-2 stops at 1,024.
  • Pruning heads from single-head ablations; removing a whole layer here hurt less than removing one of its heads.

Interview drill

Explain it simply: Why use multiple attention heads, and what does it cost?

How a strong answer sounds
One head gives each position one weighted average, so it can follow one pattern. Multi-head attention splits the query, key and value vectors into n slices, runs attention in each slice independently, concatenates the results and mixes them with an output projection, so different heads can track different relationships: the previous token, an earlier copy of the current token, and so on. It costs no extra parameters, since the projections are the same size, and the same score arithmetic, since n heads of d/n dimensions do the work of one of d. What grows is the number of T × T weight tables, which matters for a naive implementation but not for a fused kernel. I checked a from-scratch version against GPT-2's layer and it matched exactly.

Deeper: How does RoPE encode position, and why has it replaced learned position embeddings?

How a strong answer sounds
Attention is permutation-equivariant, so position must be injected; GPT-2 without its position vectors went from 37 to 3,659 perplexity. Learned embeddings add a trained vector per position to the input, which caps the length at the table size. RoPE instead rotates each pair of query and key dimensions by position times a pair-specific frequency, just before the dot product. A dot product of rotated vectors depends only on the angle difference, so scores depend on relative distance m − n: I measured the same score for positions (10, 3), (1010, 1003) and (30010, 30003). It has no parameters, relative position is the useful signal for language, and the angles can be rescaled (position interpolation, NTK, YaRN) to extend context, which a learned table cannot do. It does not extrapolate for free, though; unseen angles still degrade quality without such scaling.

🧠 Key takeaways

  • Multi-head attention splits Q, K and V into slices, attends in each, concatenates and projects; it matched GPT-2 exactly.
  • More heads cost no extra parameters and no extra score arithmetic, only more T × T tables.
  • Attention alone ignores order: shuffled inputs gave shuffled outputs to 1.8 × 10⁻⁷. GPT-2 without positions went from 37 to 3,659 perplexity.
  • Learned and sinusoidal positions add a vector to the input; GPT-2's learned table stops at 1,024 positions.
  • RoPE rotates queries and keys so scores depend only on distance; it matched Qwen2.5 to 3.4 × 10⁻⁶.
  • 84 of GPT-2's 144 heads could each be removed for less than 0.01 loss; two heads in layer 0 cost over 2.0 each.
