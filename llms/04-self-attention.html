Self-Attention from Scratch

After the embedding lookup, each position holds a vector that knows only its own token. "it" does not yet know it refers to the cat. Self-attention is the step that lets every position gather information from the positions before it, with weights it computes from the content itself. It is about fifteen lines of PyTorch.

This chapter writes those lines and checks them: they matched PyTorch's built-in attention to within 0.000002, and reproduced GPT-2's first-layer attention weights exactly. Then it measures why the fused kernel everyone uses matters: at 8,192 tokens the from-scratch version needed 3.1 GB for one layer where the fused one needed 12 MB. Finally it opens GPT-2's 144 heads, and finds one that attends to the previous token 99.97% of the time.

Mixing information between tokens

In "The cat sat on the mat because it was tired", predicting what follows "tired" needs to know what "it" is, and that information sits at another position. Something has to move information between positions. Earlier models did it with a fixed recipe: a recurrent network passes one running summary from left to right, and a convolution mixes a fixed-size window. Attention instead lets each position choose, from the content, how much to take from every earlier position, and computes the output as a weighted average.

It does that by giving each position three different vectors, each produced from its embedding by a learnt linear layer: a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what do I pass on if chosen?"). How well a query matches a key is their dot product. Softmax turns one position's dot products into weights that sum to 1, and the output is those weights applied to the values.

Queries, keys and values

def attention(q, k, v, causal=True):
    """q, k, v: (..., T, d). Returns (..., T, d) and the weights (..., T, T)."""
    d = q.shape[-1]
    scores = q @ k.transpose(-2, -1) / math.sqrt(d)          # (T, T): every query against every key
    if causal:
        T = q.shape[-2]
        mask = torch.ones(T, T, dtype=torch.bool, device=q.device).triu(1)  # True above the diagonal: the future
        scores = scores.masked_fill(mask, float("-inf"))
    w = scores.softmax(dim=-1)                               # each row sums to 1
    return w @ v, w                                           # weighted average of the values

Everything learnt lives in the three projections (and an output projection after it, Chapter 5). The attention computation itself has no parameters: it is matrix multiplies, a softmax and a mask. That makes it easy to check: on random inputs of shape (2, 12, 128, 64), this function and PyTorch's F.scaled_dot_product_attention agreed to within 1.7 × 10⁻⁶, every row of weights summed to 1 within 2.4 × 10⁻⁷, and every weight above the diagonal was exactly 0.

Scaling and softmax

The division by √d matters more than it looks. A dot product of two random d-dimensional vectors with unit-variance entries has a standard deviation of √d, so with bigger heads the scores spread further apart, and softmax of widely spread numbers puts almost all the weight on the largest. Unscaled, a 64-dimensional head (GPT-2's size) already puts 79% of its weight on one key before any training, and the gradient flowing back through the softmax is 2.6 times smaller; at 1,024 dimensions it is 9.5 times smaller. A nearly one-hot softmax barely changes when its inputs change, so the model learns slowly. Dividing by √d brings the spread back to 1 at every size, the starting weights are close to even (5.3 bits of entropy out of a possible 6), and training is left to sharpen them where useful.

The causal mask

A language model is trained to predict each next token from the ones before it (Chapter 1), and it is trained on every position of a sequence at once. If position 5 could see position 6, it could simply copy the answer. The causal mask sets every score above the diagonal to −∞ before the softmax, so those weights become exactly 0 and later positions contribute nothing.

The test is direct: change the last token's key and value, and see which outputs move. With the mask, the largest change at any earlier position was 0.0; without it, 8.8. The same mask is why generation can reuse earlier positions' work (the KV cache, Chapter 16): nothing earlier ever depends on what comes later.

Checking against the fused kernel

The from-scratch function builds the full T × T table of scores, then a second one of weights. PyTorch's F.scaled_dot_product_attention (SDPA) gives the same answer through a fused kernel that works through the keys in tiles small enough to stay in the GPU's on-chip memory, keeping a running softmax, and never stores the table. With 12 heads of 64 dimensions in bf16, causal, one layer:

The from-scratch memory grows with the square of the length: double the tokens, four times the memory. At 16,384 tokens one layer's attention for a single sequence needed 12.3 GB of this 16 GB GPU, and took 33 times longer than SDPA. SDPA's memory grew in proportion to the length, because what it stores is just the output: 12 heads × 16,384 positions × 64 values × 2 bytes is the 24 MB it used. The arithmetic is still quadratic; only the memory traffic is gone, and that is where the time went (P6).

The from-scratch function also reproduces a real model. Feeding GPT-2's first-layer queries and keys through it gave attention weights identical to the ones GPT-2 reports, with a largest difference of 0.0.

What GPT-2's heads attend to

GPT-2 has 12 layers of 12 heads. Each learns its own query, key and value projections, so each can learn a different pattern. On the sentence "The cat sat on the mat because it was tired, so the cat slept on the mat.", some are easy to name:

  • Previous-token head. Layer 4, head 11 put 99.97% of its weight on the token immediately before, at every position: a learnt version of looking one step back.
  • Induction head. Layer 5, head 5 looks for an earlier copy of the current token and attends to what came after it. At the second " cat" it put 75% of its weight on " sat", and at the second " mat" 94% on " because". Combined with a previous-token head, this is how models continue patterns they have seen earlier in the context.
  • First-token "sink". Many heads put most of their weight on the very first token, which carries little meaning. Over 50 WikiText paragraphs, the average weight on position 0 rose from 3% in layer 0 to 67% in layer 7. Softmax weights must sum to 1, so a head with nothing useful to gather parks its weight somewhere harmless.

Use case: FlashAttention and long contexts

FlashAttention, published by Tri Dao and colleagues in 2022, is the tiled, fused approach measured above: compute attention block by block in fast on-chip memory, keep a running maximum and sum so the softmax comes out exact, and never write the T × T table to GPU memory (Chapter 17 goes inside it). It changed what context lengths were practical, because the table, not the arithmetic, was what ran out first; here it was the difference between 12.3 GB and 24 MB for one layer at 16k tokens. PyTorch's scaled_dot_product_attention picks a fused kernel like this automatically when the inputs allow it, and Hugging Face models use it by default. The from-scratch version is still worth having, because it is the one you can read, test and print the weights from, as this chapter did.

⚠️
Common mistakes
  • Forgetting the √d scaling; at d = 64 the untrained weights were already 79% on one key.
  • Masking after the softmax instead of before; the remaining weights then no longer sum to 1.
  • Getting the mask the wrong way round (tril where triu(1) was meant), which hides the past and shows the future.
  • Using the from-scratch version in production; it needed 3.1 GB at 8k tokens where SDPA needed 12 MB.
  • Reading a head's weights as an explanation of the model's output; heads that park weight on the first token show weight is not the same as importance.
  • Testing with no reference; one comparison against F.scaled_dot_product_attention catches transposed keys and wrong masks.

Interview drill

Explain it simply: Walk me through what one self-attention head computes.

How a strong answer sounds
Each position's vector goes through three learnt linear layers to give a query, a key and a value. The scores are every query's dot product with every key, divided by the square root of the head size, giving a T × T table. In a language model a causal mask sets every score for a later position to minus infinity. Softmax along each row turns scores into weights that sum to 1, and each position's output is its weights times the values: a weighted average of what earlier positions offer, chosen by content. The only parameters are the projections. I would test an implementation against F.scaled_dot_product_attention; mine agreed to 2e-6 and reproduced GPT-2's first-layer weights exactly.

Deeper: Why does naive attention run out of memory at long contexts, and how do fused kernels like FlashAttention fix it?

How a strong answer sounds
Naive attention materialises the scores and then the weights as T × T tables per head, so memory grows with the square of the sequence length: for 12 heads in bf16 that was 3.1 GB at 8,192 tokens and 12.3 GB at 16,384, for one layer of one sequence. Writing and reading those tables also dominates the time, since attention's arithmetic is cheap relative to the memory traffic. FlashAttention tiles the computation: it loads a block of queries and streams blocks of keys and values through on-chip memory, keeping a running maximum and running sum so the softmax is exact, and writes only the output. Memory becomes linear in T, 24 MB at 16k here, and it ran 33 times faster. The FLOPs are still quadratic, which is why very long contexts still cost more (Chapter 18).

🧠 Key takeaways

  • Attention lets each position take a content-chosen weighted average of earlier positions' values.
  • Queries, keys and values come from three learnt linear layers; the attention computation itself has no parameters.
  • Dividing scores by √d keeps softmax from saturating: unscaled, a 64-dim head started 79% on one key.
  • The causal mask makes every later position's weight exactly 0; changing the last token moved earlier outputs by 0.0.
  • Fused SDPA gives the same answer without the T × T table: 12 MB against 3.1 GB at 8k tokens.
  • GPT-2's heads include a previous-token head (99.97%), an induction head and many first-token sinks.
