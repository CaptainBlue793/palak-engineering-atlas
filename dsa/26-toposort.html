Topological Sort

A topological order is a linear arrangement of a directed graph where every edge points forward — “do this before that”, resolved. It exists exactly when the graph is acyclic, which is why topological sort and cycle detection are the same algorithm read two ways. There are two implementations, DFS-with-a-stack and Kahn-with-indegrees, and they are worth knowing both because they answer different follow-up questions.

  • Write DFS toposort and explain why the answer is the reversed finish order
  • Write Kahn's algorithm and use its output length as a cycle test
  • Choose between them from what the problem asks next
  • Produce the lexicographically smallest valid order
  • Solve longest path in a DAG, which is only easy because of the ordering

What it is, and when it exists

Given a directed graph, order the nodes so that for every edge u → v, u comes before v. Three facts:

✅

Exists iff acyclic

A cycle a→b→c→a would require a before b before c before a. So a DAG always has one, and a graph with a cycle never does.

🔀

Usually not unique

Any two nodes with no path between them can go in either order. “Find a valid order” is the normal ask; “the smallest” needs a heap.

🎯

It makes DP on a DAG trivial

Process nodes in topological order and every predecessor is already finalised — so longest path, path counting and DAG shortest path all become one linear pass.

Method 1: DFS with a stack

Run DFS. When a node finishes — after all its descendants are done — push it onto a stack. Pop the stack at the end and you have a topological order.

toposort — DFS with a finish stackO(V + E)O(V)
// Push AFTER the loop over neighbours — that is what makes it post-order.
void DFS(unordered_map<int,vector<int>> &graph,int node,vector<bool> &visited,stack<int> &st){
	if(visited[node])return;

	visited[node]=true;
	for(auto &neighbour:graph[node]){
		if(!visited[neighbour])
		DFS(graph,neighbour,visited,st);
	}

	st.push(node);            // everything reachable from node is already on the stack
}
vector<int> toposort(int N,vector<vector<int>> &edges){
	unordered_map<int,vector<int>> graph;
	for(int i=0;i<edges.size();i++){
		int u=edges[i][0];
		int v=edges[i][1];
		graph[u].push_back(v);
		// graph[v].push_back(u); -> This is for Undirected Edges
	}

	stack<int> st;
	vector<bool> visited(N,false);

	for(int i=0;i<N;i++){
		if(!visited[i]){
			DFS(graph,i,visited,st);
		}
	}

	vector<int> ans;
	while(!st.empty()){
		ans.push_back(st.top());
		st.pop();
	}

	return ans;
}
The commented-out reverse edge is important here as documentation — topological sort is meaningless on an undirected graph, so that line must stay commented. Accidentally uncommenting it produces an algorithm that silently returns garbage rather than failing.
🧾
Why reversed finish order is a valid topological order

Take any edge u → v and show u finishes after v. Two cases. If v is unvisited when we examine the edge, we recurse into it, so v finishes before we return and finish u ✓. If v is already visited, then in a DAG it must already be finished — because a visited-but-unfinished v would mean v is an ancestor of u on the current recursion path, and the edge u → v would close a cycle, which a DAG does not have ✓. So in both cases v is pushed before u, meaning u sits above v on the stack and comes out first. Notice that the proof breaks precisely when there is a cycle — which is why DFS toposort silently produces a wrong answer on a cyclic graph unless you add the recursion-stack check from Chapter 27.

Method 2: Kahn's algorithm

Count each node's indegree. Repeatedly take a node with indegree 0 — nothing is waiting on it — emit it, and decrement its neighbours' indegrees. A neighbour that reaches 0 becomes available.

toposort — Kahn's algorithmO(V + E)O(V)
vector<int> toposort(int N,vector<vector<int>> &edges){
	unordered_map<int,vector<int>> graph;
	for(int i=0;i<edges.size();i++){
		int u=edges[i][0];
		int v=edges[i][1];
		graph[u].push_back(v);
		// graph[v].push_back(u); -> This is for Undirected Edges
	}

	vector<int> indegree(N,0);
	for(auto &it:graph){
		for(int node:it.second){
			indegree[node]++;
		}
	}

	queue<int> q;
	vector<int> ans;
	for(int i=0;i<N;i++){
		if(indegree[i]==0)
		q.push(i);
	}

	while(!q.empty()){
		int node=q.front();
		q.pop();
		ans.push_back(node);

		for(auto &neighbour:graph[node]){
			indegree[neighbour]--;          // this prerequisite is satisfied

			if(indegree[neighbour]==0)
			q.push(neighbour);
		}
	}

	if(ans.size()!=N)return {};      // CYCLE: some nodes never reached indegree 0

	return ans;
}
The size check is free cycle detection. Nodes inside a cycle permanently block each other — each is waiting on another member — so their indegree never reaches zero and they are never emitted. If fewer than N nodes come out, the remainder form (or are downstream of) a cycle. That one line is why Kahn is usually the better choice for "can this schedule be completed?" problems.
✍️
My convention: build the indegree array by iterating the adjacency list, not the edge list

for(auto &it:graph) for(int node:it.second) indegree[node]++; counts each stored edge exactly once, so it stays correct if the graph was built with any deduplication or filtering applied — whereas re-scanning the original edges vector can disagree with what actually went into the graph. It also makes the directed/undirected switch a single place: whatever you pushed is what gets counted. One caveat worth knowing: on an unordered_map this only visits nodes that have outgoing edges, which is fine because a node with no outgoing edges contributes nothing to anyone's indegree.

Lexicographically smallest order

Kahn with a min-heapO((V + E) log V)O(V)
// Among all currently-available nodes, always take the smallest.
// Greedy is correct: taking a larger available node first can never let
// a smaller one come earlier, since availability only grows over time.
vector<int> smallestTopo(int N,vector<vector<int>> &edges){
	vector<vector<int>> graph(N);
	vector<int> indegree(N,0);

	for(auto &e:edges){
		graph[e[0]].push_back(e[1]);
		indegree[e[1]]++;
	}

	priority_queue<int,vector<int>,greater<int>> pq;   // min-heap (Ch 15)
	for(int i=0;i<N;i++){
		if(indegree[i]==0)
		pq.push(i);
	}

	vector<int> ans;
	while(!pq.empty()){
		int node=pq.top();
		pq.pop();
		ans.push_back(node);

		for(int neighbour:graph[node]){
			indegree[neighbour]--;

			if(indegree[neighbour]==0)
			pq.push(neighbour);
		}
	}

	return ans.size()==N?ans:vector<int>{};
}
One container swapped, and the log factor is the whole cost. Note this is not simply "sort the output" — the constraint set changes as you emit, so the greedy must re-choose at every step from the currently available nodes. Sorting the result of plain Kahn gives an invalid order.

Longest path in a DAG

Longest path is NP-hard in general graphs. In a DAG it is linear, and the reason is purely the ordering: process nodes topologically and every predecessor's answer is already final.

longest path in a DAG — DP over a topological orderO(V + E)O(V)
// dp[v] = longest path ENDING at v. Because we process in topological order,
// every u with an edge u->v has already been finalised when we relax it.
int longestPath(int N,vector<vector<int>> &edges){
	vector<vector<pair<int,int>>> graph(N);      // {neighbour,weight}
	vector<int> indegree(N,0);

	for(auto &e:edges){
		graph[e[0]].push_back({e[1],e[2]});
		indegree[e[1]]++;
	}

	queue<int> q;
	for(int i=0;i<N;i++){
		if(indegree[i]==0)
		q.push(i);
	}

	vector<int> dp(N,0);
	int best=0;

	while(!q.empty()){
		int node=q.front();
		q.pop();
		best=max(best,dp[node]);

		for(auto &[neighbour,weight]:graph[node]){
			dp[neighbour]=max(dp[neighbour],dp[node]+weight);   // relax

			indegree[neighbour]--;
			if(indegree[neighbour]==0)
			q.push(neighbour);
		}
	}

	return best;
}
The same shape solves four problems. Change max to min and you have DAG shortest path — which works with negative weights, unlike Dijkstra. Change it to dp[neighbour] += dp[node] and you are counting paths. Add a per-node cost and it is critical-path scheduling. All of them are linear only because the topological order removes the need to iterate to convergence, which is exactly what Bellman-Ford has to do (Chapter 30).

  • Anything phrased as “X must come before Y”
🔤
Alien dictionary — where the hard part is building the graph

Given words sorted in an unknown alphabet's order, recover the alphabet. The toposort is the easy half; the graph construction has two traps. First, comparing adjacent words gives you exactly one edge — from the first position where they differ — and nothing after that position tells you anything, so you must break after adding it. Second, if one word is a prefix of the previous one ("abc" before "ab"), the input is invalid and you must return failure rather than silently producing an order. Then run Kahn, and an output shorter than the alphabet size means a contradictory ordering. Most failures on this problem are in the graph, not the sort — which is the general lesson for graph problems dressed up in a story.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 KAHN COUNTS
If Kahn emits fewer than V nodes, a cycle exists. That makes "is this schedulable?" and "give me an order" the same function with one extra check.
💡 LEX SMALLEST
Swap the queue for a priority queue and Kahn gives the lexicographically smallest topological order. A one-word change to the container.
💡 DAG DP
Longest path, path counts and critical paths are all DP in topological order — which is exactly the order that guarantees every dependency is already computed.
⚠️
Common mistakes
  • Pushing the reverse edge. Topological sort is only defined on directed graphs; an undirected edge makes the output meaningless.
  • Forgetting the ans.size() != N check in Kahn. On a cyclic graph you return a partial order that looks plausible.
  • Using DFS toposort on a possibly-cyclic graph. It produces a wrong order silently — you need the recursion-stack check (Chapter 27).
  • Pushing in DFS before recursing. That gives preorder, which is not a topological order.
  • Not reversing the DFS stack. The stack is already in reverse finish order, so popping gives the right sequence — but building a vector with push_back inside DFS and forgetting to reverse it gives the exact opposite order.
  • Forgetting the driver loop over all nodes. A DAG can be disconnected, or have several sources.
  • Sorting plain Kahn's output to get the lexicographically smallest order. You must use a min-heap during the algorithm; sorting afterwards breaks the dependencies.
  • Only checking indegree == 0 for the initial queue and never again. A node becomes available only when its last prerequisite is emitted.
  • Building indegrees from the raw edge list when the graph was deduplicated. Count what actually went into the adjacency list.

Interview drill

Warm-up: Course schedule — can all courses be finished given prerequisites? Then: return a valid order.

How a strong answer sounds
Model each course as a node and each prerequisite pair as a directed edge from the prerequisite to the course that needs it, so a valid completion order is exactly a topological order — and one exists if and only if the graph is acyclic. I would use Kahn's algorithm because it answers both parts at once. Compute every node's indegree, push all indegree-zero nodes into a queue, then repeatedly pop a node, append it to the output, and decrement each neighbour's indegree, pushing any that reach zero. At the end, if the output contains fewer than N courses, the missing ones are in or downstream of a cycle — because every node in a cycle is waiting on another member, so none of their indegrees ever reaches zero. So ans.size() == N is the feasibility answer and ans itself is the order, from the same O(V + E) pass. I would mention the DFS alternative — push each node onto a stack when it finishes, then reverse — but note it needs an extra recursion-stack array to detect the cycle, and it risks a stack overflow at 10⁵ nodes, so Kahn is the better default here. If the follow-up asked for the lexicographically smallest order I would swap the queue for a min-heap, and if it asked for the minimum number of semesters with unlimited parallel courses I would process the queue one whole level at a time and count the levels.

Deeper: Why is longest path linear in a DAG but NP-hard in a general graph?

How a strong answer sounds
Because a topological order gives me a valid evaluation order for the DP, and cycles destroy that. In a DAG I define dp[v] as the longest path ending at v, and process the nodes in topological order — by the time I reach v, every u with an edge u→v has already been finalised, so dp[v] = max over predecessors of dp[u] + weight(u,v) is computed from settled values in a single pass. No node is ever revisited, so it is O(V + E). In a general graph there is no such order: a cycle means v's value depends on u's and u's depends on v's, so there is no place to start. Worse, the problem changes character — with a cycle of positive weight you can go round forever, so "longest path" only makes sense if you forbid repeating vertices, and "longest simple path" is NP-hard. In fact the Hamiltonian path problem reduces to it directly: a simple path visiting all V vertices exists exactly when the longest simple path has V−1 edges. So the acyclicity is not a convenience, it is what makes the problem a different complexity class. The same distinction explains why DAG shortest path handles negative weights in one pass while general graphs need Bellman-Ford's V−1 rounds of relaxation.

🧠 Key takeaways

  • A topological order exists exactly when the graph is a DAG, so toposort and cycle detection are one algorithm.
  • DFS pushes on finish and the reversed stack is the answer; the proof breaks precisely when a cycle exists.
  • Kahn emits indegree-zero nodes; ans.size() != N is free cycle detection and the reason it is the default.
  • Swap Kahn's queue for a min-heap to get the lexicographically smallest order — sorting the output afterwards is wrong.
  • DP over a topological order makes longest path, path counting and negative-weight DAG shortest path all linear.

Check your understanding

In Kahn's algorithm, what does it mean if the output contains fewer than N nodes?

This is the free cycle test and the main reason Kahn is the default. Disconnected components are handled fine, since every component contributes its own indegree-zero sources.

In DFS toposort, when is a node pushed onto the stack?

Post-order. Pushing on finish guarantees everything reachable from the node is already on the stack beneath it, so popping yields a valid order. Pushing before recursing gives preorder, which is not topological.

You need the lexicographically smallest topological order. What changes?

The available set changes as you emit, so the greedy must re-choose at every step. Sorting the finished output ignores dependencies entirely and produces an invalid order.

Why is longest path solvable in O(V + E) on a DAG but NP-hard in general?

Acyclicity supplies a valid evaluation order for the DP. With a cycle, v depends on u and u on v, and the problem becomes longest simple path — to which Hamiltonian path reduces directly.

Running DFS toposort on a graph that does contain a cycle produces what?

The visited array stops the recursion, so it terminates and emits all N nodes — but the correctness proof required that a visited neighbour is already finished, which a cycle violates. Kahn's size check catches this for free; DFS needs the instack array from Chapter 27.
