SCC, Bridges & Articulation Points

These algorithms reveal the structure of a graph. Which groups of nodes can all reach each other? Which single edge or node, if it broke, would split the graph apart? Think of a road network: which roads have no detour? All of these algorithms share one idea, lowlink: the earliest discovery time a subtree can reach. Once that clicks, bridges, cut vertices, SCCs and 2-SAT all come from the same DFS, just with different bookkeeping.

Discovery time and lowlink

Why this matters. Real networks have weak spots. A single cable whose failure cuts a data centre off, or a single router that everything passes through. In code interviews this appears as "critical connections in a network". In directed graphs, the matching question is "which groups of pages, accounts or services all feed into each other?", which is what SCCs answer. All of these need one pass over the graph, not one pass per edge you might delete. The naive way (delete each edge, then check if the graph is still connected) costs O(E·(V + E)). Lowlink does it in O(V + E).

Run a DFS and number the nodes in the order you first reach them: 0, 1, 2, and so on. That number is disc[v], the discovery time. Then define:

low[v] = the smallest disc[] reachable from v's subtree, using tree edges downward plus at most one back edge

A tree edge is one the DFS used to reach a new node. A back edge leads to a node the DFS has already seen, higher up. So low[v] answers one question: “how far back up the DFS tree can v's subtree escape to?” If it cannot escape above v itself, then v is the only way in. That is exactly what makes an edge a bridge or a node a cut vertex.

Why "at most one back edge"? A back edge is a shortcut from deep in the tree up to an ancestor. That ancestor is already on the current DFS path, so it is connected to everything above it. One jump is enough to show "this subtree has another way out". Chaining several jumps would not give you a more useful answer, and it is what goes wrong if you use low instead of disc on a back edge (more on that under the code).

A dry run by hand

Take this undirected graph: a triangle 0–1–2, plus a tail 1–3 and 3–4. Start the DFS at 0 and visit neighbours in increasing order.

  1. Visit 0 (disc 0), then 1 (disc 1), then 2 (disc 2).
  2. At 2, neighbour 0 is already visited and is not 2's parent, so 2–0 is a back edge. low[2] = min(2, disc[0]) = 0.
  3. Back at 1: low[1] = min(1, low[2]) = 0. Then 1 goes on to 3 (disc 3), and 3 goes to 4 (disc 4).
  4. Node 4 has no neighbour except its parent, so low[4] = 4. Back at 3, low[3] = min(3, 4) = 3.
  5. Back at 1, low[1] stays 0. Back at 0, low[0] stays 0.

computing disc and low in one DFSO(V + E)O(V)
// timer is shared state, so it must be a reference (Chapter 1).
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low){
	disc[node]=low[node]=timer++;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;          // skip the edge we came in on

		if(disc[neighbour]==-1){
			dfs(graph,neighbour,node,timer,disc,low);

			low[node]=min(low[node],low[neighbour]);   // TREE edge: inherit the child's low
		}else{
			low[node]=min(low[node],disc[neighbour]);  // BACK edge: use disc, NOT low
		}
	}
}
The low vs. disc choice on those two lines is the most important detail in this chapter. For a tree edge, take the child's low: any escape route the child's subtree has is yours too. For a back edge, take the neighbour's disc, not its low. Using low there would borrow an escape route through a node your subtree cannot actually reach. That quietly breaks articulation-point detection, as the example below shows. Get these two lines right, and everything else in the chapter is just a condition checked on them.

A concrete case where low on a back edge goes wrong. Take two triangles that share node 1: 0–1–2 and 1–3–4. Node 1 is clearly a cut vertex, since removing it separates {0, 2} from {3, 4}. The DFS from 0 visits 0, 1, 2 (disc 0, 1, 2), and the back edge 2–0 makes low[1] = 0. Then it visits 3 and 4 (disc 3, 4), and 4 has a back edge to 1. With the correct rule, low[4] = disc[1] = 1, so low[3] = 1 ≥ disc[1] and node 1 is reported as a cut vertex. With the wrong rule, low[4] = low[1] = 0. Now low[3] = 0 < disc[1], and node 1 is missed. The subtree {3, 4} "borrowed" node 1's route back to 0, but that route goes through node 1, the very node being removed.

Bridges

An edge is a bridge if removing it splits the graph into more pieces (more connected components). In other words, there is no other route around it — like the only road onto an island.

Why the condition is low[child] > disc[node]. Everything in the child's subtree was discovered after node. If the smallest disc the subtree can reach is still bigger than disc[node], then the subtree has no edge to node or to anything above it, apart from the tree edge itself. Cut that edge and the subtree floats away. In the dry run above: for edge 3–4, low[4] = 4 > disc[3] = 3, so it is a bridge. For edge 1–3, low[3] = 3 > disc[1] = 1, so it is a bridge too. For edge 1–2, low[2] = 0, which is not greater than 1, so it is not a bridge: the triangle gives a detour. The answer is exactly the two tail edges, which matches what you see by eye.

// Condition: edge (node -> child) is a bridge iff low[child] > disc[node].
// Meaning: the child's entire subtree cannot reach node or anything above it
// by any route other than this edge, so cutting it disconnects them.
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low,vector<vector<int>> &bridges){
	disc[node]=low[node]=timer++;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;

		if(disc[neighbour]==-1){
			dfs(graph,neighbour,node,timer,disc,low,bridges);
			low[node]=min(low[node],low[neighbour]);

			if(low[neighbour]>disc[node])
			bridges.push_back({node,neighbour});
		}else{
			low[node]=min(low[node],disc[neighbour]);
		}
	}
}
vector<vector<int>> criticalConnections(int N,vector<vector<int>> &connections){
	vector<vector<int>> graph(N);
	for(auto &e:connections){
		graph[e[0]].push_back(e[1]);
		graph[e[1]].push_back(e[0]);
	}

	vector<int> disc(N,-1);
	vector<int> low(N,-1);
	vector<vector<int>> bridges;
	int timer=0;

	for(int i=0;i<N;i++){
		if(disc[i]==-1)
		dfs(graph,i,-1,timer,disc,low,bridges);
	}

	return bridges;
}
Strict >, not >=. If low[child] == disc[node], the child's subtree can reach node by another route. So the edge is not needed, and it is not a bridge. Also, skipping the parent by its node number is wrong when there are parallel edges (two edges between the same pair; see Chapter 27). With two such edges, neither is a bridge. But skipping by node number hides the second edge. If duplicates are possible, track the edge's index instead.

Articulation points

A node is an articulation point (also called a cut vertex) if removing it, along with its edges, splits the graph into more pieces. There are two separate rules, because the DFS root is a special case.

In the dry-run graph (triangle 0–1–2 with tail 1–3–4): node 1 has child 3 with low[3] = 3 ≥ disc[1] = 1, so 1 is a cut vertex. Node 3 has child 4 with low[4] = 4 ≥ disc[3] = 3, so 3 is a cut vertex too. Node 2 and node 4 have no DFS children, so they can never be cut vertices; removing a leaf of the DFS tree leaves the rest of the tree intact. The root 0 has only one DFS child (node 1, which reached 2 itself), so 0 is not a cut vertex. Check by eye: removing 0 leaves 1–2 and the tail still joined. Correct.

Non-root node v

v is a cut vertex if it has a child c with low[c] >= disc[v]. Note it is >=, not >, unlike the bridge rule. Reaching v itself does not count as an escape, because v is the node being removed.

The DFS root

The root has no parent, so the rule above never applies to it. Instead, the root is a cut vertex if and only if it has two or more DFS children. With one child, the whole graph hangs below it in one piece. With two, removing the root splits them apart.

Why the root cannot use the normal rule. The root has disc 0, the smallest value there is. So low[child] ≥ disc[root] is true for every child, always, and the normal rule would call every root a cut vertex. Example: the path 0–1–2. Start the DFS at 0 and 0 has one child (1), so it is correctly not a cut vertex. Start at 1 instead, and 1 has two DFS children (0 and 2), because nothing links them except 1. So 1 correctly is a cut vertex. Two children of the root can never be joined by a back edge, because a DFS would have walked across that edge and made them one subtree.

articulationPointsO(V + E)O(V)
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low,vector<bool> &isCut){
	disc[node]=low[node]=timer++;
	int children=0;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;

		if(disc[neighbour]==-1){
			children++;
			dfs(graph,neighbour,node,timer,disc,low,isCut);
			low[node]=min(low[node],low[neighbour]);

			// non-root: >= because reaching node itself is not an escape
			if(parent!=-1 and low[neighbour]>=disc[node])
			isCut[node]=true;
		}else{
			low[node]=min(low[node],disc[neighbour]);
		}
	}

	// root: a cut vertex iff it has 2+ DFS children
	if(parent==-1 and children>1)
	isCut[node]=true;
}
Bridges use >, cut vertices use >=. Here is why. When you remove a bridge, its two end nodes stay. So a child that reaches exactly disc[node] still has a route. When you remove a cut vertex, the node itself is gone, so reaching it does not help. Mixing up the two operators is the classic bug here, and both versions produce believable output.
✍️
My convention: one DFS, all three outputs

Bridges, articulation points and biconnected components (pieces with no cut vertex inside) all come from the same disc/low computation. So write the DFS once, adding whatever extra reference parameters the problem needs. Do not write three nearly identical functions. This is Chapter 1's "reuse the skeleton" rule at its most concrete: the traversal stays the same; only the check after the recursive call changes. And int &timer must be a reference. Otherwise each branch restarts the clock, and every disc comparison becomes meaningless.

Strongly connected components

In a directed graph (one-way edges), a strongly connected component, or SCC, is a group of nodes where every node can reach every other. The group is "maximal": you cannot add any more nodes and keep that true. Think of a set of one-way streets where you can still drive from any corner to any other. There are two classic algorithms.

A small example to keep in mind. Directed edges 0→1, 1→2, 2→0, 2→3, 3→4, 4→3. The SCCs are {0, 1, 2} (a loop) and {3, 4} (another loop). The edge 2→3 joins them, but there is no way back from 3 to 2, so they stay separate components. Every node belongs to exactly one SCC; a node with no loop through it is an SCC on its own.

Kosaraju on it, step by step. Pass 1 (DFS from 0 on the original graph) goes 0 → 1 → 2 → 3 → 4. Node 4 finishes first, then 3, 2, 1 and 0, so the stack from top to bottom is 0, 1, 2, 3, 4. Now reverse every edge: 1→0, 2→1, 0→2, 3→2, 4→3, 3→4. Pop 0 and run DFS on the reversed graph: it reaches 2, then 1, and stops. That is SCC {0, 1, 2}. Pop 1 and 2: already visited. Pop 3: the reversed edge 3→2 leads into an already visited node, so the DFS only reaches 4. That is SCC {3, 4}. Notice that the reversed edge 3→2 is what could have leaked, and it is harmless because {0, 1, 2} was already claimed.

// Pass 1: DFS on the original graph, pushing each node when it FINISHES.
// Pass 2: pop that stack and DFS on the REVERSED graph. Each DFS tree
//         in pass 2 is exactly one SCC.
void DFS(vector<vector<int>> &graph,int node,stack<int> &st,vector<bool> &visited){
	visited[node]=true;

	for(int neighbour:graph[node]){
		if(!visited[neighbour])
		DFS(graph,neighbour,st,visited);
	}

	st.push(node);            // finish order — same as toposort (Chapter 26)
}
void DFS2(vector<vector<int>> &graph,int node,vector<bool> &visited){
	visited[node]=true;

	for(int neighbour:graph[node]){
		if(!visited[neighbour])
		DFS2(graph,neighbour,visited);
	}
}
int kosaraju(int V,vector<vector<int>> &adj){
	vector<vector<int>> graph(V);
	for(auto &edge:adj){
		graph[edge[0]].push_back(edge[1]);
	}

	stack<int> toposort;
	vector<bool> visited(V,false);

	for(int i=0;i<V;i++){
		if(!visited[i])
		DFS(graph,i,toposort,visited);
	}

	// build the reversed graph
	vector<vector<int>> revAdj(V);
	for(auto &edge:adj){
		revAdj[edge[1]].push_back(edge[0]);
	}

	int SCC=0;
	visited=vector<bool>(V,false);

	while(!toposort.empty()){
		int node=toposort.top();
		toposort.pop();

		if(!visited[node]){
			SCC++;
			DFS2(revAdj,node,visited);
		}
	}

	return SCC;
}

Two full DFS passes and a graph reversal. It is simple to write and simple to explain, which is why it is the usual interview answer. O(V + E), doing roughly twice the work of a single pass.

// One DFS, using lowlink plus an explicit stack of "nodes in the current
// SCC being built". A node with low[v] == disc[v] is an SCC ROOT: pop the
// stack down to it and that is one component.
void tarjan(vector<vector<int>> &graph,int node,int &timer,
            vector<int> &disc,vector<int> &low,
            vector<bool> &onStack,stack<int> &st,
            vector<vector<int>> &sccs){
	disc[node]=low[node]=timer++;
	st.push(node);
	onStack[node]=true;

	for(int neighbour:graph[node]){
		if(disc[neighbour]==-1){
			tarjan(graph,neighbour,timer,disc,low,onStack,st,sccs);
			low[node]=min(low[node],low[neighbour]);
		}else if(onStack[neighbour]){
			// only a node still on the stack is in the SAME component
			low[node]=min(low[node],disc[neighbour]);
		}
	}

	if(low[node]==disc[node]){       // SCC root
		vector<int> comp;

		while(true){
			int x=st.top();
			st.pop();
			onStack[x]=false;
			comp.push_back(x);

			if(x==node)break;
		}

		sccs.push_back(comp);
	}
}

One pass, no graph reversal. As a bonus, it outputs the SCCs in reverse topological order. The onStack check is the crucial part. A visited neighbour that is not on the stack belongs to an SCC that is already finished, so you must ignore it — exactly like the cross edges of Chapter 27.

How Tarjan knows a component is complete. A node whose low still equals its own disc after all its children finish is the first node of its SCC that the DFS reached, called the SCC's root. Nothing in its subtree can climb above it, so every node pushed on the stack after it (and still there) belongs to its component. Pop down to it, and that is one SCC. On the example above (0→1→2→0, 2→3, 3⇄4): node 4's back edge to 3 gives low[4] = 3; node 3 then has low = disc = 3, so it pops {4, 3} first. Later node 0 has low = disc = 0 and pops {2, 1, 0}. The sink component comes out first, which is why the order is reverse topological.

// Collapse each SCC into a single node. The result is ALWAYS a DAG:
// if two components had edges both ways they would be one component.
vector<vector<int>> condense(int V,vector<vector<int>> &edges,vector<int> &comp,int C){
	vector<set<int>> seen(C);

	for(auto &e:edges){
		int a=comp[e[0]];
		int b=comp[e[1]];

		if(a!=b)seen[a].insert(b);    // skip edges inside a component
	}

	vector<vector<int>> dag(C);
	for(int i=0;i<C;i++){
		for(int j:seen[i])
		dag[i].push_back(j);
	}

	return dag;
}
// Now every DAG technique applies: toposort, longest path, DAG DP (Ch 26).
// Common uses: count components with indegree 0 (how many entry points?),
// count with outdegree 0 (how many sinks?), longest chain of components.

The condensation is the reason to compute SCCs. Squash each SCC into one node, and the result has no cycles: it is a DAG. So any question that would be easy on a DAG becomes easy on a graph with cycles too. Collapse first, then use Chapter 26. For example, "minimum edges to add to make the graph strongly connected" is max(sources, sinks) on the condensation. (A source has no incoming edges; a sink has no outgoing ones.) Why that number: every source needs at least one new edge coming in, and every sink needs at least one going out, and one added edge can fix one sink and one source at the same time, by running from a sink to a source. Edge case: if the whole graph is already one SCC, the condensation has one node that is both a source and a sink, yet the answer is 0, not 1. Check for that first.

🧾
Why Kosaraju's two passes work

Two facts do all the work.

Fact 1: an SCC is the same set of nodes in the graph and in its reverse. Say u reaches v and v reaches u. Reversing every edge just swaps those two statements, so the pair can still reach each other. The components stay identical. Only the edges between components flip direction.

Fact 2: pass 1's finish order puts the components in order. Picture the condensation DAG. The node that finishes last in pass 1 sits in a source component of that DAG: nothing outside it points in. Now run DFS from it on the reversed graph. In the reverse, that component is a sink (nothing points out). So the DFS cannot escape, and it reaches exactly the component's own members. Mark them, move to the next unvisited node in decreasing finish order, and repeat.

So the reversal is what keeps each pass-2 DFS inside a single component. The finish-order stack makes sure you always start from a component with nothing above it. Remove either one, and a single DFS would leak into downstream components and merge them.

2-SAT: SCC applied

You have some true/false variables and a list of rules, each of the form “a or b” (a clause). Can you set the variables so every rule holds? Each side of the “or” is a literal: a variable or its negation ("not x"). With exactly two literals per clause, SCC solves this in linear time. With three per clause (3-SAT), the problem is NP-complete — no fast method is known.

🔗
The reduction

The clause (a ∨ b) ("a or b") means the same as two "if–then" rules: ¬a ⇒ b (if a is false, b must be true) and ¬b ⇒ a. So build an implication graph with 2n nodes: one for each variable and one for its negation. Add two directed edges per clause, one for each rule.

The formula has no solution if and only if some variable x and its negation ¬x are in the same SCC. Why? Being in one SCC means you can follow the rules from x to ¬x and back. So x would have to be both true and false.

When a solution does exist, the condensation gives it to you. Set x to true if and only if x's component comes later than ¬x's in topological order. With Tarjan, that means x's component index is smaller (Tarjan numbers components in reverse topological order). Choosing the literal whose component is "further downstream" never breaks a rule, because in the condensation the rules only ever point from earlier components to later ones. So 2-SAT runs in O(n + m). It solves any problem shaped like “choose one of two options per item, subject to rules about pairs”.

A worked example

Two variables, two clauses: (x ∨ y) and (¬x ∨ y). Each clause gives two edges:

  • (x ∨ y) gives ¬x → y and ¬y → x.
  • (¬x ∨ y) gives x → y and ¬y → ¬x.

Follow the arrows from ¬y: it leads to both x and ¬x, and both of those lead to y. Nothing leads out of y, so y and ¬y are in different SCCs (every node here is its own SCC), and the formula is satisfiable. In topological order ¬y comes before y, so the rule sets y = true. For x, neither of x, ¬x reaches the other, so either value works. Check: with y true, both clauses hold whatever x is. Now add the clauses (¬y ∨ x) and (¬y ∨ ¬x). They add y → x and y → ¬x (plus ¬x → ¬y and x → ¬y). Now y → x → ¬y and ¬y → x → y, so y and ¬y share an SCC and there is no solution. That matches common sense: the first two clauses force y true, and then the last two demand x and ¬x at once.

How to number the nodes in code. The usual trick is node 2i for "x_i is true" and 2i+1 for "x_i is false". Then the negation of node k is simply k ^ 1 (flip the lowest bit), which keeps the edge-adding code to one line per rule.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 LOW-LINK
Bridges, articulation points and SCCs are all one DFS carrying a discovery time and a low-link value. Learn the low-link update once and three algorithms follow.
⛔ ROOT IS SPECIAL
The DFS root is an articulation point only if it has more than one child in the DFS tree. Forgetting that one case is the standard bug.
💡 CONDENSE
Collapse each SCC to a node and you get a DAG, which you can then DP over. "Minimum edges to make it strongly connected" becomes max(sources, sinks) on that DAG.
⚠️
Common mistakes
  • Using low[neighbour] for a back edge instead of disc[neighbour]. You borrow an escape route that does not exist, which quietly breaks articulation-point detection.
  • Mixing up > and >=. Bridges need low[child] > disc[node]. Articulation points need >=.
  • Forgetting the root's special case. The root is a cut vertex if and only if it has 2+ DFS children. The low rule never fires for it.
  • Passing timer by value. Every branch restarts the clock, and all disc comparisons become nonsense.
  • Skipping the parent by node number when there are parallel edges. Two edges between the same pair mean neither is a bridge. Skip by edge index instead.
  • Leaving out the onStack check in Tarjan. You would swallow already-finished components into the current one.
  • Reversing the graph in place in Kosaraju. That destroys the original graph before pass 2 needs it.
  • Using bridge or articulation-point detection on a directed graph. Those ideas are for undirected graphs. The directed version is called dominators.
  • Deep recursion. All of these use DFS, so a chain of 10⁵ nodes can overflow the call stack. Switch to an explicit stack if the limits call for it.
  • Assuming a strongly connected graph has no bridges. They are different ideas: bridges are about the undirected structure.
🎤
Interview drill

Warm-up: Find all critical connections (bridges) in a network. Explain the lowlink condition.

How a strong answer sounds
I run one DFS. Each node gets a discovery time disc[v], in the order it is first reached. I also compute low[v]: the smallest discovery time reachable from v's subtree, using tree edges downward plus at most one back edge. After returning from a child c along a tree edge, I set low[v] = min(low[v], low[c]). For a back edge to a neighbour already discovered, I set min(low[v], disc[neighbour]) — disc, not low. That matters: using low there would borrow an escape route through a node my subtree cannot actually reach, and it breaks detection in a way that is hard to see. The edge (v, c) is a bridge exactly when low[c] > disc[v]. That means the child's whole subtree has no other route to v, or to anything discovered before v. So this edge is the only link, and removing it cuts them apart. The strict greater-than is essential. Equality means the subtree can reach v another way, so the edge is not needed. O(V + E) time and O(V) space. I would also flag two edge cases. First, timer must be passed by reference, or every branch restarts the clock. Second, if parallel edges are possible, skipping the parent by node number is wrong: two edges between the same pair mean neither is a bridge. I would skip by edge index instead.

Deeper: Explain Kosaraju's algorithm and why the reversed graph is necessary.

How a strong answer sounds
It has two passes. Pass one is an ordinary DFS over the original graph. It pushes each node onto a stack when that node finishes — the same finish-order stack as DFS topological sort. Pass two pops that stack and runs DFS on the reversed graph. Each DFS tree in pass two is exactly one SCC. Two facts make it work. First, SCCs are the same in the graph and its reverse. Reversing every edge swaps "u reaches v" with "v reaches u", so the pair can still reach each other. Only the edges between components flip. Second, picture the condensation DAG. The node that finishes last in pass one must sit in a source component of that DAG, one with nothing pointing into it. In the reversed graph, that component becomes a sink. So a DFS started inside it cannot escape, and it reaches exactly its own members. Mark them, take the next unvisited node in decreasing finish order, and repeat. The reversal is exactly what keeps each pass-two DFS inside one component. Without it, a DFS from a source component would leak downstream and merge several components into one. The finish-order stack makes sure I always start from a component with nothing above it. Total cost is O(V + E), about twice the work of one pass. Tarjan's algorithm does the same in one pass, using lowlink and an on-stack flag. It is faster and reuses the bridge code. But Kosaraju is much easier to justify out loud, so I would offer Kosaraju first and mention Tarjan as the optimisation.

🧠 Key takeaways

  • low[v] is the earliest discovery time reachable from v's subtree. Tree edges pass up low[child]; back edges give disc[neighbour].
  • Bridge: low[child] > disc[node]. Articulation point: low[child] >= disc[node], plus the root's two-children rule.
  • Kosaraju works because SCCs stay the same when you reverse the graph, and the finish order always starts you in a source component.
  • Tarjan does it in one pass with an onStack flag, and outputs components in reverse topological order.
  • Squash SCCs into a condensation DAG and every Chapter 26 technique applies. 2-SAT is just SCC on an implication graph.

Check your understanding

When updating low[node] across a back edge to a neighbour, which value do you use?

The back edge gets you to that one node, not to everything that node's subtree can reach. Taking low there lowers your value too much and quietly breaks articulation-point detection (it can hide a real cut vertex).

The bridge condition is low[child] > disc[node]. What is the articulation-point condition for a non-root node?

Removing an edge leaves its two end nodes in place, so a child that reaches exactly disc[node] still has a route. Removing the vertex takes that route away too. Hence >=.

When is the DFS root an articulation point?

With one DFS child, the whole graph hangs below the root in one connected piece. With two, removing the root separates them. This special case is the part of the algorithm people forget most often.

Why does Kosaraju need the reversed graph for its second pass?

The finish order makes sure you start in a source component. The reversal turns it into a sink, so the DFS cannot leave it. Without the reversal, one DFS would leak downstream and merge several components.

In Tarjan's SCC algorithm, why check onStack[neighbour] before updating low?

This is the same cross-edge idea from Chapter 27. Only a node still on the stack can be in the same component. A node already popped belongs to a separate SCC that is already complete.
