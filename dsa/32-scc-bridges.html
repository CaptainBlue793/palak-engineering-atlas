SCC, Bridges & Articulation Points

These are the “structure of a graph” algorithms: which parts are mutually reachable, and which single edge or node holds the whole thing together. They share one idea — lowlink, the earliest discovery time reachable from a subtree — and once that clicks, bridges, cut vertices, SCCs and 2-SAT all come from the same DFS with different bookkeeping.

Discovery time and lowlink

Run a DFS and number the nodes in the order you first reach them — that is disc[v], the discovery time. Then define:

low[v] = the smallest disc[] reachable from v's subtree, using tree edges downward plus at most one back edge

So low[v] answers: “how far back up the DFS tree can v's subtree escape to?” If it cannot escape above v itself, then v is the only way in — and that is what makes an edge a bridge or a node a cut vertex.

computing disc and low in one DFSO(V + E)O(V)
// timer is shared state, so it must be a reference (Chapter 1).
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low){
	disc[node]=low[node]=timer++;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;          // skip the edge we came in on

		if(disc[neighbour]==-1){
			dfs(graph,neighbour,node,timer,disc,low);

			low[node]=min(low[node],low[neighbour]);   // TREE edge: inherit the child's low
		}else{
			low[node]=min(low[node],disc[neighbour]);  // BACK edge: use disc, NOT low
		}
	}
}
The low versus disc distinction on those two lines is the single most important detail in this chapter. For a tree edge you take the child's low, because the whole subtree's escape route is yours too. For a back edge you take the neighbour's disc, not its low — using low there would let you inherit an escape route through a node that is not actually reachable from your subtree, and it silently breaks bridge detection. Get these two lines right and everything else in the chapter is a condition on them.

Bridges

An edge is a bridge if removing it increases the number of connected components — so there is no alternative route around it.

findBridges — TarjanO(V + E)O(V)
// Condition: edge (node -> child) is a bridge iff low[child] > disc[node].
// Meaning: the child's entire subtree cannot reach node or anything above it
// by any route other than this edge, so cutting it disconnects them.
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low,vector<vector<int>> &bridges){
	disc[node]=low[node]=timer++;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;

		if(disc[neighbour]==-1){
			dfs(graph,neighbour,node,timer,disc,low,bridges);
			low[node]=min(low[node],low[neighbour]);

			if(low[neighbour]>disc[node])
			bridges.push_back({node,neighbour});
		}else{
			low[node]=min(low[node],disc[neighbour]);
		}
	}
}
vector<vector<int>> criticalConnections(int N,vector<vector<int>> &connections){
	vector<vector<int>> graph(N);
	for(auto &e:connections){
		graph[e[0]].push_back(e[1]);
		graph[e[1]].push_back(e[0]);
	}

	vector<int> disc(N,-1);
	vector<int> low(N,-1);
	vector<vector<int>> bridges;
	int timer=0;

	for(int i=0;i<N;i++){
		if(disc[i]==-1)
		dfs(graph,i,-1,timer,disc,low,bridges);
	}

	return bridges;
}
Strict >, not >=. If low[child] == disc[node], the child's subtree can reach node by another route, so the edge is redundant and not a bridge. And with parallel edges the parent-by-label skip is wrong (Chapter 27): two edges between the same pair mean neither is a bridge, but skipping by label hides the second one. Track the edge index instead if duplicates are possible.

Articulation points

A node is an articulation point (cut vertex) if removing it increases the component count. Two conditions, because the DFS root is special.

Non-root node v

v is a cut vertex if it has a child c with low[c] >= disc[v]. Note >=, not > — unlike the bridge condition. Reaching v itself is not an escape, because v is the node being removed.

The DFS root

The root has no parent, so the condition above never applies. Instead: the root is a cut vertex iff it has two or more DFS children. One child means the whole graph hangs below it in one piece; two means removing it splits them.

articulationPointsO(V + E)O(V)
void dfs(vector<vector<int>> &graph,int node,int parent,int &timer,
         vector<int> &disc,vector<int> &low,vector<bool> &isCut){
	disc[node]=low[node]=timer++;
	int children=0;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;

		if(disc[neighbour]==-1){
			children++;
			dfs(graph,neighbour,node,timer,disc,low,isCut);
			low[node]=min(low[node],low[neighbour]);

			// non-root: >= because reaching node itself is not an escape
			if(parent!=-1 and low[neighbour]>=disc[node])
			isCut[node]=true;
		}else{
			low[node]=min(low[node],disc[neighbour]);
		}
	}

	// root: a cut vertex iff it has 2+ DFS children
	if(parent==-1 and children>1)
	isCut[node]=true;
}
Bridges use >, cut vertices use >=. The difference: a bridge is removed but its endpoints remain, so a child reaching exactly disc[node] still has a route. A cut vertex is itself removed, so reaching it is no help. Mixing the two operators is the classic bug here, and both variants produce plausible output.
✍️
My convention: one DFS, all three outputs

Bridges, articulation points and biconnected components all come from the same disc/low computation — so write the DFS once with whichever extra reference parameters the problem needs, rather than three near-identical functions. This is the Chapter 1 skeleton-reuse rule at its most concrete: the traversal is fixed, only the condition tested after the recursive call changes. And int &timer must be a reference, or each branch restarts the clock and every disc comparison becomes meaningless.

Strongly connected components

In a directed graph, an SCC is a maximal set of nodes where every node reaches every other. Two classic algorithms.

// Pass 1: DFS on the original graph, pushing each node when it FINISHES.
// Pass 2: pop that stack and DFS on the REVERSED graph. Each DFS tree
//         in pass 2 is exactly one SCC.
void DFS(vector<vector<int>> &graph,int node,stack<int> &st,vector<bool> &visited){
	visited[node]=true;

	for(int neighbour:graph[node]){
		if(!visited[neighbour])
		DFS(graph,neighbour,st,visited);
	}

	st.push(node);            // finish order — same as toposort (Chapter 26)
}
void DFS2(vector<vector<int>> &graph,int node,vector<bool> &visited){
	visited[node]=true;

	for(int neighbour:graph[node]){
		if(!visited[neighbour])
		DFS2(graph,neighbour,visited);
	}
}
int kosaraju(int V,vector<vector<int>> &adj){
	vector<vector<int>> graph(V);
	for(auto &edge:adj){
		graph[edge[0]].push_back(edge[1]);
	}

	stack<int> toposort;
	vector<bool> visited(V,false);

	for(int i=0;i<V;i++){
		if(!visited[i])
		DFS(graph,i,toposort,visited);
	}

	// build the reversed graph
	vector<vector<int>> revAdj(V);
	for(auto &edge:adj){
		revAdj[edge[1]].push_back(edge[0]);
	}

	int SCC=0;
	visited=vector<bool>(V,false);

	while(!toposort.empty()){
		int node=toposort.top();
		toposort.pop();

		if(!visited[node]){
			SCC++;
			DFS2(revAdj,node,visited);
		}
	}

	return SCC;
}

Two full DFS passes and a graph reversal — simple to write and simple to explain, which is why it is the usual interview answer. O(V + E) with a constant factor of roughly 2.

// One DFS, using lowlink plus an explicit stack of "nodes in the current
// SCC being built". A node with low[v] == disc[v] is an SCC ROOT: pop the
// stack down to it and that is one component.
void tarjan(vector<vector<int>> &graph,int node,int &timer,
            vector<int> &disc,vector<int> &low,
            vector<bool> &onStack,stack<int> &st,
            vector<vector<int>> &sccs){
	disc[node]=low[node]=timer++;
	st.push(node);
	onStack[node]=true;

	for(int neighbour:graph[node]){
		if(disc[neighbour]==-1){
			tarjan(graph,neighbour,timer,disc,low,onStack,st,sccs);
			low[node]=min(low[node],low[neighbour]);
		}else if(onStack[neighbour]){
			// only a node still on the stack is in the SAME component
			low[node]=min(low[node],disc[neighbour]);
		}
	}

	if(low[node]==disc[node]){       // SCC root
		vector<int> comp;

		while(true){
			int x=st.top();
			st.pop();
			onStack[x]=false;
			comp.push_back(x);

			if(x==node)break;
		}

		sccs.push_back(comp);
	}
}

One pass, no graph reversal, and it emits the SCCs in reverse topological order for free. The onStack check is the crucial part: a visited neighbour not on the stack belongs to an already-finished SCC and must be ignored, exactly like the cross edges of Chapter 27.

// Collapse each SCC into a single node. The result is ALWAYS a DAG:
// if two components had edges both ways they would be one component.
vector<vector<int>> condense(int V,vector<vector<int>> &edges,vector<int> &comp,int C){
	vector<set<int>> seen(C);

	for(auto &e:edges){
		int a=comp[e[0]];
		int b=comp[e[1]];

		if(a!=b)seen[a].insert(b);    // skip edges inside a component
	}

	vector<vector<int>> dag(C);
	for(int i=0;i<C;i++){
		for(int j:seen[i])
		dag[i].push_back(j);
	}

	return dag;
}
// Now every DAG technique applies: toposort, longest path, DAG DP (Ch 26).
// Common uses: count components with indegree 0 (how many entry points?),
// count with outdegree 0 (how many sinks?), longest chain of components.

The condensation is the point of computing SCCs. Any question about a cyclic directed graph that would be easy on a DAG becomes easy: collapse, then apply Chapter 26. "Minimum edges to add to make the graph strongly connected" is max(sources, sinks) on the condensation.

🧾
Why Kosaraju's two passes work

Two facts do all the work.

Fact 1: an SCC is the same set in the graph and in its reverse. Mutual reachability is symmetric — if u reaches v and v reaches u, reversing every edge swaps those two statements and leaves the pair mutually reachable. So the components are identical; only the edges between them flip direction.

Fact 2: pass 1's finish order orders the components. Think of the condensation DAG. The node that finishes last in pass 1 lies in a component that is a source of that DAG — nothing outside it points in. Now DFS from it on the reversed graph: in the reverse, that component is a sink, so the traversal cannot escape it and reaches exactly its own members. Mark them, move to the next unvisited node in decreasing finish order, and repeat.

So the reversal is what confines each pass-2 traversal to a single component, and the finish-order stack is what guarantees you always start from a component with nothing above it. Remove either ingredient and a single DFS would leak into downstream components and merge them.

2-SAT: SCC applied

Given boolean variables and clauses of the form “a or b”, is there a satisfying assignment? With exactly two literals per clause this is linear, via SCC — while 3-SAT is NP-complete.

🔗
The reduction

The clause (a ∨ b) is logically equivalent to the pair of implications ¬a ⇒ b and ¬b ⇒ a. So build an implication graph with 2n nodes — one for each variable and one for each negation — and two directed edges per clause.

The formula is unsatisfiable iff some variable x and its negation ¬x lie in the same SCC. Reason: being in one SCC means x ⇒ ¬x and ¬x ⇒ x are both derivable, so x must be both true and false.

And when it is satisfiable, the condensation gives you the assignment: set x to true iff x's component comes later than ¬x's in reverse topological order — that is, Tarjan's component index for x is smaller. Assigning the literal whose component is "further downstream" never contradicts an implication, because implications only ever point from earlier components to later ones in the condensation. So 2-SAT is O(n + m), and it solves any problem shaped as “choose one of two options per item, subject to pairwise constraints”.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 LOW-LINK
Bridges, articulation points and SCCs are all one DFS carrying a discovery time and a low-link value. Learn the low-link update once and three algorithms follow.
⛔ ROOT IS SPECIAL
The DFS root is an articulation point only if it has more than one child in the DFS tree. Forgetting that one case is the standard bug.
💡 CONDENSE
Collapse each SCC to a node and you get a DAG, which you can then DP over. "Minimum edges to make it strongly connected" becomes max(sources, sinks) on that DAG.
⚠️
Common mistakes
  • Using low[neighbour] for a back edge instead of disc[neighbour]. Inherits an escape route that does not exist, and breaks bridge detection subtly.
  • Mixing up > and >=. Bridges need low[child] > disc[node]; articulation points need >=.
  • Forgetting the root's special case. The root is a cut vertex iff it has 2+ DFS children — the low condition never fires for it.
  • Passing timer by value. Every branch restarts the clock and all disc comparisons become nonsense.
  • Skipping the parent by label with parallel edges present. Two edges between a pair mean neither is a bridge; skip by edge index instead.
  • Omitting the onStack check in Tarjan. You would absorb already-finished components into the current one.
  • Reversing the graph in place in Kosaraju, destroying the original before pass 2 uses it.
  • Applying bridge or articulation-point detection to a directed graph. Those are undirected notions; the directed analogue is dominators.
  • Deep recursion. All of these are DFS-based, so a 10⁵-node chain overflows — convert to an explicit stack if the constraints allow it.
  • Assuming a strongly connected graph has no bridges. Different notions: bridges are about the undirected structure.

Interview drill

Warm-up: Find all critical connections (bridges) in a network. Explain the lowlink condition.

How a strong answer sounds
I run one DFS, assigning each node a discovery time disc[v] in the order it is first reached, and computing low[v] — the smallest discovery time reachable from v's subtree using tree edges downward plus at most one back edge. After returning from a child c, I take low[v] = min(low[v], low[c]) for a tree edge, and for a back edge to an already-discovered neighbour I take min(low[v], disc[neighbour]) — disc, not low, which matters because using low there would let me inherit an escape route through a node my subtree cannot actually reach, and it breaks the detection in a way that is hard to see. Then the edge (v, c) is a bridge exactly when low[c] > disc[v]: that says the child's whole subtree cannot reach v or anything discovered before v by any other route, so this edge is the only connection and removing it disconnects them. Strict greater-than is essential — equality means the subtree can reach v another way, so the edge is redundant. O(V + E) time and O(V) space. I would also flag two edge cases: timer must be passed by reference or every branch restarts the clock; and if parallel edges are possible, skipping the parent by label is wrong, because two edges between the same pair mean neither is a bridge — I would skip by edge index instead.

Deeper: Explain Kosaraju's algorithm and why the reversed graph is necessary.

How a strong answer sounds
Two passes. Pass one is an ordinary DFS over the original graph, pushing each node onto a stack when it finishes — the same finish-order stack as DFS topological sort. Pass two pops that stack and runs DFS on the reversed graph, and each DFS tree in pass two is exactly one SCC. Two facts make it work. First, SCCs are identical in the graph and its reverse, because mutual reachability is symmetric — reversing every edge swaps "u reaches v" with "v reaches u" and leaves the pair mutually reachable — so only the edges between components flip. Second, think of the condensation DAG: the node that finishes last in pass one must lie in a source component of that DAG, one with nothing pointing into it. In the reversed graph that component becomes a sink, so a DFS started inside it cannot escape and reaches exactly its own members. Mark them, take the next unvisited node in decreasing finish order, repeat. The reversal is precisely what confines each pass-two traversal to a single component: without it, a DFS from a source component would leak downstream and merge several components into one. And the finish-order stack is what guarantees I always start from a component with nothing above it. Total O(V + E) with about a 2× constant. Tarjan's algorithm does the same in one pass using lowlink and an on-stack flag, which is faster and reuses the bridge machinery, but Kosaraju is much easier to justify out loud — so I would offer Kosaraju first and mention Tarjan as the optimisation.

🧠 Key takeaways

  • low[v] is the earliest discovery time reachable from v's subtree; tree edges contribute low[child], back edges contribute disc[neighbour].
  • Bridge: low[child] > disc[node]. Articulation point: low[child] >= disc[node], plus the root's two-children rule.
  • Kosaraju works because SCCs survive reversal and the finish order always starts you in a source component.
  • Tarjan does it in one pass with an onStack flag, emitting components in reverse topological order.
  • Collapse SCCs into a condensation DAG and every Chapter 26 technique applies; 2-SAT is SCC on an implication graph.

Check your understanding

When updating low[node] across a back edge to a neighbour, which value do you use?

The back edge gives you access to that specific node, not to everything that node's subtree can reach. Taking low there over-optimistically lowers your value and silently breaks bridge detection.

The bridge condition is low[child] > disc[node]. What is the articulation-point condition for a non-root node?

Removing an edge leaves its endpoints, so a child reaching exactly disc[node] still has a route. Removing the vertex takes that route away too — hence >=.

When is the DFS root an articulation point?

With one DFS child the whole graph hangs below in one connected piece; with two, removing the root separates them. This special case is the most commonly forgotten part of the algorithm.

Why does Kosaraju need the reversed graph for its second pass?

The finish order guarantees you start in a source component; the reversal makes it a sink so the traversal is confined. Without the reversal, one DFS would leak downstream and merge several components.

In Tarjan's SCC algorithm, why check onStack[neighbour] before updating low?

Exactly the cross-edge distinction from Chapter 27. Only a node still on the stack can be in the same component; one already popped is in a separate, completed SCC.
