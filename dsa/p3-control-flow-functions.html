Control Flow & Functions

Every algorithm in this course is built from three things: decisions (if), repetition (loops) and named, reusable steps (functions). You may know them already. What matters here is reading them fluently, tracing them by hand without running them, and writing them in the exact shape the course uses — plus the one decision about functions that silently decides whether your solution passes: passing by value or by reference. The chapter ends with your first recursive function.

  • Write functions with parameters and return values, and return more than one value

Decisions: if, else and guard clauses

An if runs a block only when its condition is true. Chain alternatives with else if, and catch everything else with else. C++ checks the conditions top to bottom and runs only the first one that's true.

string grade(int score){
	if(score>=90)
	return "A";
	else if(score>=75)
	return "B";
	else
	return "C";
}

int big=(a>b)?a:b;                 // the ternary operator: condition ? if-true : if-false

The single most useful habit is the guard clause: deal with the special, trivial or invalid cases first and return immediately. Then the main logic below can assume the input is normal. Almost every function in this course starts with one.

int maxOf(vector<int> &a){
	if(a.empty())return 0;           // guard clause: the empty case, handled and gone

	int best=a[0];                    // safe now: a has at least one element
	for(auto &x:a)
	best=max(best,x);

	return best;
}
✍️
My convention: the shape of every function

Guard clause first, then a blank line, then the variables, then the loop, then a blank line and the return. No spaces around operators, the opening brace on the same line, tabs for indentation, and a one-line body on the next line without braces. Chapter 1 lists the full house style; after a few chapters it becomes automatic, and every solution reads the same way.

Loops

A for loop has three parts in its brackets: start; keep going while; after each round. for(int i=0;i<n;i++) reads “start i at 0; while i is less than n; add 1 to i after each round”, so i takes the values 0, 1, …, n − 1 — exactly the valid indexes of an array of size n.

for(int i=0;i<n;i++)          // forwards: 0 .. n-1
cout<<a[i]<<" ";

for(int i=n-1;i>=0;i--)       // backwards: n-1 .. 0
cout<<a[i]<<" ";

for(int i=0;i<n;i+=2)        // every other index
cout<<a[i]<<" ";

for(auto &x:a)               // range-for: every element, no index to get wrong
cout<<x<<" ";

int n2=n;
while(n2>1)                  // while: repeat as long as the condition holds
n2/=2;

Use for when you know how many rounds there will be, and while when you only know when to stop — “until the number reaches 1”, “until the queue is empty”, “until the two pointers meet”. Inside any loop, break leaves the loop immediately and continue skips the rest of this round and goes on to the next.

Functions

A function is a named block of code that takes inputs (parameters) and may give back an output (its return value). int countEven(vector<int> &a) reads: “a function called countEven that takes a vector of ints and returns an int”. A function that returns nothing has return type void.

two small functions in the house styleO(n) and O(log n)O(1)
// count the even numbers
int countEven(vector<int> &a){
	if(a.empty())return 0;

	int count=0;
	for(int i=0;i<a.size();i++){
		if(a[i]%2==0)
		count++;
	}

	return count;
}

// how many times can n be halved before it reaches 1?
int halvings(int n){
	int steps=0;
	while(n>1){
		n/=2;
		steps++;
	}

	return steps;
}
Where the cost comes from: countEven looks at each element once, so O(n). halvings cuts n in half every time round, so it runs about log₂ n times. Keep that second loop in mind; it comes back in P7 and in binary search.

A function returns one value. When you need two — say the minimum and its position — you have three options: return a pair (return {best,idx};, read with auto [v,i]=f(a);), return a small struct with named fields, or fill in variables passed by reference (next section). The course uses all three.

Value or reference: the one decision that matters

When you call a function, C++ must hand the arguments over. It can do that in two ways, and the choice changes both what your code does and how fast it runs.

  • By value (no &): the function gets its own copy. Changes inside the function do not reach the caller. Copying a vector of n elements costs O(n).
  • By reference (with &): the function works on the caller's original. Changes stick. Nothing is copied, so it costs O(1).

An everyday analogy: by value is handing someone a photocopy of your notes. They can scribble on it and your notes stay clean, but making the copy takes time. By reference is handing them your actual notebook.

#include <bits/stdc++.h>
using namespace std;

void setTo100(int x){
	x=100;                    // changes the copy only
}

int main(){
	int a=5;
	setTo100(a);
	cout<<a<<"\n";            // prints 5
	return 0;
}

The function changed its private copy, which was thrown away when it returned. a is untouched.

#include <bits/stdc++.h>
using namespace std;

void setTo100(int &x){
	x=100;                    // x IS the caller's variable
}

int main(){
	int a=5;
	setTo100(a);
	cout<<a<<"\n";            // prints 100
	return 0;
}

One character, &, and the function now edits a itself. This is how the course's helper functions fill in visited, ans and friends.

// copies all n elements on every call: O(n) before any real work
int firstByValue(vector<int> v){
	return v[0];
}

// no copy, O(1); const promises the function will not change v
int firstByConstRef(const vector<int> &v){
	return v[0];
}

Use const & when a function only reads a big object. You get the speed of a reference and the safety of a copy.

Why this decides AC versus TLE: imagine a recursive function called 10⁵ times, each time receiving a graph of 10⁵ edges by value. That's 10⁵ × 10⁵ = 10¹⁰ elements copied — minutes of work — for code that is logically perfect. Add one & and the copies vanish. Nothing warns you; the only symptom is Time Limit Exceeded.

✍️
My convention: containers always go by reference

Every vector, string, map, stack or queue parameter in this course has an &. Small values — int, long long, char, bool — go by value, because copying them is as cheap as a reference. Chapter 1 explains the full rule and its one exception (a recursive helper that wants its own copy of a small path).

Scope and lifetime

A variable exists only inside the block — the pair of braces { } — where it was declared. That region is its scope. A loop variable declared in for(int i=0;…) vanishes when the loop ends; a local variable vanishes when its function returns.

int total=0;                       // global: visible everywhere below, lives all program long
int memo[100001];                  // global arrays start filled with zeros

void f(){
	int local;                     // local, NOT initialised: holds garbage until you set it
	for(int i=0;i<3;i++){
		int sq=i*i;               // sq exists only inside this loop body
		total+=sq;
	}
	// i and sq no longer exist here
}
  • Always initialise local variables. int sum; starts with whatever bits were left in that memory. int sum=0; is what you meant.
  • Global variables are zero-initialised automatically and live for the whole program. Competitive programmers use global arrays for big tables — they also avoid the small-stack problem you'll meet in P6. On LeetCode, remember that global state persists between test cases, so reset it inside your function.
  • Shadowing: declaring a new variable with the same name inside an inner block hides the outer one. It compiles fine and causes baffling bugs. Avoid reusing names.

Your first recursive function

A function can call itself. That's recursion, and it's the natural way to express problems built from smaller copies of themselves: a tree is a node plus smaller trees; the sum of a number's digits is its last digit plus the sum of the rest. Every recursive function needs two parts:

  • A base case that answers directly, without recursing — the smallest version of the problem.
  • A recursive case that shrinks the problem and calls itself on the smaller version, trusting that call to return the right answer.
int sumDigits(int n){
	if(n<10)return n;                   // base case: a single digit

	return n%10+sumDigits(n/10);        // last digit + the sum of the rest
}
Trace sumDigits(4096)Step-through
The calls go down until the base case, then the answers come back up, each call finishing its addition with the value returned from below. Without the base case, the calls would never stop — until the program runs out of stack memory and crashes (P6).

Trust is the key mental move. To write sumDigits, you don't picture every call. You assume sumDigits(n/10) correctly sums the other digits, and write one line that uses it. If the base case is right and each call gets smaller, the whole thing is right. Chapter 11 builds on exactly this idea.

Lambdas: functions written in place

Sometimes you need a tiny function right where you use it — most often, to tell sort what order you want. A lambda is an unnamed function written inline: [](int a,int b){return a>b;}. The square brackets can capture variables from around it: [&] lets the lambda use (and change) local variables by reference. You'll see lambdas in P5 for sorting, and in later chapters for small recursive helpers.

⚠️
Common mistakes
  • Forgetting the & on a container parameter. Correct but silently many times slower. In a recursive helper, it's often the difference between AC and TLE.
  • Uninitialised locals. int count; holds garbage. Always write =0 (or the right start value).
  • Off-by-one loop bounds. i<=n on an array of size n reads one past the end. Valid indexes are 0 … n − 1.
  • No base case, or one that's never reached. Infinite recursion ends in a stack overflow (Runtime Error).
  • Missing return on some path. A non-void function that falls off the end returns garbage. -Wall warns you.
  • Changing a loop variable inside the loop by accident, or reusing i in an inner loop. Use j, k for nested loops.

Interview drill

Explain it simply: What's the difference between passing a vector by value, by reference and by const reference?

How a strong answer sounds
By value copies the whole vector — O(n) time and memory per call — and changes stay inside the function. By reference passes the original with no copy, so it's O(1) and changes are visible to the caller. By const reference also avoids the copy but forbids changes, so it's the right choice for large inputs a function only reads. I pass containers by reference by default; forgetting that in a recursive function can turn an O(n) solution into an O(n²) one.

Trace it: How many times does the inner body run in for(i=0;i<n;i++) for(j=i+1;j<n;j++) when n = 5?

How a strong answer sounds
For i = 0 the inner loop runs 4 times, then 3, 2, 1 and 0: 4 + 3 + 2 + 1 = 10, which is n(n − 1)/2 = 5 × 4 / 2. It visits each unordered pair once, so it's O(n²) even though it's about half of n².

🧠 Key takeaways

  • Start every function with a guard clause for the special cases; then the main logic can assume normal input.
  • for(int i=0;i<n;i++) visits indexes 0 … n − 1; while is for “until something happens”; break leaves, continue skips.
  • An inner loop starting at i+1 visits each pair once: n(n − 1)/2 rounds, which is O(n²).
  • Trace code by hand: write each variable's value after each line. It's the fastest debugger there is.
  • No & is a copy (O(n) for containers); & is the original; const & is the original, read-only. Containers go by reference.
  • Variables live only inside their braces; initialise locals; globals start at zero.
  • Recursion needs a base case and a smaller recursive call. Trust the smaller call.

Check your understanding

What does this print? void f(int x){x=100;} then int a=5; f(a); cout<<a;

x is passed by value, so the function changes its own copy. The caller's a is still 5. With int &x it would print 100.

A recursive DFS takes vector<vector<int>> adj (no &) and is called once per node on a graph with 10⁵ nodes and 10⁵ edges. What's the likely result?

Each of the ~10⁵ calls copies ~10⁵ entries — around 10¹⁰ operations of pure copying. The logic is correct, so it doesn't give WA; it's simply far too slow. Add &.

How many times does cnt++ run? for(int i=0;i<6;i++) for(int j=i+1;j<6;j++) cnt++;

5 + 4 + 3 + 2 + 1 + 0 = 15 = 6 × 5 / 2: one per unordered pair of 6 items.

What is missing from this function? int f(int n){ return n*f(n-1); }

Every call makes another call with a smaller n, forever: 3, 2, 1, 0, −1, … Nothing ever returns without recursing. Adding if(n<=1)return 1; makes it a correct factorial.

Inside a function you write int sum; and then add values to it. Why might the result be wrong?

Local variables start with whatever bits were in that memory. Write int sum=0;. (Global variables, by contrast, start at zero.)
