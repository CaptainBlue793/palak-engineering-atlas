Bitmask DP

Some problems need to remember which items have been used, not just how many. A set of up to about twenty items fits in one integer: bit i is 1 if item i is in the set. That integer is called a bitmask. So "a set" becomes "a number you can use as a DP array index". This technique turns 2ⁿ·n! into 2ⁿ·n². It is still exponential, but it is the difference between 20 cities being impossible and being instant.

  • Store a subset as an integer and work with it comfortably
  • Spot the tell-tale constraints: n ≤ 20, "each exactly once", orderings
  • Write the assignment DP and see why one index is not needed
  • Work out Held-Karp for the travelling salesman problem
  • Loop over all subsets of a mask in O(3ⁿ), and know when you need to

The constraint signature

Bitmask DP is easy to spot. Before working anything out, check the limits. Look for n ≤ 20 or so, plus a rule that every item is used exactly once, or that the order of the items matters. Those small limits are not a kindness. They are the problem telling you that an exponential number of states is expected.

Where does the saving over brute force come from? Think about a trip that has visited cities 1, 2 and 3 and is now standing in city 4. The routes 1→2→3→4 and 2→1→3→4 cover the same cities and stand in the same place. From here on, the rest of the trip is identical for both — the future only cares which cities are done and where you are, not the order you took. So you keep only the cheaper of the two and forget the other. Brute force carries every ordering to the end (n! of them); bitmask DP merges all orderings that share the same set, leaving about 2ⁿ sets. That merging is the whole reason it works.

🔢
Memory is usually the binding constraint, not time

A dp[1<<20][20] table of int is 20·2²⁰·4 bytes ≈ 84 MB — over the limit on most judges. Three standard ways out:

  • store int instead of long long, and use a large "unreachable" marker value instead of LLONG_MAX;
  • drop to dp[1<<n] alone when the missing index can be worked out from the mask (see the assignment DP below);
  • loop over masks in increasing order and keep only what is still needed.

Always multiply out the table size before you write it. 2ⁿ passes a gigabyte sooner than you would guess.

A subset is an integer

A quick refresher on binary. Each position in a binary number is worth a power of two, counted from the right: bit 0 is worth 1, bit 1 is worth 2, bit 2 is worth 4, and so on. So 26 is 11010 in binary, because 16 + 8 + 2 = 26. Now read each bit as a yes/no answer to "is item i in the set?". Bits 1, 3 and 4 are on, so 26 stands for the set {1, 3, 4}. Every set of items 0..n−1 matches exactly one number from 0 to 2ⁿ − 1, and back. The empty set is 0; the set of everything is 2ⁿ − 1, which is n ones in a row.

The operators you need: & (AND) keeps a bit only if it is on in both numbers, | (OR) keeps it if it is on in either, ^ (XOR) keeps it if it is on in exactly one, ~ flips every bit, and 1<<i is a 1 moved left i places — the number with only bit i on.

Two precedence traps that bite in real code. 1<<i binds looser than comparison, so mask & 1<<i == 0 parses as mask & (1 << (i==0)) — always parenthesise. And 1<<31 overflows a signed int; for N above 30 write 1LL<<i. Chapter 47 covers the bit tricks themselves in depth; here they are just the alphabet.

Try the lines on mask = 26 (11010, the set {1, 3, 4}) with i = 2:

  • (26>>2)&1: shifting right by 2 gives 110, whose last bit is 0 — item 2 is not in the set.
  • 26|(1<<2) = 11010 | 00100 = 11110 = 30, the set {1, 2, 3, 4}.
  • 26&~(1<<2) = 26, unchanged, because item 2 was not there to remove.
  • __builtin_popcount(26) = 3 items.
  • 26&-26 = 2 (00010): the smallest item is item 1. 26&25 = 24 (11000): item 1 removed.

The assignment problem

You have N people, N tasks, and a table of costs. Each person does exactly one task. Trying every ordering costs N!. But notice: if you assign people in a fixed order — person 0 first, then person 1, and so on — the number of people already assigned equals the number of 1-bits in the mask. So you do not need a separate index for "which person is next". The state shrinks to the mask alone.

Why does a plain for(mask=0; mask<=full; mask++) loop visit states in a safe order? Every transition adds a bit, and adding a bit always makes the number bigger. So each mask is complete before any mask it pushes into is processed.

minimum-cost assignmentO(2ⁿ·n)O(2ⁿ)
// dp[mask] = the minimum cost of assigning tasks in `mask` to the first
//            popcount(mask) people.
// The person index is NOT stored — it is derivable, which is the whole trick.
int minCostAssignment(vector<vector<int>> &cost){
	int N=cost.size();
	int full=(1<<N)-1;
	vector<int> dp(1<<N,INT_MAX);

	dp[0]=0;                              // nobody assigned, nothing spent

	for(int mask=0;mask<=full;mask++){
		if(dp[mask]==INT_MAX)continue;      // unreachable state, skip

		int person=__builtin_popcount(mask);   // derived, not stored

		if(person==N)continue;               // everyone already has a task

		for(int task=0;task<N;task++){
			if((mask>>task)&1)continue;        // task already taken

			int next=mask|(1<<task);

			dp[next]=min(dp[next],dp[mask]+cost[person][task]);
		}
	}

	return dp[full];
}
This is a forward, "push" DP. Each state updates the states that come after it, instead of pulling from the ones before it. Both directions work. Push is natural here because the next states are easy to list. Two details worth copying. First, skip unreachable states (dp[mask]==INT_MAX), so you never add to the marker value and overflow. Second, get person from popcount (the count of 1-bits) instead of adding a dimension — that alone divides the memory by N. The cost is O(2ⁿ·n) against N! for brute force: at N = 15, seven million operations versus 1.3 trillion.

Dry run with N = 3 and cost = [[9,2,7],[6,4,3],[5,8,1]] (row = person, column = task). Masks are written as three bits, task 2 on the left.

✍️
My convention: N for the problem's item count, sentinel-guard before every relax

I use N for the number of items the problem is about — cities, people, nodes — and lower-case n for any other local length, just as in the graph chapters. The line if(dp[mask]==INT_MAX)continue; is the same habit as if(dist[node]==INT_MAX)continue; in Bellman-Ford: never do arithmetic on the "unreachable" marker value (the sentinel). INT_MAX + cost wraps around to a large negative number. That looks like an excellent answer, and it spreads everywhere. You get a wrong answer with no crash to warn you. That is why the check is a habit, not a case-by-case decision.

Held-Karp: the travelling salesman problem

Now a case where the mask is not enough. Visit every city exactly once and return home, using the least total distance. Here the cost of the next step depends on where you are standing now, not only on which cities are done. So the state needs a second index.

Concretely: the routes 0→1→2 and 0→2→1 have both visited {0, 1, 2}, but one stands at city 2 and the other at city 1. The next hop to city 3 costs dist[2][3] for the first and dist[1][3] for the second, so they cannot be merged. The routes 0→1→3→2 and 0→3→1→2, though, share both the set and the current city — those two can be merged, and that is where the saving comes from.

TSP — Held-KarpO(2ⁿ·n²)O(2ⁿ·n)
// dp[mask][i] = the cheapest way to start at city 0, visit exactly the cities
//               in `mask`, and be standing at city i right now.
// Here the mask alone is NOT enough state: the next hop's cost depends on where
// we currently stand, so the current city must be part of the state.
int tsp(vector<vector<int>> &dist){
	int N=dist.size();
	int full=(1<<N)-1;
	vector<vector<int>> dp(1<<N,vector<int>(N,INT_MAX));

	dp[1][0]=0;                           // start at home, only home visited

	for(int mask=1;mask<=full;mask++){
		if(!(mask&1))continue;              // home is always visited

		for(int at=0;at<N;at++){
			if(!((mask>>at)&1))continue;      // cannot stand outside the mask
			if(dp[mask][at]==INT_MAX)continue;  // unreachable

			for(int next=0;next<N;next++){
				if((mask>>next)&1)continue;      // already visited

				int nextMask=mask|(1<<next);

				dp[nextMask][next]=min(dp[nextMask][next],
				                       dp[mask][at]+dist[at][next]);
			}
		}
	}

	// close the tour: from every possible last city, step back home
	int ans=INT_MAX;

	for(int at=1;at<N;at++){
		if(dp[full][at]==INT_MAX)continue;

		ans=min(ans,dp[full][at]+dist[at][0]);
	}

	return ans;
}
Three loops: mask, current city, next city — hence 2ⁿ·n². The detail people miss is the closing step. dp[full][at] is a path that has visited everything and stopped at at. That is not yet a round trip. You must add dist[at][0] and take the minimum over all at. Returning dp[full][0] instead is wrong: that state can never be reached for N > 1, because this state definition does not allow visiting city 0 twice. Held-Karp also shows the point of the chapter. TSP is NP-hard (no known fast exact method), and this does not change that. But it turns O(n!) into O(2ⁿ·n²) — the difference between 15 cities being hopeless and 20 being routine. For a path instead of a round trip, just skip the closing step and take the min over dp[full][at].

Edge cases worth a line each. With N = 1 there is only home: the closing loop runs zero times and ans stays INT_MAX, so return 0 for that case yourself. If some pairs of cities have no road, store them as the unreachable marker and skip them before adding, or the addition overflows. And dist need not be symmetric: the code reads dist[at][next] in the direction travelled, so one-way costs work as they are.

🧩
Does the mask need a companion index?

The deciding question: does the cost of the next choice depend on which item was taken last?

  • No → dp[mask] alone. Assignment, minimum sticks/partitions, "can this set be split into k equal groups". The position can be worked out from popcount.
  • Yes → dp[mask][last]. TSP, shortest superstring, arranging items where being next to each other costs something, counting Hamiltonian paths (paths that visit every node once).
  • The mask means "the edge of the previous column" → broken-profile DP. Tiling a grid column by column, where the mask records which cells stick out past the boundary. The state is dp[column][mask].

Getting this right saves a factor of N in both time and memory. It is worth thirty seconds of thought before you allocate anything.

Submask enumeration

Some problems split a set into groups. Then the transition needs every subset of the current mask (every "submask"), not just one element. Done naively, that is 2ⁿ·2ⁿ = 4ⁿ. The pattern below is O(3ⁿ), which is a huge saving.

How does sub=(sub-1)&mask find the next submask? Subtracting 1 turns the lowest 1-bit of sub into 0 and every bit below it into 1. The &mask then throws away the 1s that landed outside mask. The result is the next smaller number whose bits all lie inside mask. For mask = 1011 the loop visits 1011, 1010, 1001, 1000, 0011, 0010, 0001 and stops at 0: all 2³ − 1 = 7 non-empty submasks, and nothing else.

minimum groups — iterate the submasks of each maskO(3ⁿ)O(2ⁿ)
// The classic loop. `sub` walks every non-empty subset of `mask`, in
// decreasing order, and never touches a bit outside mask.
// Subtracting 1 borrows through the zero bits; the &mask clears the borrow.
for(int sub=mask;sub>0;sub=(sub-1)&mask){
	int rest=mask^sub;                 // the complement WITHIN mask

	// combine an answer for `sub` with an answer for `rest`
}

// dp[mask] = the fewest groups needed to cover exactly the items in mask,
//            where ok[sub] says a single group may contain exactly `sub`.
int minGroups(int N,vector<bool> &ok){
	int full=(1<<N)-1;
	vector<int> dp(1<<N,INT_MAX);

	dp[0]=0;

	for(int mask=1;mask<=full;mask++){
		for(int sub=mask;sub>0;sub=(sub-1)&mask){
			if(!ok[sub])continue;
			if(dp[mask^sub]==INT_MAX)continue;

			dp[mask]=min(dp[mask],1+dp[mask^sub]);
		}
	}

	return dp[full];
}
Why O(3ⁿ)? Each of the n bits is in exactly one of three places: in sub, in rest, or outside mask. Three choices per bit gives 3ⁿ (mask, submask) pairs in total. At n = 16 that is 43 million, which is fine. At n = 20 it is 3.5 billion, which is too slow. So submask loops hit their limit a few bits earlier than plain bitmask DP. A common fix for counting the same split twice in partition problems: always put the lowest set bit of mask into sub. Then each split appears once, instead of once per ordering of its groups.
🧮
Broken-profile DP, in one paragraph

Tiling problems ("count the ways to fill a 2×n or m×n board with dominoes") use the mask differently: the mask describes a boundary, not a set of used items. Work through the board column by column. dp[col][mask] is the number of ways to fill everything before col, where mask records which cells of column col are already covered by a tile sticking out from the left. The transition tries every legal way to place tiles in column col, and each one gives the next column's mask. The simple version is O(n·2ᵐ·2ᵐ), so make m the smaller side. For a 2×10⁵ board that is trivial; for a 10×10 board it is fine. This is the step from "mask as a set" to "mask as a shape", and it is the standard way to count grid tilings.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 n ≤ 20 IS THE HINT
A tiny bound plus "each item exactly once" is the bitmask signature. The bound is not a courtesy; it is telling you an exponential state is expected.
💡 DERIVE, DO NOT STORE
If items are taken in a fixed order, the position is popcount(mask) — no second dimension. That alone divides the memory by n.
⛔ PARENTHESISE
mask & 1<<i == 0 parses as mask & (1==0) and is always false. Always parenthesise, and never do arithmetic on INT_MAX.
⚠️
Common mistakes
  • Arithmetic on INT_MAX. It wraps to a negative number and looks like a great answer. Skip it with if(dp[...]==INT_MAX)continue;.
  • Missing parentheses: mask & 1<<i == 0 parses as mask & (1 << (i==0)).
  • 1<<i for i ≥ 31 overflows signed int; use 1LL<<i.
  • Returning dp[full][0] from TSP. Close the tour with min over at of dp[full][at]+dist[at][0].
  • Standing on a city outside the mask. Check if(!((mask>>at)&1))continue;, or you build tours through cities you have not visited.
  • Storing an index that popcount already gives you — it multiplies memory by N for nothing.
  • Allocating dp[1<<20][20] of long long — 168 MB. Multiply it out first.
  • Looping over masks in the wrong direction in a pull-style DP. A mask must be processed after every mask it reads.
  • Writing the submask loop as sub = sub-1 & mask without the parentheses, or starting at sub=mask-1 and missing the full mask.
  • Counting the same split several times because the groups were built in every order. Always put the lowest set bit on one side.
  • Reaching for bitmask DP when n is 10⁵. Re-read the limits — a different technique is intended.

Interview drill

Warm-up: N people, N tasks, a cost matrix, N ≤ 15. Minimise total cost.

How a strong answer sounds
The limit N ≤ 15 is the giveaway. It is far too small to need a polynomial algorithm, and far too large for 15! brute force. So a DP that is exponential in N, with a subset as the state, is intended. I store the set of already-assigned tasks as a bitmask, and define dp[mask] as the minimum cost of assigning exactly the tasks in mask. The key saving: I do not need to store which person we are up to. If people are assigned in a fixed order, the number already assigned is exactly popcount(mask), the number of 1-bits. So the person index can be worked out. That saves a factor of N in memory and in code. The transition, written as a push: for each reachable mask, let person = popcount(mask); for each task not yet in mask, update dp[mask | 1<<task] with dp[mask] + cost[person][task] if that is smaller. The answer is dp[(1<<N)−1]. That is O(2ᴺ·N) time — about half a million operations at N = 15 — and O(2ᴺ) memory. One line I would never leave out is the check that skips unreachable masks. Adding a cost to INT_MAX wraps to a negative number and quietly spoils the table. That gives a wrong answer, not a crash, so it pays to be strict about it. If asked to go beyond about 20, I would say the exact answer needs the Hungarian algorithm, which solves assignment in O(N³), polynomial time. It is worth naming, because assignment is the one problem in this family that is polynomial, unlike TSP.

How a strong answer sounds
I define dp[mask][i] as the cheapest way to start at city 0, visit exactly the cities in mask, and be standing at city i right now. Unlike the assignment problem, the mask alone is not enough state here. The cost of the next hop depends on where I am standing, so the current city has to be part of the state. Base case: dp[1][0] = 0 — only home visited, standing at home. The transition, pushing forward: from a reachable dp[mask][at], for every city next not in mask, update dp[mask | 1<<next][next] with dp[mask][at] + dist[at][next] if smaller. The step people get wrong is the finish. dp[full][at] is a Hamiltonian path (visits every city once), not a round trip. So the answer is the minimum over all at of dp[full][at] + dist[at][0]. Returning dp[full][0] is wrong, because that state is unreachable — this definition never visits city 0 twice. Three nested loops give O(2ᴺ·N²) time and O(2ᴺ·N) memory. At N = 18, that is about 85 million operations and a 2ᴺ·N table of ints, roughly 19 MB, which fits. I would do that memory sum out loud, because at N = 20 the same table is 84 MB and usually over the limit. At N = 100, exact Held-Karp is hopeless — 2¹⁰⁰ states — and TSP is NP-hard. So I would change the goal. For a guaranteed approximation when distances obey the triangle inequality (a "metric" instance), the minimum-spanning-tree double-walk is at most 2× the best, and Christofides is at most 1.5×. In practice, building a tour with nearest-neighbour and then improving it with 2-opt or Or-opt local search, or Lin-Kernighan, gets within a couple of percent on thousands of cities. The important thing is to say plainly that the exact answer is out of reach and name what replaces it, instead of pretending a DP will stretch that far.

🧠 Key takeaways

  • n ≤ 20 with "each item exactly once" or "order matters" is the sign of bitmask DP — the small limit is the hint.
  • Ask whether the mask needs a second index. It does when the next cost depends on which item was taken last.
  • Work out what you can from the mask (popcount gives the position) instead of storing an extra dimension.
  • Never do arithmetic on the "unreachable" marker; skip unreachable states before every update.
  • Looping over submasks with sub=(sub-1)&mask is O(3ⁿ), so it hits its limit a few bits earlier than plain 2ⁿ DP.

Check your understanding

A problem says "n ≤ 18, assign each worker exactly one job". What does that suggest?

The limit is the hint: too small to need a polynomial algorithm, too large for n! brute force. (Assignment in particular also has a polynomial solution — the Hungarian algorithm — which is worth naming if the limit grows.)

In the assignment DP, why is dp[mask] enough, without a second index for the person?

Working it out instead of storing it saves a factor of N in memory. Compare TSP, where the current city really cannot be worked out from the mask and must be stored.

Why does TSP need dp[mask][i] rather than dp[mask]?

That is the deciding question for every bitmask problem: does the next choice's cost depend on the last item taken? Yes here, no in assignment.

After filling the Held-Karp table, what is the answer?

dp[full][at] has visited everything but stopped at at. dp[full][0] can never be reached for N > 1, because city 0 cannot be visited twice. (Option 3 is right for a Hamiltonian path instead of a round trip.)

The loop for(int sub=mask; sub>0; sub=(sub-1)&mask) costs how much over all masks?

Three separate choices per bit gives 3ⁿ pairs. In practice, submask DP tops out around n = 16 instead of n = 20. Know that before you commit to it.
