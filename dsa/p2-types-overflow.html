C++ Types, Operators & Overflow

A type tells the computer how much memory a value gets and what it means. The type decides the range — the smallest and largest value it can hold — and how arithmetic behaves. Choose a type that is too small and the value silently turns into garbage, with no error message. This single mistake, called overflow, is behind a surprising share of “Wrong Answer on test 23” verdicts. This chapter teaches the handful of types and operators every chapter uses, and how to never be bitten by overflow, integer division or floating-point rounding again.

Why types matter so much in C++

In Python, integers grow as big as they need to: 10**30 just works. C++ is different. Each integer type has a fixed number of bits, chosen for speed, so it has a fixed range. When a result doesn't fit, C++ does not stop or warn you. It keeps only the low bits and carries on with a wrong number.

That's why the first thing a strong competitive programmer reads is the constraints line of a problem: “1 ≤ n ≤ 10⁵, 1 ≤ aᵢ ≤ 10⁹”. Those numbers decide the types before any algorithm is chosen. If n values up to 10⁹ are summed, the total can reach 10¹⁴ — far beyond an int.

🚗
Analogy: a car's odometer

An odometer has a fixed number of digits. Drive past 999,999 and it doesn't grow a seventh digit — it rolls over to 000,000. An int is the same, except its “digits” are 32 bits, and rolling over past about 2.1 × 10⁹ lands on a large negative number.

✍️
My rule for choosing

Indexes and sizes: int. Anything that is a sum, a product, a count of pairs, or can exceed 2 × 10⁹: long long, decided from the constraints before writing a line. Decimals: double, only when the problem truly needs fractions. When unsure, long long costs nothing noticeable and prevents a whole class of bugs.

Why the range is what it is

A 32-bit integer has 2³² ≈ 4.3 billion possible bit patterns. Signed types split them between negatives and non-negatives, using the leftmost bit as the sign (a scheme called two's complement). That gives −2³¹ to 2³¹ − 1: one more negative number than positive, because zero takes a slot on the non-negative side. Here is what happens at the top edge:

An 8-bit signed type holds −128 to 127. Slide past 127 and the stored value wraps round to −128 and upwards — exactly what a 32-bit int does past 2,147,483,647, just with smaller numbers so you can see every bit. The red-outlined bit is the sign.

Two of these deserve a closer look.

Short-circuit evaluation is a feature you'll rely on constantly. In i<n and a[i]>0, if i<n is false, C++ never evaluates a[i] — which is exactly what stops an out-of-range read. So always put the bounds check first. (The course writes and/or; they mean exactly the same as &&/||.)

Assignment vs comparison. if(x=5) doesn't compare: it sets x to 5, and 5 counts as true, so the branch always runs. -Wall warns about it — one more reason to compile with warnings on.

The overflow trap

Here is the concrete example. Two numbers of 50,000 each fit easily in an int. Their product, 2,500,000,000, does not.

the overflow trap, and the fixsilent wrong answer
int a=50000,b=50000;
int bad=a*b;                  // -1794967296 on a typical judge
long long still=a*b;          // STILL wrong: a*b is worked out as int first
long long good=1LL*a*b;       // 2500000000: 1LL makes the maths long long
long long alsoGood=(long long)a*b;
The trap in line 3: the type on the left does not matter. C++ computes a*b using the types of a and b, both int, overflows, and only then stores the broken result in a long long. Make one operand a long long before multiplying. (Strictly, signed overflow is “undefined behaviour” in C++, so the compiler is allowed to do anything. In practice you get the wrapped-around value.)

Rule of thumb: if two values up to 10⁹ are multiplied or many values are added, use long long. If even that is not enough, the problem will ask for the answer “modulo 10⁹ + 7” (P7).

Where overflow hides

Overflow rarely announces itself as “a times b”. These are the places it actually lurks in DSA code:

  • Running sums. 10⁵ values of 10⁹ each sum to 10¹⁴. The sum variable must be long long, even if every element fits in an int.
  • Squares and areas. x*x with x up to 10⁵ is 10¹⁰. Distances squared in geometry overflow constantly.
  • The middle of a range. mid=(lo+hi)/2 overflows when lo and hi are both near 2 × 10⁹. The safe form is mid=lo+(hi-lo)/2 (Chapter 7).
  • Counting pairs. n(n − 1)/2 with n = 10⁵ is about 5 × 10⁹ — over the int limit.
  • “Infinity” plus something. INT_MAX+1 overflows. When a distance array uses a big “infinity”, adding an edge weight to it can wrap round to a negative number that looks like a great shortcut. Use a smaller infinity like 1e9 or LLONG_MAX/4, or check before adding.
  • Factorials and powers. 13! already overflows int, and 21! overflows long long. That's what “modulo 10⁹ + 7” is for.

Mixing types: conversions and casts

When an expression mixes types, C++ converts them to a common type first, and the result can surprise you:

int a=7,b=2;
double x=a/b;                 // 3.0 — a/b is int division, THEN converted
double y=(double)a/b;         // 3.5 — convert first, then divide
double z=a/2.0;               // 3.5 — a double on either side is enough
int k=3.99;                   // 3   — converting to int chops the fraction (no rounding)
int r=(int)round(3.5);         // 4   — round first if you want rounding
char c='a'+2;                // 'c' — characters are numbers

The same rule as overflow applies: the conversion happens where you write it, not where you store the result. (double)(a/b) is still 3.0, because the brackets force the integer division first.

The unsigned trap: size()

v.size() returns an unsigned number — a type that can never be negative. Unsigned arithmetic wraps round at zero instead: 0 − 1 becomes 18,446,744,073,709,551,615. So on an empty vector, v.size()-1 is that enormous number, and this innocent-looking loop runs far past the end and crashes:

// BAD on an empty vector: v.size()-1 wraps around to about 1.8e19
for(int i=0;i<v.size()-1;i++)
if(v[i]>v[i+1])
cnt++;

// GOOD: move the arithmetic to the int side, or guard first
for(int i=0;i+1<v.size();i++)
if(v[i]>v[i+1])
cnt++;

Two safe habits: write i+1<v.size() instead of i<v.size()-1, or store the size in an int first — int n=v.size(); — which the course does at the top of most functions.

Floating point: double

A double stores numbers like scientific notation in binary: about 15–16 significant digits and an exponent. That covers a huge range, but most decimal fractions can't be stored exactly — just as 1/3 can't be written exactly in decimal. So 0.1+0.2 is really 0.30000000000000004, and 0.1+0.2==0.3 is false.

const double EPS=1e-9;
bool eq(double a,double b){
	return fabs(a-b)<EPS;      // "close enough" instead of ==
}

Rules for DSA:

  • Prefer integers whenever the problem allows. Compare fractions a/b < c/d as 1LL*a*d<1LL*c*b (for positive b and d), with no division at all. Geometry is often done entirely in integers (Chapter 49).
  • Never use a double for exact counting — counts, indexes, money. A double stores integers exactly only up to 2⁵³ ≈ 9 × 10¹⁵.
  • Be careful with sqrt on big integers. (long long)sqrt(x) can be off by one for large x. Adjust with a small loop: while r·r > x decrease r; while (r+1)·(r+1) ≤ x increase r.
  • Print with enough digits when the answer is a decimal: cout<<fixed<<setprecision(9)<<ans;.

Characters are small numbers

A char holds one character, stored as a number using the ASCII table. The key facts: the digits '0'–'9' are codes 48–57, uppercase 'A'–'Z' are 65–90, lowercase 'a'–'z' are 97–122, each group in order. So character arithmetic works:

int d='7'-'0';             // 7: the digit's value
int idx='e'-'a';           // 4: position in the alphabet, perfect as an array index
char up='q'-'a'+'A';       // 'Q': shift from lowercase to uppercase
vector<int> cnt(26,0);
for(auto &ch:s)
cnt[ch-'a']++;               // letter frequencies — you'll use this in every string chapter

Common mistakes
  • Using int for a sum or product that can pass 2 × 10⁹. No error, just a wrong, often negative, answer. Decide types from the constraints.
  • Casting after the arithmetic. (long long)(a*b) is too late. Write 1LL*a*b.
  • Integer division by accident. sum/n for an average of ints throws the fraction away. Use (double)sum/n.
  • v.size()-1 on an empty vector. Unsigned wrap-around. Write i+1<v.size() or copy the size to an int first.
  • Comparing doubles with ==. Use a small epsilon, or avoid doubles altogether.
  • Checking bounds second. a[i]>0 and i<n reads a[i] before checking i. Bounds first.

Interview drill

Warm-up: Your solution passes all the examples but gets “Wrong Answer on test 23”. The values go up to 10⁹. What do you check first?

How a strong answer sounds
Overflow, before anything else. Values up to 10⁹ mean any sum of two of them, or any product, can pass the 2.1 × 10⁹ limit of an int. The small examples in the statement never get near that, which is exactly why they pass. I would look at every place I add or multiply values and make sure the variable, and the arithmetic itself, is long long — for example 1LL*a*b, not (long long)(a*b). Then I would check the other usual suspects on large hidden tests: an empty or single-element input, and a negative value going into %.

Spot the bug: int lo=0,hi=2000000000; int mid=(lo+hi)/2; — what's wrong, and how do you fix it?

How a strong answer sounds
Once lo moves up, lo + hi can exceed 2,147,483,647 and overflow to a negative number, so mid becomes negative and the binary search breaks. Write mid=lo+(hi-lo)/2, which never exceeds hi, or use long long for lo and hi.

🧠 Key takeaways

  • int holds about ±2.1 × 10⁹; long long about ±9.2 × 10¹⁸. Choose from the constraints, before coding.
  • Overflow is silent. Convert before the arithmetic: 1LL*a*b. Watch sums, squares, mids, pair counts and “infinity + x”.
  • Two ints divide to an int (fraction thrown away); converting a double to int chops, not rounds.
  • size() is unsigned: v.size()-1 on an empty vector is huge. Use i+1<v.size() or int n=v.size().
  • Doubles are approximate: compare with an epsilon, prefer integers, never count with them.
  • Characters are numbers: ch-'0' gives a digit's value, ch-'a' an alphabet index.
  • Short-circuit and/or: put the bounds check first.

Check your understanding

int a=50000,b=50000; then long long c=a*b;. What is in c?

The type of the variable on the left does not change how the right side is computed. a*b uses int arithmetic, overflows, and only the broken result is stored. Write 1LL*a*b so the multiplication itself happens in 64 bits.

What does double avg=sum/n; store when sum=7 and n=2 are both int?

sum/n is integer division, giving 3, and only then is 3 converted to 3.0. Write (double)sum/n to get 3.5.

A vector v is empty. What happens in for(int i=0;i<v.size()-1;i++)?

size() is unsigned, so 0 − 1 wraps round to about 1.8 × 10¹⁹. Use i+1<v.size(), or copy the size into an int first.

What is the value of '9'-'0' in C++?

Characters are stored as numbers: '9' is 57 and '0' is 48 in ASCII, and the digits are consecutive, so the difference is 9 — the digit's value.
