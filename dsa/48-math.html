Number Theory & Math

A short list of mathematical tools shows up again and again: GCD, sieves, fast exponentiation, and modular arithmetic. None of them is deep, but each has a canonical implementation worth having in your fingers, and each has one specific failure mode — overflow, a negative remainder, an off-by-one in a sieve bound — that produces a wrong answer rather than a crash.

  • Use the Euclidean algorithm and its extended form
  • Build a sieve, and a smallest-prime-factor table that factorises in O(log n)
  • Write binary exponentiation and recognise it as a general pattern
  • Do arithmetic modulo 10⁹+7 safely, including division by modular inverse
  • Compute nCr mod p, and apply matrix exponentiation to linear recurrences

GCD and the Euclidean algorithm

gcd, lcm, and the extended versionO(log min(a,b))O(1) iterative
// gcd(a,b) = gcd(b, a%b), and gcd(a,0) = a. That is the whole algorithm.
int gcd(int a,int b){
	if(b==0)return a;

	return gcd(b,a%b);
}

// Iterative — same thing, no stack.
int gcdIterative(int a,int b){
	while(b){
		int temp=a%b;

		a=b;
		b=temp;
	}

	return a;
}

// lcm via gcd — divide FIRST to avoid overflowing on the product.
long long lcm(long long a,long long b){
	if(a==0 or b==0)return 0;

	return (a/gcd(a,b))*b;      // NOT (a*b)/gcd(a,b)
}

// Extended Euclid: find x,y with a*x + b*y = gcd(a,b).
// Needed for the modular inverse when the modulus is not prime.
int extgcd(int a,int b,int &x,int &y){
	if(b==0){
		x=1;
		y=0;

		return a;
	}

	int x1;
	int y1;
	int g=extgcd(b,a%b,x1,y1);

	x=y1;
	y=x1-(a/b)*y1;

	return g;
}
(a/gcd)*b rather than (a*b)/gcd — with two values near 10⁹ the product overflows a 64-bit integer only rarely, but with three or four LCMs chained it will, and dividing first costs nothing. The complexity is O(log min(a,b)) because consecutive remainders shrink at least as fast as Fibonacci numbers grow, which is the classic worst case. C++17 offers std::gcd and std::lcm in <numeric>; know them, but be able to write the four lines. extgcd keeps the same helper-with-references shape as the rest of this course — x and y are outputs, the return value is the gcd.
🧩
Where GCD quietly solves the problem
  • Rotating an array by k — the number of independent cycles is gcd(n,k).
  • Fractions — reduce by dividing both parts by their gcd; compare a/b and c/d as a*d vs c*b to stay in integers.
  • "Can I measure exactly t litres with jugs of a and b?" — yes iff t is a multiple of gcd(a,b) (and t ≤ max). This is Bézout's identity, which is what extgcd constructs.
  • Points visible from the origin, or lattice points on a segment — gcd(dx,dy).
  • Grouping by a common divisor — the gcd of a whole array is the fold of pairwise gcds, and it drops fast, so an early exit at 1 is worth adding.

Plain sieve
// isPrime[i] for every i up to N, in O(N log log N).
vector<bool> sieve(int N){
	vector<bool> isPrime(N+1,true);

	isPrime[0]=false;

	if(N>=1)isPrime[1]=false;   // 1 is NOT prime

	for(long long p=2;p*p<=N;p++){
		if(!isPrime[p])continue;

		for(long long multiple=p*p;multiple<=N;multiple+=p)
		isPrime[multiple]=false;
	}

	return isPrime;
}

// Single-number primality — trial division up to the square root.
bool isPrimeOne(long long n){
	if(n<2)return false;

	for(long long d=2;d*d<=n;d++){
		if(n%d==0)return false;
	}

	return true;
}

Two details. The outer loop stops at p*p <= N, because any composite up to N has a factor at most √N. And the inner loop starts at p*p, since 2p, 3p, …, (p−1)p were already crossed out by smaller primes. Use long long for p*p when N approaches 2·10⁹ — p*p overflows int well before p does.

Smallest prime factor
// spf[i] = the smallest prime factor of i. Same cost as a plain sieve, but it
// factorises any i <= N in O(log i) afterwards — far better than trial division
// when you must factorise many numbers.
vector<int> smallestPrimeFactor(int N){
	vector<int> spf(N+1,0);

	for(int i=2;i<=N;i++){
		if(spf[i])continue;           // already has a smaller factor

		for(long long j=i;j<=N;j+=i){
			if(!spf[j])spf[j]=i;      // only the FIRST (smallest) one sticks
		}
	}

	return spf;
}

// Factorise using spf — repeatedly divide out the smallest factor.
vector<pair<int,int>> factorise(int n,vector<int> &spf){
	vector<pair<int,int>> ans;

	while(n>1){
		int p=spf[n];
		int count=0;

		while(n%p==0){
			n/=p;
			count++;
		}

		ans.push_back({p,count});
	}

	return ans;
}

Build the spf table whenever the problem factorises many numbers — "count divisors of every i up to 10⁶", "group by prime factors", "Euler's totient for a range". Each factorisation is then O(log n) instead of O(√n), which at 10⁶ queries is the difference between instant and a timeout.

Binary exponentiation

Computing a^b by multiplying b times is O(b). Squaring halves the exponent each step, giving O(log b). This is the single most reusable idea in the chapter — it works for any associative operation, which is why the same skeleton gives matrix powers and, in Chapter 50, string hashing.

fast power, with and without a modulusO(log b)O(1)
const long long MOD=1000000007;

// a^b mod MOD. Read b in binary: every set bit contributes the current square.
long long power(long long a,long long b){
	long long ans=1;

	a%=MOD;

	if(a<0)a+=MOD;               // guard a negative base

	while(b>0){
		if(b&1)ans=(ans*a)%MOD;   // this bit of b is set

		a=(a*a)%MOD;               // square the base
		b>>=1;                    // next bit
	}

	return ans;
}

// Why long long: (10^9+6)^2 is about 10^18, which fits in a signed 64-bit
// integer (max ~9.2*10^18) but NOT in a 32-bit int. Every product of two
// values mod 10^9+7 must be computed in 64 bits.
The pattern, stated generally: to apply an associative operation b times, decompose b in binary, and repeatedly square the operand. It gives a^b, matrix powers for linear recurrences, and — with + in place of × — multiplication by doubling, which is how you multiply safely when even the product of two long longs would overflow. Memorise this loop. It appears in the modular inverse, in nCr, and in matrix exponentiation below, and each of those is two lines once you have it.

Modular arithmetic

🧾
The four rules, and the two traps
OperationModular formNote
Addition(a + b) % msafe
Subtraction((a - b) % m + m) % mC++ % can return a negative
Multiplication(1LL * a * b) % mneeds 64 bits
Division(a * inverse(b)) % mno such thing as /

Trap 1: C++ % follows the sign of the dividend. (-7) % 5 is -2, not 3. Any subtraction under a modulus needs the + m correction, and a negative index into an array is far worse than a wrong number. Trap 2: int * int is computed as int even when assigned to a long long — so long long c = a * b; with a, b near 10⁹ has already overflowed before the assignment. Write 1LL * a * b, or make the variables long long to begin with.

modular inverse and nCr mod pO(N) setup, O(1) per queryO(N)
// Fermat's little theorem: if MOD is PRIME and a is not a multiple of it,
// then a^(MOD-1) = 1, so a^(MOD-2) is the inverse of a.
long long inverse(long long a){
	return power(a,MOD-2);
}

// nCr mod p, with factorials precomputed once.
// The inverse factorials are built DOWNWARD with one modular inverse total,
// using invFact[i-1] = invFact[i] * i.
vector<long long> fact;
vector<long long> invFact;

void buildFactorials(int N){
	fact.assign(N+1,1);
	invFact.assign(N+1,1);

	for(int i=1;i<=N;i++)
	fact[i]=(fact[i-1]*i)%MOD;

	invFact[N]=inverse(fact[N]);          // ONE call to power()

	for(int i=N;i>0;i--)
	invFact[i-1]=(invFact[i]*i)%MOD;
}

long long nCr(int n,int r){
	if(r<0 or r>n)return 0;

	return ((fact[n]*invFact[r])%MOD*invFact[n-r])%MOD;
}
Fermat requires a prime modulus — which 10⁹+7 is, and that is exactly why problems choose it. For a composite modulus, use extgcd instead, and note the inverse exists only when gcd(a,m)==1. The downward loop for invFact is worth internalising: the naive version calls power N times for O(N log MOD), whereas this does one inverse and N multiplications. For nCr with a small non-prime modulus, or with n larger than the modulus, you need Lucas' theorem — worth naming if it comes up.
✍️
My convention: long long everywhere under a modulus, and one MOD constant

Once a problem says "modulo 10⁹+7", I make every intermediate value long long and never mix in a bare int. It costs nothing at these sizes and it removes an entire class of silent wrong answers — the int * int overflow above is the single most common cause of "my DP is right but the answer is wrong". I also declare MOD once as const long long rather than writing the literal in twenty places, because a typo in one of twenty copies of 1000000007 is almost impossible to spot by reading. The same instinct as passing state by reference rather than duplicating it: one source of truth.

Matrix exponentiation

Fibonacci in O(log n). Any linear recurrence — f(n) = c₁f(n−1) + c₂f(n−2) + … — can be written as a matrix acting on a state vector, and then the n-th term is a matrix power, which binary exponentiation computes in O(k³ log n) for a k×k matrix.

Fibonacci in O(log n)O(8 log n)O(1)
// [ F(n+1) ]   [ 1 1 ]^n   [ F(1) ]
// [ F(n)   ] = [ 1 0 ]   * [ F(0) ]
// So F(n) is an entry of the n-th power of that 2x2 matrix — and a matrix
// power is just binary exponentiation with matrix multiply instead of *.
using Matrix=vector<vector<long long>>;

Matrix multiply(Matrix &A,Matrix &B){
	int n=A.size();
	Matrix C(n,vector<long long>(n,0));

	for(int i=0;i<n;i++){
		for(int k=0;k<n;k++){
			if(A[i][k]==0)continue;

			for(int j=0;j<n;j++)
			C[i][j]=(C[i][j]+A[i][k]*B[k][j])%MOD;
		}
	}

	return C;
}

Matrix matrixPower(Matrix A,long long b){
	int n=A.size();
	Matrix ans(n,vector<long long>(n,0));

	for(int i=0;i<n;i++)
	ans[i][i]=1;                      // the identity matrix

	while(b>0){
		if(b&1)ans=multiply(ans,A);
		A=multiply(A,A);
		b>>=1;
	}

	return ans;
}

long long fibonacci(long long n){
	if(n==0)return 0;

	Matrix base={{1,1},{1,0}};
	Matrix result=matrixPower(base,n-1);

	return result[0][0];               // F(n)
}
The exponentiation loop is byte-for-byte the same as power with multiply substituted for * and the identity for 1 — that is the payoff of recognising the pattern rather than memorising the function. Use it when n is up to 10¹⁸ and the recurrence is linear with constant coefficients; an O(n) DP is better for n up to 10⁷ because the constant factor is far smaller. To build the matrix for a new recurrence, write the state vector you need (usually the last k terms) and ask what each row must be to produce the next state — the top row is the coefficients, and the rest is a shift.
📐
Other results worth recognising
  • Euler's totient φ(n) — the count of integers below n coprime to it; φ(n) = n·∏(1 − 1/p) over its distinct primes. Needed for the modular inverse under a composite modulus, via a^(φ(m)−1).
  • Chinese Remainder Theorem — a system x ≡ aᵢ (mod mᵢ) with pairwise coprime moduli has a unique solution modulo the product. Used to reconstruct a large value from several small-modulus computations.
  • Number of divisors — from the factorisation ∏pᵢ^eᵢ, it is ∏(eᵢ+1); their sum is ∏(pᵢ^(eᵢ+1)−1)/(pᵢ−1). Both are instant once you have the spf table.
  • Catalan numbers — C(2n,n)/(n+1); count balanced bracket sequences, binary tree shapes and triangulations. Under a modulus, that division is a modular inverse.
  • Inclusion-exclusion — "count numbers ≤ N divisible by at least one of p₁…pₖ" alternates signs over the 2ᵏ subsets; the natural partner of a bitmask loop (Chapter 44).
  • Miller-Rabin — deterministic primality for 64-bit values with a fixed base set, when trial division at √n is too slow.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 DIVIDE FIRST
Compute LCM as (a/gcd)*b, never (a*b)/gcd. Identical result, and the intermediate value stays inside 64 bits.
⛔ MODULAR MINUS
C++ % follows the sign of the dividend, so (-7)%5 is −2. Every modular subtraction needs ((a-b)%m + m)%m, and every product needs 1LL*.
💡 ONE INVERSE
Build inverse factorials with a single call to power and a downward loop (invFact[i-1] = invFact[i]*i). N calls to power is the wasteful way.
⚠️
Common mistakes
  • int * int overflow before the assignment. Write 1LL * a * b even when the target is long long.
  • Negative results from %. After any subtraction, apply ((x % m) + m) % m.
  • (a*b)/gcd for LCM instead of (a/gcd)*b.
  • Treating 1 as prime, or forgetting isPrime[0] and isPrime[1].
  • Starting the sieve's inner loop at 2p — correct but wasteful; p*p is the point.
  • p*p overflowing int in the sieve bound when N is large.
  • Using Fermat's inverse with a composite modulus. It needs a prime; otherwise use extgcd, and the inverse may not exist.
  • Calling power N times to build inverse factorials instead of one inverse plus a downward loop.
  • Trial division per query when a smallest-prime-factor table makes each factorisation O(log n).
  • Matrix exponentiation for n ≤ 10⁷, where a plain O(n) DP has a far smaller constant.
  • Forgetting the modulus inside the matrix multiply, so entries overflow after a few squarings.

Interview drill

Warm-up: Compute nCr mod 10⁹+7 for many queries with n up to 10⁵.

How a strong answer sounds
nCr is n! / (r! (n−r)!), and under a modulus there is no division — so I need modular inverses. Since 10⁹+7 is prime, Fermat's little theorem gives me one directly: a^(p−1) ≡ 1, so a^(p−2) is the inverse of a, computed by binary exponentiation in about 30 multiplications. The plan is to precompute fact[0..N] with a single forward pass, then the inverse factorials. The naive way is to call power once per index, which is O(N log p) — fine but wasteful. Better: compute invFact[N] with one call to power, then walk downward using invFact[i−1] = invFact[i] · i, which is O(N) multiplications total. After that each query is two multiplications: fact[n] · invFact[r] · invFact[n−r], all mod p. Every intermediate must be long long, because the product of two values near 10⁹ is about 10¹⁸ — that fits in a signed 64-bit integer but overflows a 32-bit int, and the classic bug is writing long long c = a * b; where a and b are ints, so the multiplication has already overflowed before the assignment. I would also guard r < 0 or r > n by returning 0. Two extensions worth naming: if the modulus were composite I could not use Fermat and would need the extended Euclidean algorithm, with the inverse only existing when gcd(a, m) = 1; and if n could exceed the modulus I would need Lucas' theorem.

Deeper: Return the n-th Fibonacci number mod 10⁹+7, where n can be 10¹⁸.

How a strong answer sounds
An O(n) DP is out — 10¹⁸ iterations. The recurrence is linear with constant coefficients, so I express one step as a matrix acting on the state vector: the column [F(n+1), F(n)] equals [[1,1],[1,0]] times [F(n), F(n−1)]. Applying that step n−1 times means raising the 2×2 matrix to the (n−1)-th power, and a matrix power is computed by exactly the same binary exponentiation loop as an integer power — while b > 0, if the low bit is set multiply the answer by the current base, then square the base and shift b right — with matrix multiply in place of scalar multiply and the identity matrix in place of 1. That is O(log n) matrix multiplications, each 8 scalar multiplications for a 2×2, so a few hundred operations for n = 10¹⁸. Every entry is reduced mod 10⁹+7 inside the multiply, otherwise the values overflow after a handful of squarings, and I keep everything in long long since each product of two residues is around 10¹⁸. I would note the generalisation, because that is what makes this worth knowing: any linear recurrence over the last k terms becomes a k×k matrix — top row the coefficients, remaining rows a shift — and runs in O(k³ log n). And I would give the honest caveat that for n up to about 10⁷ the plain O(n) loop is faster in practice, since its constant factor is tiny; matrix exponentiation earns its place specifically when n is astronomically large. There is also the fast-doubling identity for Fibonacci in particular, which avoids matrices and is a little quicker, but the matrix method is the one that generalises.

🧠 Key takeaways

  • gcd(a,b) = gcd(b, a%b); compute LCM as (a/gcd)*b to avoid overflow.
  • Sieve in O(N log log N), marking from p*p; a smallest-prime-factor table factorises in O(log n).
  • Binary exponentiation works for any associative operation — integers, matrices, and more.
  • Under a modulus: subtraction needs +m, multiplication needs 64 bits, and division means a modular inverse.
  • Matrix exponentiation turns any constant-coefficient linear recurrence into O(k³ log n).

Check your understanding

Why write lcm(a,b) as (a/gcd(a,b))*b?

a is exactly divisible by the gcd, so the result is identical — but the intermediate value stays small. It matters most when several LCMs are chained.

In the sieve, why does the inner loop start at p*p rather than 2*p?

Starting at 2p still gives a correct sieve, just slower. The same reasoning explains why the outer loop can stop at p*p <= N.

You need (a - b) % m where a and b are residues. What is correct in C++?

(-7) % 5 is -2 in C++, not 3. A negative residue used as an array index is considerably worse than a merely wrong number.

Fermat's little theorem gives the modular inverse as a^(MOD-2). What does it require?

Which is exactly why problems pick 10⁹+7. For a composite modulus use extended Euclid, and remember the inverse exists only when gcd(a,m)==1.

Matrix exponentiation computes the n-th term of a linear recurrence in O(k³ log n). When is a plain O(n) DP preferable?

Matrix exponentiation earns its keep when n is astronomically large — 10¹⁸ — not merely large. Below that, the simpler loop is usually faster and always easier to get right.
