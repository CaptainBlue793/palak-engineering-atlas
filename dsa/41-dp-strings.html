DP on Strings

Two-string DP has one shape: dp[i][j] over prefixes of both strings, with the transition split on whether the current characters match. LCS, edit distance, wildcard matching and the palindrome family are all that one table with different arithmetic in the two branches. Once you can draw the 3×3 corner of the table by hand, the recurrence writes itself.

  • Write the two-string template and its match / mismatch split
  • Derive LCS and edit distance, and see they are the same table
  • Handle the single-string palindrome family by iterating over lengths
  • Solve wildcard and regex matching, where the mismatch branch gets interesting
  • Reconstruct the actual subsequence or edit script

The two-string template

the shape every two-string DP takesO(n·m)O(n·m) → O(m)
// dp[i][j] = the answer for the first i characters of s and the
//            first j characters of t.
// Size (n+1) x (m+1) so row 0 and column 0 mean "empty prefix" — that
// sentinel row and column are what remove every boundary special case.
vector<vector<int>> dp(n+1,vector<int>(m+1,0));

// base cases: one string empty
for(int i=0;i<=n;i++)dp[i][0]=/* ... */;
for(int j=0;j<=m;j++)dp[0][j]=/* ... */;

for(int i=1;i<=n;i++){
	for(int j=1;j<=m;j++){
		if(s[i-1]==t[j-1]){
			dp[i][j]=/* characters MATCH: usually 1 + dp[i-1][j-1] */;
		}else{
			dp[i][j]=/* MISMATCH: combine dp[i-1][j], dp[i][j-1], dp[i-1][j-1] */;
		}
	}
}

return dp[n][m];
s[i-1], not s[i]. Row i is about the first i characters, so the i-th character sits at index i-1. That shift exists because row 0 must mean "empty", and it is the source of nearly every off-by-one in this chapter. Write the state sentence, then derive the indexing from it rather than guessing.
✍️
My convention: draw the 3×3 corner by hand before writing the loops

Take s = "ab", t = "ac", and fill dp[0][0] through dp[2][2] on paper. It takes thirty seconds and it settles three things at once: what the sentinel row and column should contain, whether the match branch adds 1, and which of the three neighbours the mismatch branch needs. Every string-DP bug I have ever written would have been caught by that 3×3 corner — and it is much faster than debugging the full table.

Switch between LCS and edit distance on the same strings. Identical table shape — only the two branches differ.
Longest common subsequence
// dp[i][j] = the length of the LCS of s[0..i-1] and t[0..j-1].
int longestCommonSubsequence(string &s,string &t){
	int n=s.size();
	int m=t.size();
	vector<vector<int>> dp(n+1,vector<int>(m+1,0));
	// base: an empty prefix shares nothing -> 0, already set

	for(int i=1;i<=n;i++){
		for(int j=1;j<=m;j++){
			if(s[i-1]==t[j-1]){
				dp[i][j]=1+dp[i-1][j-1];
			}else{
				dp[i][j]=max(dp[i-1][j],dp[i][j-1]);
			}
		}
	}

	return dp[n][m];
}

Match → take it and move both back. Mismatch → drop one character from either string, whichever is better. Note the mismatch branch never uses the diagonal, which is what makes the one-row space optimisation easy here.

Edit distance (Levenshtein)
// dp[i][j] = the minimum operations to turn s[0..i-1] into t[0..j-1].
int minDistance(string &s,string &t){
	int n=s.size();
	int m=t.size();
	vector<vector<int>> dp(n+1,vector<int>(m+1,0));

	for(int i=0;i<=n;i++)dp[i][0]=i;   // delete every char
	for(int j=0;j<=m;j++)dp[0][j]=j;   // insert every char

	for(int i=1;i<=n;i++){
		for(int j=1;j<=m;j++){
			if(s[i-1]==t[j-1]){
				dp[i][j]=dp[i-1][j-1];       // free, no operation
			}else{
				dp[i][j]=1+min({dp[i-1][j],      // delete from s
				                  dp[i][j-1],      // insert into s
				                  dp[i-1][j-1]});  // replace
			}
		}
	}

	return dp[n][m];
}

The base cases are non-zero here — turning a length-i string into an empty one costs i deletions. And each of the three mismatch terms is one named operation, which is why the recurrence is memorable rather than arbitrary.

🔗
Three problems that are LCS in disguise
  • Minimum insertions and deletions to convert s into t (no replace allowed) = (n − LCS) + (m − LCS). Everything outside the common subsequence must be deleted from one side and inserted on the other.
  • Shortest common supersequence length = n + m − LCS. The shared part is written once instead of twice.
  • Longest palindromic subsequence of s = LCS(s, reverse(s)). A palindromic subsequence reads the same forwards and backwards, so it is common to both. And therefore minimum insertions to make s a palindrome = n − LPS.

Recognising these saves writing a new recurrence. If you can compute LCS you can answer all four, and "longest palindromic subsequence = LCS with the reverse" is the kind of observation interviewers hope you will make.

The palindrome family: iterate over lengths

Single-string DP where the state is an interval dp[i][j] rather than a pair of prefixes. The loop order changes accordingly: you must fill shorter intervals before longer ones.

longest palindromic substring — interval DPO(n²)O(n²)
// dp[i][j] = is s[i..j] a palindrome?
// s[i..j] is a palindrome iff the ends match AND the inside is one.
// So dp[i][j] depends on dp[i+1][j-1] — a SHORTER interval. Hence we must
// iterate by increasing LENGTH, not by increasing i.
string longestPalindrome(string &s){
	int n=s.size();
	if(n<2)return s;

	vector<vector<bool>> dp(n,vector<bool>(n,false));
	int bestStart=0;
	int bestLen=1;

	for(int i=0;i<n;i++)
	dp[i][i]=true;                    // length 1

	for(int i=0;i<n-1;i++){
		if(s[i]==s[i+1]){
			dp[i][i+1]=true;            // length 2
			bestStart=i;
			bestLen=2;
		}
	}

	for(int len=3;len<=n;len++){       // LENGTH is the outer loop
		for(int i=0;i+len-1<n;i++){
			int j=i+len-1;

			if(s[i]==s[j] and dp[i+1][j-1]){
				dp[i][j]=true;
				bestStart=i;
				bestLen=len;
			}
		}
	}

	return s.substr(bestStart,bestLen);
}
The length-outer loop is the whole point of this section. dp[i][j] reads dp[i+1][j-1], which is two characters shorter — so any order that fills [i][j] before the shorter interval it depends on is wrong, and gives silently false values. An equivalent alternative is to iterate i downward and j upward from i, which also guarantees the dependency is already filled. Chapter 45 generalises this to all interval DP.

Wildcard and regex matching

Same table, but now the mismatch branch is where the interesting logic lives — because * can match a variable number of characters.

// '?' matches exactly one character. '*' matches ANY sequence, including empty.
// dp[i][j] = does s[0..i-1] match p[0..j-1]?
bool isMatch(string &s,string &p){
	int n=s.size();
	int m=p.size();
	vector<vector<bool>> dp(n+1,vector<bool>(m+1,false));

	dp[0][0]=true;                       // empty matches empty

	// a leading run of '*' can match the empty string
	for(int j=1;j<=m;j++){
		if(p[j-1]=='*')dp[0][j]=dp[0][j-1];
	}

	for(int i=1;i<=n;i++){
		for(int j=1;j<=m;j++){
			if(p[j-1]=='*'){
				dp[i][j]=dp[i][j-1]        // '*' matches empty
				       or dp[i-1][j];     // '*' absorbs s[i-1]
			}else if(p[j-1]=='?' or p[j-1]==s[i-1]){
				dp[i][j]=dp[i-1][j-1];
			}
			// else: stays false
		}
	}

	return dp[n][m];
}

The two-way * branch is the trick. dp[i][j-1] means "use * for nothing and move past it"; dp[i-1][j] means "let * swallow one more character and stay on it". Those two options together cover matching any length, without any loop. The dp[0][j] initialisation is essential — otherwise "" vs "*" fails.

// '.' matches one character. 'x*' matches zero or more of x — note that
// '*' here modifies the PRECEDING character, unlike wildcard.
bool isMatch(string &s,string &p){
	int n=s.size();
	int m=p.size();
	vector<vector<bool>> dp(n+1,vector<bool>(m+1,false));

	dp[0][0]=true;

	// patterns like "a*b*c*" can match empty — the star kills its pair
	for(int j=2;j<=m;j++){
		if(p[j-1]=='*')dp[0][j]=dp[0][j-2];
	}

	for(int i=1;i<=n;i++){
		for(int j=1;j<=m;j++){
			if(p[j-1]=='*'){
				char prev=p[j-2];

				dp[i][j]=dp[i][j-2];       // zero occurrences: skip "x*"

				if(prev=='.' or prev==s[i-1])
				dp[i][j]=dp[i][j] or dp[i-1][j];   // one more occurrence
			}else if(p[j-1]=='.' or p[j-1]==s[i-1]){
				dp[i][j]=dp[i-1][j-1];
			}
		}
	}

	return dp[n][m];
}

Regex * is harder than wildcard * because it comes as a pair with the preceding character. Skipping it means j-2, not j-1, and the "one more occurrence" branch is conditional on that preceding character matching. The empty-string initialisation steps by 2 for the same reason.

🔍
Subsequence vs substring: one word changes the recurrence

Subsequence allows gaps, so on a mismatch you may skip a character and keep what you have — hence max(dp[i-1][j], dp[i][j-1]). Substring must be contiguous, so a mismatch resets to zero: dp[i][j] = 0. That single difference turns LCS into longest common substring:

// dp[i][j] = length of the longest common SUBSTRING ending at s[i-1], t[j-1].
int best=0;

for(int i=1;i<=n;i++){
	for(int j=1;j<=m;j++){
		if(s[i-1]==t[j-1]){
			dp[i][j]=1+dp[i-1][j-1];
			best=max(best,dp[i][j]);   // "ending at" -> max over the table
		}
		// else dp[i][j] stays 0 — the run is broken
	}
}

And note the answer is now the maximum over the whole table, not dp[n][m], because the state is "ending at" rather than "first i and j" (Chapter 39's distinction).

Reconstruction

recovering the LCS string and the edit scriptO(n+m)needs the full table
// Walk backwards from dp[n][m], re-deciding which branch produced each cell.
string recoverLCS(string &s,string &t,vector<vector<int>> &dp){
	string ans;
	int i=s.size();
	int j=t.size();

	while(i>0 and j>0){
		if(s[i-1]==t[j-1]){
			ans+=s[i-1];            // this character is in the LCS
			i--;
			j--;
		}else if(dp[i-1][j]>=dp[i][j-1]){
			i--;                     // the better branch came from above
		}else{
			j--;
		}
	}

	reverse(ans.begin(),ans.end());

	return ans;
}
// For edit distance the same walk yields the OPERATIONS: a diagonal move on
// equal characters is "keep", a diagonal move otherwise is "replace",
// moving up is "delete", moving left is "insert".
Reconstruction is why you sometimes keep the full O(n·m) table despite the one-row optimisation being available (Chapter 38). At n = m = 1000 that is a million ints — 4 MB, entirely reasonable. If both strings are 10⁵ long the table is out of the question, and then Hirschberg's algorithm recovers the alignment in O(n·m) time with only O(min(n,m)) space by recursively finding the midpoint — worth knowing the name.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 3×3 CORNER
Fill dp[0..2][0..2] by hand for two 2-character strings before writing the loops. Thirty seconds, and it settles the base cases and the indexing at once.
⛔ OFF BY ONE
Row i means "the first i characters", so the character is s[i-1]. Derive that from the state sentence rather than guessing.
💡 LCS ANSWERS FOUR
Minimum insert/delete, shortest common supersequence, longest palindromic subsequence and minimum insertions to make a palindrome all reduce to one LCS call.
⚠️
Common mistakes
  • s[i] instead of s[i-1]. Row i is about the first i characters, so the i-th is at index i-1.
  • Zero base cases for edit distance. dp[i][0] is i, not 0 — deleting a whole prefix costs something.
  • Iterating i upward for interval DP. dp[i][j] reads the shorter dp[i+1][j-1], so loop by length, or i downward.
  • Returning dp[n][m] for longest common substring. That state is "ending at", so take the maximum over the table.
  • Forgetting the dp[0][j] row in wildcard matching. A pattern of stars must match the empty string.
  • Using j-1 instead of j-2 for regex *. The star pairs with its preceding character, so skipping it skips two pattern positions.
  • Confusing subsequence with substring. Mismatch takes a max for subsequence and resets to 0 for substring.
  • Space-optimising to one row when reconstruction is needed. The walk-back requires the whole table.
  • The one-row optimisation without saving the diagonal. Edit distance needs dp[i-1][j-1], which a single array overwrites (Chapter 38).
  • Assuming LCS is unique. Several subsequences can share the maximum length; the recovery returns one of them.

Interview drill

Warm-up: Edit distance. Derive the recurrence rather than reciting it.

How a strong answer sounds
I define dp[i][j] as the minimum number of operations to turn the first i characters of s into the first j characters of t, with the table sized (n+1) × (m+1) so that row and column 0 mean an empty prefix. The base cases follow directly: dp[i][0] = i, because turning an i-character string into nothing costs i deletions, and dp[0][j] = j for j insertions. For the general cell I look at the last characters. If s[i−1] equals t[j−1] they can be aligned at no cost, so dp[i][j] = dp[i−1][j−1] — no operation is spent. Otherwise I must spend exactly one operation, and there are three ways to do it: delete s[i−1] and solve dp[i−1][j]; insert t[j−1] and solve dp[i][j−1]; or replace s[i−1] with t[j−1] and solve dp[i−1][j−1]. So dp[i][j] = 1 + min of those three. Each term is one named operation, which is why the recurrence is memorable rather than arbitrary. O(n·m) time and space, reducible to O(min(n,m)) with a rolling row — though that requires saving the diagonal value in a temporary before overwriting, and it destroys the ability to recover the actual edit script. Before writing any of it I would fill the 3×3 corner for "ab" and "ac" by hand, which settles the base cases and the indexing in half a minute.

Deeper: Longest palindromic subsequence. Two approaches, and why the loop order matters in one of them.

How a strong answer sounds
The quickest answer is that a palindromic subsequence of s reads identically forwards and backwards, so it is a subsequence of both s and its reverse — therefore LPS(s) = LCS(s, reverse(s)). That reuses a table I already know, needs no new recurrence, and is O(n²). A useful corollary: the minimum insertions needed to make s a palindrome is n − LPS. The direct approach is interval DP: dp[i][j] is the length of the longest palindromic subsequence within s[i..j], with dp[i][i] = 1; if s[i] equals s[j] then dp[i][j] = 2 + dp[i+1][j−1], otherwise it is max(dp[i+1][j], dp[i][j−1]). And here the loop order is the trap: dp[i][j] depends on dp[i+1][j−1], which is a shorter interval, so iterating i upward from 0 reads cells that have not been computed yet and silently gets zeros. I either iterate by increasing interval length as the outer loop, or iterate i downward and j upward from i — both guarantee every dependency is already filled. That is the general rule for interval DP and it recurs in matrix chain multiplication and burst balloons (Chapter 45). I would also distinguish this from longest palindromic substring, which requires contiguity and is better solved by expand-around-centre in O(1) space, or by Manacher in O(n).

🧠 Key takeaways

  • Two-string DP is one table over prefix pairs, split on whether the current characters match — LCS and edit distance differ only in the two branches.
  • Size the table (n+1)×(m+1) so row and column 0 mean "empty", and remember the i-th character is s[i-1].
  • LCS answers four problems: min insert/delete, shortest common supersequence, longest palindromic subsequence, and min insertions to make a palindrome.
  • Interval DP over dp[i][j] must iterate by increasing length (or i downward), because it reads shorter intervals.
  • Subsequence takes a max on mismatch; substring resets to 0 and its answer is the maximum over the table.

Check your understanding

In a two-string DP with dp[i][j] over the first i and j characters, which characters do you compare?

The sentinel row and column for "empty prefix" force this shift, and it removes every boundary special case. Getting it wrong produces an off-by-one that only shows on the last character.

What are the base cases for edit distance?

Turning an i-character string into nothing costs i deletions. Leaving these at zero is the most common edit-distance bug — and it produces answers that are too small.

In interval DP for palindromes, why must the outer loop be the interval length?

Iterating i upward reads cells that are still false and silently gives wrong answers. Length-outer, or i downward with j upward — either satisfies the dependency.

Longest common substring differs from longest common subsequence how?

Contiguity is the whole difference: a mismatch breaks the run. And because the state becomes "ending at i,j", the final cell is no longer the answer.

How can you compute the longest palindromic subsequence using a function you already have?

No new recurrence needed. And it gives a bonus: the minimum insertions to make s a palindrome is n − LPS. (Expand-around-centre is for the substring version, which requires contiguity.)
