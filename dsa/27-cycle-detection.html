Cycle Detection

“Does this graph have a cycle?” has two completely different answers depending on whether the graph is directed, and confusing them is one of the most reliable ways to get a graph problem wrong. Directed cycles need a recursion stack; undirected cycles need a parent check. This chapter makes the distinction concrete, then covers the BFS alternatives and how to recover the cycle itself.

  • Explain why visited alone is insufficient for directed graphs
  • Classify an edge as tree, back, forward or cross — and know which one means a cycle
  • Write directed detection with instack, and undirected detection with a parent
  • Use Kahn's size check and undirected DSU as the BFS-style alternatives
  • Recover the actual cycle, and handle self-loops and parallel edges

Why the two cases differ

Here is the crux. In an undirected graph, reaching an already-visited node almost always means a cycle. In a directed graph, it very often does not.

Directed: not a cycle
// 0 -> 1, 0 -> 2, 1 -> 2
//
//    0
//   / \
//  v   v
//  1 -> 2
//
// DFS from 0 visits 1, then 2 (finishing it),
// then returns and sees 2 already visited via 0->2.
// Already visited, but NOT a cycle — 2 is finished,
// not an ancestor. This is a "cross/forward" edge.

So visited alone would report a false cycle here. You need to know whether the node is on the current path, not merely whether it has ever been seen.

Undirected: not a cycle either
// 0 -- 1
//
// DFS from 0 visits 1. From 1, the adjacency list
// contains 0 — because undirected edges are stored
// twice. 0 is visited, so a naive check says "cycle".
//
// But it is just the edge we arrived on.
// Fix: skip the parent.

So visited alone would report a false cycle here too — for the opposite reason. Every single edge looks like a 2-cycle unless you exclude the one you came in on.

🏷️
Edge classification — the precise statement

During a DFS of a directed graph, every edge u → v is one of four kinds:

  • Tree edge — v was unvisited; this is the edge we used to discover it.
  • Back edge — v is visited and still on the recursion stack, so v is an ancestor of u. This, and only this, means a cycle.
  • Forward edge — v is a finished descendant of u. No cycle.
  • Cross edge — v is finished and in a different subtree. No cycle.

So the whole problem reduces to distinguishing a back edge from the other two, and that is exactly what a second array — “is this node on the current path?” — buys you. A directed graph has a cycle if and only if a DFS finds a back edge. In an undirected graph the classification collapses: there are only tree edges and back edges, which is why the parent check alone suffices there.

Directed: DFS with a recursion stack

hasCycle — directed, DFS with instackO(V + E)O(V)
// Two arrays, and the difference between them is the whole algorithm:
//   visited[x] — x has been seen at some point
//   instack[x] — x is on the CURRENT recursion path (an ancestor of the node
//                we are at right now). This is what identifies a back edge.
void DFS(unordered_map<int,vector<int>> &graph,int node,vector<bool> &visited,
         stack<int> &st,vector<bool> &instack,bool &cycle){
	if(visited[node])return;

	visited[node]=true;
	instack[node]=true;        // entering: now on the current path

	for(auto &neighbour:graph[node]){
		if(!visited[neighbour]){
			DFS(graph,neighbour,visited,st,instack,cycle);
		}else if(instack[neighbour]){
			cycle=true;        // BACK EDGE -> neighbour is an ancestor
			return;
		}

		if(cycle)return;      // propagate the failure up immediately
	}

	instack[node]=false;       // leaving: no longer on the current path
	st.push(node);            // finish order, so this doubles as toposort
}
bool hasCycle(int N,vector<vector<int>> &edges){
	unordered_map<int,vector<int>> graph;
	for(int i=0;i<edges.size();i++){
		int u=edges[i][0];
		int v=edges[i][1];
		graph[u].push_back(v);
	}

	stack<int> st;
	bool cycle=false;
	vector<bool> visited(N,false);
	vector<bool> instack(N,false);

	for(int i=0;i<N;i++){
		if(!visited[i]){
			DFS(graph,i,visited,st,instack,cycle);
			if(cycle)return true;
		}
	}

	return false;
}
instack[node]=false on the way out is the line that must not be forgotten. Leave it out and instack becomes a second copy of visited, so every cross edge is reported as a cycle. And note the reverse: resetting it is only correct because we are looking for ancestors — that is why this array is different from visited and why you need both, not one.
✍️
My convention: three states in one array, when you want fewer moving parts

Two booleans can be collapsed into one vector<int> state with 0 = unvisited, 1 = in progress, 2 = finished. Same algorithm, one array, and the code reads closer to the edge classification:

// 0 = white (unvisited), 1 = grey (on the path), 2 = black (finished)
bool DFS(vector<vector<int>> &graph,int node,vector<int> &state){
	state[node]=1;               // grey: entering

	for(int neighbour:graph[node]){
		if(state[neighbour]==1)return true;        // grey -> back edge -> cycle
		if(state[neighbour]==0 and DFS(graph,neighbour,state))return true;
	}

	state[node]=2;               // black: finished

	return false;
}

Returning a bool instead of using a reference parameter also removes the if(cycle)return; propagation line. Use whichever you find clearer, but be consistent — the white/grey/black naming is standard in textbooks and worth recognising.

Undirected: DFS with a parent

hasCycle — undirected, parent checkO(V + E)O(V)
// An undirected edge is stored twice, so from v the adjacency list always
// contains the parent we arrived from. Skip exactly that one edge.
bool DFS(vector<vector<int>> &graph,int node,int parent,vector<bool> &visited){
	visited[node]=true;

	for(int neighbour:graph[node]){
		if(neighbour==parent)continue;        // the edge we came in on

		if(visited[neighbour])return true;      // any OTHER visited node = cycle

		if(DFS(graph,neighbour,node,visited))return true;
	}

	return false;
}
bool hasCycleUndirected(int N,vector<vector<int>> &edges){
	vector<vector<int>> graph(N);
	for(auto &e:edges){
		graph[e[0]].push_back(e[1]);
		graph[e[1]].push_back(e[0]);      // stored both ways
	}

	vector<bool> visited(N,false);

	for(int i=0;i<N;i++){
		if(!visited[i] and DFS(graph,i,-1,visited))return true;
	}

	return false;
}
No instack needed at all, because an undirected DFS has no cross or forward edges — every non-tree edge goes to an ancestor. But parent == neighbour is subtly wrong with parallel edges: if there are two distinct edges between u and v, that is a cycle, and comparing by node label skips both. The fix is to skip by edge id rather than by node, and the same applies to a self-loop, which is a cycle of length 1.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 DIRECTED NEEDS INSTACK
A directed cycle needs on the current path, not merely visited. Two arrays, or white/grey/black — a single visited array finds cross-edges and reports cycles that are not there.
💡 UNDIRECTED: SKIP PARENT
For undirected graphs, ignore the edge you arrived on. On a tree that single guard replaces the visited array entirely.
⛔ PARALLEL EDGES
The skip-parent trick breaks with duplicate edges or self-loops — those are cycles. Track the edge id rather than the parent node when the input allows them.

The BFS alternatives

// Kahn's algorithm from Chapter 26. If fewer than N nodes come out,
// the rest are in or downstream of a cycle. No recursion, so no stack risk.
bool hasCycle(int N,vector<vector<int>> &edges){
	unordered_map<int,vector<int>> graph;
	for(int i=0;i<edges.size();i++){
		int u=edges[i][0];
		int v=edges[i][1];
		graph[u].push_back(v);
		// graph[v].push_back(u); -> This is for Undirected Edges
	}

	vector<int> indegree(N,0);
	for(auto &it:graph){
		for(int node:it.second){
			indegree[node]++;
		}
	}

	queue<int> q;
	vector<int> ans;
	for(int i=0;i<N;i++){
		if(indegree[i]==0)
		q.push(i);
	}

	while(!q.empty()){
		int node=q.front();
		q.pop();
		ans.push_back(node);

		for(auto &neighbour:graph[node]){
			indegree[neighbour]--;

			if(indegree[neighbour]==0)
			q.push(neighbour);
		}
	}

	if(ans.size()!=N)return true;

	return false;
}

Prefer this when the graph is directed and might be deep. It is iterative, so no stack-overflow risk at 10⁵ nodes, and it gives you the topological order in the same pass when there is no cycle.

// DSU from Chapter 22. An edge joining two nodes already in the same
// component closes a cycle — which is exactly what unite() returning
// false means. Four lines of logic.
bool hasCycleUndirected(int N,vector<vector<int>> &edges){
	DSU dsu(N);

	for(auto &e:edges){
		if(!dsu.unite(e[0],e[1]))
		return true;
	}

	return false;
}
// O(E * alpha(N)). Also handles the edges arriving ONE AT A TIME,
// which DFS cannot do without re-running from scratch.
// Note: this is undirected only — DSU has no notion of direction.

The cleanest undirected answer, and the only one that works online. It is also exactly the cycle test inside Kruskal's MST (Chapter 31) — the same boolean, used for a different purpose.

// BFS version: store the parent alongside each node in the queue.
bool hasCycleBFS(vector<vector<int>> &graph,int start,vector<bool> &visited){
	queue<pair<int,int>> q;      // {node,parent}
	q.push({start,-1});
	visited[start]=true;

	while(!q.empty()){
		auto [node,parent]=q.front();
		q.pop();

		for(int neighbour:graph[node]){
			if(neighbour==parent)continue;

			if(visited[neighbour])return true;

			visited[neighbour]=true;        // neighbour, on enqueue (Ch 25)
			q.push({neighbour,node});
		}
	}

	return false;
}

Same parent logic, iterative. Useful when the graph might be a 10⁵-node path and recursion would overflow. Note visited[neighbour], not visited[node] — the Chapter 25 bug applies here too.

Recovering the cycle itself

“Is there a cycle?” is easier than “show me one”. To produce the actual node sequence, record parents and then walk back from the back edge.

findCycle — return the nodes, directedO(V + E)O(V)
// When we find a back edge u -> v, the cycle is v ... u plus the edge back.
// Walk parent pointers from u up to v to recover it.
vector<int> cycleNodes;

bool DFS(vector<vector<int>> &graph,int node,vector<int> &state,vector<int> &parent){
	state[node]=1;

	for(int neighbour:graph[node]){
		if(state[neighbour]==1){
			// back edge node -> neighbour; rebuild the cycle
			cycleNodes.clear();

			int x=node;
			while(x!=neighbour){
				cycleNodes.push_back(x);
				x=parent[x];
			}
			cycleNodes.push_back(neighbour);

			reverse(cycleNodes.begin(),cycleNodes.end());

			return true;
		}

		if(state[neighbour]==0){
			parent[neighbour]=node;
			if(DFS(graph,neighbour,state,parent))return true;
		}
	}

	state[node]=2;

	return false;
}
The while(x != neighbour) loop terminates only because neighbour is grey — that is, on the current path — so it is genuinely an ancestor of node and the parent chain reaches it. If you tried this on a cross edge the loop would run off the end of the parent chain. The correctness of the recovery depends on the same fact that makes the detection correct.
🕳️
Self-loops and parallel edges — ask before you code
  • Self-loop u → u: a cycle of length 1. The directed algorithm catches it automatically, because u is grey when the edge is examined. The undirected parent check, however, skips it if parent == u, so a self-loop needs its own test: if(neighbour == node) return true;
  • Parallel edges u — v twice, undirected: a cycle of length 2. The parent-by-label check skips both copies and misses it. Fix by skipping the specific edge id you arrived on rather than the parent node.
  • Directed parallel edges u → v twice: not a cycle, and no algorithm here is confused by them.

These are exactly the cases interviewers use to check whether you understood the algorithm or memorised it. Asking “can there be self-loops or duplicate edges?” during clarification is worth real credit.

⚠️
Common mistakes
  • Using only visited on a directed graph. Every cross and forward edge becomes a false cycle.
  • Forgetting instack[node] = false on the way out. instack degenerates into a copy of visited.
  • Using instack on an undirected graph without the parent skip. Every edge looks like a 2-cycle.
  • Skipping the parent by label when parallel edges exist. A genuine 2-cycle is missed. Skip by edge id.
  • Missing the self-loop case in undirected detection. u — u is a cycle and the parent check hides it.
  • Forgetting the driver loop. The cycle may be in a component you never started from.
  • Not propagating the failure. Without if(cycle) return;, the DFS keeps exploring and may reset instack entries you still needed.
  • Applying DSU to a directed graph. DSU has no direction, so it reports a "cycle" for a→b, a→c, b→c.
  • Recursive DFS on a 10⁵-node path. Use Kahn (directed) or DSU/BFS (undirected).

Interview drill

Warm-up: Detect a cycle in a directed graph. Why is a visited array not enough?

How a strong answer sounds
Because "already visited" and "is an ancestor of where I am now" are different things in a directed graph, and only the second one means a cycle. Take 0→1, 0→2, 1→2: DFS from 0 goes to 1, then to 2, finishes 2, returns, and then examines the edge 0→2 and finds 2 visited — but 2 is finished, not on the current path, so that is a cross or forward edge and there is no cycle. A visited-only check would report one. What I need is a second piece of state saying whether a node is on the current recursion path, so I keep an instack array, set it true on entry and false on exit, and a neighbour that is visited and instack is a back edge, which is exactly a cycle. Formally, every DFS edge is a tree, back, forward or cross edge, and a directed graph has a cycle iff a DFS finds a back edge. I like to collapse the two booleans into one three-state array — white unvisited, grey on the path, black finished — because then the code reads directly as the classification. The line most often forgotten is resetting to false on exit; without it instack becomes a duplicate of visited and every cross edge is a false positive. If the graph could be 10⁵ nodes deep I would use Kahn's algorithm instead, where fewer than N emitted nodes means a cycle, because it is iterative and cannot overflow the stack.

Deeper: Now the same question for an undirected graph. What changes, and what are the edge cases?

How a strong answer sounds
The instack array becomes unnecessary, because an undirected DFS has no cross or forward edges — every non-tree edge leads to an ancestor. But a new problem appears: an undirected edge is stored twice in the adjacency list, so standing at v I always see the parent u as a neighbour, and u is visited, so a naive check reports a cycle for every single edge. The fix is to skip the edge I arrived on, passing the parent down and doing if(neighbour == parent) continue;. After that, any other visited neighbour genuinely closes a cycle. Two edge cases break the label-based version. A self-loop u—u is a real cycle of length one, but if parent happens to equal u the check skips it, so I need an explicit if(neighbour == node) return true;. And parallel edges — two distinct edges between u and v — form a real 2-cycle, but comparing by node label skips both copies and misses it; the robust fix is to skip by the specific edge id I traversed rather than by the parent's label. So in clarification I would ask whether self-loops or duplicate edges are possible. In practice, for an undirected graph I would often just use DSU: iterate the edges and return true the first time unite returns false, which is O(E·α), needs no recursion, handles parallel edges naturally, and works even when the edges arrive one at a time.

🧠 Key takeaways

  • A directed graph has a cycle iff DFS finds a back edge — a neighbour that is on the current recursion path.
  • visited is not enough for directed graphs; you need instack (or white/grey/black), reset on exit.
  • Undirected graphs need no instack but must skip the edge they arrived on — by edge id if parallel edges exist.
  • Kahn's size check is the iterative directed test; DSU's unite returning false is the cleanest undirected one.
  • Self-loops and parallel edges behave differently in the two cases — ask about them before coding.

Check your understanding

In a directed graph, why is a visited array alone insufficient for cycle detection?

With 0→1, 0→2, 1→2, the edge 0→2 finds 2 visited but finished. You need a second state — instack, or grey in white/grey/black — to identify a back edge.

You forget instack[node] = false when leaving a node. What happens?

The array stops meaning "on the current path" and starts meaning "ever seen". That is precisely the distinction the algorithm relies on, so the whole thing collapses into the broken visited-only version.

In an undirected graph, why must DFS skip the parent?

graph[u] contains v and graph[v] contains u. Standing at v, the parent u is visited, so without the skip even a two-node graph reports a cycle.

An undirected graph has two distinct edges between u and v. Your DFS skips the parent by node label. What happens?

A false negative. Skipping by node label discards every edge back to the parent, including the second distinct one. Track and skip the specific edge id you traversed instead.

You have an undirected graph and edges arriving one at a time; you must report a cycle as soon as one forms. Best approach?

DSU is the online structure (Chapter 22): O(E·α) total instead of O(E·(V+E)) for re-running DFS. Kahn is directed-only, and Floyd is for linked lists and functional graphs.
