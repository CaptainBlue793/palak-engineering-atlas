Strings & Character Counting

A string is just an array of characters, so everything from Chapters 3 to 9 still applies. On top of that there are a few string-specific moves worth knowing by heart. String problems are where interviewers love to hide off-by-one errors. This chapter covers the 26-bucket count, the concatenation trap that turns an O(n) loop into O(n²), parsing, and the palindrome family.

  • Use the 26-bucket count array instead of a hash map, and know when it is not enough
  • Avoid the string-building patterns that are secretly quadratic
  • Solve anagrams, palindromes and character-window problems from the same few shapes
  • Parse with stringstream, substr and find without index errors
  • Say what a “character” is when the input is not ASCII

A string is an array — with two differences

In C++, std::string is basically a vector<char>. Its characters sit next to each other in memory, you can read any index in O(1), it can grow, and it knows its own size(). So two pointers, sliding windows and prefix sums all work exactly as they do on arrays. Two things are different, and both matter.

Characters are small integers

'c' - 'a' is 2. So any lowercase letter becomes an index in [0,26), that is, 0 to 25. That means the best container for letter counts is a 26-slot array, not a hash map. This is Chapter 9's "use an array for small integer keys" rule in its most common form.

Concatenation is a trap

Building a string with s = s + c in a loop copies the whole string every time, which is O(n²) in total. s += c adds to the end in amortized O(1) (cheap on average), and it is what you always want. It is the same difference as push_back versus copying the whole array.

Why 'c' - 'a' is 2. A char is stored as a number, its ASCII code. 'a' is 97, 'b' is 98, 'c' is 99, and so on up to 'z' at 122. The letters are consecutive, so subtracting 'a' turns them into 0, 1, 2, … 25. The reverse also works: char('a' + 2) is 'c'. Uppercase letters are a separate run ('A' is 65) and digits are another ('0' is 48), which is why ch - '0' turns the character '7' into the number 7.

How bad is the concatenation trap? s = s + c builds a brand-new string and copies everything into it. Building a string of length n that way copies 1 + 2 + 3 + … + n ≈ n²/2 characters. For n = 100,000 that is about 5 billion copies — seconds of wasted time. s += c writes one character into spare space at the end, so the total is about n.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 EXPAND CENTRES
For palindromic substrings, loop over 2n−1 centres and expand. O(n²) time, O(1) space, four lines — and it beats the DP table unless you need every answer.
💡 FIXED WINDOW
Anagram search is a fixed-size window plus a 26-count array. Compare counts in O(26) — constant — rather than re-sorting each window.
⛔ IN-PLACE STRINGS
Reverse-words-in-place is reverse-whole then reverse-each-word, and the hard part is collapsing runs of spaces with a write pointer. Test a string with leading, trailing and doubled spaces.

Also watch for substr inside a loop. Every call allocates new memory and copies characters. When you only need to look at part of a string, use indices, or a string_view. A string_view is just a pointer plus a length, with no copying at all.

The 26-bucket count

One small array solves a surprising number of problems. It is the string tool you will use most often. Think of it as 26 labelled tally boxes, one per letter.

For example, counting "banana" gives count[0] = 3 (a), count[1] = 1 (b), count[13] = 2 (n), and zero everywhere else. Two strings are anagrams (the same letters in a different order) exactly when their count arrays are equal. The code below saves a second array: it adds for one string and subtracts for the other. For "ab" vs "ba": after i = 0, a is +1 and b is −1; after i = 1, b goes back to 0 and a goes back to 0. All zeros, so they are anagrams.

When 26 is not enough: the moment the input can contain uppercase letters, digits, spaces or punctuation. Then c - 'a' gives a negative or too-large index and writes outside the array. Read the constraints first. “Lowercase English letters” means 26 is safe; anything else means 128 slots indexed by the raw character (or a hash map).

isAnagram — one pass up, one pass downO(n)O(1)
// Increment for s, decrement for t. Anagram iff every bucket lands on zero.
// O(1) space because the array is 26 slots regardless of input length.
bool isAnagram(string &s,string &t){
	if(s.size()!=t.size())return false;

	vector<int> count(26,0);

	for(int i=0;i<s.size();i++){
		count[s[i]-'a']++;
		count[t[i]-'a']--;
	}

	for(int c:count){
		if(c!=0)return false;
	}

	return true;
}
The length check at the top is not decoration. Without it, "a" and "ab" would read t[1] out of bounds. As always, put the guard clause (the early exit) on line one.
✍️
My convention: vector<int> count(26,0), and say the alphabet out loud

Write the 26, then say the assumption out loud: “assuming lowercase ASCII only”. Interviewers often follow up with “what if it is Unicode?”. The honest answer is a hash map keyed on the code point (the number Unicode gives each character), plus a real discussion of what a “character” means. That answer impresses far more than a 26 you cannot defend. For mixed case or full ASCII, use 128 slots; for raw bytes, use 256.

Palindromes

A palindrome reads the same forwards and backwards, like "racecar". There are three standard approaches, from simplest to cleverest. Learn all three, because interview follow-ups usually climb from one to the next.

// Converging two pointers (Chapter 4), skipping non-alphanumerics.
bool isPalindrome(string &s){
	int left=0;
	int right=s.size()-1;

	while(left<right){
		// the two guards need left<right, or they run off the end
		while(left<right and !isalnum(s[left]))left++;
		while(left<right and !isalnum(s[right]))right--;

		if(tolower(s[left])!=tolower(s[right]))return false;

		left++;
		right--;
	}

	return true;
}

The left<right inside the skip loops is essential. Without it, a string made only of punctuation walks left right past the end. This is the classic bug in this problem.

// On the first mismatch, try skipping ONE character from either side.
// Greedy is correct: the mismatch must be resolved here or never.
bool check(string &s,int left,int right){
	while(left<right){
		if(s[left]!=s[right])return false;

		left++;
		right--;
	}

	return true;
}
bool validPalindrome(string &s){
	int left=0;
	int right=s.size()-1;

	while(left<right){
		if(s[left]!=s[right]){
			// skip the left one OR the right one
			return check(s,left+1,right) or check(s,left,right-1);
		}

		left++;
		right--;
	}

	return true;
}

Still O(n). The outer loop runs once, and the two check calls together do at most O(n) work. The shape is the usual one: a small helper function plus a driver that calls it.

Dry run on "abca". left = 0, right = 3: a == a, move in. left = 1, right = 2: b ≠ c, a mismatch. Try deleting the b: check(s, 2, 2) looks at just "c", which is a palindrome, so the answer is true ("aca"). Why is it safe to try only these two options? Every outer pair before the mismatch already matched, so they can stay. The b and the c cannot both stay, so one of them must be the deleted character.

// Expand around every centre. 2n-1 centres: n single, n-1 between pairs.
int expand(string &s,int left,int right){
	while(left>=0 and right<s.size() and s[left]==s[right]){
		left--;
		right++;
	}

	return right-left-1;       // both overshot by one
}
string longestPalindrome(string &s){
	if(s.empty())return "";

	int bestLen=0;
	int bestStart=0;

	for(int i=0;i<s.size();i++){
		int odd=expand(s,i,i);        // centre on a character
		int even=expand(s,i,i+1);    // centre between two
		int len=max(odd,even);

		if(len>bestLen){
			bestLen=len;
			bestStart=i-(len-1)/2;   // derive the start from the centre
		}
	}

	return s.substr(bestStart,bestLen);
}

O(n²) time, O(1) space. You need both kinds of centre. With only odd centres (on a character) you miss even-length palindromes like "abba". Manacher's algorithm does this in O(n) (Chapter 50), and the DP version is in Chapter 41.

Where the formulas come from. When expand stops, the last matching pair was at left+1 and right-1. So the palindrome is s[left+1 .. right-1], and its length is (right−1) − (left+1) + 1 = right-left-1. For the start: a palindrome of length len centred at i reaches (len−1)/2 characters to the left of i, so it starts at i-(len-1)/2. Check it on "babad" with i = 1: expand goes 1,1 → 0,2 (b == b) → −1,3 and stops, giving length 3 − (−1) − 1 = 3 and start 1 − 1 = 0, which is "bab". For the even case "abba" with i = 1, length 4 gives start 1 − 3/2 = 0. Integer division makes the one formula work for both.

Parsing without index errors

Parsing means turning raw text into pieces you can work with — words, numbers, fields. It shows up in “reverse the words”, “simplify a file path”, “evaluate an expression” and every problem whose input is one long line. The bugs are almost always at the edges: a leading space, two spaces in a row, a trailing delimiter, an empty string. The tools below handle those edges for you, which is why they beat hand-written index loops.

Two quick examples of what each tool returns. splitWords(" hello world ") gives ["hello", "world"] — all the extra spaces vanish. splitOn("a,,b", ',') gives ["a", "", "b"] — the empty middle field is kept, which is what you want for CSV-style data where position matters.

the parsing toolkitprefer stringstream to manual indexing
// Split on whitespace — by far the cleanest way.
vector<string> splitWords(string &s){
	stringstream ss(s);
	vector<string> ans;
	string word;

	while(ss>>word)          // skips runs of whitespace automatically
	ans.push_back(word);

	return ans;
}

// Split on an arbitrary delimiter.
vector<string> splitOn(string &s,char delim){
	stringstream ss(s);
	vector<string> ans;
	string part;

	while(getline(ss,part,delim))   // keeps empty fields, unlike >>
	ans.push_back(part);

	return ans;
}

// Manual scan, when you need index control (e.g. reverse words in place).
int i=0;
while(i<s.size()){
	while(i<s.size() and s[i]==' ')i++;     // skip separators

	int start=i;
	while(i<s.size() and s[i]!=' ')i++;     // consume the token

	if(i>start){
		// token is s[start..i-1], length i-start
	}
}
Note the difference. ss >> word treats several spaces in a row as one and drops empty fields. getline(ss, part, ',') keeps empty fields, so "a,,b" gives three fields, one of them empty. CSV parsing needs getline; splitting into words wants >>. Also, s.find(x) returns string::npos when nothing is found. Compare against that, never against -1.

“Character” is not a well-defined unit outside ASCII

A char is one byte. In UTF-8 (the most common text encoding), é takes two bytes, → takes three, an emoji takes four, and a flag emoji takes eight. So:

  • s.size() counts bytes, not letters.
  • Reversing a string byte by byte breaks multi-byte characters.
  • s[i] might be half a letter.

It gets worse. Some visible characters are several code points (Unicode's numbered characters) combined, such as an e plus a separate accent mark. So even counting code points does not match what a person would call a character.

Interview answer: for ASCII problems, use a 26- or 128-slot array and say that assumption. For real text, decode to code points first. The right unit depends on the question: bytes for storage, code points for most algorithms, and grapheme clusters (what the user sees as one character) for anything shown on screen.

The string-problem shapes

Compare two strings' contents, ignoring order

→ 26-bucket count: add 1 for each letter of one string, subtract 1 for each letter of the other. Anagram, permutation check, ransom note.

vector<int> count(26,0); count[c-'a']++;

→ Sliding window plus a count array (Chapter 5). Longest substring without repeats, at most K distinct characters, minimum window.

for(right..){ count[s[right]]++; while(bad)count[s[left++]]--; }

→ Converging two pointers (Chapter 4). Palindrome, valid with one deletion, reverse in place.

⚠️
Common mistakes
  • s = s + c in a loop. Quadratic (O(n²)). Use s += c, and reserve if you know the final length.
  • substr inside a loop. Each call allocates memory and copies. Use indices, or string_view.
  • Comparing s.find(x) against -1. It returns string::npos, which is unsigned. Compare against that.
  • i < s.size() - 1 on an empty string. size() is unsigned (never negative), so 0-1 wraps around to a huge number. Write i + 1 < s.size().
  • Missing left<right in a skip loop. A string of only punctuation walks the pointer off the end.
  • Only checking odd centres in expand-around-centre. You miss every even-length palindrome.
  • Assuming one char is one character. True for ASCII, false for UTF-8. Say your assumption instead of hoping.
  • tolower on a negative char. Passing a negative value to <ctype.h> functions is undefined behaviour (anything can happen). If the input might not be ASCII, cast to unsigned char first.

Interview drill

Warm-up: Check whether two strings are anagrams. Then: what if they can be any Unicode text?

How a strong answer sounds
For lowercase ASCII: first compare lengths, which rejects many inputs cheaply. Then make one pass, adding to a 26-slot array for the first string and subtracting for the second. Finally, check that every bucket is zero. That is O(n) time and O(1) space, since the array size is fixed. I would say "assuming lowercase ASCII" out loud rather than leave it unstated. Sorting both strings also works and is one line, but it is O(n log n) and changes or copies the inputs. For Unicode, the 26-slot array no longer works, so I would decode to code points and count them in a hash map. I would also point out that "anagram" becomes genuinely ambiguous. Is "é" as one code point the same as "e" plus a separate accent mark? To a user, usually yes. So the right first step is Unicode NFC normalisation (converting both forms to one standard form) before counting. I might also use case folding instead of tolower, because tolower depends on the locale. In a question like this, naming the ambiguity matters more than the code.

Deeper: Why is building a string with s = s + c in a loop O(n²), and what is the general lesson?

How a strong answer sounds
s + c builds a brand-new string. It allocates a buffer of length s.size()+1, copies all of s, adds the character, and then assigns that temporary string back. So step i copies i characters, and the total is 1 + 2 + … + n = Θ(n²). s += c instead appends into the existing buffer, which grows by doubling. That is amortized O(1) per append and O(n) overall, by the same argument that makes push_back O(1). The general lesson: whenever strings are copied by value or cannot be changed in place, creating a new string inside a loop is quadratic. That is why Java has StringBuilder, and why Python code joins a list instead of using += on many pieces. In C++ I use += with a reserve, or write into a buffer allocated up front. The same trap applies to substr in a loop, and to any helper that "returns a modified copy" and gets called n times.

🧠 Key takeaways

  • A string is an array of small integers, so c - 'a' makes a 26-slot array the right container for letter counts.
  • s += c is amortized O(1). s = s + c is O(n) per step and O(n²) overall.
  • Palindromes: two pointers moving inwards to check one, expand-around-centre to find one. You need both odd and even centres.
  • stringstream with >> splits on any run of whitespace; getline with a delimiter keeps empty fields.
  • One char is one byte, not one character. Always state your alphabet assumption.

Check your understanding

Why is for(char c : s) ans = ans + c; O(n²)?

The total copying is 1 + 2 + … + n = Θ(n²). ans += c appends into the existing buffer, which grows by doubling, so each append is amortized O(1).

In expand-around-centre for the longest palindromic substring, why call expand twice per index?

There are 2n−1 possible centres. With only expand(s,i,i) you find "aba" but never "abba", because "abba" has no single middle character.

What does s.find("x") return when the substring is absent?

npos is the largest possible size_t value. Comparing to -1 may seem to work because of C++'s conversion rules, but it is fragile and triggers compiler warnings. Compare to string::npos directly.

You need to split "a,,b" on commas and keep the empty field. Which do you use?

>> treats repeated separators as one and drops empty pieces, so you get two fields. getline with a delimiter produces a field between every pair of delimiters, so you get the three fields that CSV requires.

Your palindrome checker crashes on the input ".,". What is wrong?

Every character gets skipped, so while(!isalnum(s[left])) left++; never finds a letter to stop at and reads out of bounds. Both skip loops need the bound: while(left<right and !isalnum(s[left])) left++;
