DP on Sequences (1D)

One-dimensional DP is where the five-step method becomes a habit your hands know. The state is almost always “the best answer for the first i elements”. The whole difficulty is what extra information the state needs besides i. This chapter walks through the standard family: stairs, house robber, decode ways, LIS (longest increasing subsequence), maximum subarray and the stock problems. For each one, you will see how it answers that question differently.

  • Write the four standard 1D recurrences from their state sentences
  • Spot when dp[i] alone is not enough and you need a second dimension
  • Solve LIS in O(n²) as DP, and in O(n log n) with "patience piles"
  • See Kadane's algorithm as a two-state DP, not a trick
  • Handle the stock-problem family by naming each state out loud

The shape of a 1D DP

Why start with 1D? These are the most common DP questions in interviews, and every harder DP (knapsack, strings, grids) is the same idea with more indices. If you can write these from a state sentence, the 2D chapters are mostly bookkeeping.

Almost all of them look like this. What changes from problem to problem is how far back the transition reads, and how many choices it tries.

the 1D templateO(n · choices)O(n), often O(1)
// dp[i] = the best answer considering the first i elements (or ending at i).
// Decide which of those two it is, IN THE COMMENT, before writing code.
vector<int> dp(n);

dp[0]=/* base case, by hand */;

for(int i=1;i<n;i++){
	dp[i]=/* combine dp[i-1], dp[i-2], ... with the choices at i */;
}

return dp[n-1];   // or max over the whole table — check which!
“The first i elements” vs. “ending at i” is the decision that matters most. For house robber, the answer is dp[n-1], because "the first i" keeps building up as i grows. For LIS and maximum subarray, the state is "ending at i". So the answer is the maximum over the whole table, because the best subsequence or subarray does not have to reach the end. Get this wrong and you get a believable answer that is too small.

A quick example of the difference. Take [3, −1, 2, −5] and ask for the best subarray sum. "Ending at i" gives 3, 2, 4, −1. The last cell is −1, but the real answer is 4 (the subarray [3, −1, 2]), which sits in the middle of the table. A "first i elements" state would instead carry the best seen so far forward: 3, 3, 4, 4, and there the last cell is the answer.

Counting: stairs and decode ways

// dp[i] = the number of distinct ways to reach step i.
// To reach i you came from i-1 (one step) or i-2 (two steps), so the
// counts ADD. This is literally Fibonacci.
int climbStairs(int n){
	if(n<=2)return n;

	int prev2=1;
	int prev1=2;

	for(int i=3;i<=n;i++){
		int current=prev1+prev2;
		prev2=prev1;
		prev1=current;
	}

	return prev1;
}

Counting DP uses + where optimisation DP uses min or max. That is the only difference in structure. Once you see it, "how many ways" problems need no new tools. Note that the counts grow like Fibonacci numbers, so for large n you need long long or a modulus.

// dp[i] = the minimum cost to REACH step i (having paid for the steps used).
// You may start at 0 or 1, and the top is one past the last step.
int minCostClimbingStairs(vector<int> &cost){
	int n=cost.size();
	int prev2=0;                // cost to reach step 0 = 0 (free start)
	int prev1=0;                // cost to reach step 1 = 0 (free start)

	for(int i=2;i<=n;i++){
		int current=min(prev1+cost[i-1],prev2+cost[i-2]);
		prev2=prev1;
		prev1=current;
	}

	return prev1;              // dp[n] — the top is index n, not n-1
}

The off-by-one here is the whole problem. "Reach step i" means you have not paid cost[i] yet. And the top is index n, one past the end of the array. Write the state sentence precisely and this sorts itself out. Guess at it and you will be off by one cost.

// dp[i] = the number of ways to decode the first i characters.
// Two choices: take one digit (if it is 1-9) or take two (if they form 10-26).
int numDecodings(string &s){
	int n=s.size();
	if(n==0 or s[0]=='0')return 0;

	int prev2=1;                // dp[0] = 1: one way to decode an empty prefix
	int prev1=1;                // dp[1] = 1, given s[0] != '0'

	for(int i=2;i<=n;i++){
		int current=0;

		if(s[i-1]!='0')
		current+=prev1;                             // one-digit decode

		int two=(s[i-2]-'0')*10+(s[i-1]-'0');
		if(two>=10 and two<=26)
		current+=prev2;                             // two-digit decode

		prev2=prev1;
		prev1=current;
	}

	return prev1;
}

The zeros are the whole difficulty. A '0' cannot be decoded on its own. And "06" is not a valid two-digit code, because of the leading zero. That is why the check is two >= 10, not two >= 1. Test "0", "06", "100" and "230". Each one breaks a different simple attempt.

Small traces, so you can check your own code:

  • Climbing stairs, n = 4. The counts for steps 1 to 4 are 1, 2, 3, 5. The five ways to reach step 4 are 1+1+1+1, 1+1+2, 1+2+1, 2+1+1 and 2+2. The three that end with a 1-step come from the 3 ways to reach step 3, and the two that end with a 2-step come from the 2 ways to reach step 2. That split is the recurrence.
  • Min cost stairs, cost = [10, 15, 20]. dp[0] = dp[1] = 0. dp[2] = min(0 + 15, 0 + 10) = 10. The top is dp[3] = min(dp[2] + 20, dp[1] + 15) = min(30, 15) = 15: start on step 1, pay 15, jump two steps to the top.
  • Decode ways, "226". dp[0] = 1, dp[1] = 1. At i = 2, the single digit "2" is valid (add dp[1] = 1) and "22" is valid (add dp[0] = 1), so dp[2] = 2. At i = 3, "6" is valid (add 2) and "26" is valid (add 1), so dp[3] = 3. The three decodings are 2-2-6, 22-6 and 2-26.

Why is dp[0] = 1 in decode ways, when there is nothing to decode? Because it is the number of ways to decode the empty string, and there is exactly one: do nothing. Setting it to 0 would make every two-digit code at the start count zero ways, which is wrong. This "empty prefix counts as one way" base case comes back in every counting DP.

✍️
My convention: prev2 / prev1 / current, in that order, updated at the bottom

Use three named variables. The two shifts are always the last two lines of the loop body. If you write prev2 = prev1 before computing current, you destroy a value you still need. If you write the two shifts in the wrong order, you destroy the other one. Keep the same shape in every rolling-array DP, and the update block stops being something you have to think about. And name the variables by what they hold — prev2, not a — so the recurrence stays readable after the array is gone.

Maximum subarray: Kadane as a two-state DP

The problem: find the contiguous stretch of an array (a subarray) with the largest sum. Kadane's algorithm solves it, and it is usually taught as a trick. It is not a trick — it is a one-line DP. Seeing it that way makes its variants obvious.

maxSubArray — KadaneO(n)O(1)
// dp[i] = the maximum sum of a subarray ENDING EXACTLY at i.
// Two choices: extend the best subarray ending at i-1, or start fresh at i.
//   dp[i] = max(dp[i-1] + a[i], a[i])
// The answer is the MAXIMUM OVER ALL i, not dp[n-1] — a best subarray
// need not reach the end.
int maxSubArray(vector<int> &a){
	int current=a[0];
	int best=a[0];

	for(int i=1;i<a.size();i++){
		current=max(a[i],current+a[i]);   // start fresh, or extend
		best=max(best,current);
	}

	return best;
}
// Note best starts at a[0], NOT 0 — an all-negative array has a negative answer.
The two-line loop body is the DP. current is dp[i] squeezed into one variable. best exists only because the state is "ending at i" rather than "first i elements". Starting best at 0 is the classic bug. It returns 0 on [-3,-1,-2] instead of −1 — yet every test that contains a positive number still passes.

A trace on [−2, 1, −3, 4, −1, 2, 1, −5, 4]. The values of current are −2, 1, −2, 4, 3, 5, 6, 1, 5. At index 1, extending gives −2 + 1 = −1, which is worse than starting fresh at 1, so it restarts. At index 3, extending gives −2 + 4 = 2, worse than 4, so it restarts again. From there it keeps extending, peaking at 6 for [4, −1, 2, 1]. best ends at 6. The rule in words: a running sum that has gone negative can only drag down whatever comes next, so drop it.

🔁
The Kadane family
  • Maximum product subarray — track both the maximum and the minimum product ending here, because multiplying by a negative number swaps them. Two states instead of one.
  • Maximum sum circular subarray (the array wraps around) — the answer is max(normal Kadane, total − minimum subarray). Special case: if every number is negative, use plain Kadane.
  • Maximum absolute sum — run Kadane once for the max and once for the min, then take whichever is bigger in size.
  • Longest subarray with sum ≥ 0 — not Kadane. That one needs prefix sums plus a monotonic structure (Chapter 6).

Maximum product on [2, −3, −2]. After 2: max = min = 2. After −3: the candidates are −3 (start fresh), 2 × −3 = −6 and 2 × −3 = −6, so max = −3 and min = −6. After −2: the candidates are −2, −3 × −2 = 6 and −6 × −2 = 12, so max = 12. The answer 12 came from the minimum, which is why you cannot throw it away.

Why "total − minimum subarray" for the circular case: a subarray that wraps around the end takes a piece from the end and a piece from the start. What it leaves out is one contiguous stretch in the middle. So the best wrapping sum is the total minus the smallest middle stretch. The all-negative special case exists because "leave out everything" would give an empty subarray with sum 0, which is not allowed.

The pattern: when one running value is not enough, add a second state instead of a special case. Maximum product is the clearest example.

Longest increasing subsequence

A subsequence keeps some elements of the array in their original order, but may skip others. The task: find the longest one whose values strictly increase. For [3, 1, 4, 2, 5], one answer is 1, 4, 5 — length 3. There are two solutions worth knowing, because the follow-up question is always "can you do better than O(n²)?"

The number of piles is the LIS length. The catch: the values on the piles do not form a valid subsequence.
O(n²) DP — gives the subsequence
// dp[i] = the length of the longest increasing subsequence ENDING at i.
int lengthOfLIS(vector<int> &a){
	int n=a.size();
	vector<int> dp(n,1);      // each element alone is length 1
	int best=1;

	for(int i=1;i<n;i++){
		for(int j=0;j<i;j++){
			if(a[j]<a[i])
			dp[i]=max(dp[i],dp[j]+1);
		}

		best=max(best,dp[i]);
	}

	return best;
}

Simple, and the dp array lets you rebuild the actual subsequence by walking backwards. Start here.

Trace on [3, 1, 4, 2, 5]: dp = [1, 1, 2, 2, 3]. The 4 extends either 3 or 1, so it gets 2. The 2 extends only the 1, so it gets 2. The 5 extends any of the length-2 ones, so it gets 3. The answer is the maximum, 3. There are n(n−1)/2 pairs (j, i), so this is fine for n up to a few thousand, but at n = 10⁵ it is 5 × 10⁹ steps.

O(n log n) — length only
// tails[k] = the SMALLEST possible tail of an increasing
// subsequence of length k+1. tails is always sorted, so
// lower_bound finds where the new value belongs.
int lengthOfLIS(vector<int> &a){
	vector<int> tails;

	for(int x:a){
		auto it=lower_bound(tails.begin(),tails.end(),x);

		if(it==tails.end())tails.push_back(x);  // extend
		else *it=x;                              // improve a tail
	}

	return tails.size();
}

tails is not the LIS. It is a list of best-possible tails, so its contents may not even be a subsequence of the input. It gives you the length only. If equal values are allowed (non-decreasing), use upper_bound instead.

Trace on [3, 1, 4, 2, 5]: [3] → 1 replaces 3: [1] → 4 extends: [1, 4] → 2 replaces 4: [1, 2] → 5 extends: [1, 2, 5]. Length 3. Now try [2, 5, 3, 1]: [2], [2, 5], [2, 3], [1, 3]. The length 2 is right, but [1, 3] is not a subsequence, because the 1 comes after the 3 in the input.

🧾
Why the patience method gives the right length

Keep this rule true at all times: tails[k] is the smallest value that can end an increasing subsequence of length k+1. This keeps tails strictly increasing, so you can binary search it. Now take a new value x. If it is bigger than every tail, it extends the longest subsequence by one, so append it. Otherwise, let k be the first position where tails[k] ≥ x. Replace tails[k] with x. The rule still holds: x can also end a length-k+1 subsequence (built on tails[k-1] < x), and it is smaller, which can only make future extensions easier. Importantly, replacing never shortens anything you could already achieve; it only improves a tail. So the array's length is always the current LIS length. And it is the longest possible, because we append whenever we can. ∎ Why the contents are not a subsequence: the entries come from different positions in the input, and some were overwritten out of order.

When dp[i] is not enough: the stock problems

You get a list of stock prices, one per day, and want the most profit from buying and selling. This family is the best example of "widening the state" — adding information to it. Each variant needs a different amount of extra information besides the day number.

the stock family, by stateO(n) or O(n·k)O(1) or O(k)
// I: ONE transaction. State: the minimum price seen so far. Not really DP.
int maxProfitOne(vector<int> &prices){
	int mini=INT_MAX;
	int best=0;

	for(int p:prices){
		mini=min(mini,p);
		best=max(best,p-mini);
	}

	return best;
}

// II: UNLIMITED transactions. State: holding or not holding.
//   hold = the best profit while currently owning a share
//   free = the best profit while owning nothing
int maxProfitUnlimited(vector<int> &prices){
	int hold=INT_MIN;
	int free=0;

	for(int p:prices){
		int prevFree=free;
		free=max(free,hold+p);          // sell today
		hold=max(hold,prevFree-p);      // buy today
	}

	return free;
}

// III / IV: AT MOST k transactions. State: (day, transactionsUsed, holding).
// The k dimension is what plain greedy cannot express.
int maxProfitK(int k,vector<int> &prices){
	if(prices.empty() or k==0)return 0;

	// k >= n/2 means unlimited, and avoids an enormous table
	if(k>=(int)prices.size()/2)return maxProfitUnlimited(prices);

	vector<int> hold(k+1,INT_MIN);
	vector<int> free(k+1,0);

	for(int p:prices){
		for(int t=1;t<=k;t++){
			hold[t]=max(hold[t],free[t-1]-p);   // buy, starting transaction t
			free[t]=max(free[t],hold[t]+p);     // sell, completing it
		}
	}

	return free[k];
}

// With COOLDOWN: a third state, "just sold and must wait".
// With FEE: subtract it once per completed transaction, in the sell step.
Naming the states is the whole technique. hold and free are not clever. They are simply the two situations you can be in on any given day: owning a share or not. Once named, each transition is obvious. When a variant adds a rule (a limit, a cooldown, a fee), add exactly the state needed to express it. The prevFree temporary matters. If you update free before hold reads it, you could buy and sell on the same day within the same transaction.

The answer is free, not hold, because ending while still owning a share means you paid for it and never got the money back. And the k ≥ n/2 shortcut in maxProfitK works because every transaction needs a buy day and a later sell day. With n days you can complete at most n/2 useful transactions, so any k at least that big puts no real limit on you.

"First i elements" vs "ending at i" — the table above is sorted by it

Notice the pattern. Problems about a contiguous subarray or a subsequence use "ending at i". Their answer is the maximum over the table, because the best one need not include the last element. Problems that build up over a prefix (the first part of the array) use "first i", and their answer is the final cell. Deciding which one before you code removes the two most common 1D bugs: returning dp[n-1] when you needed a maximum, and starting the running best at 0 when the answer can be negative.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 ENDING AT i
When the answer is a best subarray, define the state as "ending at i" and take the maximum over the whole table. That is Kadane, and it generalises.
💡 ROLL TWO VARS
A 1D DP that reads only i-1 and i-2 needs two variables, not an array. Same complexity, O(1) space, and fewer places to be wrong.
💡 PATIENCE LIS
LIS in O(n log n) is lower_bound into a tails array. The tails array is not the answer subsequence — recovering that needs parent pointers.
⚠️
Common mistakes
  • Returning dp[n-1] for an "ending at i" state. Maximum subarray and LIS both need the maximum over the whole table.
  • Starting the running best at 0. An all-negative array has a negative answer. Start at a[0] or INT_MIN.
  • Updating the rolling variables in the wrong order. Doing prev2 = prev1 before computing current loses a value you need.
  • Updating free before hold reads it in the stock DP. That lets you buy and sell on the same day within one transaction.
  • Missing the zero cases in decode ways. "0", "06", "100" and "230" each break a different simple version.
  • Treating tails as the LIS. It gives the length only. Its contents may not be a subsequence of the input.
  • Using upper_bound when you need strictly increasing (or lower_bound when you need non-decreasing). One word apart, opposite meaning.
  • Not handling large k separately in the stock problem. k ≥ n/2 is the same as unlimited. Without that check, the table can be enormous.
  • Overflow in counting DPs. Stair counts are Fibonacci numbers and grow fast. Use long long or a modulus.

Interview drill

Warm-up: Maximum subarray sum. Present Kadane as a DP, not a trick.

How a strong answer sounds
I define dp[i] as the maximum sum of a subarray ending exactly at index i. At i there are only two options. Either the best subarray ending here extends the best one ending at i−1, or it starts fresh at i. So dp[i] = max(dp[i−1] + a[i], a[i]). Put another way: extend if dp[i−1] is positive, start over if it is negative — the usual informal version. Because the state is "ending at i", the answer is the maximum over all i, not dp[n−1]. The best subarray need not reach the end of the array, and returning the last cell is one of the two classic bugs here. The other is starting the running best at 0. That returns 0 for an all-negative input like [−3,−1,−2] instead of −1. So I start both the running value and the best at a[0]. Since dp[i] only reads dp[i−1], the array shrinks to a single variable: O(n) time and O(1) space. This way of thinking pays off on the variants. Maximum product subarray needs two states instead of one: the maximum and the minimum ending here, because multiplying by a negative swaps them. Seeing that as "add a state", rather than "add a special case", is what makes it straightforward.

Deeper: LIS in O(n log n). Explain the invariant, and why tails is not the answer subsequence.

How a strong answer sounds
I keep an array tails, where tails[k] is the smallest value that can end an increasing subsequence of length k+1. That rule forces tails to be strictly increasing, which is what lets me binary search it. For each new value x, I use lower_bound to find the first position with tails[k] ≥ x. If there is none, x is bigger than every tail, so it extends the longest subsequence and I append it. Otherwise, I overwrite tails[k] with x. The overwrite is safe. x can also end a subsequence of length k+1, built on tails[k−1], which is strictly less than x. And x is smaller than the old tail, so it can only make future extensions easier. It never shortens anything already achievable. So tails.size() is always the current LIS length, and it is the longest possible because I append whenever I can. O(n log n) time, O(n) space. The catch: tails is not the LIS. Its entries were written at different times, from different positions, and some were overwritten out of order. So the contents need not even form a subsequence of the input. To recover an actual LIS, I would record for each element which pile it landed in, plus a pointer to its predecessor, then walk back. Or I would just use the O(n²) DP, whose dp array supports rebuilding naturally. One more detail: lower_bound gives strictly increasing; for non-decreasing I would switch to upper_bound.

🧠 Key takeaways

  • Decide "first i elements" vs. "ending at i" first. It decides whether the answer is dp[n-1] or the maximum over the table.
  • Counting DP is optimisation DP with + instead of min/max. Nothing else changes.
  • Kadane is a one-line DP. Its variants come from adding a second state, not a special case.
  • LIS: use the O(n²) DP if you need the subsequence itself, and patience piles with lower_bound if you only need the length.
  • When dp[i] is not enough, name the extra states out loud — hold/free, transactions used, cooldown.

Check your understanding

For maximum subarray, why is the answer the maximum over the whole dp table rather than dp[n-1]?

The "ending at i" vs. "first i elements" choice decides this. States that build up over a prefix (house robber) have their answer in the last cell. "Ending at i" states (subarray, LIS) need a scan of the whole table.

You initialise Kadane's running best to 0. On which input does it fail?

Every test that contains a positive number passes, which is why this bug survives. Start both the running value and the best at a[0].

In the O(n log n) LIS, what does tails[k] hold?

That rule keeps tails sorted, so binary search works, and makes tails.size() the LIS length. But the contents are not a subsequence of the input. The entries come from different positions and may be overwritten out of order.

Maximum product subarray needs two states. Why?

Track both the max and the min ending at i, and swap them when the current element is negative. This is the general move: when one running value is not enough, add a state instead of a special case.

In the unlimited-transactions stock DP, why save prevFree before updating?

Both transitions must read the previous day's values. It is the same kind of mistake as updating the rolling variables in the wrong order: the code runs, but reports a profit that is too high.
