DP on Sequences (1D)

One-dimensional DP is where the five-step method becomes muscle memory. The state is almost always “the best answer for the first i elements”, and the whole difficulty is what extra information the state needs beyond i. This chapter walks the standard family — stairs, robber, decode ways, LIS, maximum subarray, stock problems — and shows how each one answers that question differently.

  • Write the four canonical 1D recurrences from their state sentences
  • Recognise when dp[i] alone is insufficient and a second dimension is needed
  • Solve LIS in O(n²) as DP and O(n log n) with patience piles
  • See Kadane's algorithm as a two-state DP, not a trick
  • Handle the stock-problem family by naming the states explicitly

The shape of a 1D DP

Almost all of them look like this. The variation is in how far back the transition reaches and how many choices it enumerates.

the 1D templateO(n · choices)O(n), often O(1)
// dp[i] = the best answer considering the first i elements (or ending at i).
// Decide which of those two it is, IN THE COMMENT, before writing code.
vector<int> dp(n);

dp[0]=/* base case, by hand */;

for(int i=1;i<n;i++){
	dp[i]=/* combine dp[i-1], dp[i-2], ... with the choices at i */;
}

return dp[n-1];   // or max over the whole table — check which!
“The first i elements” versus “ending at i” is the decision that matters most. For house robber the answer is dp[n-1] because "the first i" accumulates. For LIS and maximum subarray the state is "ending at i", so the answer is the maximum over the whole table — a subsequence or subarray need not reach the end. Getting this wrong gives a plausible answer that is too small.

Counting: stairs and decode ways

// dp[i] = the number of distinct ways to reach step i.
// To reach i you came from i-1 (one step) or i-2 (two steps), so the
// counts ADD. This is literally Fibonacci.
int climbStairs(int n){
	if(n<=2)return n;

	int prev2=1;
	int prev1=2;

	for(int i=3;i<=n;i++){
		int current=prev1+prev2;
		prev2=prev1;
		prev1=current;
	}

	return prev1;
}

Counting DP uses + where optimisation DP uses min or max. That is the only structural difference, and recognising it means "how many ways" problems need no new machinery. Note the counts grow like Fibonacci, so for large n you need long long or a modulus.

// dp[i] = the minimum cost to REACH step i (having paid for the steps used).
// You may start at 0 or 1, and the top is one past the last step.
int minCostClimbingStairs(vector<int> &cost){
	int n=cost.size();
	int prev2=0;                // cost to reach step 0 = 0 (free start)
	int prev1=0;                // cost to reach step 1 = 0 (free start)

	for(int i=2;i<=n;i++){
		int current=min(prev1+cost[i-1],prev2+cost[i-2]);
		prev2=prev1;
		prev1=current;
	}

	return prev1;              // dp[n] — the top is index n, not n-1
}

The off-by-one here is the whole problem. "Reach step i" means you have not paid cost[i] yet, and the destination is index n, one past the array. Write the state sentence precisely and this resolves itself; guess at it and you will be off by one cost.

// dp[i] = the number of ways to decode the first i characters.
// Two choices: take one digit (if it is 1-9) or take two (if they form 10-26).
int numDecodings(string &s){
	int n=s.size();
	if(n==0 or s[0]=='0')return 0;

	int prev2=1;                // dp[0] = 1: one way to decode an empty prefix
	int prev1=1;                // dp[1] = 1, given s[0] != '0'

	for(int i=2;i<=n;i++){
		int current=0;

		if(s[i-1]!='0')
		current+=prev1;                             // one-digit decode

		int two=(s[i-2]-'0')*10+(s[i-1]-'0');
		if(two>=10 and two<=26)
		current+=prev2;                             // two-digit decode

		prev2=prev1;
		prev1=current;
	}

	return prev1;
}

The zeros are the whole difficulty. '0' cannot stand alone, and "06" is not a valid two-digit code because of the leading zero — hence two >= 10 rather than two >= 1. Test "0", "06", "100" and "230"; each one breaks a different naive attempt.

✍️
My convention: prev2 / prev1 / current, in that order, updated at the bottom

Three named variables, and the two shifts happen as the last two lines of the loop body. Writing prev2 = prev1 before computing current destroys the value you need; writing them in the wrong order destroys the other one. Keeping the shape identical across every rolling-array DP means the update block stops being something you think about. And name them by what they are — prev2, not a — so the recurrence remains readable after the array is gone.

Maximum subarray: Kadane as a two-state DP

Kadane's algorithm is usually presented as a trick. It is not — it is a one-line DP, and seeing it that way makes the variants obvious.

maxSubArray — KadaneO(n)O(1)
// dp[i] = the maximum sum of a subarray ENDING EXACTLY at i.
// Two choices: extend the best subarray ending at i-1, or start fresh at i.
//   dp[i] = max(dp[i-1] + a[i], a[i])
// The answer is the MAXIMUM OVER ALL i, not dp[n-1] — a best subarray
// need not reach the end.
int maxSubArray(vector<int> &a){
	int current=a[0];
	int best=a[0];

	for(int i=1;i<a.size();i++){
		current=max(a[i],current+a[i]);   // start fresh, or extend
		best=max(best,current);
	}

	return best;
}
// Note best starts at a[0], NOT 0 — an all-negative array has a negative answer.
The two-line body is the DP. current is dp[i] collapsed to one variable, and best exists only because the state is "ending at i" rather than "first i elements". Initialising best to 0 is the classic bug — it returns 0 on [-3,-1,-2] instead of −1, and every test with a positive number passes.
🔁
The Kadane family
  • Maximum product subarray — track both the maximum and the minimum ending here, because a negative number swaps them. Two states instead of one.
  • Maximum sum circular subarray — answer is max(normal Kadane, total − minimum subarray), with the special case that an all-negative array must use plain Kadane.
  • Maximum absolute sum — run Kadane for max and for min, take the larger magnitude.
  • Longest subarray with sum ≥ 0 — not Kadane; that is prefix sums plus a monotonic structure (Chapter 6).

The pattern: when one running value is not enough, add a second state rather than a special case. Maximum product is the cleanest illustration.

Longest increasing subsequence

Two solutions worth knowing, because the follow-up is always "can you do better than O(n²)?"

The number of piles is the LIS length. The pile contents are not a valid subsequence — that is the catch.
O(n²) DP — gives the subsequence
// dp[i] = the length of the longest increasing subsequence ENDING at i.
int lengthOfLIS(vector<int> &a){
	int n=a.size();
	vector<int> dp(n,1);      // each element alone is length 1
	int best=1;

	for(int i=1;i<n;i++){
		for(int j=0;j<i;j++){
			if(a[j]<a[i])
			dp[i]=max(dp[i],dp[j]+1);
		}

		best=max(best,dp[i]);
	}

	return best;
}

Straightforward, and the dp array lets you reconstruct the actual subsequence by walking backwards. Start here.

O(n log n) — length only
// tails[k] = the SMALLEST possible tail of an increasing
// subsequence of length k+1. tails is always sorted, so
// lower_bound finds where the new value belongs.
int lengthOfLIS(vector<int> &a){
	vector<int> tails;

	for(int x:a){
		auto it=lower_bound(tails.begin(),tails.end(),x);

		if(it==tails.end())tails.push_back(x);  // extend
		else *it=x;                              // improve a tail
	}

	return tails.size();
}

tails is not the LIS — it is a set of best-possible tails, so its contents may not even be a subsequence of the input. It gives the length only. For non-decreasing instead, use upper_bound.

🧾
Why the patience method gives the right length

Maintain the invariant: tails[k] is the smallest value that can end an increasing subsequence of length k+1. This makes tails strictly increasing, so binary search applies. For a new value x: if it exceeds every tail, it extends the longest subsequence by one, so append it. Otherwise, let k be the first position with tails[k] ≥ x; replacing tails[k] with x keeps the invariant, because x also ends a length-k+1 subsequence (built on tails[k-1] < x) and is smaller, which can only make future extensions easier. Crucially, replacing never shortens anything already achievable — it only improves a tail. So the array's length is always the current LIS length, and it is maximal because we append whenever possible. ∎ The reason the contents are not a subsequence is that entries come from different positions in the input and may have been overwritten out of order.

When dp[i] is not enough: the stock problems

This family is the best illustration of the "widen the state" move. Each variant needs a different amount of extra information beyond the day index.

the stock family, by stateO(n) or O(n·k)O(1) or O(k)
// I: ONE transaction. State: the minimum price seen so far. Not really DP.
int maxProfitOne(vector<int> &prices){
	int mini=INT_MAX;
	int best=0;

	for(int p:prices){
		mini=min(mini,p);
		best=max(best,p-mini);
	}

	return best;
}

// II: UNLIMITED transactions. State: holding or not holding.
//   hold = the best profit while currently owning a share
//   free = the best profit while owning nothing
int maxProfitUnlimited(vector<int> &prices){
	int hold=INT_MIN;
	int free=0;

	for(int p:prices){
		int prevFree=free;
		free=max(free,hold+p);          // sell today
		hold=max(hold,prevFree-p);      // buy today
	}

	return free;
}

// III / IV: AT MOST k transactions. State: (day, transactionsUsed, holding).
// The k dimension is what plain greedy cannot express.
int maxProfitK(int k,vector<int> &prices){
	if(prices.empty() or k==0)return 0;

	// k >= n/2 means unlimited, and avoids an enormous table
	if(k>=(int)prices.size()/2)return maxProfitUnlimited(prices);

	vector<int> hold(k+1,INT_MIN);
	vector<int> free(k+1,0);

	for(int p:prices){
		for(int t=1;t<=k;t++){
			hold[t]=max(hold[t],free[t-1]-p);   // buy, starting transaction t
			free[t]=max(free[t],hold[t]+p);     // sell, completing it
		}
	}

	return free[k];
}

// With COOLDOWN: a third state, "just sold and must wait".
// With FEE: subtract it once per completed transaction, in the sell step.
Naming the states is the entire technique. hold and free are not clever — they are just the two things you can be on any given day, and once named, each transition is obvious. When a variant adds a constraint (a limit, a cooldown, a fee), you add exactly the state needed to express it. The prevFree temporary matters: updating free before hold reads it would let you buy and sell on the same day using the same transaction.

"First i elements" vs "ending at i" — the table above is sorted by it

Notice the pattern: problems about a contiguous subarray or a subsequence use "ending at i" and their answer is the maximum over the table, because the optimal one need not include the last element. Problems that accumulate over a prefix use "first i" and their answer is the final cell. Deciding which before you code removes the two most common 1D bugs — returning dp[n-1] when you needed a maximum, and initialising the running best to 0 when the answer can be negative.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 ENDING AT i
When the answer is a best subarray, define the state as "ending at i" and take the maximum over the whole table. That is Kadane, and it generalises.
💡 ROLL TWO VARS
A 1D DP that reads only i-1 and i-2 needs two variables, not an array. Same complexity, O(1) space, and fewer places to be wrong.
💡 PATIENCE LIS
LIS in O(n log n) is lower_bound into a tails array. The tails array is not the answer subsequence — recovering that needs parent pointers.
⚠️
Common mistakes
  • Returning dp[n-1] for an "ending at i" state. Maximum subarray and LIS both need the maximum over the whole table.
  • Initialising the running best to 0. An all-negative array has a negative answer; start at a[0] or INT_MIN.
  • Updating the rolling variables in the wrong order. prev2 = prev1 before computing current loses the value you need.
  • Updating free before hold reads it in the stock DP, which allows buying and selling on the same day within one transaction.
  • Missing the zero cases in decode ways. "0", "06", "100" and "230" each break a different naive version.
  • Treating tails as the LIS. It gives the length only; its contents may not be a subsequence of the input.
  • Using upper_bound when you need strictly increasing (or lower_bound when you need non-decreasing). One character, opposite semantics.
  • Not special-casing large k in the stock problem. k ≥ n/2 is unlimited; without that check the table can be enormous.
  • Overflow in counting DPs. Stair counts are Fibonacci and grow fast — long long or a modulus.

Interview drill

Warm-up: Maximum subarray sum. Present Kadane as a DP, not a trick.

How a strong answer sounds
I define dp[i] as the maximum sum of a subarray ending exactly at index i. At i there are only two possibilities: either the best subarray ending here extends the best one ending at i−1, or it starts fresh at i — so dp[i] = max(dp[i−1] + a[i], a[i]). Equivalently, extend if dp[i−1] is positive and start over if it is negative, which is the usual informal statement. Because the state is "ending at i", the answer is the maximum over all i rather than dp[n−1] — an optimal subarray need not reach the end of the array, and returning the last cell is one of the two classic bugs here. The other is initialising the running best to 0, which returns 0 for an all-negative input like [−3,−1,−2] instead of −1; I initialise both the running value and the best to a[0]. Since dp[i] only reads dp[i−1], the array collapses to a single variable, giving O(n) time and O(1) space. The framing pays off on the variants: maximum product subarray needs two states rather than one, tracking the maximum and the minimum ending here, because multiplying by a negative swaps them — and seeing that as "add a state" rather than "add a special case" is what makes it straightforward.

Deeper: LIS in O(n log n). Explain the invariant, and why tails is not the answer subsequence.

How a strong answer sounds
I maintain an array tails where tails[k] is the smallest value that can end an increasing subsequence of length k+1. That invariant forces tails to be strictly increasing, which is what lets me binary search it. For each new value x I find the first position with tails[k] ≥ x using lower_bound: if there is none, x is larger than every tail so it extends the longest subsequence and I append it; otherwise I overwrite tails[k] with x. The overwrite is safe because x also ends a subsequence of length k+1 — built on tails[k−1], which is strictly less than x — and x is smaller, so it can only make future extensions easier. It never shortens anything already achievable. So tails.size() is always the current LIS length, and it is maximal because I append whenever possible. O(n log n) time, O(n) space. The catch: tails is not the LIS. Its entries were written at different times from different positions and may have been overwritten out of order, so the contents need not even form a subsequence of the input. To recover an actual LIS I would record, for each element, the pile index it landed in and a predecessor pointer, then walk back — or just use the O(n²) DP, whose dp array supports reconstruction naturally. One more detail: lower_bound gives strictly increasing; for non-decreasing I would switch to upper_bound.

🧠 Key takeaways

  • Decide "first i elements" versus "ending at i" first — it determines whether the answer is dp[n-1] or a maximum over the table.
  • Counting DP is optimisation DP with + instead of min/max; nothing else changes.
  • Kadane is a one-line DP, and its variants come from adding a second state rather than a special case.
  • LIS: O(n²) DP if you need the subsequence, patience piles with lower_bound if you only need the length.
  • When dp[i] is insufficient, name the extra states explicitly — hold/free, transactions used, cooldown.

Check your understanding

For maximum subarray, why is the answer the maximum over the whole dp table rather than dp[n-1]?

The "ending at i" versus "first i elements" distinction decides this. Accumulating states (house robber) end at the last cell; "ending at i" states (subarray, LIS) need a scan.

You initialise Kadane's running best to 0. On which input does it fail?

Every test containing a positive number passes, which is why this survives. Initialise both the running value and the best to a[0].

In the O(n log n) LIS, what does tails[k] hold?

That invariant keeps tails sorted so binary search applies, and makes tails.size() the LIS length. But the contents are not a subsequence of the input — entries come from different positions and may be overwritten out of order.

Maximum product subarray needs two states. Why?

Track both the max and the min ending at i and swap them when the current element is negative. This is the general move: when one running value is insufficient, add a state rather than a special case.

In the unlimited-transactions stock DP, why save prevFree before updating?

The two transitions must both read the previous day's values. Same class of error as updating the rolling variables in the wrong order — the code runs and gives an inflated profit.
