Max Flow & Bipartite Matching

Max flow is the most powerful modelling tool in graph algorithms: a surprising number of problems that look nothing like plumbing — task assignment, image segmentation, project selection, scheduling — are max flow once you build the right network. The algorithm itself rests on one counter-intuitive idea, the residual edge, which lets the algorithm undo its own earlier decisions.

  • Explain why residual (back) edges are necessary, not an optimisation
  • Write Ford-Fulkerson with BFS (Edmonds-Karp) and state its bound
  • Prove max-flow min-cut, and use it to find the actual cut
  • Reduce bipartite matching to max flow, and know Hopcroft-Karp's bound
  • Recognise the modelling patterns: node capacities, multiple sources, project selection

The problem

A directed graph with a source s, a sink t, and a capacity on every edge. Push as much flow as possible from s to t subject to two rules:

Capacity constraint

The flow on an edge never exceeds its capacity: 0 ≤ f(u,v) ≤ c(u,v).

Conservation

For every node except s and t, flow in equals flow out. Nothing is created or stored in the middle.

↩️
The residual edge — the idea that makes it work

Naive greedy fails. Push flow along any path to saturation, repeat, and you get stuck: an early path can block a better arrangement, and there is no way to take it back. The fix is that pushing f units along u → v creates a reverse capacity of f on v → u.

That reverse edge is not a real pipe. Sending flow "backwards" along it means cancelling some of the flow you previously sent forwards, freeing it to be rerouted. So a later augmenting path that uses a residual edge is the algorithm undoing an earlier decision — which is exactly the ability greedy lacked.

This is why the algorithm is correct rather than merely greedy, and it is the whole conceptual content of max flow. The classic demonstration: a network where the first path chosen saturates the middle edge and blocks everything, until a residual edge lets the flow reroute around it.

Edmonds-Karp — Ford-Fulkerson with BFSO(V·E²)O(V²)
// Capacity matrix, because we need O(1) lookup of both cap[u][v] and cap[v][u].
// Only viable for V up to a few hundred; use an edge-list residual graph beyond that.
int maxflow(vector<vector<int>> cap,int N,int s,int t){
	int total=0;

	while(true){
		// BFS for an augmenting path in the RESIDUAL graph.
		// BFS (not DFS) is what makes this Edmonds-Karp and bounds the iterations.
		vector<int> parent(N,-1);
		parent[s]=s;

		queue<int> q;
		q.push(s);

		while(!q.empty() and parent[t]==-1){
			int node=q.front();
			q.pop();

			for(int next=0;next<N;next++){
				// residual capacity > 0 covers BOTH forward and reverse edges
				if(parent[next]==-1 and cap[node][next]>0){
					parent[next]=node;
					q.push(next);
				}
			}
		}

		if(parent[t]==-1)break;        // no path left: flow is maximum

		// bottleneck = the smallest residual capacity on the path
		int bottleneck=INT_MAX;
		for(int v=t;v!=s;v=parent[v]){
			int u=parent[v];
			bottleneck=min(bottleneck,cap[u][v]);
		}

		// push it, and create the residual capacity going back
		for(int v=t;v!=s;v=parent[v]){
			int u=parent[v];
			cap[u][v]-=bottleneck;
			cap[v][u]+=bottleneck;      // THE residual edge
		}

		total+=bottleneck;
	}

	return total;
}
cap is taken by value deliberately — the function destroys it, and the caller almost always still wants the original. And cap[v][u] += bottleneck is the entire mechanism: a single matrix holds forward capacity and residual capacity, so the BFS's one condition cap[node][next] > 0 naturally traverses both kinds of edge without any special case.
⏱️
Why BFS, and why the bound is what it is

Plain Ford-Fulkerson with an arbitrary path choice is not polynomial — the famous bad case is a network with a capacity-1 middle edge where DFS alternates through it and needs O(max flow) iterations, which can be astronomically many with large capacities. Edmonds-Karp uses BFS, choosing a shortest augmenting path, and one can prove the shortest-path distance from s to t never decreases and increases at least every E augmentations — giving O(V·E) augmentations and O(V·E²) total. Dinic's algorithm improves this to O(V²E) by building a level graph once per phase and pushing many blocking paths within it, and to O(E√V) on unit-capacity networks — which is why Dinic is what you use for bipartite matching at scale.

Max-flow min-cut

An s-t cut partitions the nodes with s on one side and t on the other; its capacity is the total capacity of edges crossing forward. The theorem:

max flow = min cut

🧾
Both directions, and how to find the cut

(≤) Any flow is at most any cut's capacity. All flow must cross every s-t cut to get from s to t, and by the capacity constraint it cannot exceed what the crossing edges permit. So max flow ≤ min cut.

(≥) There is a cut equal to the max flow. When the algorithm stops, no augmenting path remains. Let S be the set of nodes reachable from s in the residual graph, and T the rest — note t ∈ T, because otherwise a path would exist. Now every edge from S to T must be saturated (no residual capacity, or its head would be in S), and every edge from T back to S must carry zero flow (otherwise it would have residual capacity backwards, putting its tail in S). So the net flow across this cut equals its full capacity. ∎

That proof is also the algorithm for finding the cut: run max flow, then BFS from s in the residual graph. The reachable set is S, and the saturated edges from S to T are the min cut. Press the button in the visualizer above to see it.

Bipartite matching as max flow

Given a bipartite graph, find the largest set of edges with no shared endpoint. The reduction is immediate:

Add a source and a sink

A virtual s and t outside the original graph.

Connect s to every left node with capacity 1

The capacity of 1 is what enforces "each left node is matched at most once".

Keep every original edge, capacity 1

Directed left → right.

Connect every right node to t with capacity 1

Enforcing "each right node is matched at most once".

Max flow = maximum matching

Because all capacities are integers, an integral maximum flow exists, and each unit of flow traces a single left–right edge. The saturated middle edges are the matching.

Kuhn's algorithm — bipartite matching without building a flow networkO(V·E)O(V)
// For each left node, try to find an augmenting path. The recursion IS the
// residual-edge idea specialised to matching: if a right node is taken, ask
// its current partner to move elsewhere.
bool tryMatch(vector<vector<int>> &graph,int u,vector<bool> &used,vector<int> &matchOf){
	for(int v:graph[u]){
		if(used[v])continue;        // already explored v in THIS attempt

		used[v]=true;

		// v is free, or v's partner can be rehoused
		if(matchOf[v]==-1 or tryMatch(graph,matchOf[v],used,matchOf)){
			matchOf[v]=u;
			return true;
		}
	}

	return false;
}
int maxMatching(vector<vector<int>> &graph,int leftN,int rightN){
	vector<int> matchOf(rightN,-1);   // matchOf[v] = the left node matched to v
	int size=0;

	for(int u=0;u<leftN;u++){
		vector<bool> used(rightN,false);   // FRESH for every left node

		if(tryMatch(graph,u,used,matchOf))
		size++;
	}

	return size;
}
The used array must be reset for every left node. It prevents revisiting a right node within a single augmenting attempt — reusing it across attempts would block legitimate matches and undercount. O(V·E) and about fifteen lines, which is why Kuhn is the practical answer for matching rather than building a full flow network. Hopcroft-Karp improves it to O(E√V) by finding many shortest augmenting paths per phase, which matters above V ≈ 10⁴.
✍️
My convention: use Kuhn for matching, reach for full max flow only when capacities are not 1

If the problem is "match As to Bs, each used once", Kuhn is fifteen lines and needs no source, sink or capacity matrix. Build the flow network only when you genuinely need capacities other than 1 — a worker who can take three tasks, a warehouse with limited stock, a node with a throughput limit. The tell is the word “at most k” rather than “at most one”.

👑
König's theorem — and why it makes matching so useful

In a bipartite graph, maximum matching = minimum vertex cover (the smallest set of nodes touching every edge). And by complementation, maximum independent set = V − maximum matching. These equivalences are why bipartite matching answers questions that never mention matching at all: "minimum number of rows and columns to cover all the marked cells", "maximum non-attacking rooks", "minimum machines to process all jobs", "maximum items I can select with no conflicts". When a problem says "minimum nodes to cover all edges" or "maximum items with no two conflicting" on a bipartite structure, compute a matching. (Note both statements fail on general graphs — minimum vertex cover is NP-hard there, and that gap is exactly what makes bipartiteness special.)

The modelling patterns

The algorithm is standard; the skill is building the network. Five patterns cover most of it.

A node has a capacity, not just its edges

→ Split the node. Replace v with v_in → v_out carrying the node's capacity, and redirect all incoming edges to v_in and outgoing edges from v_out.

cap[v_in][v_out] = nodeCapacity;
Several sources or several sinks

→ Add a super-source and super-sink. Infinite-capacity edges from the super-source to each real source, and from each real sink to the super-sink.

cap[S][src_i] = INF;
“Assign each A to at most one B”

→ Bipartite matching. Capacity 1 on the source and sink edges is what enforces "at most one".

cap[s][a] = 1; cap[b][t] = 1;
“Each worker can take up to k tasks”

→ Same network, but cap[s][worker] = k. This is a flow problem, not a matching one, which is why Kuhn no longer applies.

cap[s][worker] = k;
“Select projects with profits, but prerequisites cost money”

→ Project selection / max closure. Source to each profitable item with its profit, each cost item to sink with its cost, infinite-capacity edges for dependencies. Answer = total profit − min cut.

answer = totalProfit - maxflow(s,t);
“Minimum edges/nodes to disconnect X from Y”

→ Min cut directly, by max-flow min-cut. For node connectivity, split the nodes first.

minCut = maxflow(s,t);
🎯
When to suspect max flow at all

Flow is a heavy hammer and most problems do not need it. The signals: a bipartite structure with a one-to-one or bounded assignment; the words “minimum cut”, “disconnect”, “bottleneck” or “capacity”; a selection problem with dependencies where taking one thing forces another; or a problem where a greedy visibly fails because early choices block later ones and you need the ability to undo. If instead the problem is a plain assignment with costs to minimise, that is min-cost max flow or the Hungarian algorithm — related but distinct machinery. And in an interview, flow is more often about recognising and modelling it than implementing it; say "this is max flow, here is the network, and I would use Dinic" and then discuss the construction.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 MODEL, DO NOT IMPLEMENT
The skill being tested is the reduction: what are the two sides, what is the capacity, what does a unit of flow mean. Naming max-flow and describing the graph is usually the whole answer.
💡 MATCHING = FLOW
Bipartite matching is max-flow with unit capacities. Kőnig then gives minimum vertex cover, and the complement gives maximum independent set — three answers from one run.
💡 NODE CAPACITY
To cap a node rather than an edge, split it into in- and out-halves joined by one edge of that capacity. A standard trick worth remembering.
⚠️
Common mistakes
  • Forgetting to add the residual edge. Without cap[v][u] += bottleneck the algorithm is just greedy and returns a wrong, smaller answer.
  • Using DFS for the augmenting path and calling it Edmonds-Karp. BFS is what gives the polynomial bound.
  • Mutating the caller's capacity matrix. Take it by value, or copy it first.
  • Not resetting used per left node in Kuhn. Blocks legitimate augmenting paths and undercounts the matching.
  • Using capacity 1 when the problem says “up to k”. That silently solves a different problem.
  • Forgetting to split nodes when the node has a capacity. Edge capacities alone cannot express a throughput limit.
  • Reporting the min cut as the set of saturated edges everywhere. Only the saturated edges from S to T count, where S is the residual-reachable set.
  • Using INT_MAX for infinite capacity and then summing. Two infinite edges overflow — use a large finite value like 1e9.
  • Applying König's theorem to a non-bipartite graph. Minimum vertex cover is NP-hard in general.
  • Reaching for flow when a greedy provably works. Interval scheduling and many assignment problems have simple greedy solutions (Chapter 36).

Interview drill

Warm-up: Why does max flow need residual (back) edges?

How a strong answer sounds
Because without them the algorithm is a plain greedy and gets stuck. Pushing flow along a path saturates its bottleneck edge, and an unlucky early choice can block an arrangement that would have carried more total flow — with no mechanism to reconsider. The residual edge fixes that: when I push f units along u → v, I add f units of capacity on v → u. That reverse edge is not a real pipe; sending flow along it means cancelling flow I previously committed on u → v, which frees those units to be rerouted elsewhere. So an augmenting path that uses a residual edge is the algorithm undoing an earlier decision, and that ability to undo is exactly what turns a greedy into a correct algorithm. Implementation-wise it is elegant: a single capacity matrix holds both real and residual capacity, so the path search just asks "is cap[u][v] > 0?" and traverses both kinds of edge with no special case. And it is also what makes the min-cut proof work — when no augmenting path remains, the set of nodes reachable from the source in the residual graph defines a cut whose crossing edges are all saturated, so its capacity equals the flow.

Deeper: Model this: N workers, M tasks, each worker qualified for some tasks and able to take at most 3, each task needing exactly one worker. Maximise assigned tasks.

How a strong answer sounds
This is max flow rather than plain matching, because of the "at most 3" — Kuhn's algorithm enforces at most one per node and cannot express a larger bound. I build a network with a super-source s, the N workers, the M tasks, and a super-sink t. From s to each worker I put capacity 3, which is what encodes the workload limit. From each worker to each task they are qualified for, capacity 1 — that stops the same worker being counted twice for one task. From each task to t, capacity 1, encoding "exactly one worker per task". The maximum flow is then the maximum number of assigned tasks, and because all capacities are integral there is an integral maximum flow, so the saturated worker-to-task edges give an actual valid assignment rather than a fractional one. I would use Dinic, which is O(V²E) in general and O(E√V) on unit-capacity networks, so it handles this size comfortably; Edmonds-Karp would also work and is easier to write if V is small. Two follow-ups worth pre-empting: if a task needed up to k workers, that capacity moves to the task-to-t edge; and if each worker had a per-task cost and I had to minimise total cost among maximum assignments, this becomes min-cost max flow or the Hungarian algorithm, which is different machinery.

🧠 Key takeaways

  • The residual edge lets the algorithm cancel earlier flow, which is what makes max flow correct rather than greedy.
  • Edmonds-Karp uses BFS for the augmenting path, giving O(V·E²); Dinic is the practical choice at O(V²E), or O(E√V) on unit capacities.
  • Max flow equals min cut, and the cut is found by BFS from the source in the residual graph after termination.
  • Bipartite matching is max flow with all capacities 1 — but Kuhn's 15 lines are usually the better answer.
  • Modelling is the real skill: split nodes for node capacities, add super-source/sink for multiple endpoints, and use König to turn covers and independent sets into matchings.

Check your understanding

What does a residual (reverse) edge represent?

This is the whole conceptual content of max flow. Sending flow "backwards" undoes an earlier commitment, which is the ability plain greedy lacks — and it is also what makes the min-cut proof work.

Why does Edmonds-Karp specifically use BFS for the augmenting path?

With an arbitrary path, Ford-Fulkerson can take O(maxflow) iterations, which is not polynomial in the input size. BFS makes the s–t distance non-decreasing and forces it to grow, bounding the iterations.

After max flow terminates, how do you find the min cut?

Every S→T edge must be saturated (or its head would be reachable) and every T→S edge must carry zero flow — so the cut's capacity equals the flow. Not all saturated edges are in the cut.

A problem says each worker can take up to 3 tasks. Why can Kuhn's algorithm not be used?

The matchOf array holds one partner per node; there is nowhere to express a larger bound. The tell in a problem statement is "at most k" rather than "at most one".

This is why matching answers questions that never mention matching: "minimum rows and columns to cover all marks", "maximum non-conflicting selections". Both equalities fail on general graphs, where minimum vertex cover is NP-hard.
