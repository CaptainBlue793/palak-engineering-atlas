Shortest Paths II: Bellman-Ford, Floyd

Dijkstra's greedy choice breaks as soon as an edge can have a negative cost (Chapter 29). The fix is to drop the greedy idea completely and instead try to improve every edge, over and over, until nothing changes. Trying to improve an edge is called relaxing it: if reaching a node through one of its incoming edges is cheaper than the best route found so far, write down the cheaper number. Bellman-Ford does this from one starting node and detects negative cycles as a bonus. Floyd-Warshall does it for every pair of nodes, in three nested loops that are far subtler than they look. Both are short, and in both there is one line whose position is critical.

  • Explain why V−1 rounds of relaxing every edge are enough, and what it means if a Vth round still improves something
  • Write Bellman-Ford with the check for unreachable nodes that prevents number overflow
  • Build up Floyd-Warshall and say exactly why k must be the outermost loop
  • Use Floyd-Warshall to answer "who can reach whom" and "which route has the smallest worst step"
  • Pick between BFS, Dijkstra, Bellman-Ford, Floyd and Johnson using the problem's limits

Bellman-Ford: relax everything, V−1 times

Where do negative weights come from? Any time an edge can give back rather than cost: a road with a toll refund, a game move that restores energy, or a trade that earns money. A classic case is currency exchange: taking the logarithm of each exchange rate and negating it turns "is there a loop of trades that makes a profit?" into "is there a negative cycle?". Those are exactly the graphs Dijkstra cannot handle.

No priority queue, no set of settled nodes, no cleverness. Just this: repeat V−1 times, and each time try to improve every single edge.

🧾
Why V−1 rounds are enough

In a graph with no negative cycle, a shortest path is simple: it never visits the same vertex twice. If it did, cutting out the repeated loop would leave the path the same length or shorter. A simple path over V vertices uses at most V−1 edges.

Now build it up round by round: after round i, every node whose shortest path uses at most i edges has its final distance. Round 1 finishes all one-edge paths, since relaxing the last edge of such a path only needs the source's distance, which is already correct. Round 2 finishes all two-edge paths, because the first edge of each was settled in round 1. Each round relaxes every edge, so whatever order the edges come in, the earlier part of the path is already correct by the time you need it. By round V−1, every possible simple-path length is covered. ∎

The neat part is that the order of relaxations does not matter at all. That is exactly why this works with negative weights, where the greedy approach cannot.

🔁
And why a Vth improvement means a negative cycle

After V−1 rounds, every shortest simple path is final. So if a Vth pass can still improve something, the better path must use V or more edges. With only V vertices to go round, it must visit one of them twice, so it contains a cycle. And since this path is shorter than the best simple path, that cycle must add up to a negative total. So one extra pass is an exact test for negative cycles. One limit: it only finds cycles you can reach from the source. To find a negative cycle anywhere in the graph, add an extra made-up node with a 0-weight edge to every node, and start there.

A dry run shows why the number of rounds matters. V = 4, and the edges are listed in an unlucky order: 1→3 (2), 2→1 (−3), 0→1 (4), 0→2 (5). The source is 0, so start with dist = [0, ∞, ∞, ∞].

// Works on an EDGE LIST, not an adjacency list — it never asks
// "what are node x's neighbours?", only "relax every edge".
vector<int> bellman_ford(int V,vector<vector<int>> &edges,int S){
	vector<int> dist(V,INT_MAX);
	dist[S]=0;

	// V-1 rounds: after round i, all shortest paths of <= i edges are final.
	for(int i=1;i<=V-1;i++){
		for(auto &edge:edges){
			int u=edge[0];
			int v=edge[1];
			int w=edge[2];

			if(dist[u]!=INT_MAX and w+dist[u]<dist[v]){
				dist[v]=w+dist[u];
			}
		}
	}

	// One more pass. Any improvement means a reachable negative cycle.
	for(auto &edge:edges){
		int u=edge[0];
		int v=edge[1];
		int w=edge[2];

		if(dist[u]!=INT_MAX and w+dist[u]<dist[v])
		return {-1};                  // negative cycle
	}

	for(int i=0;i<V;i++){
		if(dist[i]==INT_MAX)
		dist[i]=-1;                   // unreachable, by this problem's convention
	}

	return dist;
}
dist[u] != INT_MAX is not optional. Here INT_MAX is the "infinity" marker for a node you cannot reach yet. Without the check, an unreachable u gives INT_MAX + w, which for positive w overflows and wraps around to a large negative number. Then dist[v] is set to nonsense, and that nonsense spreads through the whole graph. Checking the node you are relaxing from fixes it. Using long long with a smaller "infinity" such as 1e18 also works, and is what competitive programmers usually do.
✍️
My convention: unpack u, v, w on their own lines

Give the three values names instead of writing edge[0], edge[1] and edge[2] everywhere. It costs three lines and removes a whole class of bug. Writing edge[2] where you meant edge[1] compiles, runs, and gives a wrong answer that looks like a broken algorithm rather than a typo. This is the same reason the graph-building loop in Chapter 25 unpacks the edge before pushing. (In C++17 you can also write auto &[u,v,w] = edge; if the edges are tuples, which is shorter and just as clear.)

⚡
Two practical improvements
  • Stop early. If a whole round improves nothing, nothing will ever change again, so break. On real graphs this usually finishes in a handful of rounds instead of V−1, and it costs one boolean variable.
  • SPFA (the queue-based version). Keep a queue and only revisit nodes whose distance actually changed. It is often much faster in practice, but the worst case is still O(V·E), and there are known test cases built to break it. So never rely on it as a guarantee.

Neither changes the big-O bound. Say O(V·E), and mention these as speed-ups to the constant factor.

Floyd-Warshall: all pairs in three loops

The DP is elegant once you state it carefully. Let dp[k][i][j] be the shortest distance from i to j if the only nodes you are allowed to pass through on the way are {0, 1, …, k−1}. Then:

dp[k+1][i][j] = min( dp[k][i][j] , dp[k][i][k] + dp[k][k][j] )

In words: either you do not use k at all, or your route passes through k, in which case it is the best way to k plus the best way on from k. And because each layer reads the previous one in a way that turns out to be safe even when you overwrite in place, you can drop the k dimension and keep a single 2D array — which gives the famous three nested loops.

Small example with 3 nodes and edges 0→1 (3), 1→2 (1), 0→2 (10). The starting matrix holds only direct edges, so d[0][2] = 10. With k = 0, we ask "is going through node 0 better?". No edge leads into 0, so nothing changes. With k = 1: d[0][2] = min(10, d[0][1] + d[1][2]) = min(10, 3 + 1) = 4. With k = 2: nothing leaves 2, so nothing changes. The final d[0][2] is 4, via node 1. Each pivot is tried against all V² pairs, so the total is V × V² = V³ steps. At V = 500 that is 1.25 × 10⁸ simple operations, about the limit for one second — which is why Floyd-Warshall is kept for small graphs.

You also need Floyd-Warshall's matrix to start correctly: d[i][i] = 0, d[i][j] = the edge weight if there is an edge (the smallest one, if there are several), and "infinity" otherwise.

Floyd-WarshallO(V³)O(V²)
// matrix[i][j] is the direct edge weight, or -1 for "no edge".
// Convert to INT_MAX, run, convert back — the problem's convention.
void FWA(vector<vector<int>> &matrix,int N){
	for(int i=0;i<N;i++){
		for(int j=0;j<N;j++){
			if(matrix[i][j]==-1)
			matrix[i][j]=INT_MAX;
		}
	}

	for(int k=0;k<N;k++){          // PIVOT MUST BE OUTERMOST
		for(int i=0;i<N;i++){
			for(int j=0;j<N;j++){
				// guard against INT_MAX + INT_MAX overflow
				if(matrix[i][k]==INT_MAX or matrix[k][j]==INT_MAX)continue;

				int dist=matrix[i][k]+matrix[k][j];
				matrix[i][j]=min(matrix[i][j],dist);
			}
		}
	}

	for(int i=0;i<N;i++){
		for(int j=0;j<N;j++){
			if(matrix[i][j]==INT_MAX)
			matrix[i][j]=-1;
		}
	}
}
The overflow check is the line people leave out. Without it, two unreachable entries give INT_MAX + INT_MAX, which wraps around to a negative number and instantly corrupts the matrix. Skip such pairs, or use long long with an "infinity" like 1e18 that survives being added to itself. Skipping with continue is also faster, since it avoids the arithmetic.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 V−1 THEN ONE MORE
Bellman-Ford relaxes V−1 rounds; a V-th round that still improves something proves a negative cycle. That extra pass is the detector.
💡 DIST ALL ZERO
To find a negative cycle anywhere rather than only from a source, initialise every distance to 0. Neater than adding a virtual node, and one line.
⛔ FLOYD LOOP ORDER
In Floyd-Warshall, k must be the outermost loop. Any other order computes something that is not the shortest path, and it looks plausible.
🚨
k must be the outermost loop — and it is not obvious why

Put k in the innermost loop and the algorithm is wrong — quietly and subtly so. Here is why.

Layer dp[k+1] is computed from layer dp[k]. We drop the k dimension and overwrite the matrix in place, and that is only safe because of one fact: the layer-k update cannot change dp[k][i][k] or dp[k][k][j]. Going from i to k "via k" is pointless, so those two entries are already final when layer k starts. That is why it does no harm to read values from the same layer while writing to it.

With k innermost, that guarantee disappears. For one fixed pair (i, j) you run through all the pivots before moving on, so when you later handle a different pair you may read entries that were computed under a different set of allowed middle nodes. In effect you only find paths whose middle vertices happen to appear in a convenient order, and you miss valid routes. The symptom is a matrix that is almost right: often correct on small tests and wrong on longer paths, which makes it a horrible bug to track down. The rule: the pivot loop goes outermost, always.

🔧
Three variants from the same three loops
  • Transitive closure — can i reach j at all? Make the matrix true/false and use reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j]). This is Warshall's algorithm. Storing each row as a bitset makes it O(V³/64), which is genuinely fast up to about V = 5000.
  • Minimax path — make the biggest single edge on the route as small as possible. Replace the sum with max: d[i][j] = min(d[i][j], max(d[i][k], d[k][j])). This answers "what capacity do I need?" questions for every pair at once.
  • Negative cycle detection — after the run, if any matrix[i][i] < 0, then node i sits on a negative cycle: it found a way back to itself with a negative total. One extra loop over the diagonal.

Also, to rebuild the actual paths, keep a next[i][j] matrix and set it to k whenever a route improves, then follow it afterwards. That costs O(V²) extra space.

  • V = 10⁵, E = 2×10⁵, weights positive, one source: Dijkstra, about 3×10⁵ × 17 ≈ 5×10⁶ steps. Bellman-Ford would be 10⁵ × 2×10⁵ = 2×10¹⁰ — far too slow.

  • V = 400, distances between every pair needed: Floyd-Warshall, 400³ = 6.4×10⁷ steps, and twelve lines of code.
  • V = 5000, E = 10⁴, every pair, negative weights: Floyd would be 1.25×10¹¹, too slow. Johnson runs Dijkstra 5000 times on a sparse graph, roughly 5000 × 1.5×10⁴ × 13 ≈ 10⁹ — heavy, but in reach where Floyd is not.
🧮
Johnson's algorithm — how to make negative weights Dijkstra-safe

For all-pairs shortest paths on a sparse graph (few edges) with negative weights, V³ work is wasteful. Johnson's algorithm changes the weights so that Dijkstra becomes valid again, then runs Dijkstra from every node:

  1. Add a made-up node s with a 0-weight edge to every node.
  2. Run Bellman-Ford from s to get a number h(v) for each node, called its potential. (This step also detects any negative cycle.)
  3. Give every edge a new weight: w'(u,v) = w(u,v) + h(u) − h(v). These are provably never negative, because Bellman-Ford's answer satisfies h(v) ≤ h(u) + w(u,v) — which is just saying no edge can be improved any further.
  4. Run Dijkstra from each node on the new weights, then undo the shift: d(u,v) = d'(u,v) − h(u) + h(v).

Why this keeps the shortest paths the same, while the naive "add a constant to every edge" does not: add up the h terms along a path and every middle one cancels with the next. Only h(start) − h(end) is left. So every path between the same pair of nodes shifts by the same amount, no matter how many edges it has, and their ranking does not change. Adding a constant c to each edge instead shifts a k-edge path by k·c, which punishes longer paths and can change which one wins. That cancelling is the whole insight.

⚠️
Common mistakes
  • k is not the outermost loop in Floyd-Warshall. Quietly wrong, and often correct on small tests.
  • No overflow check. INT_MAX + w in Bellman-Ford, or INT_MAX + INT_MAX in Floyd, wraps around to a negative number and corrupts everything after it.
  • Running only V−2 rounds, or running V rounds and accepting the last one's improvements as real. It is V−1 rounds, then one extra pass purely to detect a negative cycle.
  • Claiming Bellman-Ford finds all negative cycles. It only finds the ones reachable from the source. Add a made-up node joined to everything to find any of them.
  • Using Dijkstra with negative weights (Chapter 29). Wrong, not slow.
  • Using Floyd-Warshall at V = 10⁴. That is 10¹² operations, and the matrix alone takes 400 MB.
  • Forgetting matrix[i][i] = 0 when setting up Floyd. The distance from a node to itself is 0, not "no edge".
  • Not handling duplicate edges when building the matrix. For a repeated pair, keep the smallest weight, not whichever one you wrote last.
  • Using Bellman-Ford when the graph is a DAG. A DP in topological order is O(V + E) and handles negative weights too (Chapter 26).

Interview drill

Warm-up: Why exactly V−1 rounds in Bellman-Ford, and what does a Vth improvement tell you?

How a strong answer sounds
Because in a graph with no negative cycle, a shortest path is simple — repeating a vertex could only keep the length the same or make it longer — and a simple path over V vertices uses at most V−1 edges. The rule I rely on is that after round i, every node whose shortest path uses at most i edges already has its final distance. Round 1 finishes all one-edge paths, since only the source's distance is needed. Round 2 finishes two-edge paths, because their first edges were settled in round 1, and so on. The key point is that each round relaxes every edge, so the order inside a round does not matter. That is exactly what lets this work with negative weights, where Dijkstra's greedy cannot. After V−1 rounds, every possible simple-path length is covered. If a Vth pass can still improve something, that better path needs V or more edges, so it must repeat a vertex and therefore contains a cycle. Since it is shorter than the best simple path, that cycle has a negative total weight. So one extra pass is an exact negative-cycle test. Two caveats. It only finds cycles reachable from the source, so to detect any negative cycle I would add a made-up source with 0-weight edges to every node. And I must guard each relaxation with dist[u] != INT_MAX, or an unreachable node overflows and poisons the whole array.

Deeper: Why must k be the outermost loop in Floyd-Warshall?

How a strong answer sounds
The DP underneath has three dimensions. dp[k][i][j] is the shortest i-to-j distance when the only nodes you may pass through are 0 up to k−1. The step is the smaller of "do not use k" and "dp[k][i][k] + dp[k][k][j]". Layer k+1 reads layer k. The reason we can drop the k dimension and update the matrix in place comes down to one fact: the layer-k update cannot change dp[k][i][k] or dp[k][k][j], because going from i to k through k is pointless. Those two entries are already final when layer k begins, so it does not matter whether we read them before or after an update. That is what makes the in-place 2D version correct, and it only holds if every pair is processed for one fixed k before moving to the next pivot — which means k must be the outermost loop. Move k inside, and for one fixed (i,j) you run through every pivot before touching other pairs. Later pairs then read entries computed under a different set of allowed middle nodes, so you only find paths whose middle vertices happen to line up in a convenient order, and you miss valid routes. The nasty part is that the result is usually almost right: small graphs and short paths often come out correct, so it survives casual testing and fails on longer paths. I would also mention the overflow check: skip the pair when either matrix[i][k] or matrix[k][j] is the infinity marker, otherwise INT_MAX + INT_MAX wraps around to a negative number and corrupts the matrix.

🧠 Key takeaways

  • Bellman-Ford relaxes every edge V−1 times, because a shortest simple path uses at most V−1 edges. The order of edges within a round does not matter.
  • One extra pass detects a negative cycle reachable from the source, exactly. A made-up source joined to every node finds cycles anywhere.
  • Check for the infinity marker before every relaxation, or overflow quietly corrupts the distances.
  • In Floyd-Warshall the pivot k must be the outermost loop. That is what makes updating a single 2D matrix in place valid.
  • Johnson reweights edges with w + h(u) − h(v). Along any path the middle terms cancel, which is why it keeps shortest paths the same while "add a constant" does not.

Check your understanding

Why does Bellman-Ford run exactly V−1 rounds?

With no negative cycle, shortest paths are simple, so they use at most V−1 edges. Each round relaxes every edge, so the earlier part of a path is always already correct, whatever order the edges come in. That is why this works where Dijkstra's greedy fails.

A Vth relaxation pass still improves some distance. What does that mean?

An exact test: with only V vertices, a path of V or more edges has to repeat one. Note it only finds cycles reachable from the source. Add a made-up source with 0-weight edges to every node to detect one anywhere.

You omit the dist[u] != INT_MAX guard in Bellman-Ford. What happens?

The overflow wraps around to a negative number, and that nonsense distance then spreads to further edges. Check the node you relax from, or use long long with an infinity like 1e18 that survives being added to.

Why does Johnson's reweighting w'(u,v) = w(u,v) + h(u) − h(v) preserve shortest paths, while adding a constant to every edge does not?

The cancelling is the whole insight. The middle potentials cancel out, so the ranking of paths is unchanged. A flat constant instead punishes paths with more edges and can change which one is shortest.
