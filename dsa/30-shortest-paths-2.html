Shortest Paths II: Bellman-Ford, Floyd

Dijkstra's greedy fails the moment an edge can be negative (Chapter 29). The fix is to abandon the greedy entirely: relax every edge, repeatedly, until nothing improves. Bellman-Ford does that for one source and detects negative cycles as a bonus; Floyd-Warshall does it for all pairs in three nested loops that are much subtler than they look. Both are short, both have one line whose position is critical.

  • Explain why V−1 rounds of edge relaxation suffice, and what a Vth improvement means
  • Write Bellman-Ford with the unreachable-node guard that prevents overflow
  • Derive Floyd-Warshall and say exactly why k must be the outermost loop
  • Use Floyd-Warshall for transitive closure and minimax paths
  • Pick between BFS, Dijkstra, Bellman-Ford, Floyd and Johnson from the constraints

Bellman-Ford: relax everything, V−1 times

No priority queue, no settled set, no cleverness. Just: for each of V−1 rounds, try to improve every edge.

🧾
Why V−1 rounds are enough

A shortest path in a graph with no negative cycle is simple — it visits no vertex twice, because removing a repeated section could only keep it the same or make it shorter. A simple path on V vertices has at most V−1 edges.

Now the induction: after round i, every node whose shortest path uses at most i edges has its final distance. Round 1 settles all 1-edge paths, because relaxing the last edge of such a path requires only the source's correct distance, which we have. Round 2 settles all 2-edge paths, since their prefixes were finalised in round 1 — and each round relaxes every edge, so whatever order they come in, the correct prefix is already available. By round V−1, every simple path length is covered. ∎ The elegance is that the relaxation order does not matter at all, which is exactly why this works with negative weights where the greedy cannot.

🔁
And why a Vth improvement means a negative cycle

After V−1 rounds, every shortest simple path is final. So if a Vth pass can still improve some edge, the improving path must use V or more edges, which by the pigeonhole principle repeats a vertex — it contains a cycle. And since it is shorter than the best simple path, that cycle must have negative total weight. So one extra pass is a complete and exact negative-cycle test. Note it detects cycles reachable from the source only; to find any negative cycle anywhere, add a virtual source with 0-weight edges to every node.

// Works on an EDGE LIST, not an adjacency list — it never asks
// "what are node x's neighbours?", only "relax every edge".
vector<int> bellman_ford(int V,vector<vector<int>> &edges,int S){
	vector<int> dist(V,INT_MAX);
	dist[S]=0;

	// V-1 rounds: after round i, all shortest paths of <= i edges are final.
	for(int i=1;i<=V-1;i++){
		for(auto &edge:edges){
			int u=edge[0];
			int v=edge[1];
			int w=edge[2];

			if(dist[u]!=INT_MAX and w+dist[u]<dist[v]){
				dist[v]=w+dist[u];
			}
		}
	}

	// One more pass. Any improvement means a reachable negative cycle.
	for(auto &edge:edges){
		int u=edge[0];
		int v=edge[1];
		int w=edge[2];

		if(dist[u]!=INT_MAX and w+dist[u]<dist[v])
		return {-1};                  // negative cycle
	}

	for(int i=0;i<V;i++){
		if(dist[i]==INT_MAX)
		dist[i]=-1;                   // unreachable, by this problem's convention
	}

	return dist;
}
dist[u] != INT_MAX is not optional. Without it, an unreachable u gives INT_MAX + w, which for positive w overflows to a large negative number — and then dist[v] gets set to nonsense that propagates through the whole graph. Guarding the source of the relaxation is the fix; using long long with a smaller sentinel like 1e18 also works and is what competitive programmers usually do.
✍️
My convention: unpack u, v, w on their own lines

Three named locals rather than edge[0], edge[1], edge[2] inline. It costs three lines and removes an entire class of bug — edge[2] where you meant edge[1] compiles, runs, and produces a wrong answer that looks like an algorithm error rather than a typo. The same reason the graph-building loop in Chapter 25 unpacks before pushing. (With C++17 you can also write auto &[u,v,w] = edge; if the edges are tuples, which is shorter and equally explicit.)

⚡
Two practical improvements
  • Early exit. If a whole round makes no improvement, nothing will ever change again — break. On real graphs this usually terminates in a handful of rounds rather than V−1, and it costs one boolean.
  • SPFA (the queue-based variant). Only re-examine nodes whose distance actually changed, using a queue. Often dramatically faster in practice, but its worst case is still O(V·E) and there are known anti-SPFA tests — so never rely on it for a guarantee.

Neither changes the asymptotic bound. Quote O(V·E) and mention these as constant-factor wins.

Floyd-Warshall: all pairs in three loops

The DP is beautiful once stated correctly. Define dp[k][i][j] as the shortest distance from i to j using only intermediate vertices from {0, 1, …, k−1}. Then:

dp[k+1][i][j] = min( dp[k][i][j] , dp[k][i][k] + dp[k][k][j] )

Either you do not use k at all, or you route through it. And because the k dimension only ever reads from the previous layer in a way that happens to be safe in place, the array collapses to 2D — giving the famous three nested loops.

// matrix[i][j] is the direct edge weight, or -1 for "no edge".
// Convert to INT_MAX, run, convert back — the problem's convention.
void FWA(vector<vector<int>> &matrix,int N){
	for(int i=0;i<N;i++){
		for(int j=0;j<N;j++){
			if(matrix[i][j]==-1)
			matrix[i][j]=INT_MAX;
		}
	}

	for(int k=0;k<N;k++){          // PIVOT MUST BE OUTERMOST
		for(int i=0;i<N;i++){
			for(int j=0;j<N;j++){
				// guard against INT_MAX + INT_MAX overflow
				if(matrix[i][k]==INT_MAX or matrix[k][j]==INT_MAX)continue;

				int dist=matrix[i][k]+matrix[k][j];
				matrix[i][j]=min(matrix[i][j],dist);
			}
		}
	}

	for(int i=0;i<N;i++){
		for(int j=0;j<N;j++){
			if(matrix[i][j]==INT_MAX)
			matrix[i][j]=-1;
		}
	}
}
The overflow guard is the line people omit. Without it, two unreachable entries give INT_MAX + INT_MAX, which overflows to a negative number and instantly corrupts the matrix. Skip the pair, or use long long with a sentinel like 1e18 that can be added twice safely. The continue version is also faster, since it skips the arithmetic.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 V−1 THEN ONE MORE
Bellman-Ford relaxes V−1 rounds; a V-th round that still improves something proves a negative cycle. That extra pass is the detector.
💡 DIST ALL ZERO
To find a negative cycle anywhere rather than only from a source, initialise every distance to 0. Neater than adding a virtual node, and one line.
⛔ FLOYD LOOP ORDER
In Floyd-Warshall, k must be the outermost loop. Any other order computes something that is not the shortest path, and it looks plausible.
🚨
k must be the outermost loop — and it is not obvious why

Put k innermost and the algorithm is wrong, silently and subtly. Here is the reason.

The DP layer dp[k+1] depends on dp[k]. We are collapsing the k dimension and updating in place, which is only valid because of a specific fact: dp[k][i][k] and dp[k][k][j] are unaffected by the layer-k update itself. Routing from i to k via k is pointless, so those two entries are already final when layer k begins, and reading possibly-updated values from the same layer is harmless.

With k innermost, that guarantee evaporates: for a fixed (i, j) you sweep all pivots before moving on, so when you later process a different pair you may read entries computed with an inconsistent set of allowed intermediates. In effect you consider only paths whose intermediate vertices happen to appear in a compatible order, and you miss valid routes. The symptom is a matrix that is almost right — often correct on small tests and wrong on longer paths, which makes it a miserable bug to find. The rule: pivot outermost, always.

🔧
Three variants from the same three loops
  • Transitive closure (can i reach j?): make the matrix boolean and use reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j]). This is Warshall's algorithm, and with bitset rows it becomes O(V³/64), which is genuinely fast to V ≈ 5000.
  • Minimax path (minimise the largest edge on the route): replace the sum with max — d[i][j] = min(d[i][j], max(d[i][k], d[k][j])). Solves "minimum capacity needed" problems for all pairs at once.
  • Negative cycle detection: after the run, if any matrix[i][i] < 0, node i lies on a negative cycle. One extra loop over the diagonal.

Also: to reconstruct paths, keep a next[i][j] matrix set to k whenever the route improves, then walk it. O(V²) extra space.

Johnson's algorithm — how to make negative weights Dijkstra-safe

For all-pairs shortest paths on a sparse graph with negative weights, V³ is wasteful. Johnson's algorithm reweights the graph so that Dijkstra becomes valid, then runs it from every source:

  1. Add a virtual source s with a 0-weight edge to every node.
  2. Run Bellman-Ford from s to get a potential h(v) for each node. (This also detects any negative cycle.)
  3. Reweight every edge: w'(u,v) = w(u,v) + h(u) − h(v). This is provably non-negative, because Bellman-Ford's output satisfies h(v) ≤ h(u) + w(u,v) — that is just the relaxation having converged.
  4. Run Dijkstra from each node on the reweighted graph, then undo the shift: d(u,v) = d'(u,v) − h(u) + h(v).

Why the reweighting preserves shortest paths and the naive "add a constant" does not: along any path the h terms telescope — all the intermediate ones cancel and only h(start) − h(end) survives. So every path between the same pair shifts by the same amount, regardless of how many edges it has, and the ordering of paths is untouched. Adding a constant c to each edge instead shifts a k-edge path by k·c, which penalises long paths and can change the winner. That telescoping is the whole insight.

⚠️
Common mistakes
  • k not the outermost loop in Floyd-Warshall. Silently wrong, often correct on small tests.
  • No overflow guard. INT_MAX + w in Bellman-Ford, or INT_MAX + INT_MAX in Floyd, wraps negative and corrupts everything downstream.
  • Running only V−2 rounds, or running V rounds and treating the last one's improvements as legitimate. It is V−1 rounds, then one detection pass.
  • Claiming Bellman-Ford finds all negative cycles. It finds those reachable from the source. Add a virtual source connected to everything to find any.
  • Using Dijkstra with negative weights (Chapter 29). Wrong, not slow.
  • Using Floyd-Warshall at V = 10⁴. 10¹² operations, and the matrix alone is 400 MB.
  • Forgetting matrix[i][i] = 0 when initialising Floyd. A node's distance to itself is 0, not "no edge".
  • Not handling multi-edges when building the matrix. Keep the minimum weight for a repeated pair, not the last one written.
  • Using Bellman-Ford when the graph is a DAG. A topological-order DP is O(V + E) and handles negative weights too (Chapter 26).

Interview drill

Warm-up: Why exactly V−1 rounds in Bellman-Ford, and what does a Vth improvement tell you?

How a strong answer sounds
Because in a graph with no negative cycle, a shortest path is simple — repeating a vertex could only leave the length the same or increase it — and a simple path over V vertices has at most V−1 edges. The invariant is that after round i, every node whose shortest path uses at most i edges has its final distance: round 1 finalises all one-edge paths since only the source's correct distance is needed, round 2 finalises two-edge paths because their prefixes were settled in round 1, and so on. Crucially each round relaxes every edge, so the relaxation order within a round does not matter — which is exactly what lets this work with negative weights where Dijkstra's greedy cannot. After V−1 rounds every simple path length is covered. If a Vth pass can still improve something, the improving path needs V or more edges, so by pigeonhole it repeats a vertex and contains a cycle — and since it is shorter than the best simple path, that cycle has negative total weight. So one extra pass is an exact negative-cycle test. Two caveats: it only finds cycles reachable from the source, so to detect any negative cycle I would add a virtual source with 0-weight edges to every node; and I must guard the relaxation with dist[u] != INT_MAX, or an unreachable node overflows and poisons the whole array.

Deeper: Why must k be the outermost loop in Floyd-Warshall?

How a strong answer sounds
The underlying DP has three dimensions: dp[k][i][j] is the shortest i-to-j distance using only vertices 0 through k−1 as intermediates, and the transition is min of "don't use k" and "dp[k][i][k] + dp[k][k][j]". Layer k+1 reads layer k, and the reason we can collapse the k dimension and update the matrix in place is a specific fact: dp[k][i][k] and dp[k][k][j] cannot be changed by the layer-k update, because routing from i to k through k is pointless. So those two entries are already final when layer k begins, and it does not matter whether we read a pre- or post-update value for them. That is what makes the in-place 2D version correct — and it only holds if all pairs are processed for a fixed k before moving to the next pivot, which means k must be outermost. Move k inside and for a fixed (i,j) you sweep every pivot before touching other pairs, so later pairs read entries computed under an inconsistent set of allowed intermediates; effectively you only find paths whose intermediate vertices happen to appear in a compatible order, and you miss valid routes. The nasty part is that the result is usually almost right — small graphs and short paths often come out correct — so it passes casual testing and fails on longer paths. I would also mention the overflow guard: skip the pair when either matrix[i][k] or matrix[k][j] is the infinity sentinel, otherwise INT_MAX + INT_MAX wraps negative and corrupts the matrix.

🧠 Key takeaways

  • Bellman-Ford relaxes every edge V−1 times because a shortest simple path has at most V−1 edges; order within a round is irrelevant.
  • One extra pass detects a reachable negative cycle exactly; a virtual source finds cycles anywhere.
  • Guard every relaxation against the infinity sentinel, or overflow silently corrupts the distances.
  • In Floyd-Warshall the pivot k must be outermost, because that is what makes the in-place 2D collapse valid.
  • Johnson reweights with w + h(u) − h(v), which telescopes along any path — which is why it preserves shortest paths and "add a constant" does not.

Check your understanding

Why does Bellman-Ford run exactly V−1 rounds?

Without a negative cycle, shortest paths are simple, so they use at most V−1 edges. Since each round relaxes every edge, the correct prefix is always available regardless of order — which is why this works where Dijkstra's greedy fails.

A Vth relaxation pass still improves some distance. What does that mean?

An exact test, by pigeonhole. Note it only finds cycles reachable from the source; add a virtual source with 0-weight edges to every node to detect one anywhere.

In Floyd-Warshall, why must the k loop be outermost?

With k inside, a fixed pair sweeps all pivots before other pairs are touched, so later reads use an inconsistent set of allowed intermediates and valid routes are missed. The result is almost right, which makes it a miserable bug.

You omit the dist[u] != INT_MAX guard in Bellman-Ford. What happens?

Signed overflow wraps, and the resulting nonsense distance then relaxes further edges. Guard the source of each relaxation, or use long long with a sentinel like 1e18 that survives being added to.

Why does Johnson's reweighting w'(u,v) = w(u,v) + h(u) − h(v) preserve shortest paths, while adding a constant to every edge does not?

Telescoping is the whole insight. The intermediate potentials cancel, so path ordering is untouched — while a flat constant penalises paths with more edges and can change which one is shortest.
