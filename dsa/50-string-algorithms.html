String Algorithms

Naive substring search is O(n·m) because on every mismatch it throws away everything it just learned. The algorithms in this chapter all fix that same waste in different ways: KMP precomputes how far to fall back, Z-function precomputes how far each position matches, Rabin-Karp compares fingerprints instead of characters, and Manacher reuses palindrome symmetry. Four answers to one question.

  • Build the KMP prefix function and understand what it actually stores
  • Use the Z-function, and see it is the same information in another form
  • Hash a rolling window, and know why two moduli matter
  • Find all palindromic substrings in O(n) with Manacher
  • Know what suffix arrays and LCP arrays are for

The cost of naive search

why O(n·m) happens, and where the waste isO(n·m)wasteful
// Try the pattern at every start position.
// Worst case: text "aaaa...a", pattern "aaa...ab" — every start matches m-1
// characters and then fails on the last one. n*m character comparisons.
int naiveSearch(string &text,string &pattern){
	int n=text.size();
	int m=pattern.size();

	for(int i=0;i+m<=n;i++){
		int j=0;

		while(j<m and text[i+j]==pattern[j])
		j++;

		if(j==m)return i;
		// THE WASTE: we learned that text[i..i+j-1] equals pattern[0..j-1],
		// then discarded it and restarted from i+1 with j=0.
	}

	return -1;
}
Name the waste before learning the fix. After matching j characters and failing, we know a great deal about the text we just read — it equals the pattern's first j characters. KMP's insight is that this information is a property of the pattern alone, so it can be precomputed once: if the pattern's first j characters have a border (a proper prefix that is also a suffix) of length k, then we may resume at j = k without moving i back at all.

KMP — prefix function and searchO(n+m)O(m)
// lps[i] = the length of the longest PROPER prefix of pattern[0..i] that is
//          also a suffix of pattern[0..i]. ("Longest prefix suffix.")
// Proper means it cannot be the whole thing, so lps[0] is always 0.
//
// Why it helps: having matched j characters and then failed, the last lps[j-1]
// of them are also a prefix of the pattern — so those are already matched and
// we resume at j = lps[j-1] WITHOUT rewinding the text.
vector<int> buildLPS(string &pattern){
	int m=pattern.size();
	vector<int> lps(m,0);
	int len=0;                      // length of the current border

	for(int i=1;i<m;i++){
		while(len>0 and pattern[i]!=pattern[len])
		len=lps[len-1];            // fall back to a shorter border

		if(pattern[i]==pattern[len])len++;

		lps[i]=len;
	}

	return lps;
}

// Find every occurrence. The text index i NEVER decreases — that is the
// whole guarantee, and it is why the search is linear.
vector<int> kmpSearch(string &text,string &pattern){
	vector<int> ans;

	if(pattern.empty())return ans;

	vector<int> lps=buildLPS(pattern);
	int n=text.size();
	int m=pattern.size();
	int j=0;

	for(int i=0;i<n;i++){
		while(j>0 and text[i]!=pattern[j])
		j=lps[j-1];

		if(text[i]==pattern[j])j++;

		if(j==m){
			ans.push_back(i-m+1);
			j=lps[j-1];              // continue, allowing overlaps
		}
	}

	return ans;
}
The two loops are the same loop. Building lps is KMP matching the pattern against itself, which is worth noticing because it means you only really have to remember one piece of code. The while is amortised O(1): len increases by at most 1 per step and each fallback strictly decreases it, so the total number of fallbacks across the whole run is bounded by the total number of increases. After a full match, j = lps[j-1] rather than 0 — that is what finds overlapping occurrences, as searching for "aa" in "aaa" should return both 0 and 1.
✍️
My convention: lps and len, and a hand-built table before any code

I name the array lps and the running border len, because "the length of the longest prefix that is also a suffix" is a mouthful and the short names keep the two-line loop readable. And before writing a single line I build the table by hand for "aabaaab" — the answer is 0 1 0 1 2 2 3. Two minutes on paper settles the two things people get wrong: that the prefix must be proper (so lps[0]=0 always), and that the fallback chain is lps[len-1] rather than len-1. The same discipline as drawing the 3×3 corner of a string-DP table in Chapter 41: derive the invariant on paper, then transcribe.

🧠
What the prefix function is good for besides searching
  • Shortest string period. For a string of length n, if n % (n − lps[n−1]) == 0 then n − lps[n−1] is the shortest period; that is how you answer "is this a repeated substring pattern?" in O(n).
  • Longest palindromic prefix. Run the prefix function on s + '#' + reverse(s); the final value is the answer. The separator matters — without it the border can straddle the join and overrun.
  • Shortest palindrome by prepending characters — the same trick, then prepend the unmatched tail reversed.
  • Count occurrences of every prefix in the string, by walking the fallback chain and accumulating.
  • Repeated substring pattern, rotation check (search b in a+a), and shortest string containing two overlapping pieces.

The separator # idiom is worth remembering on its own — it appears in half the problems that combine two strings, and it must be a character that occurs in neither.

The Z-function

Z-function — the same information, differently arrangedO(n)O(n)
// z[i] = the length of the longest substring starting at i that is also a
//        prefix of the whole string. z[0] is left as 0 by convention.
// Example: "aabxaab" -> z = 0 1 0 0 3 1 0
//
// The trick is the "Z-box" [l,r]: the rightmost interval we know matches a
// prefix. Inside it, z values can be COPIED from the corresponding earlier
// position instead of re-compared — that is what makes this linear.
vector<int> zFunction(string &s){
	int n=s.size();
	vector<int> z(n,0);
	int l=0;
	int r=0;

	for(int i=1;i<n;i++){
		if(i<r)z[i]=min(r-i,z[i-l]);   // copy what symmetry gives us

		while(i+z[i]<n and s[z[i]]==s[i+z[i]])
		z[i]++;                        // extend past the box by comparing

		if(i+z[i]>r){
			l=i;
			r=i+z[i];                  // a new, further-right box
		}
	}

	return z;
}

// Search with it: run the Z-function on pattern + '#' + text.
// Any position where z equals the pattern length is an occurrence.
vector<int> zSearch(string &text,string &pattern){
	int m=pattern.size();
	string combined=pattern+'#'+text;
	vector<int> z=zFunction(combined);
	vector<int> ans;

	for(int i=m+1;i<combined.size();i++){
		if(z[i]==m)ans.push_back(i-m-1);
	}

	return ans;
}
Z-function versus KMP: pick whichever you remember correctly. They solve the same problems in the same time, and Z is often easier to reason about because z[i] has a direct meaning ("how far does position i agree with the start") rather than KMP's more indirect border length. The min(r-i, z[i-l]) is the only subtle line: you may copy the earlier value, but never claim more than the box guarantees, because beyond r nothing has been verified. The separator must not occur in either string — with an arbitrary alphabet, use a sentinel value outside it rather than a printable character.

Rabin-Karp: compare fingerprints

rolling hashO(n+m) expectedO(1)
// Treat a window as a number in base B modulo M. Sliding the window by one
// costs O(1): drop the leading character's contribution, shift, add the new one.
const long long B=131;
const long long M=1000000007;

vector<int> rabinKarp(string &text,string &pattern){
	int n=text.size();
	int m=pattern.size();
	vector<int> ans;

	if(m>n or m==0)return ans;

	long long power=1;

	for(int i=1;i<m;i++)
	power=(power*B)%M;               // B^(m-1), the leading weight

	long long patHash=0;
	long long winHash=0;

	for(int i=0;i<m;i++){
		patHash=(patHash*B+pattern[i])%M;
		winHash=(winHash*B+text[i])%M;
	}

	for(int i=0;i+m<=n;i++){
		// A hash match is only a CANDIDATE — verify the characters.
		if(winHash==patHash and text.compare(i,m,pattern)==0)
		ans.push_back(i);

		if(i+m<n){
			winHash=(winHash-text[i]*power%M+M*M)%M;   // drop the leader
			winHash=(winHash*B+text[i+m])%M;           // shift and add
		}
	}

	return ans;
}
Two non-negotiables. (1) Verify on a hash match unless a collision is genuinely acceptable — equal hashes do not mean equal strings, and problem setters write anti-hash tests. (2) Watch the subtraction: winHash - text[i]*power%M can go negative, and C++ % preserves the sign, so add a multiple of M before the final modulus (Chapter 48). Rabin-Karp earns its place where KMP cannot go: comparing many substrings against each other (duplicate detection, longest repeated substring by binary searching the length), and 2D pattern search. For adversarial inputs use a random base or two different moduli, which makes a collision astronomically unlikely.

Manacher: all palindromes in O(n)

longest palindromic substring in linear timeO(n)O(n)
// Transform "abc" into "^#a#b#c#$" so every palindrome becomes odd-length.
// The sentinels ^ and $ remove all the bounds checks.
// p[i] = the radius of the palindrome centred at i in the transformed string,
//        which is exactly the LENGTH of the palindrome in the original.
string longestPalindrome(string &s){
	if(s.size()<2)return s;

	string t="^";

	for(auto &c:s){
		t+='#';
		t+=c;
	}

	t+="#$";

	int n=t.size();
	vector<int> p(n,0);
	int centre=0;
	int right=0;

	for(int i=1;i<n-1;i++){
		int mirror=2*centre-i;          // i reflected about `centre`

		if(i<right)p[i]=min(right-i,p[mirror]);   // reuse symmetry

		while(t[i+p[i]+1]==t[i-p[i]-1])
		p[i]++;                        // expand (sentinels stop us safely)

		if(i+p[i]>right){
			centre=i;
			right=i+p[i];
		}
	}

	int best=0;
	int bestCentre=0;

	for(int i=1;i<n-1;i++){
		if(p[i]>best){
			best=p[i];
			bestCentre=i;
		}
	}

	int start=(bestCentre-best)/2;

	return s.substr(start,best);
}
Structurally identical to the Z-function — the same min(boundary, mirrored value) reuse, with reflection about a palindrome centre instead of a prefix box. The # interleaving is what unifies odd and even palindromes, which is the messy part of expand-around-centre; and the ^/$ sentinels mean the while loop needs no bounds test, because they match nothing. Be honest about when to use it: expand-around-centre is O(n²) but four lines and O(1) space, and at n ≤ 10⁴ it is the better answer. Manacher is for n ≥ 10⁵, or when you need every p[i] — counting all palindromic substrings is then one sum.
🗂️
Suffix arrays and LCP — what they buy

The suffix array is the sorted order of all n suffixes, stored as starting indices. Built in O(n log n) by repeated doubling (sort by the first 2ᵏ characters, using the previous ranks as keys), or O(n) by more elaborate methods. The LCP array holds the longest common prefix of each adjacent pair in that order, built in O(n) by Kasai's algorithm. Together they answer:

  • Longest repeated substring = the maximum LCP value.
  • Number of distinct substrings = n(n+1)/2 − sum of LCP.
  • Longest common substring of two strings — concatenate with a separator, then take the maximum LCP between adjacent suffixes originating in different strings.
  • Pattern search in O(m log n) by binary searching the sorted suffixes.
  • k-th lexicographic substring, and counting substrings below a bound.

In an interview, recognising the tool is nearly always enough. Saying "this is longest-repeated-substring, so a suffix array with an LCP array solves it in O(n log n), or a binary search on the length with rolling hashes gets O(n log n) expected with far less code" is a complete answer — and the hashing route is the one you can actually finish in the time available. A suffix automaton or suffix tree is the heavier relative; know the names.

Tips & tricks

The things that are muscle memory rather than theory — what to check first, and the line that is wrong the first time you write it.

💡 lps BY HAND
Build the table for "aabaaab" on paper — it is 0 1 0 1 2 2 3. That settles both traps: the prefix must be proper, and the fallback is lps[len-1], not len-1.
💡 SEPARATOR TRICK
Combining two strings as a + '#' + b and running the prefix or Z function answers a surprising number of problems. The separator must appear in neither string.
⛔ VERIFY HASHES
Equal hashes do not mean equal strings, and setters write anti-hash tests. Verify the characters on a match, or use two independent moduli.
⚠️
Common mistakes
  • Falling back to len-1 instead of lps[len-1]. The chain of borders is the point; stepping down by one is not.
  • Setting j = 0 after a full KMP match, which misses overlapping occurrences.
  • Forgetting that lps uses proper prefixes, so lps[0] must be 0.
  • Omitting the separator in pattern + '#' + text, letting a match straddle the join.
  • Using a separator that occurs in the input. Pick a sentinel outside the alphabet.
  • Trusting a hash match without verifying, on a problem with anti-hash tests.
  • A negative rolling hash after the subtraction — add a multiple of M first.
  • A hash base smaller than the alphabet, or a modulus small enough to collide constantly. Use ~10⁹ and, when adversarial, two moduli.
  • Claiming more than the box guarantees in Z or Manacher — it is min(r-i, z[mirror]), not z[mirror].
  • Forgetting Manacher's sentinels and then indexing out of bounds in the expand loop.
  • Reaching for a suffix array when binary search plus hashing solves it in a third of the code.

Interview drill

Warm-up: Implement strStr — find the first occurrence of a pattern in a text — in O(n+m). Explain the prefix function.

How a strong answer sounds
The naive scan is O(n·m), and the reason is identifiable: after matching j characters and then failing, it discards the knowledge that the last j characters of the text equal the pattern's first j, and restarts one position later. KMP keeps that knowledge, and the key realisation is that what to do on a mismatch depends only on the pattern, so it can be precomputed. I build lps, where lps[i] is the length of the longest proper prefix of pattern[0..i] that is also a suffix of it — proper meaning it cannot be the whole thing, so lps[0] is always 0. Then, during the search, if I have matched j characters and the next one fails, the last lps[j−1] characters I matched are also a prefix of the pattern, so those are already in hand and I resume at j = lps[j−1] without moving the text index back at all. That monotonicity of i is the whole linearity argument. The inner while loop looks like it could be expensive, but it is amortised O(1): j increases by at most one per text character and every fallback strictly decreases it, so the total fallbacks are bounded by the total increases. Building lps is the same loop matching the pattern against itself, which is a nice economy — one piece of code, used twice. Two details I would be explicit about: after a complete match I set j = lps[j−1] rather than 0, so overlapping occurrences are found — searching "aa" in "aaa" should give both 0 and 1; and the fallback is lps[len−1], not len−1, which is the most common implementation bug. I would also sketch the table for "aabaaab" by hand first — 0 1 0 1 2 2 3 — because two minutes on paper settles both of those.

Deeper: Longest repeated substring in a string of length 10⁵.

How a strong answer sounds
Two good answers, and I would offer both. The textbook one is a suffix array plus LCP array: sort all n suffixes in O(n log n) by repeated doubling, then build the LCP array of adjacent pairs in O(n) with Kasai's algorithm, and the answer is simply the maximum LCP value — because any repeated substring is a common prefix of two suffixes, and the pair maximising that is adjacent in sorted order. That is O(n log n) and it also hands me the number of distinct substrings, which is n(n+1)/2 minus the sum of the LCP array. The answer I would actually write under time pressure is binary search on the length plus rolling hashing. The property is monotone — if some substring of length L repeats, so does one of length L−1, since any prefix of it also repeats — so I can binary search L over [0, n]. For a fixed L, I compute the rolling hash of every window of that length and put them in a hash set, which detects a duplicate in O(n) expected; with precomputed prefix hashes each window hash is O(1). Total O(n log n) expected. I would insist on verifying a hash collision by comparing the actual characters, or using two independent moduli, because problem setters do write anti-hash tests, and a single 32-bit-ish modulus over 10⁵ windows is well inside birthday-collision range. The reason I prefer this route is honest: it is a third of the code, I can get it right in the time available, and it has the same complexity. I would name the suffix array so it is clear I know the canonical tool, then implement the one I can finish.

🧠 Key takeaways

  • Naive search wastes what it just learned; every algorithm here reuses it differently.
  • lps[i] is the longest proper prefix that is also a suffix; on a mismatch, fall back to lps[j-1] and never rewind the text.
  • Z-function stores the same information more directly; both are O(n+m) and either will do.
  • Rolling hashes make substring comparison O(1) — verify matches, and mind the negative modulus.
  • Manacher is the Z-function idea applied to palindrome centres; expand-around-centre is better when n is small.
  • Suffix array plus LCP is the canonical tool for repeated-substring questions, but binary search plus hashing usually gets there with less code.

Check your understanding

What does lps[i] store in KMP?

"Proper" is why lps[0] is always 0. On a mismatch after j matches, those last lps[j-1] characters are already a prefix, so you resume there.

Why is KMP's search O(n) despite the inner while loop?

Total decreases cannot exceed total increases. That monotone i is the guarantee the naive version lacks.

In Rabin-Karp, two windows have equal hashes. What must you do?

Hashing is a filter, not a proof. Problem setters write anti-hash tests, so verify or use two independent moduli.

In the Z-function, why is it z[i] = min(r-i, z[i-l]) rather than just z[i-l]?

Symmetry is valid only inside the box. Manacher has structurally the same line, reflecting about a palindrome centre instead.

Longest palindromic substring, with n = 5,000. Which approach is most sensible?

Manacher earns its complexity at n ≥ 10⁵, or when every radius is needed. Naming it while implementing the simpler approach is the strongest answer.
