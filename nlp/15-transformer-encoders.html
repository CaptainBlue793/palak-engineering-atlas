Transformer Encoders for NLP

A transformer encoder reads a whole sentence at once: every token attends to every other token, in both directions, several times over, and comes out as a vector that knows its context. There is no recurrence, so all positions are computed in parallel. Stacked and pretrained, this is BERT; even small and untrained, it is a strong text classifier.

This chapter writes a small encoder in PyTorch, trains it from scratch on SST-2, and measures the design choices that encoder-based systems make. From random initialisation, the best variant reached 78.82% on SST-2, below every model trained from scratch in Chapters 8 and 9 (a TF-IDF classifier got 82.11, a GloVe-initialised LSTM 84.57). The architecture choices mattered less than the seed: pooling, padding mask and causal attention all landed within about a point.

  • Distinguish encoder and decoder stacks by their attention masks
  • Write multi-head self-attention, a feed-forward block and residual layer norms
  • Apply padding masks correctly
  • Pool token vectors for classification: [CLS], mean or last token
  • Train a small encoder and read its attention

Encoder vs decoder stacks

Both are stacks of the same block: multi-head self-attention, then a two-layer feed-forward network, each wrapped in a residual connection and layer normalisation. The difference is one mask. In a decoder (GPT), token t may attend only to tokens 1 … t, the causal mask, so the model can be trained to predict each next token and can generate text. In an encoder (BERT), every token attends to every other token, before and after, so each output vector reflects the whole sentence; it cannot generate left to right, but for classification, tagging and extraction, seeing both sides is exactly what you want. Build the two masks in the lab.

Bidirectional self-attention

Each token’s vector x is projected three ways: a query q = WQx, a key k = WKx and a value v = WVx. Token i’s new vector is a weighted average of all values, with weights softmaxj(qi · kj / √d). Multi-head attention runs h such attentions in parallel on d/h-dimensional slices, so different heads can track different relations (the next word, the verb’s subject, the matching quote mark), and concatenates the results. Positions are added as learned position embeddings, because attention itself has no notion of order.

class Block(nn.Module):
    def __init__(s, d, h, ff, p=0.1):
        super().__init__(); s.a = nn.MultiheadAttention(d, h, dropout=p, batch_first=True)
        s.n1, s.n2 = nn.LayerNorm(d), nn.LayerNorm(d); s.f = nn.Sequential(nn.Linear(d, ff), nn.GELU(), nn.Linear(ff, d))
    def forward(s, x, pad, causal=None):
        a, _ = s.a(x, x, x, key_padding_mask=pad, attn_mask=causal)        # pad: True where x is padding
        x = s.n1(x + a)                                                    # residual + layer norm
        return s.n2(x + s.f(x))

Padding masks

A batch pads short sentences to the longest (P2). Without a key padding mask, real tokens attend to pads and their vectors change with the amount of padding, so the same sentence is represented differently in different batches. PyTorch’s key_padding_mask takes True for positions to ignore; Hugging Face’s attention_mask takes 1 for positions to keep. Getting that polarity wrong silently masks the real tokens instead of the pads.

Pooling for classification

A classifier needs one vector per sentence. BERT prepends a special [CLS] token and classifies from its final vector: because it attends to every token in every layer, it can learn to summarise the sentence. The alternatives are the mean over all real tokens, which needs the padding mask again, and, for a causal model, the last token, the only position that has seen everything.

Mean pooling was the best variant at 78.82, 0.8 above [CLS], but [CLS]’s own three seeds ranged from 76.83 to 79.01, so the two are not reliably different. Removing the padding mask cost 0.3 points, also inside the noise: SST-2 sentences are short and batches are padded only to their longest sentence, so a real token sees only a few pads. That does not make the mask optional. Without it the same sentence gets a different vector in a different batch, which shows up as inconsistency rather than as a lower average (P2 measured a review’s positive probability falling from 70% to 51% as padding grew). The causal model with last-token pooling, a small GPT used as a classifier, scored 77.75, level with the bidirectional encoder: for one-sentence sentiment, seeing the right-hand context did not help a model this small trained this briefly. Depth did: one layer reached 75.88, two 78.29, four 78.06.

A small encoder trained here

The honest result is that this transformer is the weakest SST-2 model in the course so far. With 4 layers it has about 11 million parameters, most of them in the 30,522 × 256 embedding table, and it learns everything, including what words mean, from 67,349 short phrases in three epochs. The TF-IDF baseline gets 82.11, a small CNN 82.22 and an LSTM starting from GloVe vectors 84.57; this encoder, at best 78.82. Transformers have weak built-in assumptions about language: no notion that nearby words matter more, no pre-trained word meanings. That makes them flexible and data-hungry. Chapter 16 trains the same 4-layer encoder on 62 million word pieces of Wikipedia text first, and Chapter 17 fine-tunes models pre-trained on billions; that is where the architecture earns its place.

Use case: a fast on-premise ticket classifier

A bank cannot send customer messages to an external API and wants a classifier that runs on CPUs in its own data centre. A 4-layer, 256-wide encoder trained from scratch on 200,000 labelled messages is 11 million parameters, classifies hundreds of messages a second on a CPU, and is only level with the TF-IDF baseline, because a transformer trained from scratch has no head start on a few hundred thousand examples. The team also learns the chapter’s other lesson the expensive way: their first version used mean pooling without the padding mask and gave different labels to the same message depending on what else was in the batch. With the mask fixed, they then try a pretrained encoder (Chapter 17), which is better again, and keep the small one where latency matters most.

⚠️
Common mistakes
  • Training a transformer from scratch on a small labelled set: here it reached 78.82 on SST-2, below TF-IDF (82.11); pre-train or start from a pre-trained model.
  • Mixing mask polarities: PyTorch’s key_padding_mask is True to ignore; Hugging Face’s attention_mask is 1 to keep.
  • Concluding the padding mask does not matter from one average: removing it cost only 0.3 points here, but it makes predictions depend on batch composition.
  • Forgetting position information: without position embeddings, self-attention treats the sentence as a bag of words.
  • Training a transformer without warm-up: post-layer-norm stacks are unstable for the first few hundred steps at full learning rate.
  • Reading one head’s attention as the model’s reasoning: heads are many and redundant (Chapter 33).

Interview drill

Explain it simply: What is the difference between a transformer encoder and a decoder?

How a strong answer sounds
Both are stacks of identical blocks, self-attention plus a feed-forward network with residuals and layer norm. The difference is the attention mask. A decoder uses a causal mask, so position t sees only positions up to t; that lets it be trained to predict the next token and to generate text left to right. An encoder has no causal mask, so every token sees the whole input, which suits understanding tasks: classification, tagging, extraction, retrieval. In a small experiment here, the same 4-layer stack trained on SST-2 scored 78.06 as an encoder and 77.75 with a causal mask and last-token pooling, so for a short-sentence classifier the mask mattered little; it matters for what the model can be trained to do, generation versus bidirectional representations.

Deeper: How should you pool a transformer’s outputs for sentence classification?

How a strong answer sounds
Three standard options. The [CLS] token’s final vector, which BERT is trained to use; the mean over real tokens, which needs the padding mask so pads are excluded; or, for a causal model, the last real token, the only one that has seen the whole input. Max pooling is a fourth. I would try [CLS] and mean on a validation set over several seeds: here mean scored 78.82 and [CLS] 78.06, but [CLS]’s seeds alone spanned 2.2 points, so the difference was not real. For sentence embeddings, mean pooling is usually the better default (Chapter 20). Whatever the pooling, index the last token per row, not the last position, when the batch is padded.

🧠 Key takeaways

  • Encoders and decoders share the block; the causal mask makes a decoder, its absence an encoder.
  • Self-attention is a softmax-weighted average of value vectors, run in several heads, with positions added.
  • Measured: a 4-layer encoder trained from scratch reached 78.82 on SST-2, below TF-IDF (82.11) and a GloVe LSTM (84.57): transformers need pre-training.
  • Measured: [CLS] vs mean pooling, padding mask on or off, and causal vs bidirectional all landed within about a point, about as far apart as different seeds of one variant (s.d. up to 0.91).
  • Measured: depth helped, from 75.88 with 1 layer to 78.29 with 2 and 78.06 with 4.
