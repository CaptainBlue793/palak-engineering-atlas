Linear Classifiers & Cross-Entropy

Every classifier in this course, including fine-tuned BERT, ends in the same place: a linear layer produces one score per class, softmax turns the scores into probabilities, and cross-entropy measures how much probability went to the right answer. A linear classifier on word features is just that last layer on its own, which makes it the best place to learn how the pieces work and the baseline every later model has to beat.

This prerequisite writes logistic regression in a dozen lines of PyTorch and trains it on 25,000 IMDB reviews to 90.6% accuracy, the same as scikit-learn’s. It then measures what regularisation does, reads off what the model learned, including a rating score it should not have relied on, and fits a four-class softmax to 120,000 news headlines.

  • Write logistic regression as a linear score, a sigmoid and a loss
  • Extend it to many classes with softmax
  • Explain cross-entropy and why it, not accuracy, is the training loss
  • Tune regularisation by measuring it
  • Read the weights to find what the model learned, and what it should not have

Logistic regression

Give every feature a weight. For a document with feature vector x, the score is z = w·x + b: add up the weights of the words present, scaled by their TF-IDF values. The sigmoid σ(z) = 1 / (1 + e−z) squashes the score into a probability between 0 and 1. A score of 0 means 50%, +3 means 95%, −3 means 5%. Positive weights push towards the positive class, negative ones away from it, and that is the whole model.

w = torch.zeros(n_features, 1, requires_grad=True); b = torch.zeros(1, requires_grad=True)
opt = torch.optim.Adam([w, b], lr=0.01)
for xb, yb in batches:                                # xb: sparse TF-IDF rows, yb: 0 or 1
    z = (xb @ w).squeeze(1) + b                        # one score per review
    loss = F.binary_cross_entropy_with_logits(z, yb)   # sigmoid and log-loss in one, numerically safe
    opt.zero_grad(); loss.backward(); opt.step()

Trained on 25,000 IMDB reviews with unigram and bigram TF-IDF features (100,000 of them), this reached 87.8% test accuracy after one pass and 90.6% after fifteen. scikit-learn’s LogisticRegression on the same features reached 90.5%. They are the same model; only the optimiser differs.

Softmax over classes

With K classes, keep one weight vector per class and compute K scores, zk = wk·x + bk. Softmax turns them into probabilities: pk = ezk / Σj ezj. Each is positive, they add to 1, and adding the same constant to every score changes nothing, so only differences between scores matter. Logistic regression is the two-class case with one class’s score fixed at zero. In code, softmax regression is nn.Linear(n_features, K) followed by F.cross_entropy, and so is the classification head of every transformer later in the course.

Cross-entropy loss

The loss for one example is −log py, minus the log of the probability given to the correct class. Give the right class 90% and the loss is 0.11; 50%, 0.69; 1%, 4.6. It never reaches zero and grows without limit as a confident prediction gets more wrong, which pushes the model to be right and appropriately sure. Accuracy cannot be the training loss: it changes only when a prediction crosses 50%, so its gradient is zero almost everywhere, and it cannot tell 51% from 99%. Averaged over a dataset, cross-entropy is the same quantity as the entropy of P4, measured with the model’s probabilities, and its exponential is the perplexity used to judge language models.

Regularisation

With 100,000 features and 25,000 examples, a linear model can fit the training set perfectly by giving huge weights to words that happen to appear in only one class. L2 regularisation adds a penalty on the squared size of the weights, so the model must trade fit against simplicity. In scikit-learn the knob is C, the inverse strength: small C, strong penalty. The textbook expectation is that strong regularisation matters most with little data. Measured:

The expectation was wrong here, for a reason worth knowing. TF-IDF rows have length 1, so individual feature values are small (mostly well below 0.5), and small features need large weights; a penalty that sounds moderate is actually strong. With 1,000 reviews, every step towards weaker regularisation helped, and at C = 0.01 the model predicted one class for everything. With 25,000, C = 10 was best, and the default C = 1 was 0.6 points worse. Beyond the best value, accuracy barely moved (90.5 → 90.2) while log-loss rose by half (0.24 → 0.37): the overfit model is still mostly right, but it is too sure when it is wrong, which accuracy cannot see. The lesson is not “use a large C”; it is that the right strength depends on feature scaling and data size, so you sweep it on validation data, and watch log-loss as well as accuracy.

The from-scratch model showed the other side. Its training loss fell to 0.044 while test loss was 0.238, a large gap, yet test loss was still falling at epoch 15, and adding a small weight-decay penalty (10−5 times the sum of squared weights) made both test loss and accuracy slightly worse. A large train–test gap alone is not overfitting; a rising validation loss is.

Reading the weights

A linear model can be read directly: each feature’s weight says how much it pushes towards each class. On IMDB the largest positive weights went to great, excellent, perfect, wonderful and amazing, and the most negative to worst, awful, bad, boring and the worst. Bigrams handle simple negation: good has weight +3.3 and not good −4.7, while not bad is +2.9. Three findings are less comfortable:

  • today has the sixth-largest positive weight (+7.7), above superb. Of the 1,053 training reviews containing it, 776 (74%) are positive, in phrases like “even by today’s standards”, “as relevant today” and “most of today’s films”: older films that people still praise. A real pattern in the data, but not sentiment, and it will misfire on reviews of new films.
  • 10 10, from reviewers writing “10/10”, has weight +4.4. The model is partly reading the score the reviewer gave, not the review. Meanwhile 7/10, 4/10 and 1/10 are not features at all, because scikit-learn’s default token pattern drops single characters, so 7 vanished before the model ever saw it.
  • Strong words still win. “Not bad, actually.” scored only 15.9% positive: not bad (+2.9) cannot outweigh bad (−12.8). The model adds evidence; it does not parse.

The same check on AG News is more alarming. A softmax model on 120,000 headlines reached 92.55% on the 7,600 test headlines in 14.7 seconds of training. Its top World features are afp, iraq, canadian press and athens greece; Sci/Tech’s include reuters reuters and ap; Business’s include hellip and york reuters; Sports’ includes 39. Those are news agencies, datelines and HTML-entity debris (&#39; is an apostrophe, &hellip; an ellipsis). Part of the 92.55% is the model recognising which wire service and which text pipeline a story came from. That would not survive a change of source.

Are the probabilities right?

A probability is useful only if it means what it says: of the reviews given 80%, about 80% should be right. Logistic regression is often said to be well calibrated. On IMDB it was underconfident: in the 70–80% confidence bin, 81.6% were correct; in the 80–90% bin, 91.3%. The error is in the safe direction, but it would still mislead a system that, say, sends anything under 85% confidence to a human: it would send many reviews it gets right. Chapter 30 covers calibration and how to fix it.

🧾
Use case: routing support email to four queues

A team routes incoming support email to billing, technical, account and sales queues with a TF-IDF softmax model. It scores 94% on held-out mail and goes live, where it does noticeably worse. Reading the weights explains why: the top technical features include the first names of two engineers whose signatures appear in quoted replies, and “sent from my iphone” pushes towards billing because one large customer’s finance team writes from phones. The team strips quoted text and signatures before training, re-measures (91%, but now real), sweeps C instead of keeping the default, and keeps the weight report as a check on every retrain.

⚠️
Common mistakes
  • Keeping the default regularisation: C = 1 was 0.6 points worse than C = 10 on IMDB, and 1.5 points worse than C = 1000 on 1,000 reviews.
  • Judging overfitting by accuracy alone: past the best C, accuracy moved by 0.3 points while log-loss rose by half.
  • Not reading the weights: “10/10”, “today”, news agencies and HTML entities were all among the strongest features.
  • Assuming the tokeniser keeps everything: the default pattern silently dropped single digits, so 7/10 was invisible.
  • Applying sigmoid or softmax before F.cross_entropy or BCEWithLogits: they expect raw scores.
  • Treating probabilities as calibrated without checking: this model was underconfident by up to 6 points.

Interview drill

Explain it simply: What is cross-entropy loss, and why do we train on it rather than on accuracy?

How a strong answer sounds
Cross-entropy is minus the log of the probability the model gave to the correct class: 0.11 if it gave 90%, 0.69 for 50%, 4.6 for 1%. It is smooth, so gradient descent can follow it, and it rewards being confident when right and punishes being confident when wrong. Accuracy only changes when a prediction crosses the decision threshold, so its gradient is zero almost everywhere, and it treats 51% and 99% the same. Cross-entropy also shows things accuracy hides: on IMDB, weakening regularisation past the best point left accuracy almost unchanged but raised test log-loss from 0.24 to 0.37, because the model became overconfident on its mistakes.

Deeper: The top features of your news classifier include agency names like “afp” and “reuters”. What does that mean, and what do you do?

How a strong answer sounds
The model has learned the source as a shortcut for the label: some agencies cover some topics more, and their boilerplate appears in the text. That inflates the test score, because the test set comes from the same sources, and it will fail when the mix of sources changes. I would strip datelines, agency tags and decoded HTML entities in preprocessing, re-train, and compare the score; the drop is how much of the accuracy was shortcut. Then evaluate on data from a different source to measure real generalisation, and keep a top-weights report as a regression check. The general rule: read what a model relies on before you trust its number.

🧠 Key takeaways

  • A linear classifier is scores z = Wx + b, softmax (sigmoid for two classes), and cross-entropy: the same head every later model uses.
  • Logistic regression written in PyTorch matched scikit-learn on IMDB: 90.6% against 90.5%.
  • Regularisation strength depends on feature scale and data size: sweep it, and watch log-loss as well as accuracy.
  • Reading the weights found shortcuts: “10/10” on IMDB, news agencies and HTML entities on AG News.
  • Check calibration: this model was underconfident, 91% correct where it claimed 85%.

Check your understanding

A logistic regression gives a review a score of z = 0. What probability does it assign to the positive class?

σ(0) = 1 / (1 + e⁰) = 0.5. Positive scores give more than 50%, negative less.

The model gives the correct class a probability of 1%. What is the cross-entropy loss for that example?

−ln(0.01) ≈ 4.6. Confident mistakes are punished heavily; the loss has no upper limit.

Past the best regularisation strength on IMDB, test accuracy barely changed but test log-loss rose from 0.24 to 0.37. What happened?

Accuracy only sees which side of 50% a prediction falls on; log-loss sees how sure it was.

Why did “7/10” never become a feature, while “10/10” did?

The tokeniser decides what the model can see. “10” has two characters and survived.

How many weight vectors does a softmax classifier with 4 classes have?

Each class has its own weights and bias; softmax normalises the four scores into probabilities.
