One code style, all the way through

Every listing in this course is PostgreSQL SQL (and, where application code matters, Python with psycopg) written the same way, so the shape of the code becomes a memory aid instead of noise. This is the style, stated once and never broken.

  • Keywords in capitals, names in snake_case, one clause per line. FROM, WHERE and ORDER BY each start a line, so a diff shows exactly which clause changed.
  • Every table has a primary key and its rules as constraints. NOT NULL, CHECK and foreign keys live in the schema, not only in the application.
  • Name the columns. No SELECT * in application code: a new column shouldn't change what the code receives or make an index-only scan impossible.
  • Parameters, never string formatting. Values reach the database as %s / %(name)s parameters. That one habit removes SQL injection.
  • Measure before and after. Every performance claim comes with EXPLAIN (ANALYZE, BUFFERS) output, not intuition.
CREATE TABLE orders (
    order_id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id bigint      NOT NULL REFERENCES customers,
    total_cents bigint      NOT NULL CHECK (total_cents >= 0),
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX orders_customer_created_idx
    ON orders (customer_id, created_at DESC);

SELECT order_id, total_cents, created_at
FROM   orders
WHERE  customer_id = %(customer_id)s      -- a parameter, never an f-string
ORDER BY created_at DESC
LIMIT  20;

The index matches the query: the equality column first, then the sort column. PostgreSQL walks 20 index entries in order and stops, however many orders the customer has.
