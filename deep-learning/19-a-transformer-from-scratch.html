A Transformer from Scratch

A transformer is not a new idea so much as an assembly of the last four chapters: multi-head attention (Chapter 18) to mix information between positions, an MLP (Chapter 5) to transform each position on its own, residual connections (Chapter 15) around both, layer normalisation (Chapter 14) before both, and a way of telling the network where each token is, because attention by itself has no notion of order. This chapter builds an encoder-decoder transformer from those parts, about 80 lines with no nn.Transformer, trains it on two algorithmic tasks, and removes the parts one at a time to see what each is worth.

The tasks are reversing and sorting a sequence of 16 random digits. The full model (two encoder and two decoder blocks, 929,292 parameters, 20 seconds of training) reversed 96.5% of digits correctly and sorted 99.96%. Take away positional information and reversal collapsed to 15.9% of digits and 0% of complete sequences, while sorting was unaffected (99.9%), because sorting does not depend on where a digit started. Take away the residual connections and both tasks failed (18% of digits). Take away layer norm and reversal failed while sorting mostly survived. And the trained model’s cross-attention for reversal is an exact anti-diagonal: output position i reads input position 15 − i, a solution nobody programmed.

  • Assemble a transformer block from attention, an MLP, residuals and norms
  • Add positional information with sinusoidal or learned encodings
  • Build an encoder-decoder with cross-attention and a causal decoder
  • Train it with teacher forcing and decode greedily
  • Measure what each component contributes

The transformer block

Every block has two sub-layers, each wrapped the same way: normalise the input, apply the sub-layer, add the result back to the input (pre-norm, Chapter 15). The first sub-layer is multi-head self-attention, where positions exchange information; the second is a position-wise MLP, usually 4× wider than the model, applied to each position independently. A decoder block adds a third sub-layer between them, cross-attention, whose queries come from the decoder and whose keys and values come from the encoder’s output.

class Block(nn.Module):
    def __init__(self, d, h, cross=False):
        super().__init__(); self.cross = cross
        self.n1, self.att = nn.LayerNorm(d), MHA(d, h)                       # Chapter 18's multi-head attention
        if cross: self.n2, self.catt = nn.LayerNorm(d), MHA(d, h)
        self.n3, self.ff = nn.LayerNorm(d), nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x, mem=None):                                       # x (B, n, d)
        x = x + self.att(self.n1(x), causal=self.cross)                      # self-attention (causal in the decoder)
        if self.cross: x = x + self.catt(self.n2(x), mem)                  # cross-attention to the encoder output
        return x + self.ff(self.n3(x))                                      # position-wise MLP
# parameters per encoder block at d = 128: attention 4·d² + 4d = 66,048; MLP 8·d² + 5d = 131,712; norms 512

Positional information

Attention compares every query with every key regardless of where they are; permute the input tokens and each output is permuted the same way, nothing more. For any task where order matters, the model must be told positions. The original transformer adds a fixed sinusoidal encoding to each token’s embedding, sines and cosines of different frequencies, so each position has a unique pattern and relative offsets correspond to rotations. The alternative is a learned position embedding, one trainable vector per position. Modern language models mostly use rotary encodings (RoPE), which rotate the queries and keys instead (LLMs Chapter 5).

p = torch.arange(L)[:, None]; i = torch.arange(0, d, 2)[None]
pe = torch.zeros(L, d)
pe[:, 0::2] = torch.sin(p / 10000 ** (i / d)); pe[:, 1::2] = torch.cos(p / 10000 ** (i / d))
x = self.emb(tokens) * math.sqrt(d) + pe[:n]                 # (B, n, d): content plus position

The ablation shows exactly when this matters. Reversing a sequence is all about position: output i must copy input 15 − i, and without positional information the model has no way to tell which input digit is which. It reached 15.9% of digits, little more than chance (10%), and not one complete sequence. Sorting is different: the output depends only on which digits are present, not where they were, so a model with no positional information on the encoder side sorted 99.05% of sequences perfectly. (The decoder still needs to know which output position it is producing; with no positions anywhere, it can count through the causal mask, which is enough here.)

Encoder and decoder

The encoder is a stack of blocks over the source sequence, bidirectional, with no mask. The decoder generates the target one token at a time. In training it is fed the correct previous tokens, shifted right behind a start token (teacher forcing), and a causal mask stops each position from seeing the ones after it, so all 16 positions are trained in one parallel pass. At test time it decodes greedily: start from the start token, predict the next token, append it, repeat 16 times. All accuracies here are from greedy decoding on 2,000 unseen sequences, so an early mistake can cascade.

Training on a toy task

Loss is cross-entropy over the 16 output positions, with teacher forcing; optimisation uses the recipe of the last few chapters: AdamW, a short warm-up, gradient clipping. The full model trained in 3,000 steps (20 seconds), and the cross-attention map shows what it learned for reversal: the first output position puts its weight on input position 15, the second on 14, and so on down the anti-diagonal, with a single blemish (two adjacent outputs both attending to position 7, which produced an error in that example). For sorting there is no such clean map; the model has to work out, for each output position, which value belongs there, which the encoder can do by comparing every digit with every other.

Three components were essential. Residual connections: without them neither task trained beyond chance, the degradation problem of Chapter 15 at only four blocks deep. Positions: essential for reversal, irrelevant for sorting, exactly as the task structure predicts. Layer norm: without it reversal failed and sorting lost 15 points of whole-sequence accuracy. The rest were matters of degree: more depth helped reversal (55% → 75% → 84% of sequences for 1, 2 and 4 blocks per side), learned positions beat sinusoidal ones for reversal and lost for sorting on one seed each, and four heads against one made little difference on tasks this simple. PyTorch’s own nn.Transformer with the same sizes and recipe scored slightly lower (70.1% of sequences); implementation details such as initialisation differ, and with one seed per run differences of a few points are within noise (P8).

Use case: a transformer for event sequences

A payments company models each card’s recent transactions as a sequence of tokens (merchant category, amount bucket, hour, country) to score fraud. A small transformer encoder, exactly the blocks on this page, attends across the last 64 events, and the score comes from a head on the final position. The team’s first version left out positional information to “let attention decide”, and it could not tell a burst of foreign transactions in the last minute from the same events spread over a month. Adding learned position embeddings, plus an embedding of the time gap between events, fixed it: in event data, as in reversal, order is information.

⚠️
Common mistakes
  • Forgetting positional information: order-dependent tasks fail (reversal: 0% of sequences).
  • Removing residuals or norms to “simplify”: both tasks failed without residuals.
  • No causal mask in the decoder: teacher-forced training sees the answer and learns to copy it; greedy decoding then fails.
  • Not shifting the decoder input right behind a start token: same leak.
  • Judging by digit accuracy alone: 96.5% of digits was 75.3% of complete sequences.

Interview drill

Explain it simply: Walk through one transformer block.

How a strong answer sounds
A block takes a sequence of vectors of width d and returns another of the same shape. First, layer-normalise and apply multi-head self-attention, so each position gathers information from the others, and add the result back to the input. Second, layer-normalise and apply a position-wise MLP, usually 4d wide with GELU, to each position independently, and add that back too. In a decoder there is a causal mask on the self-attention and a cross-attention sub-layer between the two that reads the encoder’s output. Positional encodings are added at the input because attention alone ignores order. At d = 128 an encoder block has about 198,000 parameters, two thirds of them in the MLP. In my ablations, removing the residuals made the model fail completely and removing positions broke reversal but not sorting.

Deeper: Why does a transformer need positional encodings, and when does it not?

How a strong answer sounds
Self-attention is permutation-equivariant: it scores every query against every key with no reference to where they are, so shuffling the inputs just shuffles the outputs. Any task whose answer depends on order, like language, time series or reversing a list, needs position information injected, through sinusoidal or learned embeddings added to the inputs, or rotary encodings applied to queries and keys. A task whose answer depends only on the set of inputs does not; I trained the same model to sort 16 digits without positional encodings and it got 99% of sequences right, while reversal without them got 0%. In practice the decoder can also recover some position information through the causal mask.

🧠 Key takeaways

  • A block is pre-norm attention plus a pre-norm MLP, each with a residual; decoders add cross-attention and a causal mask.
  • Attention ignores order, so positions are added: essential for reversal (0% without), unnecessary for sorting (99% without).
  • Residual connections were essential: without them neither task trained.
  • Train with teacher forcing and a causal mask; evaluate with greedy decoding and whole-sequence accuracy.
  • The trained cross-attention for reversal was an anti-diagonal: the model found the algorithm itself.
