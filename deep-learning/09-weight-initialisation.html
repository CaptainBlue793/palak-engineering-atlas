Weight Initialisation

Before the first step of training, every weight needs a value, and in a deep network that choice can decide everything. Each layer multiplies its input by a weight matrix; if those matrices make the signal a little larger on average, fifty layers make it astronomically larger, and if they make it a little smaller, fifty layers make it vanish. The gradient travels back through the same matrices and suffers the same fate. Good initialisation chooses the scale of the random weights so that the size of the signal, forward and backward, stays the same from layer to layer.

This chapter derives that scale and measures what happens without it. Through 50 ReLU layers, Kaiming initialisation kept the activations’ standard deviation between 0.86 and 2.2; Xavier, designed for tanh, shrank it to 7 × 10⁻⁸; unit-variance weights overflowed. Twenty-layer networks trained with identical settings reached about 86% when initialised with Kaiming or Xavier and stayed at 10%, chance, with weights that were too small, too large, or PyTorch’s own default. And initialising every weight to the same value left exactly one distinct hidden unit out of 256 after three epochs of training.

  • Explain why weights must be random, not equal
  • Derive the variance rule Var(Wx) = n · Var(w) · Var(x)
  • Choose Xavier for tanh and Kaiming for ReLU, and know why they differ by a factor of 2
  • Measure signal and gradient through depth to diagnose an initialisation
  • Know when the framework default is not good enough

Symmetry breaking

Why not start every weight at zero, or at one small constant? Because then every hidden unit in a layer computes the same function of the input, receives the same gradient, takes the same update, and stays identical forever: a layer of 256 units behaves like one unit copied 256 times. Random initial weights break that symmetry so units can specialise. Measured on a 2-hidden-layer MLP after three epochs of SGD:

Initial weightsDistinct rows in the first layer after trainingRank of the 256 × 784 weight matrixTest accuracy
All zero10 (still all zero)10.0%

Kaiming normal25625686.9%

With all-zero weights the hidden layer outputs zero, so even the first layer’s gradient is zero and nothing moves. With a constant, the units move, but all together: 256 rows, one value. Biases can safely start at zero; it is the weights that need randomness.

The variance rule

Take a layer z = Wx with n inputs, weights drawn independently with mean 0 and variance Var(w), and inputs with mean 0 and variance Var(x). Each output is a sum of n independent products, so its variance is the sum of theirs:

Var(z) = n · Var(w) · Var(x)

Checked numerically with n = 784, Var(w) = 0.05² and Var(x) = 1: predicted 1.96, measured 1.95. To keep the signal’s size constant from layer to layer, then, choose Var(w) = 1/n. Two refinements give the two standard schemes. Xavier (Glorot and Bengio, 2010) balances the forward pass, which depends on fan-in, with the backward pass, which depends on fan-out, and uses Var(w) = 2/(fan_in + fan_out); it was derived for tanh, which is roughly linear near zero. Kaiming or He initialisation (He et al., 2015) accounts for ReLU zeroing half its inputs, which halves the second moment at every layer, and doubles the variance to compensate: Var(w) = 2/fan_in. With Kaiming weights, the mean square of a ReLU layer’s output measured 1.004.

for layer in model.modules():
    if isinstance(layer, nn.Linear):
        nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")   # std = sqrt(2 / fan_in)
        nn.init.zeros_(layer.bias)
# tanh:    nn.init.xavier_normal_(layer.weight)                      std = sqrt(2 / (fan_in + fan_out))

Activations exploding and vanishing

Each layer multiplies the signal’s variance by about n · Var(w) (times ½ for ReLU), so through L layers it is multiplied by that factor to the power L. Above 1 it explodes; below 1 it vanishes, exponentially in both cases. Measured through 50 layers of width 256 on 1,000 Fashion-MNIST images, the standard deviation of the activations:

Xavier on ReLU is a factor of 2 too small per layer, and ½⁴⁹ ≈ 2 × 10⁻¹⁵ of the variance is about what remained. Kaiming kept the ReLU signal at a usable scale all the way down (it drifted up to 1.9 because of finite width and the input’s own statistics). The default is subtler: PyTorch’s default weight variance is 1/(3 · fan_in), six times smaller than Kaiming’s, so the input’s contribution shrinks layer after layer, and what is left is a small constant signal produced by the random biases. The activations look alive (0.025), but they no longer carry information about the image: the first layer’s gradient at initialisation was 2 × 10⁻¹⁹.

The rule of thumb is visible in one table: match the scheme to the activation, Kaiming for ReLU and Xavier (or Kaiming, which is close for tanh at these widths) for tanh. Xavier on ReLU still trained, slowly, because the optimiser could grow the weights from a shrunken start; the default could not, because its first layers received essentially no gradient. This is not a criticism of PyTorch’s default for normal use: almost every modern network has normalisation layers (Chapter 14) or residual connections (Chapter 15), which make the initial scale far less critical. In a deep plain stack it matters a great deal.

Use case: a speech model that would not start

An audio team ports a 30-layer fully connected keyword-spotting model from an old framework, where layers were initialised with Kaiming normal, to PyTorch, where they quietly take the default. Training loss sits at log(12) for every one of twelve keywords for the first two epochs and the run is killed as broken. A forward pass that prints each layer’s activation standard deviation shows the input signal fading to the bias floor by layer 10. Adding an explicit kaiming_normal_ call restores the old behaviour; adding LayerNorm between blocks would also have fixed it.

⚠️
Common mistakes
  • Zero or constant weights: one distinct unit out of 256 after training.
  • Xavier for a deep ReLU stack: the signal halves at every layer (7 × 10⁻⁸ after 50).
  • Unit-variance weights: ReLU overflowed; tanh saturated and never trained (11.6%).
  • Trusting the default in a deep plain network: 20 layers stayed at 10%; use Kaiming or add normalisation.
  • Initialising and never checking: one forward pass printing per-layer statistics catches all of the above.

Interview drill

Explain it simply: Why does Kaiming initialisation use variance 2/fan_in rather than 1/fan_in?

How a strong answer sounds
A layer’s output variance is fan_in times the weight variance times the input’s second moment, so to keep the signal’s scale constant you want fan_in · Var(w) = 1 for a linear layer. ReLU zeroes the negative half of its input, which halves the second moment at every layer, so with 1/fan_in the signal halves each layer and vanishes exponentially. Doubling the variance to 2/fan_in compensates. I measured it through 50 ReLU layers: with Kaiming the activations stayed around 1; with Xavier, which has the 1/n scale, they fell to 10⁻⁷; and a 20-layer network trained to 86% with Kaiming against 83% with a slow start under Xavier.

Deeper: A new deep model’s loss stays at log(number of classes) from the first step. How would you check whether initialisation is the cause?

How a strong answer sounds
Run one forward pass on a batch and print the standard deviation of every layer’s activations, then one backward pass and print each layer’s gradient norm. If the activations shrink towards zero or a constant, or grow without bound, or the first layers’ gradients are many orders of magnitude below the last layers’, the initial scale is wrong for the activation. Fixes are Kaiming for ReLU, Xavier for tanh, zero biases, and in deep networks normalisation layers or residual connections. In a measured case, a 20-layer plain ReLU network with PyTorch’s default initialisation stayed at chance: its activations had fallen to a constant set by the biases and the first layer’s gradient was 10⁻¹⁹.

🧠 Key takeaways

  • Weights must be random to break symmetry; equal weights left one distinct unit out of 256.
  • Var(Wx) = n · Var(w) · Var(x): choose Var(w) ≈ 1/n to keep the signal’s size, ×2 for ReLU.
  • Kaiming (2/fan_in) for ReLU, Xavier (2/(fan_in + fan_out)) for tanh; Xavier on ReLU halves the signal per layer.
  • Twenty plain layers trained to ~86% or stayed at 10% depending only on the initial scale.
  • Normalisation and residuals make this less critical; always print per-layer statistics once.
