Embeddings & Learned Representations

A trained network is more than its final prediction. Every layer computes a representation of the input, a vector in which some distinctions have been made easy and others thrown away, and much of modern deep learning is about those vectors: looking things up in them, comparing them, and reusing them for tasks the network was never trained on. For discrete inputs such as words, users, products or cities the representation starts at the very first layer, an embedding table with one learned vector per category.

This chapter measures both ends. An embedding lookup is exactly a one-hot vector times a matrix, 236 times faster as a lookup, and its gradient touches only the 253 rows of a 10,000-row table that appeared in the batch. Inside a trained Fashion-MNIST MLP, a linear classifier on the raw pixels scored 80.9% and on the third hidden layer 89.2%: each layer made the classes more separable. Then a cautionary measurement: features learned on five clothing classes were reused for five other classes (shoes and bags) and did worse than raw pixels, 91.6% against 93.0%. Learned features are only as general as what they were trained on. Finally, for a categorical variable with 2,000 levels, a 4-dimensional embedding beat a 2,000-dimensional one-hot input.

  • Implement and train an embedding table, and know why its gradients are sparse
  • Treat hidden layers as features and test them with linear probes and nearest neighbours
  • Visualise a representation and read it with care
  • Judge when learned features will transfer to a new task
  • Use entity embeddings for high-cardinality categorical inputs

Embedding tables

An embedding table is a matrix E of shape (number of categories, d). Looking up category i returns row i. That is exactly what multiplying a one-hot vector by E does, and checked, the two agreed to the last bit. The lookup is just never written as a multiply, because the one-hot vector is almost all zeros: for 8,192 lookups into a 10,000 × 64 table, indexing took 0.011 ms and the one-hot product 2.67 ms.

E = nn.Embedding(10000, 64)                  # 640,000 parameters: one 64-d vector per id
v = E(ids)                                      # ids (256,) -> (256, 64)
v_same = F.one_hot(ids, 10000).float() @ E.weight   # identical (max difference 0.0), 236× slower
# after backward: only the rows whose ids were in the batch have a non-zero gradient (253 of 10,000 here)

The backward pass of a lookup adds each output gradient into the row it came from, so every row that was not used gets a gradient of zero. With a vocabulary of millions of products and a batch of thousands, almost every row is untouched in a given step. Two consequences. Optimisers with momentum or Adam’s moving averages still update the unused rows (their buffers keep moving), which is wasteful and slightly changes their behaviour; sparse=True with a sparse optimiser, or simply accepting it, are the options. And rare categories get very few updates, so their vectors stay close to their random initialisation: a reason to group rare levels into an “other” bucket or share a hashed table.

The big step is the first layer: from pixels to 512 learned features, a straight line goes from 80.9% to 87.7%, and pairs of same-class images become far more likely to be neighbours. Later layers add a point or so each while compressing from 512 to 128 dimensions. A representation where similar things are close is useful far beyond classification: retrieval, de-duplication, recommendation and anomaly detection all work by nearest neighbours in some learned space (vector search is covered in RAG).

Visualising representations

Projecting a representation to two dimensions gives a picture of it: here, the first two principal components of 2,000 test images. On raw pixels the classes overlap heavily, with footwear on one side and tops in a cloud. On the third hidden layer the picture becomes three arms and a clump: trousers on one arm, bags on another, the three kinds of footwear along a third (partly separated from each other), and T-shirts, pullovers, dresses, coats and shirts packed into one clump, which is where Chapter 10 found most of the errors. Read such plots with care: two dimensions hold a small fraction of a 128-dimensional space, PCA keeps only the directions of largest variance, and t-SNE or UMAP (ML Fundamentals) can invent or exaggerate clusters. The probes above are the measurement; the picture is an illustration.

Reuse across tasks

The promise of representation learning is reuse: train once, then solve new tasks with a small model on top of the learned features. Measured on a deliberately hard split: a network trained only on five clothing classes (T-shirt, trouser, pullover, dress, coat), frozen, then probed on the other five (sandal, shirt, sneaker, bag, ankle boot) with a few labelled examples each.

Features for classes 5–950 labelled examples2001,0005,000
Raw pixels85.0%87.6%91.6%93.0%
A randomly initialised network80.6%85.7%90.1%92.3%
The network trained on classes 0–479.9%86.3%89.5%91.6%

The learned features were worse than raw pixels at every size, and no better than random ones. A network trained to separate tops, trousers and dresses learned what distinguishes those, and threw away what distinguishes a sandal from a sneaker, which it had no reason to keep. This is negative transfer, and it is the normal outcome when the source task is narrow and unrelated. Transfer works when the source task is broad enough to need general features, which is why reuse in practice starts from models pretrained on millions of varied images or documents (Chapter 28 measures it; Computer Vision and NLP cover the pretrained models).

Entity embeddings for categorical inputs

Tabular data often has categorical columns with many levels: city, product, merchant, user. One-hot encoding gives each level its own input dimension and lets the network learn nothing shared between them. An entity embedding (Guo and Berkhahn, 2016) gives each level a short learned vector, so levels that behave alike end up close and can share statistical strength. Measured on a synthetic but structured problem, 2,000 cities whose effect on the target comes mostly from which of 20 regions they belong to:

How the city enters the networkInputs for the cityTest MSE (target variance 1.27)
Ignored00.909
One-hot2,0000.139
Embedding, 4 dimensions4 (8,000 parameters)0.109
Embedding, 16 dimensions16 (32,000 parameters)0.117

The embedding cut the error by about 22% against one-hot with a far smaller input. The 4-dimensional table was enough because the structure behind the cities is low-dimensional (20 regions); more dimensions added parameters to fit noise in rarely seen cities. Chapter 29 compares embeddings with gradient boosting on real tables.

🛍️
Use case: product embeddings for “customers also bought”

A retailer trains a model to predict the next product in a basket, with a 64-dimensional embedding per product among 3 million. The trained table is then used on its own: nearest neighbours in it give “similar items”, averaging a customer’s recent items gives a profile vector, and a small model on top predicts churn. Two lessons from this chapter show up in production. New and rare products have nearly random embeddings because they received few gradient updates, so the team falls back to category embeddings for them. And a churn model built on embeddings trained only for basket completion underperforms one trained with churn in mind, until they add a few features the basket task had no reason to encode.

⚠️
Common mistakes
  • Assuming learned features transfer: features from five clothing classes were worse than pixels on five others.
  • Trusting a 2-D plot as evidence: measure with probes or nearest neighbours.
  • One-hot for thousands of levels in a network: an embedding had 22% lower error here and far fewer inputs.
  • Ignoring rare categories: their embeddings barely train; bucket or hash them.
  • Not comparing against raw inputs and a random network when evaluating reused features.

Interview drill

Explain it simply: What is an embedding layer, and how is it trained?

How a strong answer sounds
It is a matrix with one learned vector per category, and looking up category i returns row i, which is mathematically a one-hot vector times the matrix. It is trained by backprop like any layer: the gradient of each output vector is added into the row it came from, so only the rows that appeared in the batch get updated in that step. I checked that a lookup equals the one-hot product exactly and is over 200 times faster, and that a batch of 256 ids touched 253 rows of a 10,000-row table. The practical consequences are that rare categories learn slowly and that optimisers with momentum keep nudging unused rows.

Deeper: How would you test whether a network’s internal features are useful for a new task?

How a strong answer sounds
Freeze the network, extract features from a chosen layer for the new task’s data, and fit a simple model on them, a linear probe or nearest neighbours, at several training-set sizes. Compare against the same simple model on raw inputs and on features from a randomly initialised network of the same shape; reused features are only useful if they beat both. In a measured case, features from an MLP trained on five clothing classes did worse than raw pixels on five other classes at every size, from 50 to 5,000 examples, because the source task was narrow. Transfer tends to work when the source task is broad, like pretraining on millions of varied images.

🧠 Key takeaways

  • An embedding lookup is a one-hot matrix multiply done as indexing; its gradient touches only the rows used.
  • Each hidden layer is a representation: probes rose from 80.9% (pixels) to 89.2% (third hidden layer).
  • Two-dimensional views illustrate a representation; probes and neighbours measure it.
  • Learned features are only as general as their training task: narrow ones transferred worse than pixels.
  • Entity embeddings beat one-hot for a 2,000-level categorical (MSE 0.109 vs 0.139).
