Training an MLP End to End

The Beginner level ends by putting the parts together into a workflow you can reuse for any new dataset: establish baselines so you know what “good” means, prove the model can learn at all on a single batch, train with a validation set and read the curves, choose the checkpoint, and then look at what the model gets wrong, because an accuracy number on its own says almost nothing about where a model fails.

The dataset is Fashion-MNIST: 50,000 training, 10,000 validation and 10,000 test images of ten kinds of clothing. Predicting the majority class gives 10.0%, logistic regression 83.5%, and 5-nearest-neighbours 85.1%. A 784-512-256-10 MLP with dropout reached 90.5% after 40 epochs. Early stopping on validation loss chose epoch 11, with 88.9% on the test set, because validation loss rose while accuracy kept improving. The overfit-one-batch check caught a planted bug (inputs zeroed) in 300 steps, and missed another (labels shuffled), which is worth knowing. Of 1,108 test errors, 190 were made with more than 90% confidence: a mix of garments a person would also hesitate over, images whose label looks wrong, and plain failures.

  • Set up baselines before training a network
  • Run the overfit-one-batch test, and know what it does and does not prove
  • Read training and validation curves and choose a checkpoint
  • Use a confusion matrix and per-class accuracy
  • Inspect the confident errors

Baselines first

A network’s accuracy means nothing until you know what simple methods score on the same split. Baselines also catch pipeline bugs: if a network scores below logistic regression, something is wrong with the network, not the data.

The MLP beat the best baseline by about five points. That gap, not the 90.5% on its own, is what the network is worth on this task, and it is the yardstick for the better architectures later in the course; Chapter 16 runs a CNN on the same data.

Overfit one batch

Before a long run, train on one fixed batch of 64 images for a few hundred steps with regularisation off. A model wired correctly can memorise 64 examples: the loss should go to almost zero. If it cannot, nothing longer will work. Three runs:

The test proves that gradients reach the parameters and the model has the capacity to fit; it does not prove the data is right. With zeroed inputs the network can only learn how often each label occurs in the batch, so the loss stalls at 2.24; with shuffled labels a 536,000-parameter network memorises 64 meaningless pairs as easily as meaningful ones. Data bugs show up later, as a validation loss that never falls, which is why the next step watches both curves.

xb, yb = xtr[:64], ytr[:64]                       # one fixed batch
model = make_model(dropout=0.0); opt = torch.optim.Adam(model.parameters(), 1e-3)
for step in range(300):
    loss = F.cross_entropy(model(xb), yb); opt.zero_grad(); loss.backward(); opt.step()
assert loss.item() < 0.01, "cannot even fit one batch: check the wiring before anything else"

Train and validation curves

The full recipe: 784-512-256-10 with ReLU, dropout 0.2, AdamW (learning rate 10⁻³, weight decay 10⁻⁴), a cosine learning-rate schedule over 40 epochs, batch 128, evaluating training and validation loss and accuracy after every epoch. Every choice is explained later in the course; here the point is what the curves show.

for epoch in range(40):
    model.train()
    for xb, yb in train_loader:
        loss = F.cross_entropy(model(xb), yb); opt.zero_grad(); loss.backward(); opt.step(); sched.step()
    val_acc, val_loss = evaluate(model, val)                 # model.eval() and no_grad inside
    if val_acc > best_acc:                                       # keep the checkpoint by the metric you report
        best_acc, best_state = val_acc, copy.deepcopy(model.state_dict())

Validation loss bottomed out at epoch 11 (0.311) and then rose to 0.406 by epoch 40, the textbook sign of overfitting. Validation accuracy, though, kept improving, from 89.1% to 90.4%, and the test accuracy of the last epoch (90.5%) beat the epoch with the lowest validation loss (88.9%) by 1.6 points. Both are true at once because loss also measures confidence: as training continues the model becomes over-confident on the examples it gets wrong, which raises their loss sharply, while it keeps getting more examples right. Early stopping on validation loss stopped too early for anyone who reports accuracy. Select checkpoints with the metric you will report, and fix the confidence separately if you need probabilities (Chapter 31). Without dropout the same pattern held more strongly: training accuracy reached 99.9%, validation loss rose to 0.68, and the last epoch still scored 89.9% against 88.7% at the lowest validation loss.

Reading the errors

A confusion matrix puts true classes in rows and predictions in columns. Per-class accuracy ranged from 97.6% (bags) and 96.7% (trousers) down to 67.9% for shirts. The five largest off-diagonal cells were all among tops: shirts predicted as T-shirts (128), coats as pullovers (108), T-shirts as shirts (95), pullovers as coats (83) and shirts as pullovers (83). In 28 × 28 greyscale, a shirt is a T-shirt with a collar and buttons that the resolution barely shows.

The most useful single look at a model is its confident errors: the mistakes it made with the highest probability. Of 1,108 test errors, 190 had confidence above 0.9. Sorted by confidence, the top of the list mixes three kinds of example. Some are genuinely ambiguous garments. Some look mislabelled: a “trouser” predicted as a dress with probability 1.0, or a “T-shirt” predicted as a bag. And some are true model failures. Confident errors are where label noise, dataset artefacts and the model’s blind spots surface first, and they cost minutes to inspect. Chapter 39 makes this a systematic tool.

👕
Use case: the product catalogue classifier

An online retailer trains a classifier to route new product photos to the right catalogue category and celebrates 94% accuracy. The confusion matrix shows that almost all errors are between “shirts” and “tops”, which the merchandising team does not distinguish consistently itself. Sorting the confident errors reveals 300 images labelled “shirt” that are photos of folded stacks of several items. The fixes come from the error analysis, not from the model: merge the two categories in the routing logic, relabel the stack photos as their own class, and report per-category accuracy in the weekly review.

⚠️
Common mistakes
  • No baseline: 90.5% means little until you know logistic regression scores 83.5%.
  • Trusting the overfit test to check the data: it memorised shuffled labels as easily as real ones.
  • Early stopping on a different metric than the one you report: lowest validation loss gave 88.9%, the last epoch 90.5%.
  • Reporting one number: shirts were 67.9%, bags 97.6%.
  • Never looking at the errors: 190 of them were made with more than 90% confidence, some on mislabelled images.
  • Tuning on the test set while reading these curves: decide on validation, test once.

Interview drill

Explain it simply: You get a new classification dataset. What do you do before training a deep network on it?

How a strong answer sounds
Make a fixed train, validation and test split, then run cheap baselines on it: predicting the majority class, a linear model, maybe nearest neighbours or gradient boosting, so I know what accuracy a network has to beat and can catch pipeline bugs. Then build the network and check that it can overfit a single batch, which proves the wiring and gradients work. Only then train for real, logging training and validation curves. On Fashion-MNIST the baselines were 10%, 83.5% and 85.1%, and the MLP reached 90.5%, so the network was worth about five points.

Deeper: Validation loss starts rising at epoch 11, but validation accuracy keeps improving until epoch 40. Which checkpoint do you ship?

How a strong answer sounds
It depends on what the model is for. Rising loss with rising accuracy means the model is getting more examples right while becoming over-confident on the ones it gets wrong, which loss punishes heavily. If I report accuracy or make hard decisions, I select by validation accuracy, which here meant the last epoch: 90.5% on test against 88.9% at the lowest-loss epoch. If downstream code uses the probabilities, I would still take the later checkpoint and fix calibration with temperature scaling on the validation set, rather than give up accuracy. Either way I make the choice on validation, and look at the test set once.

🧠 Key takeaways

  • Baselines first: majority 10.0%, logistic regression 83.5%, 5-NN 85.1%; the MLP’s 90.5% is worth the gap.
  • Overfit one batch to check wiring; it caught zeroed inputs but memorised shuffled labels.
  • Validation loss can rise while accuracy improves; select checkpoints by the metric you report.
  • Per-class accuracy and the confusion matrix show where the model fails: shirts at 67.9%, mostly confused with other tops.
  • Read the confident errors: label noise and blind spots surface there first.
