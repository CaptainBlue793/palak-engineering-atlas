Tensors, Shapes & Broadcasting

Every number a neural network touches lives in a tensor: a block of memory plus a shape that says how to read it. A batch of 128 Fashion-MNIST images is a tensor of shape (128, 784); the weights of the first layer are (256, 784); their product is (128, 256). Most deep-learning code is shape arithmetic, and most of its silent bugs are shape bugs: code that runs, trains and produces a number, just the wrong one.

This prerequisite explains how a tensor is laid out in memory, which operations copy and which only reinterpret, how broadcasting stretches shapes to match, and how reductions pick an axis. Then it measures two shape bugs that raise no error. A linear regression whose prediction had shape (1000, 1) and whose target had shape (1000,) learned a weight of exactly 0.0 and predicted the mean for every input: R² fell from 0.98 to 0.00. A classifier whose softmax ran over the batch axis instead of the class axis fell from 84.0% to 36.6% accuracy.

Tensors and dtypes

A tensor is an n-dimensional array of one element type, the dtype. A scalar has 0 dimensions, a vector 1, a matrix 2, a batch of greyscale images 4: (batch, channels, height, width). The shape is a tuple; x.ndim is its length and x.numel() is the product of its entries.

import torch
x = torch.zeros(60000, 784, dtype=torch.uint8)    # Fashion-MNIST training images, one row per image
x.shape, x.ndim, x.numel()                          # torch.Size([60000, 784]), 2, 47,040,000
x.element_size() * x.numel() / 2**20              # 44.9 MB as uint8; 179.4 MB as float32
torch.tensor([1, 2]).dtype                          # torch.int64: Python ints become 8 bytes each
(torch.arange(3) / 2).dtype                          # torch.float32: true division promotes
(torch.arange(3) // 2).dtype                         # torch.int64

The dtype decides the memory bill. The same 47 million pixels measured here:

The float64 row is a common accident: torch.from_numpy keeps NumPy’s float64, every later operation runs in double precision, and on a consumer GPU double precision is many times slower than float32. Convert once with .float() at the edge of your data pipeline.

Shapes, strides and views

Memory is one-dimensional. A tensor of shape (3, 4) is twelve numbers in a row plus a rule for finding element [i, j]: its offset is i × stride[0] + j × stride[1]. For a freshly made (3, 4) tensor the strides are (4, 1): move 4 elements to go down a row, 1 to go across. A tensor whose strides match this row-major layout is contiguous.

Many operations change only the shape and strides, not the memory. These are views: they are free, and they share storage with the original, so writing through one changes the other.

a = torch.arange(12).reshape(3, 4)     # (3, 4), strides (4, 1), contiguous
a.t().stride()                         # (1, 4): same memory read column-first; not contiguous
a[:, 1].stride()                       # (4,): every 4th element, starting at offset 1
a.unsqueeze(0).shape                    # (1, 3, 4): a new axis of size 1 costs nothing
v = a[0]; v[0] = 100; a[0, 0]           # 100: v is a view, so a changed too
a.t().view(12)                        # RuntimeError: view size is not compatible with input tensor's size and stride
a.t().reshape(12)                     # works: reshape copies when a view is impossible

view refuses when no set of strides can describe the new shape over the existing memory; reshape returns a view when it can and silently copies when it cannot; contiguous() forces a row-major copy. On this GPU, transposing an 8,192 × 8,192 float32 matrix (256 MB) took 0.0013 ms because it only swaps two strides; making the transpose contiguous took 1.41 ms, nearly twice a straight copy of the same matrix (0.74 ms), because reading it column-first is a scattered access pattern.

Broadcasting rules

Element-wise operations need matching shapes, but you often want to add a bias of shape (256,) to activations of shape (128, 256), or subtract a per-feature mean. Broadcasting lets the smaller tensor be stretched without copying. PyTorch and NumPy apply the same rules:

So (3, 4) + (4,) is fine: (4,) becomes (1, 4) and stretches down the rows. (3, 4) + (3,) fails, because aligned on the right it compares 4 with 3. Broadcasting is how the bias in a linear layer works, how you normalise features, and how you compute all pairwise distances in one line with (N, 1, d) − (1, M, d). It is also how the worst shape bug in this chapter happens, because (5, 1) and (5,) broadcast too, to (5, 5).

Stretching really is free. Broadcasting a (1, 4096) row to (4096, 4096) with expand gave strides (0, 1) and allocated 0.0 MB; repeat, which makes real copies, allocated 64 MB. Use expand (or let broadcasting do it) unless you need to write to the result.

Reductions along an axis

A reduction (sum, mean, max, the normaliser inside softmax) collapses one axis. The dim argument names the axis that disappears: on a (128, 10) tensor of logits, dim=1 reduces over the 10 classes and leaves one value per example; dim=0 reduces over the 128 examples and leaves one value per class. keepdim=True keeps the reduced axis as size 1, so the result broadcasts back against the input:

logits = model(xb)                                   # (128, 10)
m = logits.max(dim=1, keepdim=True).values             # (128, 1): one max per example
p = (logits - m).exp()                                # (128, 10) - (128, 1) broadcasts across classes
p = p / p.sum(dim=1, keepdim=True)                    # (128, 10), each row sums to 1
# without keepdim the sum is (128,), which lines up with the 10 classes on the right: a RuntimeError here,
# but a silent wrong answer whenever the batch size happens to equal the number of columns

Choosing the wrong axis usually runs without complaint. A logistic regression on Fashion-MNIST trained with log_softmax(dim=1) reached 84.0% test accuracy in 5 epochs. The same model trained with log_softmax(dim=0), so each class’s scores were normalised across the batch, reached 36.6%. Worse, at serving time with a batch of one, a softmax over dim 0 normalises each score against only itself and returns probability 1.0 for all ten classes.

Silent shape bugs

The most common one in regression code: the model outputs shape (N, 1) because a linear layer always keeps a feature axis, and the targets arrive as (N,) because that is how a column comes out of a data frame. Subtracting them broadcasts to (N, N): every prediction minus every target. The mean of that matrix is a perfectly good scalar, so backward() runs.

pred = lin(x)                         # (1000, 1)
loss = ((pred - y) ** 2).mean()      # y is (1000,): pred - y is (1000, 1000), no error, no warning
loss = ((pred - y[:, None]) ** 2).mean()   # (1000, 1): what was meant
assert pred.shape == target.shape, (pred.shape, target.shape)   # the one-line guard

The broadcast loss is the mean over all pairs (i, j) of (pᵢ − yⱼ)², which is minimised by making every prediction equal to the mean of y, whatever x is. That is exactly what training found. With correct shapes, SGD recovered w = 2.989 and b = 2.023 (truth: 3 and 2), reaching the noise floor of 0.24 within 30 steps, and R² = 0.98. With the bug it learned w = 0.000 and b = 2.12, the mean of y, and R² = 0.00: a model that ignores its input. F.mse_loss would have warned (“Using a target size that is different to the input size… This will likely lead to incorrect results due to broadcasting”); a hand-written loss does not.

Use case: the delivery-time model that predicted the average

A logistics team trains a small network to predict delivery minutes from distance, time of day and traffic. Validation loss falls during the first epoch, then flattens at a value suspiciously close to the variance of the targets, and every prediction in the dashboard is 34 minutes. The model outputs (batch, 1); the targets come from a pandas column as (batch,); the hand-written MSE broadcasts to (batch, batch), and its minimum is the mean. One assert pred.shape == y.shape in the training step finds it on the first batch. The lesson the team writes down: a loss that plateaus at the variance of the target is the signature of a model that predicts a constant.

⚠️
Common mistakes
  • (N, 1) against (N,) in a hand-written loss: it broadcasts to (N, N) and the model learns the mean. Measured: R² 0.98 → 0.00.
  • Softmax or a sum over the wrong dim: measured 84.0% → 36.6%, and a batch of one gets probability 1.0 for every class.
  • Forgetting keepdim=True before broadcasting a reduction back: it errors only if the sizes happen to clash.
  • Assuming a slice is a copy: writing to it changes the original tensor.
  • Calling view after transpose: it fails; use reshape or contiguous() first.
  • float64 by accident from NumPy: twice the memory and much slower on a consumer GPU.

Interview drill

Explain it simply: What are strides, and why is a transpose free in PyTorch?

How a strong answer sounds
A tensor is a flat block of memory plus a shape and strides; the stride for an axis is how many elements you skip in memory to move one step along it. A (3, 4) tensor has strides (4, 1). A transpose does not move any data: it swaps the shape to (4, 3) and the strides to (1, 4), so it is a view that reads the same memory column-first. That is why it is free, and why the result is non-contiguous, so view refuses it and some kernels copy it first. On a 256 MB matrix I measured the transpose at about 1 microsecond and making it contiguous at 1.4 ms.

Deeper: A regression model’s loss plateaus at the variance of the target and every prediction is the same. What do you suspect, and how do you check?

How a strong answer sounds
That the model is predicting a constant, and the classic cause is broadcasting in the loss: predictions of shape (N, 1) minus targets of shape (N,) give an (N, N) matrix, and the mean squared value of that matrix is minimised by predicting the mean of the targets for everything. I would print pred.shape and y.shape inside the training step, or add an assertion that they match, and use F.mse_loss, which warns about mismatched shapes. In a measured run with y = 3x + 2, the bug drove the weight to exactly 0 and the bias to the mean of y; fixing the shape recovered w = 2.99, b = 2.02.

🧠 Key takeaways

  • A tensor is memory plus shape, strides and dtype; the dtype sets the memory bill (float32 is 4 bytes per element).
  • Transpose, slice, unsqueeze and expand are views: free, and they share storage. reshape copies only when it must.
  • Broadcasting aligns shapes on the right; an axis matches if the sizes are equal or one of them is 1.
  • dim names the axis that disappears; keepdim=True keeps it so the result broadcasts back.
  • Measured: (N, 1) − (N,) made a regression learn the mean (R² 0.98 → 0.00); softmax over the batch axis cost 47 points.
  • Assert shapes in the training step; it is the cheapest bug detector there is.
