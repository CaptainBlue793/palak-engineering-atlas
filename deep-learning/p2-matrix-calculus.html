Matrix Calculus: Jacobians & the Chain Rule

Training a network means asking one question millions of times: if I nudge this weight, how much does the loss change? The answer is a derivative, and because a network is a chain of functions on vectors and matrices, it is a derivative computed with the chain rule for vectors. Backpropagation (Chapter 4) is nothing more than that chain rule, organised so it never builds the huge matrices the textbook version suggests.

This prerequisite builds the calculus you need in the form code uses: gradients that have the same shape as the thing they differentiate, Jacobians, the chain rule as a product of Jacobians, and the gradients of a matrix multiply, which are most of what any network needs. Every formula is checked against PyTorch’s autograd; in float64 all of them agreed to the last bit (a maximum difference of 0.0). Then it measures two practical facts: finite-difference checks only work in a narrow band of step sizes, and building a full Jacobian of a 2,048-wide function took 1,360 times longer than the one vector-Jacobian product backprop actually needs.

  • Write the gradient of a scalar loss with the same shape as its input
  • Build a Jacobian, and read the softmax Jacobian
  • Apply the chain rule as vector-Jacobian products, right to left
  • Derive dW and dX for Y = XW from the shapes alone
  • Check a gradient with finite differences, in the right precision and step size

Partial derivatives and gradients

A loss L is one number that depends on many: every weight in the network. The partial derivative ∂L/∂wij is how fast L changes when only wij moves. Collect all of them and you have the gradient. The convention that makes code simple: the gradient of a scalar with respect to a tensor has the same shape as that tensor. If W is (784, 256), then ∂L/∂W is (784, 256), and the update W -= lr * W.grad is element-wise.

The gradient points in the direction of steepest increase, so stepping against it lowers the loss, at least for a small enough step. That is gradient descent, which ML Fundamentals covers for classical models (Gradient Descent); here the work is computing the gradient through many layers.

Jacobians

For a function from n inputs to m outputs, y = f(x), the derivative is a matrix: the Jacobian J, of shape (m, n), with Jij = ∂yi/∂xj. Row i says how output i responds to every input; column j says how every output responds to input j.

Two Jacobians appear everywhere. An element-wise function such as ReLU or tanh has a diagonal Jacobian, because output i depends only on input i; multiplying by it is just element-wise multiplication by the local derivative (for ReLU, a 0/1 mask). Softmax has a full one, because every output depends on every input through the shared normaliser: J = diag(p) − p pᵀ. For logits (2.0, 1.0, 0.1, −1.0), PyTorch’s jacobian matched that formula exactly, and every row summed to 0, because the probabilities always sum to 1, so a nudge to any logit can only move probability around.

from torch.autograd.functional import jacobian
z = torch.tensor([2.0, 1.0, 0.1, -1.0], dtype=torch.float64)
J = jacobian(lambda v: torch.softmax(v, 0), z)            # (4, 4)
p = torch.softmax(z, 0)                                   # (4,) 0.638, 0.235, 0.095, 0.032
(J - (torch.diag(p) - torch.outer(p, p))).abs().max()       # 0.0

The chain rule for vectors

If x → u = f(x) → y = g(u), the Jacobian of the whole is the product of the parts: Jy,x = Jg · Jf, with shapes (m, k) · (k, n). A network is a long chain, ending in a scalar loss. The gradient of that scalar is a row vector times a stack of Jacobians:

∂L/∂x = ∂L/∂y · Jg · Jf

The order of multiplication is a choice, and it matters enormously. Going right to left multiplies big Jacobians together first. Going left to right starts from the 1 × m row vector ∂L/∂y and only ever multiplies a vector by a matrix: a vector-Jacobian product (VJP). Each layer only needs to know how to turn the gradient of its output into the gradient of its input; nobody ever builds a Jacobian. That is reverse-mode differentiation, and backpropagation is its name in deep learning.

Gradients of a matrix multiply

Most of a network’s compute is Y = XW: a batch X of shape (B, n) times weights W of shape (n, m), giving Y of shape (B, m). Backprop hands this layer G = ∂L/∂Y, also (B, m), and asks for ∂L/∂W and ∂L/∂X. You can derive them with indices, or let the shapes do it: the answer must be (n, m) for W and (B, n) for X, and it must be built from X, W and G. Only one product of each fits:

Y = X @ W + b                # X (64, 784), W (784, 256), b (256,), Y (64, 256)
# given G = dL/dY, shape (64, 256):
dW = X.t() @ G               # (784, 64) @ (64, 256) = (784, 256): same shape as W
db = G.sum(0)                  # (256,): b was broadcast over the batch, so its gradient sums over it
dX = G @ W.t()               # (64, 256) @ (256, 784) = (64, 784): same shape as X
# against autograd in float64: max |difference| = 0.0 for all three

Two rules generalise. A product’s gradient with respect to one factor is the upstream gradient times the transpose of the other factor, placed on whichever side makes the shapes work. And anything that was broadcast in the forward pass, like the bias over the batch, has its gradient summed over the broadcast axis in the backward pass. Note also that dW sums over the batch: X.t() @ G adds up 64 per-example outer products, which is why the loss is usually a mean, so the gradient does not grow with the batch size.

Checking by finite differences

A hand-written backward pass (Chapters 3, 4 and 37) is checked against the definition of a derivative: nudge one input by h each way and measure the change, (f(x + h) − f(x − h)) / 2h. The catch is that h must be small enough for the approximation to hold, but not so small that the two function values are equal in floating point and their difference is noise. Measured on a small tanh network:

In float32 the best possible check agrees only to about four digits, which is not enough to tell a correct gradient from one with a small bug. In float64 the error falls as h² (the truncation error of a central difference) until about h = 10⁻⁵ and then rises as rounding takes over. That is why torch.autograd.gradcheck insists on float64 inputs and uses h = 10⁻⁶ by default.

Why not just build the Jacobian?

Because it is enormous and almost never needed. For f(x) = tanh(W tanh(Wx)) with n inputs and n outputs, the full Jacobian needs n backward passes, one per output row. One VJP needs one:

The VJP time stayed flat because at these sizes the GPU is limited by launch overhead, not arithmetic; the Jacobian time grew with n because it is n of them. A real first layer maps 784 inputs to 256 activations for each of 128 examples: its Jacobian with respect to the weights alone has (128 × 256) × (784 × 256) entries, about 6.6 billion, 26 GB in float32. Backprop never builds it. Asking PyTorch to vectorise the full Jacobian (vectorize=True) helped (78.5 ms at n = 2,048) but is still 450 times the VJP.

Use case: a custom loss for a search ranker

A search team writes a pairwise ranking loss with a hand-written backward pass, because the autograd version materialises a (queries × documents × documents) tensor that does not fit in memory. Before shipping it they run gradcheck on a tiny input in float64; it fails, and the cause is a missing transpose in the gradient of one document term, the same “other factor, transposed” rule as dW = XᵀG. In float32 the same check had passed with a relative error of 2 × 10⁻³, which looked like rounding noise. The fix took one line; finding it needed float64.

⚠️
Common mistakes
  • Gradient shapes that do not match the parameter: dW must have W’s shape; if it does not, a transpose is missing.
  • Forgetting to sum over broadcast axes: a bias gradient must be summed over the batch.
  • Finite-difference checks in float32: the best agreement measured was four digits, not enough to catch small bugs. Use float64.
  • A step size that is too small: at h = 10⁻⁹ in float32 the two function values were identical and the estimate was 0.
  • Building Jacobians you do not need: 1,360 times slower than a VJP at width 2,048, and impossible at the size of a real layer.
  • Treating ReLU’s derivative as 1: it is a mask; a unit with negative input passes back nothing.

Interview drill

Explain it simply: For Y = XW, what are the gradients of the loss with respect to W and X?

How a strong answer sounds
If G is the gradient of the loss with respect to Y, then dW = XᵀG and dX = GWᵀ. You can check it with shapes: X is (B, n), W is (n, m), G is (B, m), so XᵀG is (n, m) like W and GWᵀ is (B, n) like X, and no other product of those three matrices has those shapes. If there is a bias added across the batch, its gradient is G summed over the batch axis. I checked these against PyTorch autograd in float64 and they agree exactly.

Deeper: Why does deep learning use reverse-mode differentiation rather than forward mode?

How a strong answer sounds
Because the loss is one number and the parameters are millions. Reverse mode computes the gradient of one output with respect to all inputs in a single backward sweep, by passing a vector backwards through each layer’s vector-Jacobian product; forward mode would need one pass per parameter. The price of reverse mode is memory, since the forward activations must be kept for the backward pass, which is why activation memory and checkpointing matter. Building full Jacobians is never needed: at width 2,048 I measured a full Jacobian at 238 ms against 0.18 ms for one VJP.

🧠 Key takeaways

  • The gradient of a scalar loss has the same shape as the tensor it is taken with respect to.
  • A Jacobian holds every ∂yᵢ/∂xⱼ; element-wise functions have diagonal ones, softmax has diag(p) − ppᵀ.
  • Backprop is the chain rule evaluated left to right as vector-Jacobian products, never forming a Jacobian.
  • For Y = XW: dW = XᵀG, dX = GWᵀ, and broadcast terms such as biases sum their gradient over the broadcast axis.
  • Check gradients with central differences in float64; float32 managed only about four digits at its best step size.
