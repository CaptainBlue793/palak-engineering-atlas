Graph Neural Networks

Much of the world’s data is a graph: papers that cite papers, users who follow users, molecules made of bonded atoms, roads joining junctions. A grid of pixels and a sequence of tokens are special cases with fixed neighbours. A graph neural network handles the general case with one idea, message passing: each node updates its vector by combining its neighbours’ vectors, and stacking k such layers lets information travel k hops. The same weights are used at every node, which is what lets one network work on graphs of any size and shape.

This chapter builds message passing from scratch and measures it on three citation graphs with their standard splits, 10 seeds each. On Cora, with only 140 labelled papers, an MLP that ignores the citations scored 58.9%; a two-layer GCN that uses them scored 82.2%, and a linear model on twice-smoothed features 81.1%. Then the limits. Deeper is not better: after 8 layers a GCN’s node vectors were 99.8% alike and accuracy fell to 24%. The graph helps only when linked nodes tend to share labels: replacing two-thirds of Cora’s edges with random ones pushed GCN below the MLP. And for whole-graph tasks, the choice of aggregation decides what the network can even detect.

Graphs as data

A graph is a set of nodes, a set of edges between them, and usually a feature vector per node. The three datasets here are the standard benchmarks for node classification: each node is a scientific paper with a bag-of-words feature vector, each edge a citation, and the task is to predict each paper’s topic from a handful of labelled papers.

Homophily is the fraction of edges that join two nodes with the same label: 81% of Cora’s citations link papers on the same topic. That number turns out to predict most of what follows. The graph is stored as an edge list, two rows of node indices, rather than as an adjacency matrix, which for PubMed would have 389 million entries, all but 0.03% of them zero.

Message passing

One message-passing layer computes, for every node, a weighted sum of its neighbours’ vectors and its own. Written as a matrix, that is Â H, where Â is the adjacency matrix with self-loops, normalised by degree. Written as code over the edge list, it is a gather (each edge reads its source node’s vector) and a scatter-add (each edge adds it into its destination). Both were computed for a random 16-dimensional H on Cora and agreed to 4.8 × 10⁻⁷, float rounding over 13,264 directed edges and self-loops.

# edges as (src, dst) pairs in both directions, plus self-loops; w = 1 / sqrt(deg[src] * deg[dst])
out = torch.zeros_like(h).index_add_(0, dst, h[src] * w[:, None])   # gather, weight, scatter-add
out = torch.sparse.mm(A_hat, h)                                         # the same thing as a sparse matrix product

class GCNLayer(nn.Module):                       # Kipf and Welling, 2017
    def forward(self, h, A_hat): return torch.sparse.mm(A_hat, self.lin(h))
class SAGELayer(nn.Module):                      # Hamilton et al., 2017, mean aggregator
    def forward(self, h, M): return self.self_lin(h) + self.neigh_lin(torch.sparse.mm(M, h))   # M averages neighbours

GCN mixes a node with its neighbours using symmetric degree normalisation, then applies one weight matrix to the result. GraphSAGE keeps the node’s own vector and its neighbours’ average separate, with a weight matrix each, so a node can weigh itself differently from its neighbourhood. Both share weights across all nodes, like a convolution shares weights across pixel positions.

Using the graph added 23 points on Cora and 15 on CiteSeer. Most of that comes from the smoothing itself: SGC (Wu et al., 2019) has no non-linearity and no hidden layer, just features averaged over each node’s two-hop neighbourhood fed to a logistic regression, and it came within a point of GCN and beat it on CiteSeer. Label propagation, which ignores the words entirely and spreads the 140 known labels along citations, already scored 71% on Cora. On these benchmarks the graph is the signal, and the differences between architectures are small. For large graphs, GraphSAGE’s design allows neighbour sampling: each mini-batch uses at most 10 neighbours of each node and 5 of each of those, so memory no longer depends on the graph’s size. Trained that way on PubMed it reached 77.2%, against 77.3% full-batch.

Over-smoothing

If two layers see two hops, why not twenty layers? Because each message-passing step is an averaging step, and repeated averaging over a connected graph drives every node towards the same vector. Measured as the mean cosine similarity between the final hidden vectors of random pairs of nodes on Cora:

A deep plain GCN fails for two reasons at once: its node vectors collapse together, and a deep network without residual connections is hard to train anyway (Chapter 15). SGC separates the two, because it has no trainable depth: it applies k smoothing steps to the raw features and fits a logistic regression. Accuracy rose from 59.9% at k = 0 to a peak of 81.7% at k = 4, then fell to 57.6% at 64 steps and 28.1% at 128, while the similarity between nodes climbed steadily from 0.06 to 0.85. That is over-smoothing in its pure form: a few hops of averaging remove noise, many hops remove the differences between nodes. Residual connections delayed it: at 16 layers they still held 73%. In practice most GNNs use 2 to 4 message-passing layers, and get a wider view from sampling, jumping knowledge or attention rather than depth.

Homophily: when the graph helps

Message passing assumes that neighbours are informative: averaging a node with its neighbours helps only if they tend to share its label. Replacing a fraction of Cora’s edges with random ones lowers the homophily and measures what the graph is worth:

Between half and three-quarters of the edges replaced, the graph went from helping to hurting: GCN averages each node with neighbours that now mostly carry other labels and loses the node’s own evidence. Fraud rings, where fraudsters connect to legitimate accounts, and molecules, where bonded atoms are usually of different types, are naturally heterophilous. Compute the homophily of your graph before choosing a GNN. When it is low, keep the node’s own features separate (GraphSAGE’s self term does this) or use architectures designed for heterophily.

Graph classification

For a whole-graph label, such as whether a molecule is toxic, the node vectors after message passing are pooled into one graph vector, by sum, mean or max, and a classifier reads that. The aggregation inside each layer then decides what the network can perceive. A test: 600 random graphs of 30 to 60 nodes, half Erdős–Rényi (edges placed uniformly at random) and half Barabási–Albert (preferential attachment, which creates hubs), with the same number of edges, and every node’s feature set to the constant 1, so all information is in the structure.

Aggregation in each layerTest accuracy (200 graphs)
Mean of neighbours77.5%
Sum of neighbours100%

With identical starting vectors, the mean of a node’s neighbours is the same for every node however many neighbours it has, so mean aggregation cannot see degree, and degree is exactly what separates hubs from uniform graphs. It reached 77.5% only through a side door: Erdős–Rényi graphs sometimes contain isolated nodes, whose empty neighbourhood gives a different vector. Sum aggregation counts neighbours and separated the two families perfectly. This is the expressiveness argument behind GIN (Xu et al., 2019): sum aggregation can distinguish neighbourhoods that mean and max cannot, up to the limit of the Weisfeiler–Lehman graph isomorphism test.

Use case: detecting mule accounts in a payments graph

A bank builds a graph of 40 million accounts, with an edge wherever money moved between two accounts in the last 90 days, and wants to flag “mule” accounts that launder money. A first GCN does worse than gradient boosting on account features alone. The homophily check explains it: mules mostly transact with ordinary customers, so averaging a mule with its neighbours makes it look ordinary. The team switches to a GraphSAGE-style model that keeps each account’s own features separate from its neighbourhood summary, adds edge features (amount, timing), and trains with neighbour sampling so a mini-batch never needs the whole graph. It beats the boosting baseline by catching accounts whose own features look clean but whose neighbourhoods do not.

⚠️
Common mistakes
  • No MLP or label-propagation baseline: label propagation alone scored 71% on Cora.
  • Stacking many layers for a wider view: 8 plain GCN layers made node vectors 99.8% alike.
  • Using a GCN on a heterophilous graph: with homophily 0.33 it scored 11.6 points below the MLP.
  • Mean aggregation when counts matter: it could not see degree; sum could.
  • Forgetting self-loops or degree normalisation: a node then ignores its own features, or high-degree nodes explode.
  • Dense adjacency matrices: PubMed’s would be 389 million entries; use edge lists and sparse operations.

Interview drill

Explain it simply: What does a graph neural network layer do?

How a strong answer sounds
Each node collects its neighbours’ vectors, combines them with a permutation-invariant operation such as a degree-normalised sum or a mean, mixes the result with its own vector through learned weights, and applies a non-linearity. The same weights are used for every node, so it works on any graph. Stacking k layers lets information travel k hops. Implemented over an edge list it is a gather and a scatter-add; as matrices it is a sparse product with the normalised adjacency. On Cora, with 140 labels, a two-layer GCN scored 82% against 59% for an MLP that ignored the citations.

Deeper: Why are GNNs usually shallow, and when does a GNN fail to help?

How a strong answer sounds
Over-smoothing: each layer averages over neighbourhoods, and repeated averaging makes node vectors converge. I measured it with SGC, which only smooths the features: accuracy peaked at 4 steps and fell to 28% at 128, while node similarity rose from 0.06 to 0.85; a plain 8-layer GCN had node vectors 99.8% alike. Residual connections delay it. A GNN also fails when the graph is heterophilous, when neighbours do not share labels: replacing three-quarters of Cora’s edges with random ones dropped homophily to 0.33 and put GCN 12 points below a plain MLP. So I check homophily first and always compare against an MLP and label propagation.

🧠 Key takeaways

  • Message passing is a gather and scatter-add over edges, equivalently a sparse matrix product.
  • On citation graphs the graph was worth 15–23 points; even linear smoothing (SGC) came within a point of GCN.
  • Repeated averaging makes node vectors identical: keep GNNs shallow, or use residuals.
  • Homophily predicts usefulness: somewhere between 0.5 and 0.33 here, GCN fell below ignoring the graph.
  • Sum aggregation can count neighbours; mean cannot, which matters for graph-level tasks.
