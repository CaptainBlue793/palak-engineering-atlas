Scaling Width & Depth: μP and Hyperparameter Transfer

Tuning a model costs many training runs, and for the largest models even one run is expensive. The obvious shortcut, tune a small version and train the big one with the same settings, fails in the usual way networks are parameterised: as a network gets wider, the best learning rate moves. The maximal update parameterisation, μP (Yang and Hu, 2021; Yang et al., 2022), changes how initialisation and learning rates scale with width so that the best settings stay put, which turns “tune small, train big” into a working method.

Measured on a byte-level transformer language model at widths 128 to 1,024, with a 10-point learning-rate sweep at every width. In the standard parameterisation the best Adam learning rate halved every time the width doubled, from 2⁻⁸ at width 128 to 2⁻¹¹ at 1,024, and taking the width-128 optimum to width 1,024 cost a full bit per byte (3.49 against 2.50 when tuned). Under μP the best rate stayed at 2⁻⁸ from width 128 to 512 and 1,024, and the rate tuned at width 128 gave 2.516 bits per byte at width 1,024 with no further search, within 0.014 of a fully tuned standard model. Getting there took a correction: a first μP version with a zero-initialised output layer, a common recommendation, transferred its learning rate perfectly but trained 0.47 bits per byte worse at width 1,024 in this short run. Depth, from 2 to 16 blocks, moved the best rate far less than width did.

Standard parameterisation

In the standard parameterisation (SP), every weight matrix is initialised with variance about 1/fan-in (Chapter 9) and every parameter shares one learning rate. That keeps activations the right size at initialisation for any width, but not their updates. With Adam, each weight moves by roughly the learning rate per step whatever its gradient’s size, and a hidden unit sums the updates of all n incoming weights, which tend to point the same way. A layer twice as wide therefore changes its outputs about twice as much per step at the same learning rate, so the stable rate falls as 1/width.

μP

μP keeps every layer’s update of the same order as its activations at any width. For Adam, the rules that matter in a transformer are short (Yang et al., 2022, Table 3):

# base width 128; m = width / 128
hidden weight matrices (attention and MLP):  lr = base_lr / m      # Adam updates sum over fan-in
embeddings, biases, LayerNorm:               lr = base_lr          # one input dimension each
output logits:                                logits = readout(h) / m
attention scores:                             q·k / d instead of q·k / √d

Everything is identical to SP at the base width, which is why μP and SP matched at width 128 (2.577 and 2.561). The difference appears as the width grows: SP’s effective step grows with width and pushes the optimum down; μP divides it back out.

The first version of this experiment followed a common μP recommendation and also initialised the output layer to zero. Its best learning rate transferred: the rate tuned at width 128 was also the best at 1,024. But it trained badly, ending at 2.97 bits per byte at width 1,024 against 2.50 for tuned SP and 3.28 even at the base width. A zero readout means the gradient reaching every earlier layer is zero at the first step; the body only starts learning once the readout has grown, and in a 1,000-step run that delay was most of the budget. With a normal readout initialisation the same μP rules gave losses as good as SP’s and the same stable optimum. Hyperparameter transfer and good training are separate properties; a parameterisation can give the first without the second.

Tuning small, training big

In SP, the transferred rate was eight times too high for the wide model and the run made little progress. Under μP the width-128 optimum was the width-1,024 optimum, and the model trained to within 0.014 bits per byte of the best SP result found with a full sweep. With a 10-run sweep at width 128 taking an eighth of the time of one at width 1,024 here (60 s against 469 s), and a far smaller fraction at real model sizes, that is the whole economic argument for μP: the expensive model needs one run, not a sweep. In real use the small proxy is tuned for more than the learning rate (initialisation scale, output multiplier, warm-up), and μP is designed to carry those over too.

Depth scaling

μP as above is about width. Depth is a separate axis: each extra residual block adds to the residual stream, and without care the stream’s size and the effective step grow with the number of blocks. One proposed fix scales each block’s output by 1/√depth. Measured at width 256 in SP, depths 2 to 16:

From 4 to 16 blocks the best rate did not move with either scheme, and the branch scaling made almost no difference to the loss. At this depth and with pre-norm blocks, which already normalise each branch’s input, depth was not a hyperparameter-transfer problem. The two-block runs were erratic: the plain version’s sweep was non-monotone, with a good result at the highest rate tried after a failure at the one below it, a reminder that single runs at aggressive learning rates are close to the edge of stability. Depth-μP schemes matter for much deeper networks than these; at 16 blocks, more depth simply helped, by half a bit per byte over 2.

Use case: sizing up a speech model on a fixed compute budget

A team plans a 1-billion-parameter speech recogniser and can afford one full training run. In the standard parameterisation they would have to guess its learning rate from smaller models, knowing it shifts with width. Instead they implement μP, run 40 short trials of a 30-million-parameter proxy to tune the learning rate, warm-up and output multiplier, and check the transfer with 5 trials at 120 million parameters, where the optimum sits at the same value. The 1-billion run uses those settings unchanged and trains stably the first time. They also learn a caution: a colleague’s zero-initialised readout transferred perfectly in the proxy sweep but trained visibly slower, and they drop it.

⚠️
Common mistakes
  • Reusing a small model’s learning rate in SP: at 8× the width it cost a full bit per byte.
  • Judging μP only by whether the optimum transfers: the zero-readout version transferred and trained badly.
  • Applying the width scaling to every parameter: embeddings, biases and norms keep the base rate.
  • Sweeping too coarsely: at width 1,024 one factor of two either side cost 0.4–0.6 bits per byte.
  • Expecting μP to fix depth: it is a width rule; depth needs its own treatment.
  • Trusting one run at an aggressive rate: the two-block sweep was non-monotone.

Interview drill

Explain it simply: Why does the best learning rate change as a network gets wider?

How a strong answer sounds
Standard initialisation keeps activations the right size at any width, but not updates. With Adam each weight moves by about the learning rate per step, and a hidden unit sums the updates of all its incoming weights, which are correlated, so the output change grows with width. To keep it stable the rate must shrink as one over the width. I measured it on a byte-level transformer: the best rate halved with each doubling, from 2^-8 at width 128 to 2^-11 at 1,024, and using the width-128 rate at 1,024 cost a full bit per byte.

Deeper: What does μP change, and how do you know it worked?

How a strong answer sounds
For Adam, it divides the hidden weight matrices’ learning rate by the width multiplier, keeps the base rate for embeddings, biases and norms, divides the output logits by the multiplier, and uses 1/d attention scaling. At the base width it is identical to the standard parameterisation. I check two things separately: that the optimum stays at the same learning rate across widths, and that the loss at each width is as good as a tuned standard model. In my runs a variant with a zero-initialised readout passed the first test and failed the second, 2.97 against 2.50 bits per byte at width 1,024, because nothing upstream learns until the readout grows. With a normal readout init both tests passed.

🧠 Key takeaways

  • In SP the best Adam rate halved per doubling of width (2⁻⁸ → 2⁻¹¹ from 128 to 1,024).
  • The width-128 rate at width 1,024 cost a full bit per byte; tuning small does not transfer in SP.
  • μP rescales hidden learning rates, readout and attention so the optimum stays put across width.
  • Transfer is not the same as good training: a zero-initialised readout transferred and trained 0.47 bits/byte worse.
  • From 4 to 16 pre-norm blocks the best rate did not move; 1/√depth scaling changed little.
