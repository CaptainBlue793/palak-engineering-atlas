Attention from First Principles

A recurrent network passes everything it knows about the past through one hidden vector, step by step (Chapter 17). Attention lets every position look directly at every other position and decide how much of each to use. Mechanically it is a soft dictionary lookup: each position issues a query, every position offers a key and a value, and the result is a weighted average of the values, weighted by how well each key matches the query. Because the weights come from a softmax, the whole lookup is differentiable and can be learned.

This chapter writes attention in four lines and checks it against PyTorch’s kernel (agreement to 8 × 10⁻⁷, causal mask included). It measures why the scores are divided by √d: without it, the attention weights collapse onto a single key as the dimension grows (entropy 0.13 at d = 1,024 against 3.69 when scaled). On a lookup task, “given 16 key-value pairs and a query key, return its value”, a 14,496-parameter attention model scored 100% and a 3.25-million-parameter MLP 12%. And it measures the price: attention’s score matrix grows with the square of the sequence length, 8.2 GB of memory at 16,384 tokens for the textbook version, 16 MB for PyTorch’s fused kernel.

A soft dictionary lookup

A Python dictionary returns the value whose key exactly equals the query. Attention returns a blend of all values, weighted by similarity: score each key against the query with a dot product, turn the scores into weights that sum to 1 with softmax, and average the values with those weights. If one key matches far better than the others, the softmax puts almost all the weight on it and attention behaves like an exact lookup; if several match, it blends them. The weights are smooth functions of the queries and keys, so gradients tell the network how to make better ones.

def attention(q, k, v, mask=None):              # q (B, n_q, d), k (B, n_k, d), v (B, n_k, d_v)
    s = q @ k.transpose(-2, -1) / math.sqrt(q.shape[-1])   # (B, n_q, n_k): every query against every key
    if mask is not None: s = s.masked_fill(~mask, float("-inf"))   # forbidden pairs get weight exactly 0
    w = s.softmax(-1)                                  # each row sums to 1
    return w @ v                                       # (B, n_q, d_v): weighted average of the values
# against F.scaled_dot_product_attention: max |difference| 8.3e-7 (no mask), 6.0e-7 (causal)

Queries, keys and values

In self-attention the queries, keys and values all come from the same sequence, through three learned linear maps: q = xW_Q, k = xW_K, v = xW_V. Each position decides what it is looking for (its query), what it advertises about itself (its key) and what it contributes if chosen (its value), and these can be quite different things. In cross-attention the queries come from one sequence and the keys and values from another, which is how a decoder reads an encoder’s output (Chapter 19, NLP Chapter 13). The lookup task below makes this concrete: 16 (key, value) pairs and one query key; the network must output the value stored under that key. Attention learned it almost immediately: loss 0.044 after 200 steps, 100% test accuracy, and after training each query put 99.9% of its weight on the matching key. An MLP given the same inputs concatenated, with 224 times as many parameters, reached 12.1%: it has no operation that compares the query with each key, so it would have to learn every combination separately.

Why scale by √d

If q and k have d independent entries of variance 1, their dot product has variance d: the scores spread out as the dimension grows. Softmax of widely spread scores is nearly one-hot, and a nearly one-hot softmax is saturated: its gradient is close to zero for every key except the winner (P2’s softmax Jacobian). Dividing by √d brings the scores back to unit variance whatever d is. Measured with random queries and keys, 64 keys per query:

Without scaling, at the head sizes real models use (64 to 128), each query already puts most of its weight on one random key before any training; at d = 1,024, 95%. With scaling the weights start spread out and the same at every d, so learning can decide where to focus. The scale is part of the definition: F.scaled_dot_product_attention applies it by default.

Masks

A mask forbids some query-key pairs by setting their scores to −∞ before the softmax, which makes their weights exactly 0 and leaves the rest summing to 1. A causal mask lets position i see only positions ≤ i, so a model trained to predict the next token cannot peek at it; measured, the weights above the diagonal summed to exactly 0. A padding mask hides padded positions in a batch of variable-length sequences (NLP P2). Using a large negative number instead of −∞ almost works; using 0 does nothing at all, because a score of 0 is an ordinary score.

Multi-head attention

One attention operation produces one weighted average per position, so it can follow one kind of relationship at a time. Multi-head attention runs h smaller attentions in parallel, each with its own query, key and value maps of width d/h, and concatenates their outputs before a final linear map. With the same total width it costs about the same, and different heads can attend to different things: one to the previous token, one to a matching bracket, one to the subject of a sentence.

B, n, d = x.shape; h = 8; dk = d // h
q, k, v = self.qkv(x).chunk(3, -1)                       # each (B, n, d)
split = lambda t: t.view(B, n, h, dk).transpose(1, 2)        # (B, h, n, dk): h independent attentions
y = F.scaled_dot_product_attention(split(q), split(k), split(v), is_causal=True)
y = self.out(y.transpose(1, 2).reshape(B, n, d))         # concatenate heads, mix them

The cost of attention

Every query scores every key, so the score matrix has n × n entries per head: compute grows as n² and, in the textbook version, so does memory. For one layer of 8 heads in fp16 the score matrix alone is 4 MB at 512 tokens and 4 GB at 16,384; the four-line implementation needed 8.2 GB at peak there, because the scores and the softmax output both exist at once. PyTorch’s F.scaled_dot_product_attention dispatches to a fused kernel (FlashAttention or a memory-efficient variant) that computes the softmax in tiles and never stores the n × n matrix:

Use case: matching invoice lines to purchase orders

A finance team matches each line of an incoming invoice to the most likely line of the corresponding purchase order: different wording, different order, sometimes a line split in two. A cross-attention layer, with invoice lines as queries and purchase-order lines as keys and values, learns the matching directly: each invoice line’s attention weights over the order lines are the match probabilities, readable for an auditor. It is the lookup task of this chapter, with learned keys, and it handles any number of lines without retraining.

⚠️
Common mistakes
  • Forgetting the 1/√d: weights start nearly one-hot (largest weight 0.79 at d = 64, 0.95 at 1,024).
  • Masking with 0 instead of −∞: a score of 0 is not a mask.
  • Softmax over the wrong axis: it must normalise over keys, the last dimension of the scores.
  • Writing attention by hand for long sequences: 8.2 GB at 16,384 tokens; use the fused kernel.
  • Mixing up the transposes when splitting heads: (B, n, h, d/h) must become (B, h, n, d/h) before the matmul.

Interview drill

Explain it simply: What is attention, and why divide by √d?

How a strong answer sounds
Attention is a differentiable lookup. Each position has a query, and every position has a key and a value; the scores are query-key dot products, softmax turns them into weights that sum to 1, and the output is the weighted average of the values. The division by √d keeps the scores at unit variance: with d independent unit-variance entries, a dot product has variance d, and a softmax of widely spread scores is nearly one-hot, saturated, with tiny gradients for most keys. I measured random queries and keys: unscaled, the largest weight was 0.79 at d = 64 and 0.95 at d = 1,024; scaled, it stayed around 0.11 at every d.

Deeper: What are attention’s time and memory costs in sequence length, and how do fused kernels change them?

How a strong answer sounds
For n tokens and width d, computing all scores is O(n²d) time and the score matrix is O(n²) memory per head. A naive implementation materialises that matrix and its softmax, so memory grows quadratically: I measured 8.2 GB for one 8-head layer at 16,384 tokens. FlashAttention-style kernels tile the computation, keep running softmax statistics, and never write the n × n matrix to memory, so memory becomes linear in n and the kernel is faster because it moves far less data; I measured 16 MB and about three times the speed. The arithmetic is still O(n²), which is why long-context work also uses sparse or linear attention and state-space models.

🧠 Key takeaways

  • Attention = softmax(QKᵀ/√d) V: a weighted average of values, weighted by query-key similarity.
  • It solved a key-value lookup with 14,496 parameters where an MLP with 3.25 million could not.
  • Divide by √d: unscaled weights collapse onto one key as d grows (entropy 0.13 vs 3.69 at d = 1,024).
  • Masks set forbidden scores to −∞; multi-head attention runs several smaller attentions in parallel.
  • Cost is O(n²); fused kernels keep the arithmetic but cut memory from 8.2 GB to 16 MB at 16,384 tokens.
