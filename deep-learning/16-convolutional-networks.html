Convolutional Networks: the Core Idea

An MLP treats an image as 784 unrelated numbers. It must learn separately that an edge in the top-left corner and the same edge in the bottom-right corner mean the same thing, and it would need a weight for every pair of input and output pixels. A convolutional layer builds in two facts about images: nearby pixels matter together (locality), and a pattern means the same thing wherever it appears (weight sharing). It slides one small filter over the whole image, so a 3 × 3 filter has 9 weights per input channel whatever the image size.

This chapter writes a convolution as a matrix multiply and measures what those two assumptions buy. Our im2col convolution matched cuDNN to within its TF32 rounding (0.002), and showed why libraries avoid materialising it: 144 MB of patches for a 16 MB input. With the same 140,000 parameters, a small CNN beat an MLP by 2.5 points on Fashion-MNIST and 22 points on CIFAR-10. Shifting every test image six pixels to the side cost the CNN 24 points and left the MLP at 10.9%, which is chance. The deep dive into CNN architectures is the Computer Vision course; this is the mechanism.

Locality and weight sharing

A convolutional layer with C_in input channels, C_out output channels and a k × k kernel has C_out × C_in × k × k weights plus C_out biases. For 64 → 128 channels with 3 × 3 kernels that is 73,856 parameters, the same for a 32 × 32 image as for a 1,000 × 1,000 one. A fully connected layer mapping the same 64 × 32 × 32 input to a 128 × 32 × 32 output would need 8.6 billion weights. The convolution is the fully connected layer with almost every weight forced to zero (locality) and the rest forced to be copies of one another (sharing).

conv = nn.Conv2d(64, 128, kernel_size=3, padding=1)     # weight (128, 64, 3, 3): 73,728 + 128 bias
y = conv(x)                                          # x (B, 64, 32, 32) -> y (B, 128, 32, 32)
# output size per dimension: floor((H + 2·padding − kernel) / stride) + 1
#   3×3, padding 1, stride 1: 32 -> 32     3×3, padding 0: 32 -> 30     3×3, padding 1, stride 2: 32 -> 16

Convolution as a matrix multiply

At every output position, a convolution takes the dot product of the kernel with the k × k × C_in patch of input under it. im2col makes that a single matrix multiply: unfold every patch into a column (here 64 × 3 × 3 = 576 numbers per patch, 1,024 patches per image), flatten the kernel into a row per output channel, and multiply.

def conv_im2col(x, w, b, stride=1, padding=1):
    B, C, H, W = x.shape; O, _, k, _ = w.shape
    cols = F.unfold(x, k, padding=padding, stride=stride)     # (B, C·k·k, L) = (64, 576, 1024): every patch as a column
    out = w.view(O, -1) @ cols + b[:, None]                  # (128, 576) @ (64, 576, 1024) -> (64, 128, 1024)
    Ho = (H + 2 * padding - k) // stride + 1; Wo = (W + 2 * padding - k) // stride + 1
    return out.view(B, O, Ho, Wo)
# against F.conv2d: max |difference| 0.002 (cuDNN uses TF32 for convolutions by default)

On a batch of 64 images of 64 channels at 32 × 32, the im2col version took 1.22 ms and cuDNN 0.36 ms for the same 9.7 GFLOP. The difference is memory: each input value is copied into 9 columns, so the 16 MB input became a 144 MB patch matrix that must be written and read back. cuDNN computes the same product without ever building it, using tiled “implicit GEMM”, Winograd or FFT algorithms, and torch.backends.cudnn.benchmark = True lets it time several and keep the fastest for your shapes. The backward pass is the same idea in reverse: the gradient for the kernel is a matrix multiply of the output gradient with the patches, and the gradient for the input scatters the patches back with F.fold.

Padding, stride, channels and pooling

Padding adds zeros around the border so a 3 × 3 convolution keeps the size (padding 1). Stride moves the filter more than one pixel at a time, downsampling. Channels are separate feature maps: the first layer turns 1 or 3 colour channels into, say, 32 learned features, each the response of one filter at every position. Max pooling keeps the largest value in each 2 × 2 window, halving the resolution, adding a little tolerance to small shifts, and cheaply widening what later layers can see. A typical block is two convolutions then a pool, with the channel count doubling as the resolution halves.

Receptive fields

A unit’s receptive field is the patch of the input that can influence it. One 3 × 3 convolution sees 3 × 3 pixels; a second on top sees 5 × 5; a 2 × 2 pool doubles the step between later units, so each subsequent 3 × 3 convolution adds 4 pixels instead of 2. Through the stack used here, the receptive field grows 3, 5, 6 (pool), 10, 14, 16 (pool), 24, 28: by the last layer, each unit can see the whole 28 × 28 image. This is how a CNN combines local evidence into global decisions: early layers see edges, middle layers see parts, late layers see objects (Chapter 1’s probes measured the same progression from the outside). Stacking small kernels is also cheaper than one large one: two 3 × 3 layers see 5 × 5 with 18 weights per channel pair, against 25 for one 5 × 5 layer, and get an extra non-linearity in between.

On Fashion-MNIST, where garments are centred, an MLP can memorise where things usually are and the CNN’s lead is modest. On CIFAR-10, where objects appear anywhere at any size, it is 22 points. The shift test isolates the assumption: moving Fashion-MNIST images six pixels to the right, a translation no training image showed, took the MLP from 88.4% to chance, because every one of its weights is tied to a pixel position. The CNN lost 24 points: convolution is equivariant to shifts (shift the input, the feature maps shift too) but padding, pooling boundaries and the wrap-around of the shift break perfect invariance. Data augmentation with random crops (Chapter 1’s CNN, Computer Vision Chapter 5) teaches the rest.

Use case: convolutions that are not about images

An audio team detects a short alarm sound in 10-second microphone clips. An MLP on the raw spectrogram works only when the alarm falls at the time position it was trained on. A 1-D convolution over time (nn.Conv1d, the frequency bins as channels) shares the same detector across every time step, so it finds the alarm wherever it occurs, with a fraction of the parameters. The same idea applies to any signal where a pattern can occur anywhere along an axis: sensor time series, genomic sequences, log events.

⚠️
Common mistakes
  • Forgetting padding: each unpadded 3 × 3 convolution shrinks the image by 2 pixels.
  • Assuming CNNs are shift-invariant: a 6-pixel shift still cost this CNN 24 points; augment.
  • Materialising im2col yourself in production: 9× the memory; use the library convolution and cudnn.benchmark.
  • Channels-first vs channels-last confusion when loading images: PyTorch wants (B, C, H, W).
  • A receptive field smaller than the object: late layers must see the whole thing; add depth or pooling.

Interview drill

Explain it simply: Why do CNNs work better than MLPs on images?

How a strong answer sounds
They build in two properties of images. Locality: a unit only looks at a small neighbourhood, because nearby pixels are what form edges and textures. Weight sharing: the same filter is applied at every position, so a pattern learned in one place is recognised everywhere, and the parameter count does not depend on image size. Stacking layers grows the receptive field so later units see larger structures. I measured a CNN and an MLP with the same 140,000 parameters: 71% against 49% on CIFAR-10, and when I shifted Fashion-MNIST test images by six pixels, the MLP fell to chance while the CNN kept 67%.

Deeper: A 3 × 3 convolution maps 64 channels to 128 on a 32 × 32 input with padding 1. Give the output shape, parameters and FLOPs, and describe how it maps to a matrix multiply.

How a strong answer sounds
Output (B, 128, 32, 32), since padding 1 keeps the size. Parameters: 128 × 64 × 3 × 3 = 73,728 weights plus 128 biases. Each output value is a dot product of length 576, so the multiply-adds are 128 × 32 × 32 × 576 ≈ 75.5 million per image, about 151 MFLOP, or 9.7 GFLOP for a batch of 64. With im2col you unfold each 3 × 3 × 64 patch into a column, giving a (576, 1,024) matrix per image, and multiply by the kernel reshaped to (128, 576). In practice cuDNN avoids building that matrix, which is 9 times the input’s size; I measured 1.22 ms for the explicit version against 0.36 ms for cuDNN.

🧠 Key takeaways

  • Convolution = locality + weight sharing: 73,856 parameters for 64 → 128 channels at any image size.
  • It is a matrix multiply over unfolded patches (im2col); libraries avoid building the 9× larger patch matrix.
  • Output size = ⌊(H + 2p − k) / s⌋ + 1; padding 1 keeps size, stride 2 halves it.
  • Receptive fields grow with depth and pooling (3 → 28 pixels here), so late layers see whole objects.
  • At equal parameters the CNN beat an MLP by 2.5 (Fashion-MNIST) and 22 (CIFAR-10) points, and held up far better under shifts.

⌊(32 + 2 − 3) / 2⌋ + 1 = 16.

What does im2col do?

Two stacked 3 × 3 convolutions (stride 1) have what receptive field?
