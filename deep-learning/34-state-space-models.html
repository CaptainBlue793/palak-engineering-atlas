State-Space Models & Long Sequences

Attention compares every position with every other, so its cost grows with the square of the sequence length, and generating each new token means reading a cache of every previous one. Recurrent networks carry a fixed-size state instead, but train one step at a time and forget (Chapter 17). State-space models (SSMs) are linear recurrences designed to get the best of both: during training the whole sequence is processed in parallel, as a convolution or a scan, and during generation they run as a recurrence with a state that does not grow.

This chapter builds two from scratch and measures them. An S4D layer computed as a recurrence and as an FFT convolution agreed to 9 × 10⁻⁶. A selective, Mamba-style layer, whose dynamics depend on the input, computed with a parallel scan matched a step-by-step loop to 8 × 10⁻⁵. On sequential MNIST, digits read one pixel at a time for 784 steps, S4D reached 98.9% with 43,000 parameters where an LSTM managed 85.6% and a transformer 96.3%. On selective copying the tables turned: S4D managed 50.3%, while attention and the selective SSM reached 100% and 99.9%. Generating a token cost an SSM a constant 0.031 ms, against 10.2 ms for attention over a 262,144-token cache. And the honest part of the comparison: in training at these lengths, a fused attention kernel was faster and leaner than my straightforward SSM implementations, which shows how much of the SSM advantage lives in specialised kernels.

Recurrence vs attention cost

For a sequence of length L, attention does work proportional to L² in training and, when generating, reads all L cached keys and values for every new token. A recurrence does work proportional to L and carries a fixed-size state. Generating one token after a context of length L, measured for one layer of width 256 (attention with 8 heads over a bf16 KV cache; an SSM state of 512 channels × 16):

The SSM’s step cost and its 32 KB state were the same at every length; attention’s grew in proportion to the context, 330 times slower at 262,144 tokens. That is the property that makes SSMs attractive for long-context generation, streaming audio and genomics: memory and latency that do not depend on how much has been seen. The training side, measured below, is more nuanced.

Linear state-space layers

A state-space model describes a continuous system: a hidden state x(t) evolves as x′ = A x + B u, driven by the input u, and the output is y = C x + D u. To run it on a sequence, it is discretised with a step size Δ. With zero-order hold, Ā = exp(ΔA) and B̄ = (Ā − 1)A⁻¹B, and the layer becomes a linear recurrence:

x_k = Ā · x_{k−1} + B̄ · u_k          # a fixed-size state, updated once per step
y_k = Re(C · x_k) + D · u_k

S4D (Gu et al., 2022) makes A diagonal and complex, so each state dimension is an independent damped oscillator, initialised with decay rates and frequencies spread out so that some remember for a few steps and others for thousands. That initialisation, not the architecture alone, is what lets these models hold information across very long sequences, where an LSTM’s memory fades. Each layer here has 256 channels × 32 complex modes; layers are stacked with a non-linearity and a mixing linear layer between them.

The convolutional view for training

Because the recurrence is linear and time-invariant, unrolling it gives y = K ∗ u + D·u, a convolution with the kernel K_l = Re(C · Ā^l · B̄). The whole kernel for a sequence of length L can be computed at once, and the convolution done with the FFT in O(L log L), all positions in parallel. Run both ways on the same random input, the S4D layer’s outputs agreed to a maximum difference of 8.8 × 10⁻⁶ on values of size about 1: train as a convolution, generate as a recurrence.

K = 2 * (C * (A_bar - 1) / A)[..., None] * A_bar[..., None] ** torch.arange(L)   # (H, modes, L), summed over modes
y = torch.fft.irfft(torch.fft.rfft(u, n=2*L) * torch.fft.rfft(K.sum(1).real, n=2*L), n=2*L)[..., :L]

Attention’s time grew close to quadratically beyond 4,096 tokens, as theory says, yet it was still the fastest and leanest at every length measured. The reason is implementation, not mathematics. FlashAttention is a fused kernel that never stores the attention matrix (Chapter 23). My S4D materialises the whole kernel as a (channels × modes × length) complex tensor before summing it, 16.6 GB at 65,536 tokens; production S4 implementations compute it with a specialised Cauchy or Vandermonde kernel in a fraction of the memory. My selective scan, below, materialises its full (length × channels × state) tensor, which real Mamba avoids with a fused CUDA kernel that keeps the state in on-chip memory. The asymptotic advantage of SSMs is real; collecting it needs kernels as engineered as attention’s.

Selective state spaces

S4D’s dynamics are the same at every step: Ā, B̄ and C do not depend on the input. That is what makes the convolution possible, and it is also a limit. A time-invariant system cannot decide, based on what it is reading, to remember this token and ignore that one; every input is mixed in with the same fixed weights. Selective SSMs (Mamba, Gu and Dao, 2023) make the step size Δ, and B and C, functions of the current input. A large Δ lets the input overwrite the state; a small one keeps the state and largely ignores the input. The price is that the kernel is no longer fixed, so there is no convolution; instead the recurrence h_t = a_t h_{t−1} + b_t is computed for all t with a parallel scan, here in log space:

# h_t = Σ_{s≤t} (Π_{r=s+1..t} a_r) b_s  =  exp(P_t) · Σ_{s≤t} exp(−P_s) b_s,  with P = cumsum(log a)
P = torch.cumsum(log_a, -1)
h = torch.exp(P + torch.logcumsumexp(torch.log(b_pos) - P, -1)) - (same for b_neg)   # signs handled separately

Against a plain loop over time steps on the same input, the scan’s outputs agreed to 8.2 × 10⁻⁵, a little looser than the convolution because of the exponentials. It is a parallel algorithm, but a memory-hungry one written this way, as the training-cost table showed.

Long-range tasks measured

Two tasks with opposite demands. Sequential MNIST feeds a 28 × 28 digit one pixel at a time, 784 steps, and asks for its class at the end: a long-range dependency with no need to be selective. Selective copying scatters 16 data tokens among 240 blanks at random positions and asks for the 16 tokens in order at the end: the model must decide, based on content, what to store.

Model (4 layers, width 64)ParametersSequential MNISTSelective copying
LSTM (128 units)101k85.6%54.5%
Transformer251k96.3%100.0%
S4D (time-invariant)43k98.9%50.3%
Selective SSM182knot run (see below)99.9%

The two tasks separate the models cleanly. On sequential MNIST, where the answer depends on the whole 784-step sequence but nothing has to be chosen, the time-invariant S4D was the best model by 2.6 points with a sixth of the transformer’s parameters, and the LSTM, whose memory fades over hundreds of steps (Chapter 17), was far behind. On selective copying the order flipped. Chance is 12.5%; S4D reached only 50.3% and the LSTM 54.5%, while attention, which can look up any earlier position, solved it, and so did the selective SSM, at 99.9%: making Δ, B and C depend on the token lets the state ignore the blanks and store the data tokens. That is the result Gu and Dao used to motivate Mamba, reproduced. One honest gap: the selective SSM was not run on sequential MNIST, because my naive scan at 784 steps and batch 64 filled the 16 GB GPU, spilled into system memory and slowed to a crawl; a fused scan kernel is what makes that length practical.

Use case: wake-word detection on a smart speaker

A device team needs a model that listens continuously and flags a wake word, running on a small processor with a fixed memory budget. A transformer over a sliding window of the last two seconds would recompute attention for every new frame and hold a growing cache. A stack of S4-style layers is trained in parallel on recorded audio as a convolution, then exported as a recurrence: each new 10 ms frame updates a state of a few kilobytes in constant time, no matter how long the speaker has been listening. The team checks the exported recurrent model against the convolutional one on a test set, frame by frame, before shipping, exactly the equivalence measured in this chapter.

⚠️
Common mistakes
  • Assuming O(L) beats O(L²) in practice: a fused attention kernel beat my naive SSMs at every length up to 65k.
  • Materialising kernels or states: my S4D kernel took 16.6 GB at 65k tokens; production code avoids it.
  • Using a time-invariant SSM for content-dependent memory: it cannot choose what to store.
  • Skipping the recurrence check: verify that the convolutional and recurrent forms agree before deploying the recurrent one.
  • Ignoring initialisation: SSMs owe their long memory to carefully spread decay rates, not to the recurrence alone.

Interview drill

Explain it simply: What is a state-space model, and why can it train like a convolution and run like an RNN?

How a strong answer sounds
It is a linear recurrence: a hidden state updated as x_k = Ā x_{k−1} + B̄ u_k, with output y_k = C x_k, discretised from a continuous system. Because it is linear and the matrices do not change over time, unrolling it gives a convolution with kernel C Ā^l B̄, which can be applied to a whole sequence at once with the FFT for training. At generation time you run the recurrence: one small state update per token. I checked both forms of an S4D layer and they agreed to 9e-6. The payoff is generation cost: a constant 0.03 ms per token, against attention’s 10 ms at a 262k-token context.

Deeper: Why did Mamba make the SSM parameters depend on the input, and what did that cost?

How a strong answer sounds
A time-invariant SSM mixes every input into its state with the same fixed weights, so it cannot decide based on content what to keep, which matters for tasks like selective copying or in-context recall. Making the step size and the B and C projections functions of the input lets the model gate what it writes and reads. The cost is that the convolution no longer exists, so training needs a parallel scan over the sequence, and a naive scan materialises a length by channels by state tensor: mine ran out of memory at 65k tokens. Mamba’s contribution was as much the fused, hardware-aware scan kernel as the selectivity itself.

🧠 Key takeaways

  • SSMs generate with a fixed-size state: 0.031 ms per token at any context, against attention’s 10.2 ms at 262k.
  • A time-invariant SSM is both a recurrence and a convolution; both forms agreed to 9 × 10⁻⁶.
  • On 784-step sequential MNIST, S4D reached 98.9% with 43k parameters (LSTM 85.6%, transformer 96.3%).
  • Selective SSMs make dynamics input-dependent, which needs a scan instead of a convolution.
  • Asymptotic advantages need engineered kernels: fused attention beat my naive SSM code in training.
