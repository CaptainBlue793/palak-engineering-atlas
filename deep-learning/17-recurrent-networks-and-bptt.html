Recurrent Networks & Backprop Through Time

A sequence of any length can be read one step at a time by applying the same small network over and over, carrying a hidden state from each step to the next. That is a recurrent neural network: weight sharing again, this time across time instead of across positions in an image. Training it means unrolling the loop into a very deep network, one layer per time step, all with the same weights, and backpropagating through all of them. Everything Chapters 9 and 15 said about depth applies, now with depths of hundreds or thousands.

This chapter measures the consequences. A hand-written tanh cell matched nn.RNN. Pushing a gradient back 100 steps through a recurrent matrix scaled to spectral radius 0.5 left 10⁻¹⁵ of it; at 1.5 it grew to 10¹⁷: vanishing and exploding are the same multiplication either side of 1. Gradient clipping turned a run whose first gradient (norm 196) wrecked it into one that solved the task (loss 2.10 against 0.002). On a task that requires remembering the first token through 30 steps of noise, a plain LSTM and a GRU stayed at chance; an LSTM whose forget gate started open solved it perfectly. At 100 steps nothing did. NLP Chapter 9 applies these networks to text; this chapter is the mechanism.

Recurrence and hidden state

At every step t the cell combines the current input with the previous hidden state: h_t = tanh(W_x x_t + W_h h_{t−1} + b). The same W_x, W_h and b are used at every step, so a sequence of 10 or 10,000 steps uses the same parameters. The hidden state is the network’s only memory of everything before step t.

h = torch.zeros(B, H)                                       # h_0
for t in range(T):                                         # x (B, T, D)
    h = torch.tanh(x[:, t] @ W_x.t() + h @ W_h.t() + b)   # (B, H): the same weights every step
    outs.append(h)
# matched nn.RNN (cuDNN) to 4e-4, its TF32 rounding; nn.LSTM and nn.GRU replace this line with gated updates

Unrolling and BPTT

To train, unroll the loop: T steps become T layers that share weights. Backpropagation through time is ordinary backprop on that unrolled graph; because the weights are shared, each one’s gradient is the sum of its gradients from every step. It costs memory proportional to T, since every step’s hidden state must be kept for the backward pass, and it is sequential: step t cannot be computed before step t − 1, which is the fundamental reason transformers (Chapter 19) replaced RNNs for long text on GPUs.

The gradient of the last hidden state with respect to one k steps earlier is a product of k Jacobians, each W_hᵀ times the tanh derivatives at that step. Roughly, its size behaves like ρᵏ, where ρ is the spectral radius of W_h (its largest eigenvalue in absolute value). Measured with a 64-unit recurrent matrix scaled to each radius:

Below 1 the gradient vanishes exponentially: with ρ = 0.9 a hundred steps leave 10⁻⁵ of it (10⁻⁷ with tanh), so whatever happened 100 steps ago has no influence on learning. Above 1 a linear recurrence explodes; tanh limits the explosion, because its derivative shrinks when units saturate, but that same saturation then makes the gradient vanish. There is a knife edge at ρ ≈ 1, and training moves W_h off it.

Exploding gradients and clipping

An exploding gradient does damage in a single step: one update of size lr × (huge) throws the weights into a region where the units saturate, and the network may never recover. Gradient clipping rescales the whole gradient vector whenever its norm exceeds a threshold, keeping its direction and capping its size. Measured on a vanilla RNN deliberately initialised with a large recurrent matrix: the first gradient had norm 196. Without clipping, that one step sent the loss to 2.10, chance level for 8 classes, where it stayed for 1,500 steps. With the norm clipped at 1.0, the same run solved the task (loss 0.0023). Clipping costs one line and is standard for RNNs and transformers alike.

loss.backward()
gn = torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # returns the norm before clipping: log it
opt.step()

Vanishing gradients and gates

Clipping cannot help a gradient that is too small. The fix for vanishing is architectural: gated cells. An LSTM keeps a separate cell state c_t updated additively, c_t = f_t ⊙ c_{t−1} + i_t ⊙ g_t, where the forget gate f_t, a sigmoid, decides how much of the old state to keep. When f_t ≈ 1 the cell state passes through a step almost unchanged, and so does its gradient: the same idea as a residual connection (Chapter 15), applied through time. A GRU does something similar with fewer gates. The memory task measures it: output the first of T tokens after T − 1 tokens of noise.

Gates alone did not solve 30 steps: with PyTorch’s default initialisation the forget gate starts near σ(0) = 0.5, so the cell state halves every step and the useful gradient shrinks like 0.5³⁰ ≈ 10⁻⁹, and the default LSTM and GRU learned nothing (their largest gradient norm in training was 0.23 to 0.34). Setting the forget-gate bias to 1, so the gate starts near σ(1) = 0.73 and leans towards remembering, solved it completely; that one-line change was proposed by Gers et al. in 2000 and is still easy to forget, and NLP Chapter 9 found the same. At 100 steps every configuration failed within this budget. Long-range memory remains hard for recurrent networks, which is part of why attention (Chapter 18) and state-space models (Chapter 34) exist.

lstm = nn.LSTM(D, H, batch_first=True)
with torch.no_grad():                                        # gate order in PyTorch: input, forget, cell, output
    lstm.bias_ih_l0[H:2 * H].fill_(0.5); lstm.bias_hh_l0[H:2 * H].fill_(0.5)   # forget bias 1 in total

Truncated BPTT

For a long stream, such as a whole book, full BPTT is impossible: memory grows with the length. Truncated BPTT cuts the stream into windows of k steps, carries the hidden state from one window to the next (so the forward pass still sees the past), but stops the gradient at each window boundary with h.detach(). Gradients then reach back at most k steps. Measured on a character-level LSTM language model with the same 2 million training characters for each k: windows of 5 reached 2.43 bits per character, 20 reached 2.55, and 100 reached 2.82. That ordering is a budget effect, not a statement that short windows model language better: with a fixed number of characters, k = 5 made 20 times as many optimiser updates as k = 100 (and took 15 s against 3.1 s, since short windows use the GPU poorly). Longer windows let gradients teach longer dependencies, but each update is more expensive in data. In practice k is chosen as long as memory allows, with enough total training to exploit it.

Use case: predicting machine failures from sensor streams

A factory streams vibration and temperature readings from each machine once a second and wants an alarm an hour before a bearing fails. A GRU reads the stream online, one reading at a time, which suits a model that must run continuously on a small edge device with constant memory. Trained with truncated BPTT over 10-minute windows and gradient clipping, it learns short-term signatures well; the hour-long drift that precedes failures is handled better by feeding hourly summary features alongside the raw stream, because 3,600 steps is far beyond what the gradient can reach. Recurrent models remain a good choice exactly here: streaming, constant memory, short-range structure.

⚠️
Common mistakes
  • No gradient clipping on an RNN: one exploding step left this run at chance for 1,500 steps.
  • Default forget-gate bias: the LSTM could not learn a 30-step dependency; bias 1 solved it.
  • Forgetting detach() between windows in truncated BPTT: the graph grows without bound and memory runs out.
  • Expecting an RNN to learn 100-step dependencies easily: none did here.
  • Comparing window lengths at a fixed data budget without noting the update count differs.

Interview drill

Explain it simply: Why do vanilla RNNs have trouble with long sequences?

How a strong answer sounds
Backprop through time multiplies the gradient by the recurrent Jacobian once per step, so the gradient from k steps back scales roughly like the recurrent matrix’s spectral radius to the power k. Below 1 it vanishes exponentially and the network cannot learn long-range dependencies; above 1 it explodes and a single update can wreck training. I measured a 64-unit recurrence: after 100 steps the gradient was 10⁻⁵ at radius 0.9 and 10¹⁷ at radius 1.5. Clipping fixes explosion; gated cells like LSTMs, with their additive cell state, fix much of the vanishing, especially with the forget-gate bias initialised to 1.

Deeper: What is truncated BPTT, and what does it give up?

How a strong answer sounds
You split a long sequence into windows of k steps, carry the hidden state from one window to the next so the forward pass still sees the whole history, but detach it at each boundary so the backward pass only goes k steps back. Memory becomes proportional to k instead of the sequence length, and you get an update every k steps. What you give up is gradient signal for dependencies longer than k: the model can still use long-range information in the forward pass if it learned to keep it, but nothing teaches it to keep information for longer than k steps. Comparisons of k at a fixed data budget are confounded by the number of updates, which I saw on a character model where k = 5 beat k = 100 simply by making 20 times as many updates.

🧠 Key takeaways

  • An RNN applies the same cell at every step; BPTT is backprop through the unrolled loop, summing gradients over steps.
  • Gradients scale like ρᵏ: 10⁻¹⁵ at ρ = 0.5 and 10¹⁷ at ρ = 1.5 after 100 steps here.
  • Clipping the gradient norm stops a single exploding step from wrecking training.
  • Gates give an additive path through time; an LSTM needs its forget bias near 1 to use it (30-step memory: 12.7% → 100%).
  • Truncated BPTT bounds memory by k but only teaches dependencies up to k steps.
