Backpropagation on Tensors

Chapter 3’s engine computed correct gradients one scalar at a time and was 2,479 times slower than PyTorch. The fix is not a cleverer algorithm but a coarser one: treat a whole layer as one operation on tensors, and write its backward rule once, as a few matrix multiplies. A linear layer, a ReLU and a softmax-plus-cross-entropy loss need about fifteen lines of backward code between them, and with those you can train a real network without autograd at all.

This chapter writes that code for a 784-256-256-10 MLP and holds it to account. In float64 its gradients matched PyTorch’s autograd to a relative error of 10⁻¹⁶ in every layer, and finite differences agreed to 4 × 10⁻⁸. Trained on Fashion-MNIST with plain SGD it reached 87.1%, against 86.9% for the identical autograd model. Then three plausible bugs are planted. Forgetting to divide by the batch size, or to subtract 1 at the true class, collapsed training to 10%. Averaging the bias gradient instead of summing it trained to 86.9%, indistinguishable from correct, and only a gradient check, wrong by 98%, gave it away. Backward cost 1.4 times the forward pass.

  • Backpropagate through an element-wise activation as a mask
  • Use the fused softmax cross-entropy gradient, (p − onehot) / B

Backward of a linear layer

PyTorch stores a linear layer’s weight as (out, in) and computes z = x Wᵀ + b for a batch x of shape (B, in). Backprop hands the layer dz = ∂L/∂z, shape (B, out), and needs three things: dW (shape of W), db (shape of b) and dx (shape of x, to pass to the layer below). As in P2, only one product of the available matrices has each shape:

# forward:  z = x @ W.t() + b          x (B, in), W (out, in), b (out,), z (B, out)
dW = dz.t() @ x                       # (out, B) @ (B, in) = (out, in): sums the B per-example outer products
db = dz.sum(0)                       # (out,): b was broadcast over the batch, so its gradient sums over it
dx = dz @ W                           # (B, out) @ (out, in) = (B, in): what the layer below receives

The backward pass needs x, the layer’s input, to compute dW. That is why the forward pass keeps activations around (and why P4 measured 3.5 times more memory with autograd on). It does not need z, the output, for these three formulas.

Backward of activations

An element-wise activation h = φ(z) has a diagonal Jacobian, so its backward pass is element-wise too: dz = dh ⊙ φ′(z). For ReLU, φ′ is 1 where z > 0 and 0 elsewhere, so the backward pass is a mask, and the network must keep either z or the mask. A unit whose input was negative passes back nothing; if that is true for every example, the unit is dead (Chapter 6).

h = z.clamp_min(0)                    # forward ReLU, (B, 256)
dz = dh * (z > 0)                     # backward: gate the gradient with the forward mask
# tanh:    dz = dh * (1 - h**2)          uses the output h
# sigmoid: dz = dh * h * (1 - h)         uses the output h

The softmax cross-entropy gradient

The loss is the mean over the batch of −log softmax(z)[y]. Backpropagating softmax on its own would mean a (10 × 10) Jacobian per example (P2); combined with the log and the mean, the algebra collapses to something much simpler. With p = softmax(z):

∂L/∂z = (p − onehot(y)) / B

Each example pushes its own probabilities down and its true class’s probability up, by exactly how wrong it was, and the 1/B comes from taking the mean. Fusing the softmax and the loss into one backward rule is cheaper and avoids the numerical trouble of differentiating a log of a probability that has rounded to 0, which is why frameworks provide cross_entropy rather than softmax followed by log and nll.

def backward(params, cache, logits, y):
    B = len(y)
    dz = logits.softmax(1)                         # (B, 10)
    dz[torch.arange(B), y] -= 1                    # p - onehot(y)
    dz /= B                                        # the mean over the batch
    grads = []
    for k in reversed(range(len(params))):           # last layer first
        W, b = params[k]; x_in = cache.inputs[k]   # the input this layer saw in the forward pass
        grads.insert(0, (dz.t() @ x_in, dz.sum(0)))
        if k > 0:
            dz = (dz @ W) * (cache.pre[k - 1] > 0)   # through the linear layer, then the ReLU mask
    return grads

Gradient checking

A hand-written backward pass is checked two ways. Against autograd, compare whole gradient tensors by relative error ‖g_hand − g_auto‖ / ‖g_auto‖: in float64 the correct implementation scored between 0.8 × 10⁻¹⁶ and 2 × 10⁻¹⁶ in every layer, which is rounding error. Without a reference, use finite differences on a sample of individual weights (P2): twenty random weights of the first layer agreed to a relative error of at most 3.6 × 10⁻⁸ at h = 10⁻⁶. The rule of thumb: in float64, below 10⁻⁷ is correct, above 10⁻³ is a bug, and anything in between needs a closer look.

The first two bugs announce themselves. Without the 1/B, every step is 64 or 128 times too large and the loss overflows; without the −1, the gradient pushes every probability down, including the true class’s, so the logits run off to −∞. The third is the dangerous kind. Averaging instead of summing makes every bias gradient B times too small (relative error 1 − 1/64 = 0.984), so the biases barely train, and with zero-initialised biases and ReLU networks that hardly matters on this task: 86.9% against 87.1%. A model shipped with that bug would underperform somewhere it mattered, and nobody would know why. Gradient checks exist for exactly this.

Hand-written vs autograd in training

With the same initial weights and the same batches, the hand-written and autograd models produced identical sampled losses for the first 140 steps and then drifted apart slightly: after three epochs their first-layer weights differed by at most 0.0076, and their accuracies were 87.07% and 86.88%. Both are correct; they add the same numbers in a different order (autograd’s fused cross-entropy kernel, for instance), and float32 rounding differs. The difference is well within the seed-to-seed spread of P8 (standard deviation 0.27), a reminder that “matches autograd” means “to rounding error”, not bit-for-bit.

Cost of backward vs forward

A linear layer’s forward pass is one matrix multiply; its backward pass is two (dW and dx), so backward costs roughly twice the forward FLOPs, minus the first layer’s dx, which nobody needs. For a 4096-4096-4096-4096-10 MLP on a batch of 4,096 that is 413 GFLOP forward and 688 GFLOP backward. Measured, the forward pass took 15.9 ms and the hand-written backward 22.0 ms, 1.4 times as long, rather than 1.7, because the last, narrow layer and the element-wise work are cheap either way. PyTorch’s autograd did forward plus backward in 38.6 ms, the same as the sum of the two. This is where the familiar estimate comes from: training costs about three forward passes per step, one forward and two for backward.

Use case: a hand-written loss for a recommender

A recommendations team needs a sampled softmax over 2 million items: for each user, score the clicked item against 1,000 sampled negatives. They write the forward and backward passes by hand as a fused autograd.Function so that the 2-million-wide logits are never materialised. Their gradient is the same (p − onehot) / B rule as this chapter, applied only to the sampled columns, plus a correction for the sampling probability. Before it goes near training they run torch.autograd.gradcheck in float64 on a 50-item toy problem; it catches a missing 1/B on the correction term, a bug that would otherwise have shown up only as a mysteriously worse model.

⚠️
Common mistakes
  • Forgetting the 1/B from the mean: gradients 64× too large here; the loss went NaN.
  • Averaging a gradient that should be summed (biases over the batch): trained to 86.9%, invisible without a gradient check.
  • Dropping the −1 at the true class: the gradient pushes every class down; collapse to 10%.
  • Confusing W’s layout: PyTorch’s Linear stores (out, in); dW = dzᵀx has that shape, xᵀdz has its transpose.
  • Gradient checking in float32, or expecting bit-identical results to autograd in training.

Interview drill

Explain it simply: What is the gradient of softmax cross-entropy with respect to the logits, and why is it so simple?

How a strong answer sounds
It is p minus the one-hot target, divided by the batch size if the loss is a mean. Cross-entropy is −log of the softmax probability of the true class, which is −z_y + log Σ e^z. The derivative of the log-sum-exp with respect to each logit is that logit’s softmax probability, and the −z_y term contributes −1 at the true class, so the Jacobian of softmax never has to be formed. It also means a confident wrong prediction gets a gradient near −1 at the true class, which is why cross-entropy trains well. In my implementation, forgetting either the −1 or the 1/B collapsed training to chance.

Deeper: Roughly how much does a backward pass cost compared with a forward pass, and why?

How a strong answer sounds
About twice the FLOPs. Each linear layer’s forward pass is one matrix multiply, x times Wᵀ. Its backward pass needs two of the same size: dzᵀx for the weight gradient and dz times W for the input gradient, except at the first layer, where no input gradient is needed. Element-wise operations add a little. So a training step costs about three forward passes, which is the usual estimate of 6 × parameters × tokens FLOPs for training a language model. I measured a deep 4,096-wide MLP at 15.9 ms forward and 22.0 ms backward; the ratio was under 2 because the narrow last layer and element-wise work are cheap.

🧠 Key takeaways

  • Linear layer backward: dW = dzᵀx, db = Σ dz over the batch, dx = dz W; shapes pick the formulas.
  • Element-wise activations backprop element-wise; ReLU’s backward is a mask.
  • Softmax cross-entropy fuses to (p − onehot) / B: no softmax Jacobian needed.
  • Hand-written gradients matched autograd to 10⁻¹⁶ (float64); one planted bug trained normally and only a gradient check caught it.
  • Backward is about two forward passes of matrix multiplies (1.4× measured); a training step costs about three.
