IPv6

IPv4 has 4.3 billion addresses, and the world ran out of unallocated ones in 2011. NAT has hidden the shortage since, at the price of the complications in Chapter 9. IPv6 is the actual fix: addresses of 128 bits, enough to give every device a public one many times over. It has been "the future" for twenty-five years and is now the present for much of the internet. Most mobile networks are built on it, and nearly half of the traffic reaching large sites arrives over it. Day to day it is the same job as IPv4, getting packets from one address to another. The differences that matter are how the addresses are written, how a host gets one, and the fact that both versions run side by side for the foreseeable future.

Address format and shortening

An IPv6 address is 128 bits, written as eight groups of four hexadecimal digits separated by colons. Two rules make it shorter:

2001:0db8:0000:0000:0000:ff00:0042:8329      # the full form
2001:db8:0:0:0:ff00:42:8329                  # rule 1: drop leading zeros in each group
2001:db8::ff00:42:8329                       # rule 2: replace ONE run of all-zero groups with ::

The double colon may appear only once, because otherwise you couldn't tell how many groups each one stands for. A prefix length is written after a slash, as in IPv4. One convention simplifies everything else: a subnet is always a /64. The first 64 bits identify the network, and the last 64, the interface ID, identify the host within it. There is no subnet arithmetic of the Chapter 4 kind. An organisation is typically given a /48, which is 65,536 subnets, each with room for 18 billion billion hosts.

The short form follows the usual convention: lower case, no leading zeros, and the longest run of two or more zero groups replaced by a double colon (the first such run, if two are equally long). In the split, the network part is green and the interface ID is blue.

Things to notice. The first example shrinks from 39 characters to 22. ::1 and :: are complete addresses: all but the last bit zero, and all zero. 2001:db8::1::2 is rejected, because with two double colons there is no way to know how the missing groups are divided between them. In the fe80:: example the interface ID has ff:fe in its middle, the mark of an ID built from a network card's MAC address, and the panel recovers the MAC from it. That is the privacy problem that made systems switch to random interface IDs. The last example is an IPv4 address written inside an IPv6 one, a form you will meet in the logs of servers that listen on both.

SLAAC and neighbour discovery

An IPv6 host can configure itself with no DHCP server, by a process called stateless address autoconfiguration (SLAAC). It works because the interface ID is 64 bits, big enough for a host to pick one at random and be almost certain that nobody else on the link has it.

All of those messages are ICMPv6, and together they are called Neighbour Discovery. The same protocol replaces ARP (Chapter 3). To find the MAC address of a neighbour, a host sends a Neighbour Solicitation, not to everybody as a broadcast, but to a multicast group derived from the last 24 bits of the target address, which in practice only the target is listening to.

$ ip -6 addr show dev eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500
    inet6 2001:db8:1:2:9c1e:44ff:a07b:3d20/64 scope global temporary dynamic        # random, rotated daily: used for outgoing connections
    inet6 2001:db8:1:2:5a31:c0de:7f09:11b4/64 scope global dynamic mngtmpaddr     # stable for this network
    inet6 fe80::5a31:c0de:7f09:11b4/64 scope link                              # link-local: always there

$ ip -6 route show default
default via fe80::1 dev eth0 proto ra metric 100                              # the gateway is the router's link-local address
$ ip -6 neigh show                                                              # the neighbour cache: IPv6's ARP table
fe80::1 dev eth0 lladdr 00:1c:7f:3a:9b:02 router REACHABLE

An interface normally has several IPv6 addresses at once, and that is by design. DHCP still exists for IPv6, and networks use it when they want a central record of which device had which address.

Without NAT, a connection really is end to end: the address a server sees is the client's own, there is no translation table to expire or run out of ports, and two hosts can reach each other without tricks. Two consequences catch people out.

  • NAT was never the firewall, but it behaved like one. With public addresses on every device, the rule "allow replies, refuse unsolicited connections from outside" has to be stated in a real firewall (Chapter 35). Home routers ship with that rule. A network you build yourself has it only if you add it.
  • ICMPv6 must not be blocked. In IPv4, dropping all ICMP is a bad habit that mostly goes unpunished. In IPv6, ICMP is the mechanism for finding neighbours, finding routers and learning that a packet is too big for the path. A firewall that drops it gets a network where small requests work and large responses silently vanish.

Dual stack and Happy Eyeballs

IPv4 and IPv6 don't interoperate: a host with only one can't talk to a host with only the other. So the transition is to run both, dual stack. Hosts have an address of each kind, and names have both an A and an AAAA record (Chapter 10). A client must then decide which to use for each connection.

🧠
The 0.1% who made everyone wait: how Happy Eyeballs unblocked IPv6

Around 2010, large web sites had IPv6 working and kept it switched off. The reason was a measurement. For a small share of users, somewhere near one in a thousand, the computer believed it had IPv6 connectivity when it didn't, because of a misconfigured home router or a broken tunnel. Operating systems prefer IPv6 when a name has both kinds of address, so on such a machine a browser would try the IPv6 address first and wait for the connection to time out, 20 seconds or more, before falling back to IPv4. If a site published a AAAA record, those users saw it apparently hang. One user in a thousand, for a site with a billion users, is a million people who think the site is broken, so Google would give AAAA records only to networks it had checked by hand, and others published none at all. The fix came from the client side and has a memorable name. With Happy Eyeballs, standardised in 2012, the client doesn't wait. It starts the IPv6 connection, and if that hasn't succeeded within about a quarter of a second it starts an IPv4 connection as well and uses whichever completes first. Broken IPv6 now costs 250 ms where it used to cost 20 seconds. Once browsers and operating systems shipped it, the risk of publishing AAAA records disappeared, and on 6 June 2012, "World IPv6 Launch", the major sites turned IPv6 on for good.

$ dig +short example.com A example.com AAAA
93.184.216.34
2606:2800:220:1:248:1893:25c8:1946

$ curl -v https://example.com 2>&1 | grep -E 'Trying|Connected'
*   Trying [2606:2800:220:1:248:1893:25c8:1946]:443...          # IPv6 first
*   Trying 93.184.216.34:443...                                  # IPv4 started 200 ms later, in case
* Connected to example.com (2606:2800:220:1:248:1893:25c8:1946) port 443

$ curl -4 https://example.com ; curl -6 https://example.com      # force one or the other when debugging

Where running two full networks is too costly, operators run IPv6 only and translate at the edge. Many mobile networks give phones no IPv4 address at all. A gateway translates their traffic to IPv4 for the sites that still need it, with help from a DNS server that invents AAAA records for IPv4-only names. Large data centres do the same in reverse: IPv6 inside, with IPv4 terminated at the load balancers. Since 2024 at least one large cloud provider has charged for every public IPv4 address by the hour, which has made the economics of the change concrete.

⚠️
Common mistakes
  • Firewalling IPv4 and forgetting IPv6. A server with both is reachable over both. Rules must exist for each.
  • Blocking all ICMPv6. It breaks neighbour discovery and path-MTU discovery. Allow the necessary types.
  • Assuming NAT's side effects. No NAT means no accidental inbound blocking and no shared address. Write the firewall rule.
  • Storing addresses in 15-character fields, or parsing them by splitting on a colon. Use an IP address library, and brackets in URLs.
  • Comparing addresses as strings. 2001:db8::1 and 2001:0DB8:0:0:0:0:0:1 are the same address. Normalise first.
  • Testing only over IPv4. A broken AAAA record or IPv6 path affects only some users, and Happy Eyeballs hides it from you.

Interview drill

Explain it simply: What are the main differences between IPv4 and IPv6?

How a strong answer sounds
The headline is address size: 32 bits against 128, written as eight groups of hex with zero compression. That removes the scarcity that forced NAT, so in IPv6 every device can have a globally routable address and connections are end to end, with a stateful firewall doing explicitly what NAT did by accident. Subnets are a fixed /64, which leaves 64 bits for the interface ID and makes self-configuration possible: with SLAAC a host builds its own address from a prefix announced in router advertisements, with no DHCP server required. There is no broadcast; ARP is replaced by Neighbour Discovery, which uses ICMPv6 and multicast. The header is a fixed 40 bytes with no checksum, and routers don't fragment, so the sender relies on "packet too big" messages, which is one reason ICMPv6 mustn't be blocked. The two protocols don't interoperate, so networks run both, and clients use Happy Eyeballs to pick whichever connects first.

Deeper: After you add an AAAA record for a service, a few users report that the site takes a long time to start loading, and others that large pages fail to load. What do you look at?

How a strong answer sounds
Both point to a broken IPv6 path that works well enough to be attempted. A delay before loading suggests IPv6 connections aren't completing, so clients fall back to IPv4 after the Happy Eyeballs delay, or after a much longer timeout in clients that don't implement it, such as some libraries and older systems. I'd test with curl -6 from outside, check that the server and load balancer actually listen on IPv6, and check that security groups and firewalls have IPv6 rules, since those are often written for IPv4 only. Large pages failing while small ones work is the signature of a path-MTU problem: IPv6 routers don't fragment, they send an ICMPv6 "packet too big" back to the sender, and if a firewall drops ICMPv6 the sender never learns to use smaller packets, so anything bigger than the smallest MTU on the path disappears. I'd confirm with a ping at increasing sizes over IPv6 and by looking for dropped ICMPv6 on the firewall, then allow the required ICMPv6 types. If I couldn't fix it quickly I'd withdraw the AAAA record, remembering that its TTL has to run out before clients stop using it.

🧠 Key takeaways

  • IPv6 addresses are 128 bits: eight hex groups, with leading zeros dropped and one run of zero groups written as a double colon.
  • A subnet is a /64. Global addresses start with 2 or 3, link-local ones with fe80, private ones with fd, multicast with ff.
  • Hosts configure themselves from router advertisements (SLAAC), and Neighbour Discovery over ICMPv6 replaces ARP.
  • There is no NAT and no broadcast. A firewall must state what NAT used to imply, and ICMPv6 must be allowed.
  • IPv4 and IPv6 run side by side. Names have A and AAAA records, and Happy Eyeballs races the two.
  • Mobile networks and data centres increasingly run IPv6 only and translate to IPv4 at the edge.

Check your understanding

What is the shortest correct way to write 2001:0db8:0000:0000:0000:0000:0000:0001?

Leading zeros go from each group, and the single run of six zero groups becomes a double colon.

Why is 2001:db8::1::2 not a valid address?

Five groups are missing, and nothing says how they divide between the two gaps.

A host's only IPv6 address begins with fe80::. What can it reach?

It has had no router advertisement with a global prefix. The IPv6 equivalent of "no DHCP answer".

How does an IPv6 host find the MAC address of a neighbour on its LAN?

Neighbour Discovery replaces ARP, and multicast replaces broadcast.

What problem does Happy Eyeballs solve?

The client tries IPv6, starts IPv4 a moment later, and uses whichever connects first.
