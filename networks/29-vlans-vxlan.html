VLANs & Overlay Networks (VXLAN)

Physical networks are slow to change. Someone has to buy a switch and run a cable. The networks people actually want are fluid: the finance team kept apart from the guest Wi-Fi though they share a building, or ten thousand customers each with a private network of their own inside one cloud data centre, created in seconds by an API call. The way out is to separate the network that is cabled from the networks that are seen. VLANs did that first, with four bytes added to an Ethernet frame, and they still run every office. VXLAN does it at cloud scale, by carrying entire virtual networks inside ordinary IP packets. Both are the same move as the tunnels of Chapter 28, applied one layer down.

Why split a switch

Every device plugged into a switch is in one broadcast domain (Chapter 2): each ARP request and each DHCP discover reaches all of them, and any of them can talk to any other directly. On a network of a few thousand devices that is a problem three ways. Broadcasts add up to a constant background load on every machine. Anything can reach anything, so the visitor's laptop is one hop from the payroll server. And a fault spreads to everybody: a loop or a misbehaving device floods the whole network at once.

A VLAN, a virtual LAN, divides one physical switch into several logical ones. Each port is assigned to a VLAN, identified by a number. Frames arriving on a port in VLAN 10 are only ever delivered to other ports in VLAN 10. As far as the hosts can tell, they are on separate switches that happen to share a box.

802.1Q tags

Inside one switch, the VLAN of a frame is simply the VLAN of the port it came in on. When a frame has to travel to another switch, it must carry its VLAN number with it. The standard for that, 802.1Q, inserts a four-byte tag into the Ethernet header:

The VLAN ID is 12 bits, which allows 4,094 usable VLANs. Ports come in two kinds, according to whether frames on them carry the tag.

Separation at layer 2 is complete, which raises the obvious question of how engineering reaches finance's file server at all. The answer is the one from Chapter 5: through a router. Each VLAN is given its own IP subnet, and a router, or a switch that can route, has an interface in each and is the default gateway for both. Traffic between VLANs passes through that one point, which is exactly where you put the rules about who may talk to whom.

That is one of the most common faults in real networks: the hosts are configured correctly and the VLAN simply wasn't added to a trunk somewhere along the way.

VXLAN encapsulation

VLANs carried data centres for two decades, and then ran into three limits at once:

  • 4,094 isn't enough. A cloud provider needs a separate network for every customer, and has millions of them.
  • Layer 2 doesn't stretch. A VLAN must be carried, switch by switch, to everywhere its members are. Large layer-2 networks need a loop-prevention protocol that blocks redundant links, and one fault can flood all of it.
  • Virtual machines move. A VM that migrates to a server in another row must keep its IP address, which means it must stay in the same layer-2 network, wherever it physically lands.

VXLAN answers all three by turning the virtual network into a payload. A whole Ethernet frame from a virtual machine is wrapped in a VXLAN header, then in UDP (port 4789), then in an ordinary IP packet addressed from one physical server to another:

The identifier in the VXLAN header, the VNI, is 24 bits: 16 million virtual networks. The physical network underneath, the underlay, has one job, which is to route IP packets between servers. The virtual networks on top are the overlay. A VTEP learns which server each virtual MAC address lives on either by flooding and learning as a switch does, or, in most modern deployments, from a control plane that simply tells it (Chapter 39).

The wrapper costs 50 bytes (Chapter 28's panel has the arithmetic), so either the virtual machines use an MTU of 1,450, or the underlay is configured for larger frames so that a full 1,500-byte packet still fits. Clouds do the second.

The overlay is what makes a cloud's network feel like software. Two customers can both choose 10.0.0.0/16, since their packets carry different network identifiers and never meet. A virtual network is created by writing a few table entries, with no switch reconfigured. A VM can move to another server and keep its address, because only the mapping "this MAC is behind that server" changes. And the physical network can be built in the simplest and most robust way there is, pure IP routing with many equal paths, which is the subject of Chapter 30. The large clouds use their own encapsulations in place of VXLAN itself, and the design is the same. Kubernetes network plugins use the same technique to give every pod an address (Chapter 31).

🧠
November 2002: four days without a network at a Boston hospital

Beth Israel Deaconess Medical Center had a network that had grown, over years of mergers and new buildings, into one enormous layer-2 domain: thousands of devices on switches chained together, all in effect one LAN. On 13 November 2002 a researcher's application began sending an unusual volume of data. In a network of that shape the load destabilised the protocol that switches use to keep a layer-2 topology free of loops, and the network started forwarding frames in circles. A looped frame is never discarded, since Ethernet has nothing like IP's hop limit, so the traffic multiplied until every switch was saturated. Nothing could be isolated, because nothing was separate. The hospital's network was down or unusable for most of four days. Doctors wrote orders on paper, laboratory results were carried by hand, and staff who had never worked without the computer system had to be taught the paper procedures. The hospital's chief information officer, John Halamka, published a detailed account so that others would learn from it, and it has been taught ever since. The repair wasn't a better switch. It was a redesign: break the network into many small layer-2 segments with routing between them, so that a loop or a storm is confined to the segment it starts in. The same reasoning, taken to its conclusion, gives the data-centre designs of the next chapter, where layer 2 ends at the server and everything between is routed.

⚠️
Common mistakes
  • A VLAN missing from a trunk. Hosts in it on either side are configured correctly and can't reach each other. Check every trunk on the path.
  • Treating a VLAN as a security boundary by itself. It separates layer 2. The policy is in the router or firewall that connects the VLANs.
  • One VLAN, one subnet, forgotten. Two subnets in one VLAN, or one subnet across two, produce faults that look like ARP problems.
  • Stretching one layer-2 domain everywhere. Every broadcast and every loop goes with it. Keep segments small and route between them.
  • Ignoring the 50 bytes. An overlay with a 1,500-byte underlay and 1,500-byte virtual interfaces is an MTU black hole in waiting.
  • Debugging an overlay only from inside. A capture on the physical interface shows the outer UDP packets, and the fault is often in the underlay or in the mapping.

Interview drill

Explain it simply: What is a VLAN, and how do devices in different VLANs talk to each other?

How a strong answer sounds
A VLAN splits one physical switched network into several separate layer-2 networks. Each switch port is assigned to a VLAN, and the switch forwards frames, including broadcasts, only among ports in the same VLAN, so devices in different VLANs behave as if they were on different switches. Between switches, frames travel over trunk links with an 802.1Q tag, four bytes in the Ethernet header carrying a 12-bit VLAN ID, so that the receiving switch knows which VLAN each frame belongs to; on access ports to end devices the frames are untagged and the device is unaware. Because the separation is at layer 2, hosts in different VLANs can't reach each other directly. Each VLAN is its own IP subnet, and traffic between them goes through a router or a layer-3 switch that has an interface in each VLAN acting as its default gateway. That routing point is also where access rules between the VLANs are enforced.

Deeper: Why do cloud providers build their networks as overlays and not with VLANs?

How a strong answer sounds
Scale, flexibility and the simplicity of the physical network. A VLAN ID is 12 bits, about four thousand networks, and a cloud needs an isolated network per tenant, millions of them; VXLAN's identifier is 24 bits. VLANs also have to be configured on every switch along the path and kept in a contiguous layer-2 domain, which doesn't scale to a large data centre: big layer-2 networks need spanning tree, waste redundant links, and have a blast radius equal to the whole domain. With an overlay, the virtual network's Ethernet frames are encapsulated in UDP and IP by a tunnel endpoint in the hypervisor, and the physical underlay only routes IP between servers, so it can be a plain layer-3 leaf–spine fabric using all its links with equal-cost multipath. The tenant networks exist only as mappings in software, so they can be created through an API in seconds, tenants can use overlapping address ranges, and a virtual machine can move between hosts and keep its IP because only its location mapping changes. The costs are encapsulation overhead, about 50 bytes, so the underlay needs a larger MTU, and harder troubleshooting, because the path you see from inside a VM isn't the physical one.

🧠 Key takeaways

  • A VLAN divides a switched network into separate broadcast domains by assigning each port a VLAN number.
  • Between switches, an 802.1Q tag of four bytes carries the 12-bit VLAN ID. Access ports are untagged, and trunks carry many tagged VLANs.
  • Hosts in different VLANs communicate only through a router, which is where policy between them is enforced.
  • VXLAN wraps a whole Ethernet frame in UDP and IP, with a 24-bit network identifier, so virtual layer-2 networks can cross a routed network.
  • The underlay just routes IP between servers. The overlay holds the tenants' networks as mappings in software.
  • Overlays give clouds millions of isolated networks, overlapping addresses, movable VMs and API-driven changes, for 50 bytes a packet.

Check your understanding

Two PCs are plugged into the same switch, one in VLAN 10 and one in VLAN 20. One sends an ARP broadcast. Does the other receive it?

Each VLAN is its own broadcast domain, even inside one physical switch.

How does a host in VLAN 10 reach a server in VLAN 20?

The VLANs are separate subnets. Crossing between them is routing, like any two networks.

What is a trunk port?

Trunks join switches (and routers and hypervisors), and the tag tells the far end which VLAN each frame is in.

What does VXLAN put inside a UDP packet?

It is layer 2 carried over layer 3, with the VNI saying which virtual network the frame belongs to.

Two cloud customers both use the range 10.0.0.0/16 on servers in the same data centre. Why don't their packets collide?

The overlay keeps tenants apart. The underlay never sees the inner addresses.
