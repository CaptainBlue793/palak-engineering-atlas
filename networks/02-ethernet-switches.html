Ethernet, MAC Addresses & Switches

Every packet that crosses the internet spends its first and last metres inside an Ethernet frame, or a Wi-Fi frame that behaves the same way. Inside a data centre, Ethernet is the whole network. This chapter covers the frame format, the 48-bit MAC address, and the trick that makes switches work without any configuration: they learn where every host is by watching the traffic go past, and when they don't know, they send to everyone.

The Ethernet frame

Ethernet (IEEE 802.3) carries data in frames. On the wire, each frame is:

Preamble + SFD8 B Destination MAC6 B Source MAC6 B EtherType2 B Payload46–1500 B (an IP packet, ARP …) FCS4 B

The preamble (alternating 1s and 0s, then a start-of-frame delimiter) lets the receiver's clock lock on; capture tools never show it. The destination comes first so a switch can start choosing an output port after reading just 6 bytes (cut-through switching). The EtherType names the payload: 0x0800 IPv4, 0x86DD IPv6, 0x0806 ARP, 0x8100 a VLAN tag (Chapter 29). The payload must be at least 46 bytes, padded if needed, so the minimum frame is 64 bytes including the 4-byte FCS, a CRC-32 checksum. A receiver that finds a bad FCS silently drops the frame; Ethernet has no retransmission, so recovering from that is TCP's job.

MAC addresses

A MAC address is 48 bits, written as six hex bytes: 3c:22:fb:91:0a:7e. The first three bytes are the OUI (Organisationally Unique Identifier), assigned by the IEEE to a manufacturer; the rest is a serial number the vendor picks. Two bits of the first byte have special meaning:

  • The lowest bit (I/G) set means a group address: multicast, or broadcast when all 48 bits are 1, ff:ff:ff:ff:ff:ff.
  • The second-lowest bit (U/L) set means locally administered: chosen by software, not burned in. Docker containers get 02:42:…, and phones use random locally administered addresses on each Wi-Fi network for privacy. You can spot them because the second hex digit is 2, 6, A or E.
$ ip link show eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT qlen 1000
    link/ether 3c:22:fb:91:0a:7e brd ff:ff:ff:ff:ff:ff

$ python3 -c "b=0x02; print('multicast' if b&1 else 'unicast', 'local' if b&2 else 'global')"
unicast local                                     # 02:42:ac:11:00:02, a Docker container

A MAC address only means something on one link. It doesn't say where a host is, only who it is, so it can't be routed; and it's replaced at every router (P7). It's also trivially changeable in software, so it's an identifier, not a security credential.

How a switch learns

A switch has several ports and one table, the MAC address table (also called the CAM table or forwarding database): "MAC address → port". It fills the table with no configuration, using three rules:

  1. Learn: for every frame that arrives, record its source MAC against the port it arrived on (with a timestamp).
  2. Forward: look up the destination MAC. If it's in the table, send the frame out of that one port only (and drop it if that's the port it came in on).
  3. Flood: if the destination is unknown, or is broadcast, send the frame out of every port except the one it came in on.

Entries age out, typically after 300 seconds without traffic from that MAC, so the table follows hosts that move or disappear. Flooding is safe because every host's network card ignores frames whose destination isn't its own MAC (unless it's in promiscuous mode, as Wireshark puts it). One flood is enough: the reply teaches the switch where the other host is, and from then on traffic between them goes point to point.

Broadcast domains and loops

A broadcast domain is the set of hosts that receive a frame sent to ff:ff:ff:ff:ff:ff. Switches forward broadcasts everywhere, so everything connected through switches is one broadcast domain; a router doesn't forward them, so it ends the domain. Broadcasts are necessary (ARP and DHCP depend on them: Chapter 3, Chapter 19), but every host has to process every one, so very large flat L2 networks get slow and fragile. That's one reason networks are divided by routers and VLANs.

Ethernet frames have no TTL. If switches are cabled in a loop, a single broadcast is flooded round the loop forever, and copied at every switch, so within seconds the links are saturated: a broadcast storm. The Spanning Tree Protocol (STP, IEEE 802.1D, and its faster successor RSTP) prevents this: switches exchange messages, agree on a loop-free tree, and block the redundant ports until a link fails. Data-centre fabrics avoid the problem differently, by routing at layer 3 down to the rack (Chapter 30).

🧠
One patch cable, one office offline

Someone tidying a meeting room finds a loose network cable and plugs its free end into the spare port of the same small desk switch it came from. Within seconds the whole floor loses connectivity: every ARP and DHCP broadcast now loops between the two ports of that cheap unmanaged switch, which doesn't run spanning tree, and is copied to the upstream switch on every pass. The upstream port shows 100% utilisation of broadcast frames, and every host's CPU is busy discarding them. The fix is to unplug the cable; the lessons are to enable STP (or at least BPDU guard and storm control) on every access port, and that "the network is down" sometimes has a physical cause no log will show. The same storm, in a data centre, is why modern fabrics route instead of switching at scale.

⚠️
Common mistakes
  • Thinking switches are configured with MAC tables. They learn them, from the source address of every frame.
  • Thinking MAC addresses are globally routable or secret. They're local to one link, and anyone can change theirs.
  • Expecting a switch to stop broadcasts. It floods them; only routers (or VLANs) bound a broadcast domain.
  • Forgetting that a full MAC table means flooding. When the table overflows (or is attacked with fake MACs), unknown unicast floods to every port, and anyone can sniff it. Port security limits MACs per port.
  • Building loops without STP. Ethernet frames have no TTL.

Interview drill

Explain it simply: How does a switch know which port to send a frame to?

How a strong answer sounds
It learns. For every frame that arrives, it records the source MAC address against the incoming port in its MAC table. To forward, it looks up the destination MAC: if it's known, the frame goes out of that one port; if it's unknown or the broadcast address, the frame is flooded to every other port, and the hosts it wasn't for discard it. The destination's reply then teaches the switch where that host is. Entries age out after a few minutes of silence, so the table tracks hosts that move. No configuration is needed, which is why you can plug a switch in and it just works.

Deeper: A VM live-migrates to a host on another switch port. Why might it be unreachable for a few minutes, and how do hypervisors avoid that?

How a strong answer sounds
The switches still have the VM's MAC learned on the old port, so frames for it are sent there, into a hypervisor where the VM no longer exists, until the entry ages out (300 seconds by default) or the VM sends something from its new location. Hypervisors fix this by sending a frame from the VM's MAC on the new port as soon as it resumes, usually a gratuitous ARP or a RARP broadcast (VMware and KVM do this). The broadcast reaches every switch, each relearns the MAC on the new port, and traffic switches over within milliseconds. The same idea moves a floating IP between servers (Chapter 3).

🧠 Key takeaways

  • An Ethernet frame is destination MAC, source MAC, EtherType, 46–1500 bytes of payload and a CRC; bad frames are silently dropped.
  • MAC addresses are 48 bits: a vendor OUI plus a serial; the low bits of the first byte mark multicast and locally administered addresses.
  • Switches learn source MACs per port, forward known destinations to one port, and flood unknown and broadcast frames.
  • Entries age out (300 s by default); moved hosts announce themselves with a broadcast.
  • Switches extend a broadcast domain; routers end it. Loops without STP cause broadcast storms.

Check your understanding

A switch receives a frame whose destination MAC isn't in its table. What does it do?

Unknown unicast is flooded. The destination's reply then teaches the switch which port it's on.

Which field of a frame does a switch learn from?

The source MAC tells the switch "this host is reachable through the port this frame came in on".

Which device ends a broadcast domain?

Routers don't forward L2 broadcasts. Switches and hubs pass them to every port, so everything behind them shares one broadcast domain (per VLAN).

Two switches are connected by two cables and neither runs spanning tree. What happens when a host sends one ARP broadcast?

Ethernet frames have no TTL, so loops never drain. STP blocks redundant links to keep the topology a tree.

What does the MAC address 02:42:ac:11:00:02 tell you?

First byte 0x02: the multicast bit (0x01) is clear and the locally administered bit (0x02) is set. Docker assigns 02:42: followed by the container's IP.
