IP Addresses & Binary Arithmetic

192.168.1.10 looks like four numbers. It is one: a 32-bit unsigned integer, written in a friendlier way. Once you see it as a number, the rest of IP addressing is a handful of bit operations. A mask is a run of 1 bits, the network an address belongs to is a single AND, and "is this host on my network?" is one comparison. Every host does that comparison for every packet it sends, and it decides whether the packet goes straight to the destination or to a router.

  • Turn a prefix length into a mask, and find the network an address belongs to

  • Recognise private, loopback, link-local and other special ranges

An IPv4 address is a 32-bit number

An IPv4 address is 32 bits, carried in the IP header as 4 bytes in network byte order. Dotted-decimal notation writes each byte as a decimal number from 0 to 255, separated by dots. So 192.168.1.10 is the bytes c0 a8 01 0a, which is the integer:

192 × 2²⁴ + 168 × 2¹⁶ + 1 × 2⁸ + 10 = 3,232,235,786

There are 2³² ≈ 4.29 billion possible addresses, which is why the world ran out (Chapter 20 covers IPv6's answer). The binary form is the one that matters for everything below:

  192      168       1        10
11000000 10101000 00000001 00001010

Converting one octet by hand is the place-value table 128, 64, 32, 16, 8, 4, 2, 1: 168 = 128 + 32 + 8 = 10101000. With practice you will learn the handful that come up constantly: 128 = 10000000, 192 = 11000000, 224 = 11100000, 240 = 11110000, 248, 252, 254, 255.

def to_int(dotted: str) -> int:
    a, b, c, d = (int(x) for x in dotted.split("."))
    return (a << 24) | (b << 16) | (c << 8) | d          # shift each byte into place

def to_dotted(n: int) -> str:
    return ".".join(str((n >> shift) & 0xFF) for shift in (24, 16, 8, 0))

>>> to_int("192.168.1.10"), to_dotted(3232235786)
(3232235786, '192.168.1.10')
>>> format(to_int("192.168.1.10"), "032b")
'11000000101010000000000100001010'

AND, OR and NOT on addresses

Three bitwise operations do all the work. Each works bit by bit across all 32 positions:

  • AND (&): 1 only where both bits are 1. ANDing with a mask keeps the bits under the mask's 1s and clears the rest.
  • OR (|): 1 where either bit is 1. ORing with the inverted mask sets all the host bits, which gives the last address in a range.
  • NOT (~): flips every bit. In Python integers are unbounded, so write ~mask & 0xFFFFFFFF to stay within 32 bits.

A subnet mask is a 32-bit value made of some 1s followed by all 0s. The 1s mark the network part of an address (shared by every host on that network), the 0s mark the host part (different for each host). Because a valid mask is always contiguous 1s, it can be written as just the count of 1s: the prefix length. /24 means 24 ones, which is 255.255.255.0.

def mask(prefix: int) -> int:
    return (0xFFFFFFFF << (32 - prefix)) & 0xFFFFFFFF     # 'prefix' ones, then zeros

addr = to_int("172.20.47.200")
m = mask(20)
>>> to_dotted(m)                                # 11111111.11111111.11110000.00000000
'255.255.240.0'
>>> to_dotted(addr & m)                         # network: keep the first 20 bits
'172.20.32.0'
>>> to_dotted(addr | (~m & 0xFFFFFFFF))         # last address: set all 12 host bits
'172.20.47.255'

Only the third octet needed thought there, because the mask boundary falls inside it. 47 is 0010 1111; ANDing with 240 (1111 0000) keeps 0010 0000 = 32. A shortcut that gives the same answer: the mask octet 240 means blocks of 256 − 240 = 16, and 47 falls in the block that starts at 32.

Special and private ranges

Some blocks are set aside and never appear as ordinary public addresses. The three private ranges from RFC 1918 can be used by anyone inside their own network; routers on the public internet drop them, and NAT (Chapter 9) translates them on the way out. You will meet the rest constantly in logs and configs:

Hand arithmetic is for understanding and interviews. In code, use ipaddress: it validates input, handles IPv6 with the same API, and doesn't have the off-by-one mistakes hand-written masks tend to.

🧠
The Docker bridge that ate the VPN

A developer's laptop can reach every internal service except the build server at 172.17.4.20, and only since Docker was installed. Docker creates a bridge network docker0 at 172.17.0.0/16 and adds a route for it. The build server's address ANDed with /16 is 172.17.0.0, which matches the local Docker network, so the laptop sends those packets to the bridge, where no such host exists, instead of into the VPN tunnel. Nothing is "down"; two networks overlap and the host's arithmetic picks the wrong one. The fix is to move Docker's range ("bip" in daemon.json) to a block the company doesn't use. Overlapping private ranges cause the same trouble when peering two cloud VPCs that were both created with the default 10.0.0.0/16.

⚠️
Common mistakes
  • Assuming all of 172.x.x.x is private. Only 172.16.0.0–172.31.255.255 is. 172.32.0.1 is a public address.
  • Comparing addresses as strings. "10.0.0.9" sorts after "10.0.0.10" as text. Convert to integers (or ipaddress objects) before comparing or sorting.
  • Forgetting the 32-bit limit in Python. ~mask is negative; mask it with & 0xFFFFFFFF.
  • Thinking only the last octet can change. Masks end anywhere: /20 splits the third octet, /10 the second.
  • Binding a server to 127.0.0.1 and wondering why other machines can't reach it. Bind to 0.0.0.0 (all interfaces) or the specific interface address.
🎤
Interview drill

Explain it simply: What does /24 mean in 10.1.2.3/24, and how does a host use it?

How a strong answer sounds
The address is a 32-bit number and /24 is the prefix length: the first 24 bits are the network, the last 8 identify the host. As a mask that's 255.255.255.0. ANDing the address with the mask gives the network, 10.1.2.0, which has 256 addresses. When the host sends a packet, it ANDs the destination with the same mask. If the result is 10.1.2.0, the destination is on the local network and the host sends straight to it after an ARP lookup. Otherwise it sends the packet to its default gateway.

Deeper: Host X is 192.168.1.10/24 and host Y is 192.168.1.200/25, on the same switch. Can they talk?

How a strong answer sounds
Partly, and asymmetrically, because each host decides with its own mask. X computes 192.168.1.200 & 255.255.255.0 = 192.168.1.0, its own network, so it ARPs for Y and sends directly. Y computes 192.168.1.10 & 255.255.255.128 = 192.168.1.0, but Y's own network is 192.168.1.128/25, so Y thinks X is remote and sends its replies to its gateway. If the gateway routes them back onto the LAN it may work, slowly, through an extra hop; if Y has no gateway or a firewall drops the asymmetric flow, it fails. Mismatched masks on one segment are a classic cause of "ping works one way only". The fix is consistent masks, usually handed out by DHCP.

🧠 Key takeaways

  • An IPv4 address is a 32-bit integer; dotted decimal is just four bytes written in base 10.
  • A mask is contiguous 1s (network bits) then 0s (host bits); the prefix length counts the 1s.
  • addr & mask gives the network; addr | ~mask gives the last address in it.
  • Two hosts are on the same network if their addresses ANDed with the mask are equal; each host decides with its own mask.
  • Private ranges: 10/8, 172.16/12, 192.168/16. Also know 127/8, 169.254/16 and 100.64/10.
  • In code, use Python's ipaddress instead of hand-written bit masks.

Check your understanding

What 32-bit integer is the address 0.0.1.0?

The third octet is worth 2⁸ = 256 per unit, so 0.0.1.0 = 1 × 256 = 256. (0.1.0.0 would be 65,536.)

What is the subnet mask for a /20 prefix?

20 ones: 8 + 8 fill the first two octets with 255, and the remaining 4 ones make the third octet 11110000 = 240.

Which network does 172.20.47.200/20 belong to?

The mask splits the third octet: 47 AND 240 = 00101111 AND 11110000 = 00100000 = 32. Equivalently, blocks of 16, and 47 is in the block starting at 32.

Which of these addresses is not in a private (RFC 1918) range?

172.16.0.0/12 runs from 172.16.0.0 to 172.31.255.255. 172.32.0.1 is one past the end, so it's a public address.

Host 10.0.1.20/24 sends a packet to 10.0.2.9. What does it do?

10.0.2.9 AND 255.255.255.0 = 10.0.2.0, which differs from the host's own network 10.0.1.0, so the packet goes to the gateway (whose MAC the host finds with ARP).
