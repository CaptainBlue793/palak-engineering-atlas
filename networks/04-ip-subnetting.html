IP Addressing & Subnetting

Every cloud account, office network and Kubernetes cluster starts with the same decision: which block of addresses, cut into which pieces. Get it right and nobody thinks about it again. Get it wrong and you find out a year later, when the cluster can't schedule pods because a subnet ran out of IPs, or two networks can't be connected because they overlap. This chapter turns the bit arithmetic from P2 into planning: CIDR blocks, network and broadcast addresses, splitting a block into subnets of different sizes, and joining routes back together.

  • Read any CIDR block: network, broadcast, first and last usable address, host count
  • Split a /24 (or any block) into equal subnets by borrowing bits
  • Plan subnets of different sizes from one block (VLSM) without overlaps or gaps
  • Aggregate contiguous, aligned networks into one supernet route
  • Apply real-world rules: cloud reserved addresses, /31 links, leaving room to grow

From classes to CIDR

Until 1993, IPv4 addresses came in fixed classes: class A networks were /8 (16.7 million addresses), class B /16 (65,536) and class C /24 (256), with the class decided by the first bits of the address. An organisation needing 2,000 addresses was too big for a C, so it got a B and wasted 63,000 addresses, and the internet was heading for exhaustion and for routing tables with a separate entry for every class C network.

Classless Inter-Domain Routing (CIDR, RFC 1519 in 1993, now RFC 4632) removed the classes: any prefix length is allowed, written after a slash. That fixed both problems. That organisation gets a /21 (2,048 addresses), and a provider can announce one route for all its customers' blocks. When you hear "class C" today, the speaker almost always means "a /24".

Anatomy of a block

A block like 192.168.10.64/27 has 232−27 = 32 addresses. Two of them are reserved on an ordinary subnet:

  • The network address, all host bits 0: 192.168.10.64. It names the subnet in routing tables.
  • The broadcast address, all host bits 1: 192.168.10.95. A packet to it reaches every host on the subnet.
  • Everything between is usable: .65 to .94, 30 hosts. By convention the gateway takes the first, .65.

The formula, usable = 2(32 − prefix) − 2, has two exceptions. A /31 has just two addresses and no broadcast (RFC 3021), which is ideal for point-to-point links between routers. A /32 is a single host, used for loopback addresses and host routes. Cloud providers reserve more: AWS keeps the first four and the last address of every subnet (network, VPC router, DNS, future use, broadcast), so a /28 gives 11 usable addresses, not 14.

>>> import ipaddress
>>> n = ipaddress.ip_network("192.168.10.64/27")
>>> n.network_address, n.broadcast_address, n.num_addresses
(IPv4Address('192.168.10.64'), IPv4Address('192.168.10.95'), 32)
>>> hosts = list(n.hosts()); hosts[0], hosts[-1], len(hosts)
(IPv4Address('192.168.10.65'), IPv4Address('192.168.10.94'), 30)

Splitting a /24 by borrowing bits

To split a block into equal subnets, move the prefix right: each bit "borrowed" from the host part doubles the number of subnets and halves their size. A /24 split with 2 borrowed bits becomes four /26s. The quickest mental tool is the block size, 256 minus the mask's last non-255 octet: a /26 mask is 255.255.255.192, so blocks of 64, starting at .0, .64, .128 and .192.

Supernetting: joining routes

The reverse of splitting is aggregation (supernetting, or route summarisation): describing several networks with one shorter prefix. 10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24 and 10.1.3.0/24 share their first 22 bits, so a router can advertise one route, 10.1.0.0/22, instead of four. Two conditions must hold: the networks must be contiguous, and the group must be aligned, starting on a multiple of its own size. 10.1.1.0/24 + 10.1.2.0/24 are contiguous but can't be one /23, because a /23 has to start on an even third octet: the /23s are 10.1.0.0 and 10.1.2.0.

>>> nets = [ipaddress.ip_network(f"10.1.{i}.0/24") for i in range(4)]
>>> list(ipaddress.collapse_addresses(nets))
[IPv4Network('10.1.0.0/22')]
>>> list(ipaddress.collapse_addresses([nets[1], nets[2]]))      # contiguous but not aligned
[IPv4Network('10.1.1.0/24'), IPv4Network('10.1.2.0/24')]

Aggregation is why careful address planning pays off beyond one network: fewer routes mean smaller tables in every router (Chapter 5), and on the internet the global BGP table, now around a million IPv4 routes, depends on providers announcing aggregates instead of every customer block (Chapter 25).

The Kubernetes cluster that ran out of IPs, not CPU

A team builds an EKS cluster in a VPC with three /24 subnets, one per availability zone, which looks generous for 30 nodes. But the AWS VPC CNI gives every pod a real VPC IP address, and each node also pre-allocates a warm pool of addresses. A /24 has 251 usable addresses on AWS; 10 nodes per zone running 25 pods each, plus warm pools, exhaust it. New pods sit in ContainerCreating with "failed to assign an IP address to container" while the nodes have plenty of CPU and memory free. Subnets can't be resized in place. The fixes were to add a secondary CIDR to the VPC with large pod subnets (often from 100.64.0.0/10, which doesn't collide with corporate ranges) and to enable prefix delegation, which hands each node /28 blocks instead of single IPs. The lesson for any plan: size subnets for what will consume addresses (pods, load-balancer interfaces, Lambda ENIs), not just for the number of machines (Chapter 31).

⚠️
Common mistakes
  • Forgetting the two reserved addresses (five on AWS). A /29 holds 6 hosts, not 8.
  • Allocating small subnets first. The next large block then has to skip forward to its boundary, leaving holes, or overlaps.
  • Sizing for today. Subnets can't be grown in place in most clouds. Leave space between allocations.
  • Overlapping with networks you'll connect to later: the office VPN, a partner, another VPC, Docker's 172.17.0.0/16.
  • Assuming contiguous networks always aggregate. They must also be aligned to the supernet's size.
🎤
Interview drill

Explain it simply: Split 10.20.0.0/16 between six teams that each need up to 2,000 hosts.

How a strong answer sounds
2,000 hosts plus network and broadcast needs 2,002 addresses; the next power of two is 2,048, which is a /21 (32 − 11). A /16 holds 221−16 = 32 /21s, so six fit easily: 10.20.0.0/21, 10.20.8.0/21, 10.20.16.0/21, 10.20.24.0/21, 10.20.32.0/21, 10.20.40.0/21, each stepping by 8 in the third octet. That uses 12,288 of 65,536 addresses, leaving 26 more /21s. I'd leave a gap after each team's block (or give each a /20) so a team can grow without renumbering, and if this is AWS I'd remember the five reserved addresses per subnet.

Deeper: Can 10.1.1.0/24 and 10.1.2.0/24 be summarised as one route? What about 10.1.2.0/24 and 10.1.3.0/24?

How a strong answer sounds
The first pair can't be a single /23. A /23 covers two /24s whose third octets are an even number and the next odd one, because the 23rd bit must be the last network bit: 1 is 00000001 and 2 is 00000010, so they differ in the 23rd and 24th bits and share only 22 bits. The smallest single route covering both is 10.1.0.0/22, which also includes 10.1.0.0/24 and 10.1.3.0/24 that may belong to someone else. The second pair, 2 (00000010) and 3 (00000011), differ only in the 24th bit, so 10.1.2.0/23 covers exactly those two. Contiguous isn't enough: aggregates must be aligned.

🧠 Key takeaways

  • CIDR replaced fixed classes with any prefix length; "class C" now just means /24.
  • A block has 2(32−prefix) addresses; subtract network and broadcast (5 on AWS) for usable hosts; /31 and /32 are special.
  • Borrowing bits splits a block into equal subnets; the block size (256 − mask octet) finds boundaries fast.
  • VLSM: round each need up to a power of two, allocate largest first, and every block lands aligned.
  • Aggregate only contiguous, aligned networks; fewer routes keep tables small.
  • Plan for growth and for every network you'll ever connect to.

Check your understanding

How many usable host addresses does a /26 have on an ordinary LAN?

26 = 64 addresses, minus the network and broadcast addresses = 62. (On AWS it would be 59.)

What is the broadcast address of 192.168.10.64/27?

A /27 is 32 addresses: .64 to .95. The broadcast is the last one, with every host bit set.

What's the longest prefix (smallest subnet) that can hold 500 hosts?

500 + 2 = 502 addresses needed. A /24 has 256, a /23 has 512, which is the smallest power of two that fits.

Which single route summarises 10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24 and 10.1.3.0/24 exactly?

Four contiguous /24s starting at a multiple of 4 share their first 22 bits. /23 covers only two of them; /16 covers far more.

How many usable addresses does a /28 subnet give you in an AWS VPC?

AWS reserves the first four addresses (network, VPC router, DNS, future use) and the last one: 16 − 5 = 11.
