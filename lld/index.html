One code style, all the way through

Every listing in this course is Java written the same way, so the shape of the code becomes a memory aid instead of noise. This is the style, stated once in Chapter 1 and never broken.

  • Interface first. Name the role — EvictionPolicy, SpotAllocator — before writing any class that plays it.
  • Constructor injection, final fields. Every collaborator arrives through the constructor and never changes. No new buried in a method, no statics.
  • Fail fast at the boundary. Validate arguments in the constructor or public method, then trust them everywhere inside.
  • Small classes, no reflex getters. Behaviour lives next to the data it changes: tell, don’t ask.
  • Every design names its pattern and its extension point — the change it survives without editing old code.
public interface EvictionPolicy<K> {
	void keyAccessed(K key);
	K evict();
}

public final class Cache<K, V> {
	private final EvictionPolicy<K> policy;
	private final int capacity;

	public Cache(int capacity, EvictionPolicy<K> policy) {
		if (capacity <= 0) throw new IllegalArgumentException("capacity must be positive");
		this.capacity = capacity;
		this.policy = Objects.requireNonNull(policy);
	}
}

LRU, LFU and FIFO are three small classes behind one interface. Adding a fourth never touches Cache. That is the whole idea.
