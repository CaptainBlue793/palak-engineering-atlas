Python for Backend Work

Every service in this course is Python, and a service is a different kind of Python program from a script or a notebook. It lives in a package of several modules, it is started by a server rather than by you, it runs for weeks, and the data it receives comes from strangers. This page covers the parts of the language and tooling that matter for that: an environment per project, type hints and what they do and do not check, dataclasses, and how packages and imports actually work.

The last of those trips up almost everyone once. The same project imports perfectly when started one way and fails with ModuleNotFoundError: No module named 'app' when started another, because Python decides where to look for imports from how the program was launched. The simulator lets you try every combination and see why.

  • Create a virtual environment per project and pin its dependencies
  • Read and write type hints, and know that plain Python does not enforce them
  • Use dataclasses for internal data and Pydantic models for data from outside
  • Lay out a package and choose between absolute and relative imports
  • Explain how python file.py, python -m and uvicorn set the import path

One environment per service

Each service gets its own virtual environment: an isolated Python installation with its own installed packages, so one project's FastAPI version cannot break another's. Create it inside the project, activate it, install, and record exactly what you installed. A pyproject.toml lists the direct dependencies with version ranges; a lock file (from pip-tools, uv or Poetry) pins every package, including the dependencies of your dependencies, to an exact version, ideally with hashes, so production installs the same bytes you tested.

# once per project
python -m venv .venv
.venv\Scripts\activate                     # Windows; on macOS and Linux: source .venv/bin/activate
python -m pip install "fastapi[standard]"      # FastAPI plus uvicorn, httpx and the fastapi CLI
python -m pip freeze > requirements.lock    # exact versions of everything installed

Use python -m pip rather than bare pip: it guarantees the packages go into the Python you are actually running, a frequent source of "but I installed it" confusion when several Pythons are on the machine.

Type hints, dataclasses and Pydantic

Type hints annotate what a variable, parameter or return value should be: def total(items: list[int]) -> int. Plain Python ignores them at run time. They are read by tools: editors for completion, type checkers such as mypy and pyright to catch mistakes before running, and frameworks. FastAPI reads them to decide how to parse each parameter, validate it and document it.

A dataclass generates the boilerplate for a class that mainly holds data. It is ideal for values that come from your own code, but it does not check anything: construct one with the wrong type and it stores the wrong type. A Pydantic model looks almost identical and validates and converts on construction, which is what you want for data that comes from outside, such as a request body.

from dataclasses import dataclass
from pydantic import BaseModel

@dataclass
class OrderDC:
    sku: str
    quantity: int

class OrderPM(BaseModel):
    sku: str
    quantity: int

OrderDC(sku="A1", quantity="3")    # OrderDC(sku='A1', quantity='3'): a str, silently
OrderPM(sku="A1", quantity="3")    # quantity=3, converted to int
OrderPM(sku="A1", quantity="three")  # ValidationError: int_parsing
OrderPM(sku="A1", quantity=3.5)      # ValidationError: int_from_float

Pydantic's default "lax" mode converts when the meaning is unambiguous: in Pydantic 2.13 the strings "3" and "3.0", the float 3.0 and even True all become the integer 3 or 1, while "three" and 3.5 are rejected. If that is too forgiving for a field, strict mode turns the conversions off (Chapter 5).

Packages and imports

A module is one .py file; a package is a folder of modules, usually with an __init__.py. A service is a package, so that app/main.py can import app/services/orders.py. An absolute import names the full path from the top: from app.services.orders import total. A relative import starts from the current package: from .services.orders import total.

To find app, Python searches the folders in sys.path in order, and the first entry depends on how the program was started. Run a file directly, python app/main.py, and sys.path[0] is the folder containing that file, app/ itself, where there is no app package to find. Run it as a module, python -m app.main, and sys.path[0] is the current working directory. uvicorn adds the working directory too: its --app-dir option defaults to it. Relative imports have their own rule: they only work when the module was imported as part of a package, never when its file is run directly.

Things to try.

  • From projects/shop/, run python app/main.py. The file is found, but sys.path[0] is shop/app/, which contains no folder called app, so the import fails with ModuleNotFoundError: No module named 'app'.
  • Same folder, python -m app.main. Now sys.path[0] is shop/ and the import works. So does uvicorn app.main:app, the way the service is really started.
  • Switch to the relative import. python app/main.py now fails differently: attempted relative import with no known parent package, because a file run directly is not part of any package. The -m and uvicorn commands still work.
  • Move the terminal to projects/shop/app/. Nothing works with the absolute import: from inside the package, the package itself cannot be found. python main.py and uvicorn main:app find the file but not app.
  • Move to projects/ and try python -m shop.app.main. With the absolute import it fails, because the code expects app at the top level; with the relative import it works, because the package is now shop.app. Rule of thumb: run from the project root with -m or uvicorn, and keep imports absolute from the package name.

Running a service

A service has one entry point, usually app/main.py defining app = FastAPI(). You do not call it yourself; an ASGI server imports it and calls it once per request (Prerequisite 8). Start it from the project root: uvicorn app.main:app --reload during development, or fastapi dev app/main.py, which uses the same machinery. Code that should only run when a file is executed directly goes under if __name__ == "__main__":, because __name__ is "__main__" only for the module Python was asked to run.

Use case: the package that was not PyTorch's

Between 25 and 30 December 2022, anyone who installed the nightly build of PyTorch with pip on Linux also installed a malicious package. PyTorch's nightly builds depended on a package called torchtriton, hosted on PyTorch's own package index, and the install instructions added that index with --extra-index-url. Someone uploaded a package with the same name to the public Python Package Index, PyPI, and because pip considers every configured index and PyPI took precedence, pip installed the impostor. It uploaded data from the machine, including SSH keys and environment details, to a remote server. The PyTorch team removed the dependency, published a warning and asked users to uninstall it. The attack has a name, dependency confusion, and the defences are the habits on this page: one environment per project, a lock file with exact versions and hashes, and installing from known indexes only. A service runs whatever is in its environment, so the environment is part of the code.

⚠️
Common mistakes
  • Installing into the system Python or the wrong environment; use python -m pip with the project's environment active.
  • No lock file, so a fresh install months later pulls different versions.
  • Running a module inside a package as a script (python app/main.py) and patching the error with sys.path.append.
  • Trusting type hints to validate input; plain Python and dataclasses check nothing at run time.
  • Naming a module like a library, such as fastapi.py or redis.py, which shadows the real package.
  • Mutable default arguments such as def f(items=[]), shared across calls in a long-running process.

Interview drill

Explain it simply: Why does python app/main.py fail with "No module named 'app'" when python -m app.main works?

How a strong answer sounds
Python looks for imports in the folders listed in sys.path, and the first one depends on how the program was started. Running a file directly puts that file's own folder first, which is app/, and inside app/ there is no folder called app, so from app.services import … cannot be resolved. Running with -m puts the current directory first instead, which is the project root, where the app package lives. The fix is to start services from the project root with python -m or the ASGI server, not to edit sys.path.

Deeper: When would you use a dataclass and when a Pydantic model in a service?

How a strong answer sounds
Pydantic models at the boundaries: request and response bodies, configuration, messages from queues, anything parsed from outside, because they validate, convert, produce JSON Schema for the API documentation and give clear error messages. Dataclasses inside the service for values my own code creates and already trusts, such as domain objects passed between functions, because they are lighter, have no validation cost and are standard library. The rule is to validate once at the edge and then work with trusted types inside. I would also add a type checker in CI, since neither the interpreter nor dataclasses enforce the hints.

🧠 Key takeaways

  • One virtual environment per service, with dependencies pinned in a lock file.
  • Type hints document and drive tools; plain Python and dataclasses do not enforce them.
  • Pydantic validates and converts data from outside; use it at every boundary.
  • A script run directly puts its own folder on sys.path; -m and uvicorn use the current directory.
  • Start services from the project root and use absolute imports from the package name.

Check your understanding

What does plain Python do with def f(x: int) when you call f("hello")?

Hints are for tools such as type checkers and frameworks. Validation needs something like Pydantic.

You run python app/main.py from the project root. What is sys.path[0]?

Running a file directly puts that file's folder first, which is why import app then fails.

Which error appears when a file using from .services import orders is run directly as a script?

A file run directly is the top-level __main__ module with no package, so there is nothing for the dot to be relative to.

What does Pydantic (default lax mode) do with quantity: int given the string "3"?

Lax mode converts unambiguous values. "three" or 3.5 would be rejected; strict mode would reject "3" as well.

Why use python -m pip install rather than pip install?

A bare pip on the PATH may belong to a different Python than the one running your service.
