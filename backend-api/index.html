One code style, all the way through

Every listing is Python with FastAPI and Pydantic and follows the same five rules, so each one is also a small lesson in building services that behave. This is the style, stated once and never broken.

  • Validate at the boundary. Every request body and response is a Pydantic model, so bad input becomes a 422 before any logic runs.
  • Types everywhere. Handlers declare their parameters and response_model, and the OpenAPI document is generated from them.
  • Thin handlers. A handler parses, calls a service function and returns; business rules live in one place that tests can reach.
  • Every network call has a timeout. Databases, Redis and other services alike; nothing waits forever.
  • Errors are a contract. Failures return problem details with a stable code, never a stack trace.
from fastapi import FastAPI, status
from pydantic import BaseModel, Field

app = FastAPI()

class OrderIn(BaseModel):
    sku: str = Field(min_length=1, max_length=40)
    quantity: int = Field(gt=0, le=100)

class OrderOut(BaseModel):
    id: int
    sku: str
    quantity: int

@app.post("/orders", response_model=OrderOut, status_code=status.HTTP_201_CREATED)
async def create_order(body: OrderIn) -> OrderOut:
    return await orders.create(body)        # the rules live in the service layer

Send {"sku": "A1", "quantity": 0} and FastAPI answers 422 with the field and the reason before create_order runs; the response model keeps any internal fields the service returns out of the reply (Chapters 3 and 5).
