Multi-Agent Frameworks Compared

Frameworks promise to take the plumbing off your hands: the loops, the hand-offs, the state, the structured output. They do, and in exchange they decide things for you, such as which prompt the model sees, how tools are offered and how the final answer is forced into shape. Those decisions are mostly invisible until a run goes wrong. The only way to compare frameworks honestly is to build the same thing in each and look at what reaches the model.

The task is Chapter 4's release-readiness check on 4 estates, two safe to release and two blocked. A lead finds every dependency, workers check one each, and the lead returns {go, blocking}. It was built four ways, each in the style its documentation teaches: plain Python with asyncio, LangGraph (1.2), AutoGen AgentChat (0.7.5) and CrewAI (1.15). All four ran on qwen3:14b with the same prompts and options. Each framework talked to Ollama through a logging proxy that recorded every request: the messages, the tools, the options and the token counts.

Plain code

The plain version is 30 lines: one agent loop, one gather for the workers and one final call for the verdict, all through the ollama client. Nothing happens that the code does not say. That cut both ways. As first written, it crashed on 2 of 4 estates. The lead's constrained JSON list looped until it hit the 2,048-token output cap, and the cut-off JSON could not be parsed. The fix was three lines: retry once, and drop duplicates. After that it got 3 of 4 right. Its lead followed every dependency down the graph, which the LangGraph and AutoGen leads did not: 22 model calls per estate against their 9. Plain code shows you everything, including every case you did not handle.

Graph-based: LangGraph

LangGraph made the shape explicit: a plan node, a fan-out with Send to one check node per service, and a decide node. The fan-out and the merging of findings came for free, through a reducer on the state. The lead and workers were LangChain's create_agent with a response_format. The proxy showed what that does. It adds the response format to the model as an extra tool, named Services or Finding, and the agent's result is whatever that tool was called with. On 3 of 4 estates the model never called it, and the structured response was empty. The fix was to fall back to with_structured_output when it was missing. Then 3 of 4, at about 3,200 tokens and 4.4 s per estate, the cheapest of the four.

Conversation-based: AutoGen

AutoGen's idiom is agents that talk. The lead is an AssistantAgent whose tools are get_dependencies and the worker agent itself, wrapped as an AgentTool. It was the shortest version, 28 lines. As first written, the lead also had output_content_type=Verdict for a typed answer. The proxy showed every call carrying both the tools and the verdict schema as Ollama's format. That forces the reply into JSON, so the model could never call a tool. It answered every estate in one call of 12 tokens, "go, nothing blocking". It was "right" on the 2 safe estates without looking at anything. Moving the typed output to a separate, tool-less agent fixed it: 3 of 4.

Role/crew-based: CrewAI

CrewAI describes work as agents with a role, a goal and a backstory, doing tasks with an expected output. It also rewrites the prompt more than the others. The proxy showed my system prompt wrapped as "You are Release manager. … Your personal goal is: …". The task arrived as a template with the output schema written into the text and the instruction "you MUST return the actual complete content as the final answer". The first request was 1,376 characters, against 521 for the other three. It went through Ollama's OpenAI-compatible endpoint with reasoning_effort: "none". As first written, the manager never called get_dependencies. It invented the dependencies, "search_index, user_auth, data_cache", "service1, service2, service3", and the checkers dutifully queried services that do not exist. It took two rounds of changes to get a manager that used its tool. The first gave each dependency its own check. The second, like AutoGen's fix, let the manager answer in free text and had a tool-less task format the list. That reached 2 of 4, at the highest cost of the four: 8,800 tokens and 16 s per estate.

Choosing

After fixing, the frameworks ended within one estate of each other, so the choice is not about accuracy. It is about what each makes easy and what each hides. LangGraph makes the structure visible and cheap, and hides how structured output is requested. AutoGen makes agents-as-tools very short, and hides that typed output and tools collide on this backend. CrewAI makes roles quick to declare, and hides a lot of prompt. Plain code hides nothing and handles nothing. Two habits matter more than the choice. Put a logging proxy or tracer between the framework and the model and read what it actually sends. And measure every framework on the same task set, because each one's first version here looked like it worked on at least one estate while doing something entirely different.

Use case: frameworks in the field

LangGraph is widely used for production agents because it makes control flow and state explicit and supports checkpoints and human interrupts. AutoGen, from Microsoft Research, popularised conversational multi-agent patterns and group chats; its successor work continues in the Microsoft Agent Framework. CrewAI is popular for quickly declaring role-based teams. Model providers ship their own SDKs too, such as the OpenAI Agents SDK, Anthropic's Claude Agent SDK and Google's Agent Development Kit. All of them are moving targets, with frequent releases and changing defaults. Pin versions, read what the framework sends, and keep a plain-code baseline for the parts where you need to know exactly what happens.

⚠️
Common mistakes
  • Asking for typed output on a tool-using agent and getting no tool calls at all (AutoGen, as first written).
  • Trusting a framework's structured response without checking it was produced (LangGraph, 3 of 4 empty).
  • Not reading the prompts a framework adds: CrewAI's first request was 2.6 times the length of ours.
  • Taking a lucky right answer as a working system: "right" on the safe estates without one tool call.
  • Comparing frameworks on different tasks or without a plain-code baseline.
  • Leaving versions unpinned, so defaults change under you.

Interview drill

Explain it simply: How would you choose a multi-agent framework?

How a strong answer sounds
Build one representative task in plain code and in the candidates, and run them on the same cases while logging exactly what each sends the model. When I did this for a release check, every version's first build had a hidden problem: a structured-output setting that stopped tool calls, a response format offered as a tool the model skipped, a manager that invented its inputs. After fixing, they ended within one case of each other, so I would choose on visibility, structure and cost, not on promises.

Deeper: Your agent framework returns plausible answers but the agent never seems to use its tools. What do you check?

How a strong answer sounds
The raw requests. Put a logging proxy or tracer in front of the model and look at what the framework sends. In one case the framework sent the tools and also forced a JSON output format, so the model could only answer, never call a tool. It "passed" the easy cases with zero tool calls. In another, the framework wrote the output schema into the prompt and the model skipped the tool and invented its inputs. The fix in both was to separate the tool-using step from the step that produces typed output.

🧠 Key takeaways

  • Build the same task in each framework and read what reaches the model through a proxy or tracer.
  • Typed output and tool calls collided twice: AutoGen sent a forced format, CrewAI wrote the schema into the prompt.
  • LangGraph's response format is an extra tool the model may never call: check it, fall back.
  • After fixing, three builds got 3 of 4 and CrewAI 2 of 4; LangGraph was the cheapest, CrewAI the dearest.
  • Plain code hides nothing and handles nothing; keep it as the baseline.
