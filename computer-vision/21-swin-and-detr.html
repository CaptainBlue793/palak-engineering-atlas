Swin & DETR

Chapter 19 left two problems. Global attention costs grow with the square of the tokens, which rules out high-resolution images, and a plain ViT outputs one vector, not the multi-scale feature maps that detectors and segmenters are built on. Swin Transformer fixes both by attending within small windows and merging patches stage by stage. DETR takes the transformer in a different direction, turning detection into predicting a set of boxes directly, with no anchors and no non-maximum suppression.

This chapter measures both. Window attention against global attention at up to 12,544 tokens; Swin-T, ViT-B/16 and ResNet-50 from 224 to 896 pixels (at 896, ViT-B took 263 ms and Swin-T 31); and DETR on the same 500 COCO images as Chapters 14 and 15, where adding NMS made it slightly worse.

Swin: attention inside windows

Swin (2021) starts like a ViT with small 4 × 4 patches, so a 224-pixel image becomes a 56 × 56 grid of tokens, 3,136 of them. Instead of letting all 3,136 attend to each other, it cuts the grid into non-overlapping 7 × 7 windows and runs attention inside each window only. Every token attends to 49 others, whatever the image size, so the cost grows linearly with the number of tokens rather than with its square.

Windows alone would never exchange information, so alternate blocks shift the window grid by half a window (3 tokens) in each direction: a token at the edge of one window in block k sits in the middle of a window in block k + 1, and information flows across boundaries over successive blocks. Between stages, patch merging concatenates each 2 × 2 group of tokens and projects it, halving the grid and doubling the channels: 56 → 28 → 14 → 7 tokens per side, 96 → 768 channels. The result is a pyramid with the same strides as a ResNet (4, 8, 16, 32), which is why Swin dropped straight into Mask R-CNN and UPerNet as a backbone. Attention also adds a learned relative position bias per window offset instead of absolute position embeddings, so it handles any resolution that is a multiple of 32.

def window_attention(x, ws=7):                           # x (B, S, S, C): an S x S grid of tokens
    B, S, _, C = x.shape
    w = x.view(B, S // ws, ws, S // ws, ws, C).permute(0, 1, 3, 2, 4, 5).reshape(-1, ws * ws, C)   # (B * windows, 49, C)
    a = (w @ w.transpose(1, 2) / C ** 0.5).softmax(-1)            # 49 x 49 per window, never S^2 x S^2
    return a @ w
# shifted block: torch.roll(x, (-3, -3), dims=(1, 2)) before, roll back after (plus a mask so wrapped tokens do not mix)

From 224 to 896 pixels (16 times the pixels), ResNet-50’s time grew 5.8 times, Swin-T’s 4.9 times and ViT-B’s 67 times. At 224, Swin-T was actually slower than the much larger ViT-B: its many small windowed matrix multiplies, shifts and reshapes use the GPU less efficiently than ViT’s few large ones. Pretrained on ImageNet, torchvision reports 81.5% top-1 for Swin-T, 81.1% for ViT-B/16 and 80.9% for ResNet-50 (V2 weights). On every second Imagenette validation image, 1,962 photos, predicting among all 1,000 classes, the order changed: ViT-B 92.4%, ResNet-50 87.2%, Swin-T 85.4%. Ten classes are a small slice of ImageNet; a leaderboard’s average does not tell you which model is best on your classes.

DETR: detection as set prediction

Every detector so far produced thousands of overlapping candidates and relied on hand-tuned NMS to delete duplicates. DETR (DEtection TRansformer, 2020) asks the network to output the final set directly. A ResNet-50 produces a feature map at stride 32; it is flattened into tokens, with positional encodings, and passed through a 6-layer transformer encoder. A 6-layer decoder takes 100 learned object queries, vectors that each learn to ask “is there an object around here, of this kind?”, lets them attend to the image tokens and to each other, and each query outputs a class (including a special “no object”) and a box. Because queries attend to each other, they can agree that only one of them reports a given object.

Training needs a way to compare 100 predictions with, say, 4 true objects. DETR uses Hungarian matching: build a 100 × 4 cost matrix (how badly each prediction would fit each object, combining class probability, L1 box distance and generalised IoU), find the one-to-one assignment with the lowest total cost, then train the 4 matched predictions towards their objects and the other 96 towards “no object”. Since each object can be claimed by only one prediction, duplicates are penalised by the loss itself, and NMS becomes unnecessary. The panel’s last view lets you try the assignment yourself.

DETR beat the original Faster R-CNN on these images with a simpler pipeline, and was the fastest of the four (forward pass only, at its own 800-pixel resize). Adding NMS lowered its AP by 1.0 point: its overlapping outputs are not duplicates but genuinely different neighbouring objects, and NMS deleted some of them. Of its 100 queries, on average 11.1 per image predicted an object with probability above 0.5. These 500 images are easier than the full set, as in earlier chapters (DETR’s published full-val AP is 42.0). The size breakdown shows its character. On large objects DETR scored 61.7, far above the original Faster R-CNN’s 50.4 and close to the much-improved v2’s 63.2, because global attention sees the whole object and its context. On small objects it scored 24.0, the lowest of the four, against 29.0–33.6 for the FPN detectors: it reads a single stride-32 feature map, where a 20-pixel object is less than one cell. That and training time were its weaknesses: 500 epochs on COCO against 12–36 for Faster R-CNN, because the queries take a long time to learn where to look. Deformable DETR (sparse attention around reference points, multi-scale features) and later DINO-style detectors fixed both, and the set-prediction idea now runs through Mask2Former, SAM’s decoder (Chapter 25) and most modern detectors.

🧾
Use case: satellite and pathology images

A satellite tile or a pathology slide region of 1,024 × 1,024 pixels at 4-pixel patches is 65,536 tokens: global attention over that is out of the question (Chapter 19 ran out of memory at 2,305 tokens with naive attention), while windowed attention costs about the same per token at any size. That is why hierarchical, windowed backbones (Swin and its successors) became standard in remote sensing and medical segmentation, plugged into UPerNet or Mask R-CNN heads exactly where a ResNet would go. For counting things such as buildings, cells or vehicles, DETR-family detectors are attractive because there is no NMS threshold to tune for densely packed objects, which is precisely where NMS deletes true neighbours.

⚠️
Common mistakes
  • Assuming Swin is faster than ViT at every size: at 224 pixels Swin-T was slower than ViT-B here; its advantage is scaling.
  • Feeding Swin a size that is not a multiple of 32 (patch 4 × window 7 × merges): it pads, which shifts features and costs time.
  • Adding NMS to DETR “to be safe”: it cost 1.0 AP here.
  • Training DETR for 50 epochs and calling it broken: the original needs hundreds; use Deformable DETR or a modern variant for short schedules.
  • Expecting DETR to handle more objects than it has queries: 100 queries cap the outputs at 100 per image.

Interview drill

Explain it simply: How does Swin make transformers practical for high-resolution images?

How a strong answer sounds
It restricts attention to fixed 7 × 7 windows of tokens, so each token attends to 49 others regardless of image size and the cost grows linearly instead of quadratically. To let information cross windows, every other block shifts the window grid by half a window. Between stages it merges 2 × 2 patches, halving the grid and doubling the channels, which produces a pyramid at strides 4 to 32 like a ResNet, so it drops into detection and segmentation heads. I measured one attention head at 12,544 tokens: global took 21.7 ms and 5 GB, windows 0.19 ms and 215 MB. Whole models from 224 to 896 pixels: ViT-B’s time grew 67 times, Swin-T’s 4.9 times; at 224, though, Swin-T was slower than ViT-B.

Deeper: Why does DETR not need NMS, and what is Hungarian matching doing during training?

How a strong answer sounds
Classic detectors assign many anchors or points to each object during training, so they learn to fire several times per object and need NMS to clean up. DETR’s training instead finds a one-to-one assignment between its 100 predictions and the true objects with the Hungarian algorithm on a cost combining class probability, L1 box error and GIoU. Only the matched prediction is trained towards each object, and every other prediction is trained towards “no object”, so a second prediction on the same object is penalised directly. The decoder’s self-attention between queries lets them coordinate at inference. Measured on 500 COCO images, DETR scored 45.4 AP without NMS and 44.4 with it, because NMS removed real neighbouring objects. The cost is slow convergence and weak small-object accuracy, which Deformable DETR addresses with sparse multi-scale attention.

🧠 Key takeaways

  • Swin attends within 7 × 7 windows, shifts them every other block, and merges patches into a ResNet-like pyramid.
  • Window attention scales linearly: at 12,544 tokens, 115× faster than global with 23× less memory.
  • From 224 to 896 px, ViT-B slowed 67×, Swin-T 4.9×, ResNet-50 5.8×; Swin-T was slower than ViT-B at 224.
  • DETR predicts a set with 100 object queries, trained with Hungarian matching, and needs no NMS.
  • Measured: DETR 45.4 AP, 44.4 with NMS added; weak on small objects and slow to train.

Check your understanding

Why does Swin shift its windows in alternate blocks?

With fixed windows, tokens in different windows never meet. Shifting by half a window puts boundary tokens together in the next block.

How does window attention’s cost grow with the number of tokens T, for a fixed window size?

Each token attends to a fixed 49 others: T × 49 scores. Global attention has T × T.

At 224 pixels, which was faster in the measurement: Swin-T (28 M params) or ViT-B/16 (87 M)?

Few large matrix multiplies use a GPU better than many small windowed ones. Swin overtook from 448 pixels and was 8.5× faster at 896.

In DETR training, what happens to a prediction that is not matched to any true object?

That is what suppresses duplicates: a second prediction on an object is pushed to “no object” by the loss.

What did adding NMS do to DETR’s AP on the 500 COCO images?

45.4 → 44.4: DETR’s overlapping boxes were mostly real neighbouring objects, and NMS deleted some.
