Detection Basics: Boxes, IoU, Anchors & NMS

A detector answers “what, and where” with a list of boxes, each with a class and a score. Four small pieces of machinery sit under every detector, from Faster R-CNN to YOLO to DETR: a way to write a box down, a way to measure how much two boxes agree (IoU), a set of reference boxes to predict relative to (anchors), and a way to remove duplicate detections of the same object (non-maximum suppression).

This chapter writes all four from scratch and checks them against torchvision’s implementations, measures how well Faster R-CNN’s anchors cover the 7,117 objects in 1,000 COCO images, and then switches NMS off and on in a real detector. Without it, AP for people fell from 60.6 to 18.4; with too tight or too loose a threshold, crowds lose people.

Boxes and IoU

An axis-aligned box is four numbers, written two common ways: corners (x1, y1, x2, y2), which torchvision uses, or centre and size (cx, cy, w, h), which most regression targets use. COCO’s annotation files use a third, (x, y, w, h) from the top-left corner. Mixing them up produces boxes that look plausible and are wrong, so convert at the boundary with torchvision.ops.box_convert and keep one format inside.

Intersection over union measures how well two boxes agree: the area they share divided by the area they cover together. 1 is identical, 0 is disjoint. It is how a detection is matched to a ground truth, how anchors are assigned in training, and how NMS decides two boxes are duplicates.

def box_iou(a, b):                                       # a (N, 4), b (M, 4), x1 y1 x2 y2 -> (N, M)
    lt = torch.maximum(a[:, None, :2], b[None, :, :2])         # (N, M, 2) top-left of each intersection
    rb = torch.minimum(a[:, None, 2:], b[None, :, 2:])         # (N, M, 2) bottom-right
    wh = (rb - lt).clamp(min=0)                               # zero when the boxes do not overlap
    inter = wh[..., 0] * wh[..., 1]
    area = lambda x: (x[:, 2] - x[:, 0]) * (x[:, 3] - x[:, 1])
    return inter / (area(a)[:, None] + area(b)[None, :] - inter)

On 300 × 200 random boxes it matched torchvision.ops.box_iou exactly (maximum difference 0.0). Four values worth remembering: two equal boxes overlapping by half have IoU 1/3, not 1/2; a box inside another a quarter its size has 0.25; and a one-pixel shift in both directions costs a 10-pixel box 32% of its IoU (0.68) but a 100-pixel box only 4% (0.96). Small objects are hard to detect partly because IoU punishes them for the same error in pixels.

Predicting a box: offsets from an anchor

Regressing raw pixel coordinates is hard to learn: values range over hundreds of pixels and depend on image size. Detectors instead predict a box relative to a reference box, an anchor, with four offsets that are small numbers for good anchors: the centre shift in units of the anchor’s size, and the log of the size ratio.

def encode(gt, an):                                        # both (N, 4) x1 y1 x2 y2 -> deltas (N, 4)
    aw, ah = an[:, 2] - an[:, 0], an[:, 3] - an[:, 1]; ax, ay = an[:, 0] + aw / 2, an[:, 1] + ah / 2
    gw, gh = gt[:, 2] - gt[:, 0], gt[:, 3] - gt[:, 1]; gx, gy = gt[:, 0] + gw / 2, gt[:, 1] + gh / 2
    return torch.stack([(gx - ax) / aw, (gy - ay) / ah, torch.log(gw / aw), torch.log(gh / ah)], 1)
# anchor (100, 100, 200, 180), ground truth (110, 95, 230, 190)
# -> deltas (0.200, 0.031, 0.182, 0.172); decode(encode(gt)) == gt exactly

The network predicts these four numbers for every anchor, and a classification score for each class. Training needs to know which anchors should predict which object: an anchor whose IoU with a ground-truth box is above a high threshold (0.7 in Faster R-CNN’s region proposals, 0.5 in RetinaNet) becomes a positive for that object, below a low one (0.3–0.4) a negative, in between it is ignored.

Anchors: do they cover the objects?

Anchors are placed on a grid at every feature-map position, in several sizes and aspect ratios. If no anchor overlaps an object well, that object has no positive anchor during training and is hard to learn. For the 7,117 non-crowd objects in the first 1,000 COCO validation images, resized so the shorter side is 800 pixels as Faster R-CNN does, the best IoU any anchor achieves with each object:

One anchor size cannot cover objects from a 10-pixel bottle to a whole bus; one shape cannot cover both standing people (tall) and cars (wide). Faster R-CNN’s set of 15 anchors across five feature-pyramid levels gives 86% of objects an anchor with IoU ≥ 0.5, but only 36% one with IoU ≥ 0.7. That gap is why the RPN’s matching also makes the single best anchor for each object a positive even below the threshold, and it motivated anchor-free detectors, which skip the question altogether (Chapter 15).

Non-maximum suppression

Every anchor near an object predicts a box for it, so a detector’s raw output has many overlapping boxes per object: Faster R-CNN on the COCO images below gave 549 candidate boxes per image above a score of 0.01 before suppression. NMS keeps the highest-scoring box, removes every remaining box of the same class whose IoU with it exceeds a threshold, and repeats with the next highest.

def nms(boxes, scores, thr):                                 # boxes (N, 4), scores (N,) -> indices kept
    order = scores.argsort(descending=True); keep = []
    while order.numel():
        i = order[0]; keep.append(int(i))                        # the best remaining box survives
        if order.numel() == 1: break
        ious = box_iou(boxes[i:i + 1], boxes[order[1:]])[0]
        order = order[1:][ious <= thr]                          # drop its duplicates
    return torch.tensor(keep)

It returned exactly the same boxes as torchvision.ops.nms at thresholds 0.3, 0.5 and 0.7, and was much slower: for 5,000 boxes 450 ms in Python, 11.0 ms for torchvision on the CPU and 1.4 ms on the GPU. Per class, run it with batched_nms, which offsets each class’s boxes so different classes never suppress each other.

Choosing the threshold, measured

The NMS threshold is a trade-off between duplicates and missed neighbours. Too low, and two people standing close together suppress each other; too high, and duplicates survive as false positives. Without NMS, AP collapsed from about 60 to 18: the top 100 boxes per image were mostly duplicates of a few people. Between 0.4 and 0.7 the choice moved AP by under a point, which is why 0.5 is a common default; recall kept rising with the threshold as close neighbours stopped being suppressed, while AP50 peaked at 0.5. For very crowded scenes (pedestrians, shelves of products), greedy NMS’s assumption, that two heavily overlapping boxes are the same object, is simply wrong, which led to Soft-NMS (lower the overlapping boxes’ scores instead of deleting them), learned NMS, and detectors such as DETR that are trained to output one box per object (Chapter 21).

🧾
Use case: counting people at an entrance

A camera above a shop door counting visitors relies on one detection per person per frame. In busy periods people overlap heavily, and greedy NMS at 0.5 merges pairs walking shoulder to shoulder into one box, so counts run low exactly when traffic is highest. Teams handle this by raising the NMS threshold for the person class, using a head detector (heads overlap far less than bodies) or a top-down camera angle, and validating counts against a manually counted busy hour rather than an average day. ⚠️
Common mistakes
  • Mixing box formats (xyxy, xywh, cxcywh) between a dataset, a model and a metric.
  • Forgetting to rescale boxes when the image was resized or padded for the model.
  • Running NMS across classes so a person suppresses an overlapping bicycle; use batched_nms.
  • Leaving NMS out of an evaluation (AP fell from 60.6 to 18.4) or tuning its threshold on the test set.
  • Using anchors that cannot match your objects (tiny defects, very long thin objects) without checking coverage.
  • Assuming one IoU threshold fits every object size: a 1-pixel error costs a 10-pixel box a third of its IoU.

Interview drill

Explain it simply: Write NMS and say what its threshold trades off.

How a strong answer sounds
Sort the boxes by score; repeatedly take the highest remaining box, keep it, and remove every remaining box of the same class whose IoU with it is above the threshold; stop when none remain. It is O(N²) in the worst case, which is why libraries run it on the GPU (1.4 ms for 5,000 boxes here). The threshold trades duplicates against neighbours: low values suppress true detections of overlapping objects, high values let duplicates through as false positives. On COCO people with Faster R-CNN, AP was flat within a point between 0.4 and 0.7 and peaked around 0.5–0.6; without NMS it fell from 60.6 to 18.4. For dense crowds, Soft-NMS or a set-prediction detector like DETR avoids the problem.

Deeper: Why do detectors predict offsets from anchors instead of box coordinates directly, and what goes wrong when anchors are poorly chosen?

How a strong answer sounds
Offsets relative to an anchor (centre shift divided by anchor size, log of the size ratio) are small, roughly zero-centred and independent of the image size, so a convolutional head can regress them with the same weights at every position, and the anchor assignment tells each position which object it is responsible for. If the anchors do not resemble the objects, objects get no anchor above the positive IoU threshold, so they produce few or no positive training examples and are under-detected: with one 128-pixel square anchor only 15% of COCO objects had an anchor at IoU ≥ 0.5, against 86% for Faster R-CNN’s 15 anchors over five pyramid levels. Fixes are anchor sizes and ratios fitted to the dataset (k-means on box shapes, as YOLOv2 did), matching rules that always assign each object its best anchor, or anchor-free heads that predict distances from points instead.

🧠 Key takeaways

  • Boxes come as xyxy, xywh or cxcywh; convert once at the boundary.
  • IoU = intersection / union; a 1-pixel shift costs a 10-pixel box 32% of its IoU and a 100-pixel box 4%.
  • Detectors predict small offsets from anchors; encode and decode are exact inverses.
  • Faster R-CNN’s 15 anchors over 5 levels gave 86% of COCO objects an anchor at IoU ≥ 0.5, one square anchor only 15%.
  • NMS removes duplicates: without it person AP fell from 60.6 to 18.4; thresholds 0.4–0.7 were within a point.
  • Greedy NMS fails in crowds; Soft-NMS and set-prediction detectors address it.

Check your understanding

Two equal boxes overlap by half their width. What is their IoU?

Intersection is half a box; the union is one and a half boxes: 0.5 / 1.5 = 1/3.

Why is predicting log(w_gt / w_anchor) better than predicting the width in pixels?

Relative, log-scaled targets are near zero for good anchors whatever the object’s size, which makes regression much easier to learn.

What happened to person AP when NMS was switched off in Faster R-CNN?

The top 100 boxes per image were mostly duplicates, each counted as a false positive.

Why use batched_nms instead of one NMS over all boxes?

A person on a bicycle has heavily overlapping boxes of two classes; both should survive.
