Autoencoders & VAEs

An autoencoder squeezes an image through a narrow code and rebuilds it. Nothing about it needs labels, and the code it learns is a compressed description of the image. The question this chapter follows is whether you can turn that around: pick a code yourself, decode it, and get a new image. For a plain autoencoder the answer is no. A variational autoencoder (VAE) reshapes the code space so the answer becomes yes, at the price of blur.

Every model here was trained on this GPU on CIFAR-10 in about 20 seconds: four autoencoders with codes of 8 to 512 numbers, and three VAEs with different weights on their extra loss term. The largest autoencoder reconstructed test images at 26.7 dB, but its decoded random codes were coloured noise. The VAEs’ random codes decoded to blurry but image-like scenes, and the KL weight traded one for the other: at β = 4 only 11 of 128 code dimensions carried any information.

Autoencoders

An autoencoder is two networks. The encoder maps a 32 × 32 × 3 image (3,072 numbers) to a code z of, say, 128 numbers; the decoder maps z back to an image. Training minimises the reconstruction error, here the mean squared error between input and output. The code is a bottleneck: with fewer numbers than pixels, the network must keep what matters most for rebuilding the image and drop the rest.

class Enc(nn.Module):        # 32x32x3 -> 16 -> 8 -> 4 (256 ch) -> z
    ...  nn.Conv2d(3, 64, 4, 2, 1), nn.ReLU(), nn.Conv2d(64, 128, 4, 2, 1), ..., nn.Flatten(), nn.Linear(4096, z)
class Dec(nn.Module):        # z -> 4x4x256 -> 8 -> 16 -> 32x32x3, sigmoid output
    ...  nn.Linear(z, 4096), ..., nn.ConvTranspose2d(64, 3, 4, 2, 1), nn.Sigmoid()
x_hat = dec(enc(x)); loss = F.mse_loss(x_hat, x)

Reconstruction quality is usually reported as PSNR, peak signal-to-noise ratio: 10 log10(1 / MSE) for pixels in [0, 1], in decibels, higher is better. Each extra 3 dB halves the error; around 20 dB looks recognisable but soft, 30 dB is hard to tell from the original at a glance.

Each quadrupling of the code bought 3–4 dB, roughly halving the error each time. With 8 numbers the network can only store the overall colour layout of a scene; with 512 it keeps edges and shapes. Even the largest code smooths fine texture: mean squared error is dominated by large regions, and the cheapest way to lower it is to get those right and average the rest.

Why you cannot sample a plain autoencoder

Training only asks the decoder to work on the codes the encoder produces. Those codes occupy some odd-shaped region of the code space, with gaps and holes where no training image landed, and nothing in the loss tells the decoder what to do there. The panel shows what happens. Each AE’s “samples” decode random codes whose every dimension is drawn from a normal with the same mean and spread as the training codes. For the 8-number code they look like its reconstructions, soft colour blobs, because 8 dimensions are densely filled. For the 512-number code they are colourful noise: matching each dimension’s spread is not enough when the real codes lie on a thin, curved surface inside a 512-dimensional space, and almost every random point is far from it.

Variational autoencoders

A VAE (2013) makes the code space usable by changing two things. First, the encoder outputs a distribution rather than a point: a mean μ and a (log-)variance σ² per code dimension, and the decoder is trained on a code sampled from it. Nearby codes must therefore decode to similar images, which fills the holes. Second, a penalty pulls every such distribution towards a standard normal N(0, 1), so all the codes together pack into one round, gap-free cloud. Sampling is then simple: draw z from N(0, 1) and decode.

The penalty is the KL divergence between the encoder’s Normal(μ, σ²) and N(0, 1), which has a closed form per dimension: ½(μ² + σ² − log σ² − 1). It is zero only when μ = 0 and σ = 1, that is, when the code carries no information about the image. The full loss balances the two pulls:

loss = reconstruction error + β × KL( N(μ, σ²) ‖ N(0, 1) )

With β = 1 and a Gaussian decoder this is the negative evidence lower bound (ELBO) of the original paper; β above 1 (a “β-VAE”) trades reconstruction for a smoother, more organised code space.

The reparameterisation trick

You cannot backpropagate through “draw a random sample”. The trick is to move the randomness outside the network: sample ε from N(0, 1), a constant as far as gradients are concerned, and compute z = μ + σ · ε. Now z is a differentiable function of μ and σ, and the encoder learns through it.

mu, logvar = enc(x)                                   # each (N, 128)
z = mu + torch.randn_like(mu) * (0.5 * logvar).exp()        # reparameterised sample
rec = F.mse_loss(dec(z), x, reduction="sum") / len(x)
kl = -0.5 * (1 + logvar - mu ** 2 - logvar.exp()).sum(1).mean()
loss = rec + beta * kl
samples = dec(torch.randn(8, 128))                        # generation: decode N(0, 1) codes

The KL weight prices information. At β = 0.1 information is cheap: the encoder uses all 128 dimensions, carries 117 nats about each image, and reconstructs nearly as well as the plain autoencoder (22.7 dB against 23.5), while its samples are more varied but less coherent. At β = 1 the encoder keeps 23 nats in 49 dimensions and switches the other 79 off, sitting exactly on the prior, a behaviour called posterior collapse when it goes too far. At β = 4 only 11 dimensions are used and reconstructions fall to the 8-dimension autoencoder’s level, 16.4 dB. Every VAE’s samples are image-like in layout, with sky, ground and a central blob, which no plain autoencoder with a large code achieved; and the interpolation row shows the other benefit of a filled-in code space: walking from a cat’s code to an aeroplane’s decodes to a smooth sequence of in-between images, not to noise.

Why VAE samples are blurry

None of the VAEs produced a sharp sample, at any β. Under mean squared error, the best prediction for an uncertain pixel is the average of the possibilities; a VAE decoding a code that could have come from several images outputs their average, and averages of images are blurry. The panel’s last row shows the same effect without any network: the pixel mean of each image’s 10 nearest training images. Later models attacked this from different sides: GANs (Chapter 27) replace pixel error with a learned critic that punishes blur, VQ-VAEs make the code discrete, and latent diffusion (Chapter 29) keeps a VAE only as a compressor with a small, information-rich code, and lets a diffusion model do the generating.

🧾
Use case: anomaly detection and the compressor inside Stable Diffusion

Autoencoders trained only on normal images reconstruct normal images well and anomalies badly, so reconstruction error is a simple anomaly score: factories use it to flag scratched parts, and it needs no examples of defects. The catch, visible in this chapter’s results, is that a large enough code reconstructs almost anything, so the bottleneck size has to be tuned on held-out anomalies. The other big use is compression: Stable Diffusion’s VAE turns a 512 × 512 × 3 image into a 64 × 64 × 4 latent, 48 times fewer numbers, with the KL weight set very low so reconstructions stay sharp, and every generated image passes through its decoder (Chapter 29).

⚠️
Common mistakes
  • Sampling a plain autoencoder and expecting images: its decoder was never trained off the codes it saw.
  • Averaging the KL over dimensions but summing the reconstruction over pixels (or the reverse): it silently changes β by a factor of thousands.
  • Using the sampled z for evaluation: reconstruct from μ.
  • Setting β too high: at β = 4 only 11 of 128 dimensions carried information and reconstructions fell to 16.4 dB.
  • Judging generators by reconstruction PSNR: a model can reconstruct well and sample badly.

Interview drill

Explain it simply: What does a VAE add to an autoencoder, and why?

How a strong answer sounds
A plain autoencoder maps each image to one code and is only trained on those codes, so the code space has holes and decoding a random code gives garbage. A VAE’s encoder outputs a mean and variance per dimension, the decoder is trained on a random sample from that distribution, which forces nearby codes to decode to similar images, and a KL penalty pulls every distribution towards a standard normal, packing the codes into one gap-free cloud. Then you can sample z from N(0, 1) and decode. Training through the sampling uses the reparameterisation trick, z = μ + σε with ε drawn outside the graph. In my CIFAR-10 runs, an autoencoder with a 512-number code reconstructed at 26.7 dB but decoded random codes to noise, while a VAE’s samples from N(0, 1) were blurry but image-like.

Deeper: Why are VAE samples blurry, and how would you get sharper images?

How a strong answer sounds
With a pixel-wise Gaussian (MSE) decoder, the optimal output for a code compatible with several images is their mean, and means are blurry; the KL term makes codes deliberately imprecise, so there is always some of that uncertainty. Options: a perceptual or adversarial loss on the decoder, as in VQ-GAN, so blur is penalised; a more expressive prior or a discrete codebook (VQ-VAE) with an autoregressive or diffusion model over codes; or, as Stable Diffusion does, use the VAE only as a compressor with a weak KL so reconstructions are sharp, and generate in its latent space with a diffusion model. I measured the trade-off directly: raising β from 0.1 to 4 cut the information in the code from 117 to 7 nats and the active dimensions from 128 to 11, and PSNR fell from 22.7 to 16.4 dB, with samples blurry throughout.

🧠 Key takeaways

  • An autoencoder compresses to a code and reconstructs; reconstruction PSNR rises with code size.
  • Measured: 16.6 dB with an 8-number code, 26.7 dB with 512; random codes from a large plain autoencoder decode to noise.
  • A VAE encodes a distribution, samples with z = μ + σε, and adds β × KL to N(0, 1) to the loss.
  • β prices information: β 0.1 used all 128 dimensions (117 nats), β 4 only 11 (7 nats), with PSNR 22.7 → 16.4 dB.
  • MSE decoders produce averages, which is why VAE samples are blurry; GANs and diffusion fix the generation step.

Check your understanding

Why do random codes decoded by a plain autoencoder rarely look like images?

Nothing in the reconstruction loss constrains what the decoder does away from training codes.

What does the reparameterisation trick do?

Sampling is moved outside the network; z becomes a differentiable function of the encoder’s outputs.

When is the KL term for one code dimension zero?

½(μ² + σ² − log σ² − 1) is zero only at the prior; every bit of information a dimension carries costs KL.

What does raising β in a β-VAE do?

β prices information in the code; a high price means the model keeps less of it.

Why are VAE samples typically blurry?

The same effect appears with no network at all: the pixel mean of an image’s nearest neighbours.
