Vision Transformers from Scratch

A convolutional network builds in the assumption that nearby pixels matter most. A Vision Transformer (ViT, 2020) drops that assumption: it cuts the image into 16 × 16 patches, treats each patch as a word, and runs the same transformer encoder used for text, so every patch can attend to every other patch from the first layer.

This chapter writes a ViT-B/16 in about 30 lines of plain PyTorch, loads torchvision’s ImageNet weights into it and checks that the outputs match to within 2 × 10−6. Then it takes the model apart: where its 86.6 million parameters live, why its cost grows with the square of the number of patches, what fused attention does to memory, and what the class token looks at.

Patches as tokens

A 224 × 224 image cut into 16 × 16 patches gives a 14 × 14 grid: 196 patches, each a vector of 16 × 16 × 3 = 768 numbers. A learned linear layer projects each patch to the model width (768 for ViT-Base). The transformer never sees pixels again, only these 196 vectors, so “ViT-B/16” means the Base size with 16-pixel patches. Halving the patch size to 8 quadruples the tokens to 784; doubling the resolution to 448 does the same.

The projection of non-overlapping patches is exactly a convolution with a 16 × 16 kernel and stride 16, which is how every implementation writes it. Measured on the cat photo, a Conv2d(3, 768, 16, stride=16) and F.unfold followed by a matrix multiply with the same weights agreed to 3.1 × 10−6: the same computation, up to rounding.

The class token and position embeddings

Two learned additions turn the patch vectors into the encoder’s input. A class token, one extra learned vector, is prepended, giving 197 tokens; it belongs to no patch, gathers information from all of them through attention, and its final state is what the classifier reads. And because attention treats its input as a set, a learned position embedding (one 768-vector per token position) is added so the model knows which patch came from where. Nothing tells it that patch 15 is below patch 1; it learns that from data.

The encoder, in plain PyTorch

Self-attention in one paragraph. Every token is projected three ways, to a query, a key and a value. Each token’s query is compared with every key by a dot product, the scores are scaled by √d and softmaxed into weights that sum to 1, and the token’s output is the weighted average of all values. With 12 heads, this happens 12 times in parallel on 64-dimensional slices, so different heads can attend to different things. Each of the 12 blocks is a standard pre-norm transformer block: LayerNorm, multi-head self-attention with 12 heads of 64 dimensions, a residual add, LayerNorm, an MLP that widens to 3,072 with GELU and narrows back, and another residual add.

class Block(nn.Module):
    def forward(s, x):                                                        # x (B, T, D), T = 197, D = 768
        B, T, D = x.shape
        q, k, v = s.qkv(s.ln1(x)).view(B, T, 3, s.h, D // s.h).permute(2, 0, 3, 1, 4)  # each (B, 12, T, 64)
        att = (q @ k.transpose(-1, -2) / math.sqrt(D // s.h)).softmax(-1)      # (B, 12, T, T): every token to every token
        x = x + s.proj((att @ v).transpose(1, 2).reshape(B, T, D))
        return x + s.fc2(F.gelu(s.fc1(s.ln2(x))))                            # MLP 768 -> 3072 -> 768

class ViT(nn.Module):
    def forward(s, x):                                                        # x (B, 3, 224, 224)
        x = s.patch(x).flatten(2).transpose(1, 2)                                # Conv2d(3, 768, 16, 16) -> (B, 196, 768)
        x = torch.cat([s.cls.expand(len(x), -1, -1), x], 1) + s.pos              # (B, 197, 768)
        for b in s.blocks: x = b(x)
        return s.head(s.ln(x)[:, 0])                                            # classify from the class token

Copying torchvision’s vit_b_16 ImageNet weights into this model (renaming keys: torchvision stores the q, k and v projections as one in_proj_weight, the same layout as qkv here) and running both on the same image: the largest difference among the 1,000 logits was 1.9 × 10−6, and both called the cat an Egyptian cat at 66.1%. On every second Imagenette validation image (1,962 photos, 1,000-way prediction), the from-scratch model was right 92.31% of the time; torchvision reports 81.1% top-1 on ImageNet for these weights.

Cost grows with the square of the tokens

Self-attention compares every token with every other, so its cost and the size of its T × T score matrix grow with T². At 224 pixels that is a small part of the work; at high resolution it takes over. Same model, positions interpolated to each size, batch 16 in bf16:

From 224 to 768 pixels the token count grew 11.7 times and the fused model’s time 17.5 times: faster than the tokens, because attention’s share of the arithmetic rose from 4% to a third. Naive attention was worse on both counts. It materialises the full score matrix, 16 images × 12 heads × T × T, in every block: at 512 pixels that is 16 × 12 × 1,025² ≈ 200 million numbers, and the softmax runs in float32, so peak memory doubled from 224; at 768 the matrix alone needed 3.8 GB in one allocation and the run ran out of the 14.5 GB budget. The fused kernel computes the softmax in tiles without ever storing the matrix, so its memory grew only from 1.3 to 2.2 GB and it was 2.4 times faster at 512. ResNet-50 was 2.5–3.3 times faster than ViT-B/16 at every size; it does about a quarter of the arithmetic (4.1 against 17.6 billion multiply-adds per image at 224).

Changing resolution: interpolate the positions

The weights are resolution-free except the position table: at 384 pixels there are 24 × 24 = 576 patches but only 14 × 14 learned positions. The standard fix is to reshape the 196 position vectors into their 14 × 14 grid and resize it with bicubic interpolation to 24 × 24, keeping the class token’s entry. Without any fine-tuning, the 224-trained model at 384 pixels scored 89.40%, against 92.31% at 224: interpolated positions keep the model working, but 2.9 points are lost until it is fine-tuned at the new size on the same Imagenette images. Fine-tuning a few epochs at the higher resolution, which is what DeiT and the original ViT did for their 384 models, recovers and usually improves on that.

What the class token looks at

The panel’s first view shows the class token’s attention to the 196 patches, averaged over heads, in blocks 1, 6 and 12, and the mean distance between each patch and the patches it attends to. Block 1 is diffuse, close to uniform. The middle blocks are the most local and, on these photos, the class token focuses on the object’s distinctive parts. Block 12 is not what most explanations show: a third to a half of the class token’s attention goes to five patches in plain, low-detail regions, not on the object. Large supervised ViTs learn to use a few uninformative patches as storage for global information (the “registers” finding of 2023), so last-block attention maps are not explanations; Chapter 10’s attribution methods are.

Use case: one backbone for images, text and documents

Because a ViT turns an image into a sequence of tokens, it plugs straight into the rest of the transformer ecosystem. CLIP (Chapter 24) trains a ViT image encoder alongside a text transformer; multimodal assistants feed ViT patch tokens into a language model as if they were words; document models read scanned pages as patches. The cost lesson from this chapter decides the engineering: a screenshot at 1,344 × 1,344 with 14-pixel patches is 9,216 tokens, so production systems tile large images, merge neighbouring tokens, or use windowed attention (Swin, Chapter 21) rather than one global attention over everything.

⚠️
Common mistakes
  • Feeding a ViT a new resolution without interpolating positions: the shapes do not even match, and copying a smaller table silently scrambles locations.
  • Assuming cost scales with pixels. Linear layers do; attention scales with pixels squared, and naive attention’s memory does too.
  • Writing attention by hand in production instead of F.scaled_dot_product_attention, which picks a fused kernel and never stores the T × T matrix.
  • Using ImageNet normalisation from another model: some ViT weights expect mean and std of 0.5, others ImageNet statistics. Read the weights’ transforms.
  • Training a ViT from scratch on a small dataset and concluding transformers do not work for vision (Chapter 20).

Interview drill

Explain it simply: How does a Vision Transformer process an image?

How a strong answer sounds
It cuts the image into fixed patches, 16 × 16 pixels for ViT-B/16, so a 224-pixel image becomes 196 patches. Each patch is flattened and linearly projected to a 768-dimensional token, which is the same as a 16 × 16 convolution with stride 16. A learned class token is prepended and a learned position embedding is added to every token, because attention by itself does not know order. Twelve standard transformer blocks of self-attention and MLP follow, with no downsampling, and the classifier reads the final class token. I wrote one in about 30 lines, loaded torchvision’s weights, and its logits matched to about 2 × 10⁻⁶. Most of the 86.6 M parameters are in the MLPs, and attention lets any patch use any other from the first layer.

Deeper: You need to run a ViT on 1,024 × 1,024 inspection images. What breaks, and what do you change?

How a strong answer sounds
With 16-pixel patches that is 4,096 tokens instead of 196. The linear layers and MLPs grow about 21 times, but attention grows with the square, about 430 times, and a naive implementation stores a 12 × 4,096 × 4,096 score matrix per layer per image, which is what ran out of memory in my measurement already at 768 pixels with batch 16. First, use fused attention (scaled_dot_product_attention with a flash kernel), which keeps memory linear in tokens though compute stays quadratic. Second, interpolate the position embeddings and fine-tune at the new resolution. Then decide whether global attention is needed: windowed attention (Swin), token merging, a larger patch size, or tiling the image into 224–512 crops all cut the quadratic term. For defect detection I would test tiling first, because defects are local.

🧠 Key takeaways

  • A ViT turns an image into patch tokens (a strided convolution), adds a class token and learned positions, and runs a plain transformer encoder.
  • A 30-line ViT loaded with torchvision’s weights matched it to about 2 × 10⁻⁶.
  • Two thirds of ViT-B’s 86.6 M parameters are MLPs; no parameter depends on resolution except the position table.
  • Attention cost and naive memory grow with tokens squared; fused attention fixes the memory, not the compute.
  • A new resolution needs interpolated position embeddings, and ideally a short fine-tune.

Check your understanding

How many patch tokens does ViT-B/16 make from a 224 × 224 image?

224 / 16 = 14 per side, 14 × 14 = 196; with the class token the sequence has 197.

The patch embedding is equivalent to which layer?

Non-overlapping patches, each projected by the same linear map: that is a strided convolution, which matched unfold + matmul here to rounding error.

Why does a ViT need position embeddings?

Shuffle the patches and attention gives the same outputs, shuffled. Positions break that symmetry.

Where are most of ViT-B/16’s parameters?

56.7 M of 86.6 M are MLP weights; attention projections are 28.3 M.

You double the input side from 224 to 448 with the same patch size. Roughly how does attention’s score-matrix size change?

Tokens grow 4× (twice per side), and the T × T matrix grows with the square: about 16×.
