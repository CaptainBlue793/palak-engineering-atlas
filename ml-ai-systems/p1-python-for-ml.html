Python for ML

Almost all machine-learning code is written in Python: the training scripts, the data pipelines, the notebooks, and the libraries such as NumPy, pandas, scikit-learn and PyTorch. You don't need to be a Python expert to follow this course. ML code uses a small part of the language, over and over. This chapter teaches exactly that part, from zero, with snippets you can run and a quick game to check yourself.

  • Run Python in a terminal or a notebook, and install packages in a virtual environment
  • Use the basic types — int, float, str, bool, None — and avoid the classic division surprise
  • Work with lists, tuples, dicts and sets, including slicing
  • Write loops, conditions, functions and comprehensions
  • Read a class the way ML frameworks use them: parameters as attributes, predict as a method
  • Import libraries and read and write files, including JSON

Why Python, and how to run it

Python is slow at raw arithmetic compared with C or C++. So why does all of ML use it? Because the heavy maths doesn't actually run in Python. Libraries like NumPy and PyTorch are written in fast compiled languages and run on CPUs and GPUs; Python is the friendly glue that tells them what to do. You get readable code and fast execution at the same time.

There are three common ways to run Python:

💻

Interactive prompt

Type python (or python3) in a terminal. You get a >>> prompt; type a line, press Enter, see the result. Great for trying one idea.

📄

Script

Save code in a file like train.py and run python train.py. This is how real training jobs and services run.

📓

Notebook

Jupyter or Google Colab: code in cells you run one at a time, with results, tables and charts shown underneath. The standard tool for exploring data. Colab runs in a browser with nothing to install.

Packages and virtual environments

Libraries are installed with pip, Python's package installer: pip install numpy pandas scikit-learn. Different projects often need different versions of the same library, so each project gets its own virtual environment — a private folder of installed packages:

# create and activate a virtual environment for this project
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install numpy pandas matplotlib scikit-learn
pip freeze > requirements.txt    # record exact versions so others can reproduce your setup

Recording versions matters more in ML than elsewhere: a model trained with one library version can behave slightly differently with another. You'll see why reproducibility is a whole topic in Chapter 11.

Values, variables and types

A variable is a name attached to a value. You create one by assigning with =. Python works out the type by itself — you never declare it.

epochs = 10                 # int: a whole number
learning_rate = 3e-4       # float: a decimal number (3e-4 means 3 × 10⁻⁴ = 0.0003)
model_name = "resnet50"    # str: text, in single or double quotes
use_gpu = True             # bool: True or False (capital letters)
checkpoint = None          # None: "no value yet"

print(type(learning_rate))                        # <class 'float'>
print(f"Training {model_name} for {epochs} epochs")  # Training resnet50 for 10 epochs

That last line is an f-string: put f before the quotes and anything inside { } is replaced by its value. You'll use them constantly for log messages. You can also format numbers: f"{0.123456:.3f}" gives 0.123.

Two layout rules are worth knowing on day one. Python uses indentation (the spaces at the start of a line) to group code, where other languages use braces { } — so spacing isn't just style, it's meaning. And lines starting with # are comments, notes that Python ignores. In this course a comment after print(...) shows what it prints.

Numbers and the division surprise

You'll see // and % in ML code more than you'd expect. For example, splitting 1,050 examples into batches of 32 gives 1050 // 32 = 32 full batches, with 1050 % 32 = 26 examples left over for a smaller last batch.

🔢
Floats are approximate

0.1 + 0.2 prints 0.30000000000000004. Computers store decimals in binary, and most decimal fractions can't be stored exactly — just as 1/3 can't be written exactly in decimal. This isn't a Python bug; every language does it. In ML it means: never compare floats with ==; check they're close instead (abs(a - b) < 1e-9, or math.isclose). You'll meet the consequences of limited precision again in P8.

Lists and tuples

A list is an ordered collection in square brackets. Positions, called indices, start at 0. Negative indices count from the end, so [-1] is the last item. A slice a[start:stop] takes items from start up to but not including stop.

losses = [2.31, 1.87, 1.42, 1.10, 0.95]
losses.append(0.88)                  # add to the end
print(losses[0], losses[-1], len(losses))   # 2.31 0.88 6
print(losses[1:3])                     # [1.87, 1.42]
print(losses[-3:])                     # [1.1, 0.95, 0.88]  — the last three
print(min(losses), sorted(losses)[:2])   # 0.88 [0.88, 0.95]

Slicing trips everyone up at first. Play with it:

Each box shows the item and both of its indices (positive on top, negative below). Highlighted boxes are the ones the slice returns. Notice that stop is never included, and that a[i:i] is always empty.

A tuple is like a list but written with round brackets and can't be changed after it's made: shape = (32, 224, 224, 3). Tuples are used for things that are fixed, such as the shape of an array. You can unpack them into variables in one line: batch, height, width, channels = shape. Functions often return tuples: train_X, test_X = split(X).

Dicts and sets

A dict (dictionary) maps keys to values, like a phone book maps names to numbers. You look things up by key, not by position. Looking up a missing key with d[key] raises an error; d.get(key, default) returns a default instead.

config = {"lr": 3e-4, "batch_size": 32, "epochs": 10}
config["epochs"] = 20                           # change a value
config["dropout"] = 0.1                        # add a new key
print(config["lr"], config.get("seed", 42))   # 0.0003 42
for key, value in config.items():
    print(key, "=", value)                      # lr = 0.0003, batch_size = 32, ...

# counting things: a classic dict pattern
counts = {}
for label in ["cat", "dog", "cat", "cat"]:
    counts[label] = counts.get(label, 0) + 1
print(counts)                                  # {'cat': 3, 'dog': 1}

You'll meet dicts as training configs, as a vocabulary mapping each word to an id number (Chapter 15), as label counts when checking class balance (Chapter 3), and as JSON — the format most APIs, including LLM APIs, speak. Looking up a key in a dict takes about the same time whether it holds ten items or ten million, which is why they're used everywhere.

A set is an unordered collection with no duplicates: {"cat", "dog"}. Use it to remove duplicates (set(labels)), or to check membership fast (if user_id in seen:). A classic ML use: checking that no example appears in both your training and test data — set(train_ids) & set(test_ids) should be empty.

Loops and conditions

An if statement runs code only when a condition is true. Conditions use == (equal), != (not equal), <, >, <=, >=, combined with the words and, or and not.

val_loss = 0.42
if val_loss < 0.3:
    print("great")
elif val_loss < 0.5:          # "else if"
    print("ok")                 # prints ok
else:
    print("keep training")

A for loop repeats a block once for each item. Three helpers appear in nearly every ML loop:

  • range(n) gives 0, 1, …, n − 1. for epoch in range(10): runs ten epochs.
  • enumerate(items) gives the position and the item together: for i, batch in enumerate(loader):.
  • zip(a, b) walks two lists side by side: for pred, target in zip(preds, targets):.
for epoch in range(3):
    for step, batch in enumerate(["b0", "b1"]):
        print(epoch, step, batch)       # 0 0 b0, 0 1 b1, 1 0 b0, ...

best = float("inf")                   # start with "infinitely bad"
for loss in [0.9, 0.7, 0.75, 0.6]:
    if loss < best:
        best = loss                     # remember the best result so far
print(best)                             # 0.6

A while loop repeats as long as a condition holds, and break leaves a loop early. Early stopping — halting training when the validation loss stops improving — is often written this way (Chapter 9).

🐢
Loops are for control, not for maths

Python loops are perfectly fine for epochs, batches and files — a few thousand iterations. They are very slow for doing arithmetic on millions of numbers one at a time: often 50–100× slower than the same maths in NumPy. That's the whole reason the next chapter exists (P2).

Functions

A function is a named, reusable piece of code. It takes inputs (arguments) and hands back a result with return. Here is a real ML function, mean squared error — the average of the squared differences between predictions and true answers:

def mse(preds, targets):
    """Mean squared error between two equal-length lists."""
    total = 0.0
    for p, t in zip(preds, targets):   # pairs: (2.5, 3.0), (0.0, -0.5)
        total += (p - t) ** 2
    return total / len(preds)

print(mse([2.5, 0.0], [3.0, -0.5]))   # 0.25

Work it by hand once: the differences are −0.5 and 0.5; squared, 0.25 and 0.25; averaged, 0.25. The string in triple quotes is a docstring, a description that tools and editors show when you hover over the function.

Three features show up in every ML library:

  • Default and keyword arguments. def train(model, lr=0.01, epochs=10): lets you call train(m) or train(m, epochs=50), naming only what you change. Library calls like LogisticRegression(C=0.5, max_iter=1000) use this style everywhere.
  • Returning several values. return loss, accuracy returns a tuple; the caller unpacks it with loss, acc = evaluate(model).
  • Small anonymous functions. lambda x: x[1] is a one-line function without a name, handy as a sort key: sorted(results, key=lambda r: r["val_loss"]) sorts experiment results from best to worst.

One gotcha: variables created inside a function are local: they vanish when the function returns and can't be seen from outside. But if you pass in a list or dict and change it inside the function, the caller sees the change, because both names refer to the same object.

Comprehensions: loops in one line

A list comprehension builds a new list from an old one: “give me this for each x in that, if condition”. It's the loop-and-append pattern, written compactly — and it's everywhere in ML code.

Loop and append

squares = []
for x in [1, 2, 3, 4]:
    if x % 2 == 0:
        squares.append(x * x)
# [4, 16]

Comprehension

squares = [x * x for x in [1, 2, 3, 4]
           if x % 2 == 0]
# [4, 16]
words = ["The", "cat", "sat"]
lower = [w.lower() for w in words]                   # ['the', 'cat', 'sat']
vocab = {w: i for i, w in enumerate(lower)}          # {'the': 0, 'cat': 1, 'sat': 2}
ids = [vocab[w] for w in ["the", "sat"]]              # [0, 2]

Those last three lines are a tiny tokenizer: text in, id numbers out. Real tokenizers (Chapter 15) are smarter about splitting words, but their output is exactly this kind of list of ids. The {w: i for …} form is a dict comprehension.

Classes: bundling data with behaviour

A class is a template for making objects that bundle data (attributes) with the functions that use it (methods). __init__ runs when you create an object, and self means “this particular object”. You rarely need to write big classes, but every model in every framework is one: its weights are attributes, and predicting is a method.

class LinearModel:
    def __init__(self, w=0.0, b=0.0):
        self.w = w          # the parameters live on the object
        self.b = b

    def predict(self, x):
        return self.w * x + self.b

m = LinearModel(w=2.0, b=1.0)
print(m.predict(3))      # 7.0
m.w = 0.5                   # "training" is just changing these numbers
print(m.predict(3))      # 2.5

That comment is the big idea of the whole course in one line: a trained model is a set of numbers, and training means changing them. P7 shows how the changes are chosen.

You'll also see inheritance: class MyNet(nn.Module): means “MyNet is a kind of PyTorch Module, with all its abilities, plus what I add”. And libraries follow shared conventions so all models look alike: scikit-learn models have .fit(X, y) and .predict(X); PyTorch modules define forward(x) and are called like a function, model(x).

Reading and writing files

Use with open(...) as f: to work with a file. The with block closes the file for you, even if something goes wrong halfway. The json module converts between Python dicts/lists and JSON text:

import json

# save the results of an experiment
results = {"model": "logreg", "val_acc": 0.912, "params": {"C": 0.5}}
with open("results.json", "w") as f:     # "w" = write (replaces the file)
    json.dump(results, f, indent=2)

# load it back
with open("results.json") as f:          # default mode "r" = read
    loaded = json.load(f)
print(loaded["params"]["C"])                # 0.5

# read a text file line by line (e.g. one training sentence per line)
with open("sentences.txt", encoding="utf-8") as f:
    sentences = [line.strip() for line in f if line.strip()]

For tabular files such as CSVs you'll almost always use pandas (pd.read_csv("data.csv")) instead, which you'll meet in the next chapter.

When things go wrong: reading an error

When Python hits a problem it stops and prints a traceback. Read it from the bottom up: the last line names the error type and message; the lines above show the chain of calls that led there, ending with the exact line. The errors you'll see most:

ErrorUsually means
IndexErrorYou asked for position 10 of a list with 10 items (the last one is 9).
KeyErrorA dict doesn't have that key — often a typo in a column or config name.
TypeErrorWrong kind of value, e.g. adding a string to a number.
ValueErrorRight type, bad value — in NumPy, very often shapes that don't match.
ModuleNotFoundErrorThe library isn't installed in the environment you're running.

Common mistakes
  • Off-by-one in slices. a[0:3] is three items (0, 1, 2), not four. The stop index is never included.
  • Mixed-up indentation. A line indented one level too little silently leaves the loop. Use 4 spaces consistently.
  • Comparing floats with ==. 0.1 + 0.2 == 0.3 is False. Compare with a tolerance.
  • Changing a list you're looping over. Removing items mid-loop skips elements. Build a new list with a comprehension instead.
  • Installing into the wrong environment. If import fails after pip install, you're probably running a different Python. Activate the project's virtual environment first.
  • Doing big maths in Python loops. Correct but painfully slow. Use NumPy.

Interview drill

Code it: Given a list of predicted labels and a list of true labels, write a function that returns accuracy.

How a strong answer sounds
def accuracy(preds, targets): return sum(p == t for p, t in zip(preds, targets)) / len(targets). It pairs the lists with zip, counts matches (True counts as 1), and divides by the number of examples. I'd mention two edge cases: raise an error if the lists differ in length (zip would silently truncate), and handle an empty list to avoid dividing by zero. For large data I'd use NumPy: (preds == targets).mean().

Explain it simply: Python is slow — so why is it the language of machine learning?

How a strong answer sounds
Because Python only coordinates the work. The heavy maths runs inside libraries like NumPy and PyTorch, written in C, C++ and CUDA and executed on CPUs and GPUs. Python gives readable, quick-to-write code and a huge ecosystem; as long as you keep the arithmetic inside those libraries instead of Python loops, you get near-native speed.

🧠 Key takeaways

  • Run Python as a prompt, a script or a notebook; install packages with pip inside a per-project virtual environment.
  • Basic types: int, float, str, bool, None. / gives a float, // rounds down, % is the remainder. Floats are approximate.
  • Lists are ordered and 0-indexed; slices exclude the stop index; tuples are fixed lists; dicts map keys to values; sets hold unique items.
  • for-loops with range, enumerate and zip drive training loops; comprehensions build lists and dicts in one line.
  • Functions take arguments (with defaults and names) and return values; classes bundle parameters with methods like predict.
  • Import libraries with their standard nicknames, use with open for files, and read tracebacks from the bottom up.

Check your understanding

What does [10, 20, 30, 40, 50][1:4] give?

Indices start at 0, so position 1 is 20. The slice runs up to but not including position 4, giving positions 1, 2 and 3: 20, 30, 40.

You have 1,000 examples and a batch size of 64. Which expression gives the number of full batches?

// is floor division: 1000 // 64 = 15 full batches. / gives 15.625, and % gives the 40 leftover examples that form a smaller last batch.

What does {"lr": 0.01}.get("epochs", 5) return?

.get returns the default when the key is missing. Writing d["epochs"] instead would raise a KeyError.

Which comprehension gives the lengths of only the words longer than 3 letters in words?

The expression before for is what goes into the new list (the length); the if at the end filters which words are used. Option 2 returns the words themselves, and option 3 builds a dict.

In a model class, what is the role of self.w?

Attributes set on self belong to that object and live as long as it does. Model parameters are stored this way, so predict can use them and training can update them.
