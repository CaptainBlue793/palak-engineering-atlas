Neural Networks & Backpropagation

A neural network is several logistic regressions stacked on top of each other, with a bend in between. That bend — the nonlinearity — lets the network learn shapes a straight line never could. Backpropagation is the bookkeeping that works out how to adjust every weight in the stack, which is what makes training it possible at all.

Why stack at all?

Logistic regression draws one straight boundary between the classes. Plenty of real problems can't be split by a line. The classic example is XOR: the positives sit in two opposite corners and the negatives in the other two. No single line separates them.

Concretely, XOR (“exclusive or”) is true when exactly one input is on. The four points are (0,0) → 0, (1,0) → 1, (0,1) → 1 and (1,1) → 0. Why can no line work? A line splits the plane into two sides. If both 1s, (1,0) and (0,1), are on the “1” side, then so is every point on the segment between them, including its midpoint (0.5, 0.5). But (0.5, 0.5) is also the midpoint of the two 0s, (0,0) and (1,1) — and if both of those were on the “0” side, that midpoint would have to be on the “0” side too. It can't be on both, so at least one point is always misplaced. Real data is full of this kind of pattern: “risky if the amount is high and the account is new, but not if only one of those is true”.

Stacking two linear layers without a nonlinearity doesn't help. W₂(W₁x) = (W₂W₁)x — the two weight matrices multiply into one matrix, so you still get one line.

With single numbers it's obvious: multiply by 3, then by 2, and you've just multiplied by 6. However many linear steps you chain, the result is one linear step. Now add a bend. Here is a hand-built network with two ReLU units that solves XOR exactly (ReLU(z) = max(0, z)):

  • h₁ = ReLU(x₁ + x₂) and h₂ = ReLU(x₁ + x₂ − 1), then output h₁ − 2·h₂.
  • (0,0): h₁ = 0, h₂ = 0 → output 0.
  • (1,0) and (0,1): h₁ = 1, h₂ = 0 → output 1.
  • (1,1): h₁ = 2, h₂ = 1 → output 2 − 2 = 0.

The second unit only switches on when both inputs are on, and then it cancels the first. That “switching on” is the nonlinearity doing its job. Training finds weights like these by itself.

🔑
The whole trick, in one line

Put a nonlinear function between the layers — a = f(W₁x), then ŷ = W₂a — and the whole thing is no longer linear. Each hidden unit cuts the space in two with one line. The next layer combines those cuts into any shape it needs. Each extra layer multiplies how many shapes the network can build, so depth grows this ability exponentially.

Anatomy of a network

Learn these four words and you can read almost any architecture diagram:

🔢

Neuron

a = f(w·x + b). Multiply inputs by weights and add them up, add a bias, then pass the result through a squashing function. That's the basic building block.

📚

Layer

Many neurons that all read the same input. Computing them all at once is one matrix multiply: A = f(XW + b).

🏗️

Depth

Layers stacked on top of each other. Early layers learn simple features; later ones combine them into more complex ones.

🎯

Head

The final layer, shaped to fit the task: 1 output + sigmoid for yes/no, K outputs + softmax for K classes, or a raw number for regression.

Counting the weights. The network in the diagram below has 2 inputs, 3 hidden units and 1 output. The first layer has 2 × 3 = 6 weights plus 3 biases (9 parameters). The second has 3 × 1 = 3 weights plus 1 bias (4 parameters). That's 13 learnable numbers in total. The same arithmetic, input size × output size + output size, gives the size of any fully connected layer: a 4,096 → 4,096 layer has about 16.8 million parameters. That's how models reach billions.

Softmax, used by multi-class heads, is the many-class version of sigmoid. It turns K raw scores into K probabilities that add up to 1: raise e to each score, then divide by the total. Scores [2, 1, 0] become [7.39, 2.72, 1.00], which sum to 11.11, giving probabilities [0.67, 0.24, 0.09]. The biggest score still wins, but now you also get a confidence.

One forward pass, one backward passStep-through
  1. One example comes in as a list of numbers (a vector), e.g. x = [0.7, −0.3]. In real training, thousands of examples are stacked into a matrix (a batch) and processed together. That's what makes GPUs worth using.
  2. Each hidden unit computes z = w·x + b. That's three dot products, done together as one matrix multiply. Every line in the diagram is one weight the network can learn.
  3. Apply ReLU(z) = max(0, z) to each unit. Any negative value becomes exactly zero, so that unit is “off” for this example. Because different units switch off for different inputs, the network is made of many straight pieces joined together (piecewise-linear) rather than one straight line.
  4. The hidden units' outputs are combined into one number. A sigmoid then squashes it into a probability between 0 and 1. For K classes you'd have K outputs and a softmax instead.
  5. Compare the prediction with the true label: L = −[y·log(ŷ) + (1−y)·log(1−ŷ)]. This one number, the loss, is the only feedback the whole network gets.
  6. Now go backwards. First work out how the loss changes when the output changes (its derivative, or gradient). With sigmoid + cross-entropy this simplifies to just ∂L/∂z = ŷ − y: prediction minus truth.
  7. Each weight's gradient is (ŷ − y) × hᵢ: “how wrong we were, times how much this unit contributed”. The error also flows further back to each hidden unit.
  8. ReLU's derivative is 1 where the unit was on and 0 where it was off. So the gradient flows back only through units that fired. Units that were off learn nothing from this example.
  9. Multiply once more to get the gradients for the first weight matrix. After one backward sweep you know every gradient in the network. That sweep costs roughly 2× the forward pass, however deep the network is.
  10. The optimizer nudges every weight: w ← w − η·g (η is the learning rate, g the gradient). The gradients are reset to zero and the next batch starts. Training is just this loop, repeated millions of times.
🏭
Analogy: blame assignment on a production line

A faulty product comes off the line. Backprop walks the line backwards and asks each station: “given how much you changed the product, how much of this fault is yours?” Each station adjusts a little, in proportion to its share of the blame. Doing this for billions of stations is only possible because each station's answer is a simple local derivative.

The same passes, with real numbers

Shrink the network to one input, one ReLU hidden unit and one sigmoid output, with biases set to zero so the arithmetic stays short. Take x = 1, true label y = 1, and starting weights w₁ = 0.5, w₂ = 2.

  1. Forward, hidden: z₁ = w₁·x = 0.5, and h = ReLU(0.5) = 0.5.
  2. Forward, output: z₂ = w₂·h = 1.0, and ŷ = σ(1.0) ≈ 0.731.
  3. Loss: L = −log(0.731) ≈ 0.313.
  4. Backward, output: ∂L/∂z₂ = ŷ − y ≈ −0.269. Negative: pushing z₂ up would lower the loss.
  5. Gradient for w₂: z₂ = w₂·h, so ∂L/∂w₂ = −0.269 × h = −0.269 × 0.5 ≈ −0.134.
  6. Error sent back to h: ∂L/∂h = −0.269 × w₂ = −0.538. The error is passed back along the same weight it came forward on.
  7. Through the ReLU: the unit was on (z₁ > 0), so its derivative is 1 and ∂L/∂z₁ = −0.538. Had it been off, this would be 0 and w₁ would learn nothing.
  8. Gradient for w₁: ∂L/∂w₁ = −0.538 × x = −0.538.
  9. Update with η = 0.1: w₂ = 2 + 0.013 ≈ 2.013 and w₁ = 0.5 + 0.054 ≈ 0.554. Both grow, which raises ŷ toward the correct answer of 1.

Every backward step was one multiplication by a local derivative — that's the chain rule: ∂L/∂w₁ = ∂L/∂z₂ × ∂z₂/∂h × ∂h/∂z₁ × ∂z₁/∂w₁. Notice also that step 6 reused the number from step 4 instead of recomputing it. That reuse is why one backward sweep gets every gradient. At each layer you do roughly two matrix multiplies the size of the forward one (one for the weights' gradients, one to pass the error further back), which is where “about 2× the forward pass” comes from.

Activation functions

The activation function is the nonlinearity applied inside each unit. It decides how well gradients flow backwards. This isn't a cosmetic choice: it can be the difference between a network that trains and one that doesn't.

The reason is the derivative, which the backward pass multiplies by at every layer (step 7 of the trace above). Sigmoid's derivative is at most 0.25, at z = 0, and by z = 5 it has shrunk to about 0.007. So even in the best case, ten sigmoid layers scale the gradient by at most 0.25¹⁰ ≈ 0.000001. ReLU's derivative is exactly 1 whenever the unit is on, so an active path passes the gradient back at full strength. Width, depth and what a network can represent

The universal approximation theorem says a network with one hidden layer, given enough units, can approximate any continuous function. As practical advice it's nearly useless, because “enough” can mean an exponentially huge number of units.

Depth gets you the same power at a manageable size. Each layer builds on the features of the layer before, instead of having to list every possible pattern separately.

An everyday comparison: to recognise any word, you could memorise every possible word as a whole picture (one enormous flat layer), or learn letters first and then words as combinations of letters (two layers). The second way needs far less memory, because the letter detectors are reused by every word. Deep networks win for the same reason — later layers reuse what earlier layers learned.

Wider

More units per layer, so more features at each level. Easy to run in parallel but uses lots of memory. Gains come fast at first, then shrink. Modern large models tend to grow width and depth together.

Deeper

More layers building on each other — edges → textures → objects. Far more expressive for the same number of weights, but harder to train: gradients have to survive more multiplications on the way back (the subject of Chapter 9).

In practice: for tabular data or small experiments, 2–4 hidden layers of 64–512 units is a sensible starting point; go wider first if the model underfits, since wide networks are easier to train. Go deeper when the input has layered structure — pixels, audio, text — and then use an existing architecture with residual connections rather than stacking plain layers yourself.

Vanishing and exploding gradients

Backprop multiplies a long chain of derivatives, one per layer. Multiply 30 numbers that average 0.6 and you get 2×10⁻⁷. The gradient reaching the early layers is so tiny they stop learning — it has vanished. Multiply 30 numbers that average 1.4 and you get 24,000. The gradient has exploded, and the update blows the weights apart.

Why does the chain multiply at all? In the trace above, the gradient for w₁ was a product of one factor per layer it passed through: a weight and an activation derivative each time. With 30 layers there are 30 such factors, and a product of many numbers is extremely sensitive to whether they sit a little below or a little above 1. Sigmoid's derivative, at most 0.25, practically guarantees the “below 1” case — which is why it was abandoned for hidden layers. The fixes in the table all aim to keep each factor close to 1.

🛣️
Residual connections, in one sentence

Each block outputs x + f(x) instead of just f(x): its input is added back to its output. That gives the gradient a shortcut where it passes through unchanged (derivative 1), however deep the stack. It's why networks jumped from ~20 layers to 1,000+ almost overnight, and why every transformer block has two of them (Chapter 14).

The maths behind “unchanged”: the derivative of x + f(x) with respect to x is 1 + f′(x). Even if f′(x) is tiny, the factor stays close to 1 rather than close to 0, so 50 blocks multiply to something reasonable instead of vanishing. A useful side effect: a block that has nothing useful to add can simply learn f(x) ≈ 0 and pass its input through, so adding layers can't easily make the network worse.

⚠️
Common mistakes
  • Forgetting the nonlinearity (or adding an activation after the final layer when the loss function already applies one). Both quietly cripple the model, with no error message.
  • Applying softmax, then a cross-entropy loss that expects raw scores (logits). The loss applies softmax again, and the double softmax flattens the gradients.
  • Setting all weights to zero at the start. Every unit computes the same thing and gets the same gradient forever, so the layer acts like a single neuron.
  • Not scaling inputs. A feature ranging from 0 to 100,000 pushes activations into their flat regions right away, and the first layer never recovers.
  • Reaching for a deeper network before checking the data. Extra depth rarely fixes noisy labels, leakage or a missing feature.

Interview drill

Warm-up: Why can't a 10-layer network without activation functions learn XOR?

How a strong answer sounds
Chaining linear functions just gives another linear function. The weight matrices multiply into a single matrix, so however deep the model is, it can only draw one flat boundary (a hyperplane). XOR can't be split by any flat boundary. The nonlinearity is what makes each added layer add power instead of collapsing into one.

Deeper: Your 40-layer network trains far worse than the 8-layer version on the same data. What's happening and what do you do?

How a strong answer sounds
Most likely a training (optimization) problem, not a capacity one. The deeper model can represent everything the shallow one can, so it shouldn't do worse. I'd check the size of the gradients in each layer. If early-layer gradients are many times smaller, the signal is vanishing. Fixes, biggest impact first: residual connections, normalization (LayerNorm/BatchNorm), a sensible initialization scaled by the number of inputs per unit (fan-in), learning-rate warmup, and gradient clipping if some gradients spike. If gradients look healthy and it's still worse, I'd suspect a learning rate too high for that depth, or too little data for that many parameters.

🧠 Key takeaways

  • Without a nonlinearity, any stack of linear layers collapses to one linear layer.
  • Backprop is the chain rule applied backwards through the network. One backward sweep gives every gradient, at roughly 2× the cost of the forward pass.
  • ReLU-style activations keep gradients alive; ones that go flat at the ends (sigmoid, tanh) choke them.
  • Depth lets layers build on each other; residual connections are what make deep networks trainable.
  • Vanishing and exploding gradients have clear symptoms and standard fixes — diagnose before you redesign.

Check your understanding

You remove all activation functions from a 5-layer network. What is the result equivalent to?

The weight matrices multiply into one matrix. The model trains fine — it just can't learn anything nonlinear.

What is ReLU's derivative for a negative input?

That's both ReLU's strength and its weakness. Strength: many units are off at once, which is cheap. Weakness: a unit that's negative for every example gets no gradient and never recovers — the “dying ReLU”.

You initialize every weight to 0. What goes wrong?

If every unit starts the same, they all compute the same outputs and get the same gradients, so they never become different. Starting with random weights breaks that symmetry.

A 50-layer network's early-layer gradients are ~1e-9 while the last layer's are ~1e-2. What helps most?

Classic vanishing gradients. A shortcut path with derivative 1 lets the gradient reach the early layers without shrinking. Normalization keeps the size of the activations stable along the way.

Roughly how expensive is a backward pass compared with a forward pass?

In the backward step, each layer computes gradients for both its inputs and its weights — two matrix multiplies instead of one. Rule of thumb: a full training step costs about 3× a forward pass. That's where the “6ND FLOPs” training estimate in Chapter 16 comes from.
