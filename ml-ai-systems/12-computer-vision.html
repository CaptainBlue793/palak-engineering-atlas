An image is a tensor

A 224×224 colour (RGB) photo is a tensor of shape (3, 224, 224). That is three grids of numbers — red, green and blue — each pixel an 8-bit brightness from 0 to 255. Before the image reaches the network, each channel is normalised: shifted and scaled so its values average about 0 with a spread (variance) of about 1.

A batch of B images adds one more dimension: (B, 3, 224, 224). Everything the network does is arithmetic on that block of numbers.

A worked example of normalising one pixel. Say its red value is 200. First divide by 255 to get a number between 0 and 1: 200 ÷ 255 ≈ 0.784. The standard ImageNet red channel has mean 0.485 and standard deviation 0.229, so the normalised value is (0.784 − 0.485) ÷ 0.229 ≈ 1.31. Why bother? Weights start small and are tuned for inputs near 0. Raw values up to 255 would make the first layer's outputs, and its gradients, far too large, and training would be unstable.

🎨
Match the preprocessing to the pretrained model

Say you fine-tune a model that was trained with ImageNet normalization. Then use those same channel means and standard deviations, the same resize method and the same channel order (RGB vs BGR). A mismatch here costs several accuracy points and gives no error message. It is one of the most common bugs when reusing a pretrained model.

Convolution, concretely

Take a small grid of weights, say 3×3, called the kernel. Slide it across the image. At each position, multiply each weight by the pixel under it and add the results up (a dot product). That sum becomes one pixel of the output, called a feature map.

Here is one step with real numbers. A vertical-edge kernel has the rows [−1, 0, 1], repeated three times. Place it over a patch that is dark on the left (0) and bright on the right (1). Each row gives −1×0 + 0×(middle) + 1×1 = 1, so the three rows sum to 3: a strong response. Place it over a flat patch where every pixel is 1. Each row gives −1 + 0 + 1 = 0, so the sum is 0: nothing there. That is exactly what “this kernel detects vertical edges” means.

On a colour image the kernel also spans all input channels, so a “3×3” kernel on RGB really holds 3×3×3 = 27 weights (plus one bias). Its output is still a single number per position.

Think of the kernel as a stencil that lights up when the patch beneath it matches its pattern. One kernel finds one kind of local pattern, such as a vertical edge. A conv layer has hundreds of kernels, and the network learns what their weights should be.

Why convolution instead of a dense layer?

A dense layer connecting 224×224×3 inputs to 1,000 units has 150 million weights. Worse, it must learn “an eye in the top-left” separately from “an eye in the middle”.

A convolution uses the same small kernel everywhere. So you get three things for free. First, translation equivariance: if the object moves, its detected pattern moves with it. Second, thousands of times fewer parameters. Third, a built-in assumption that nearby pixels belong together. That built-in assumption (an “inductive bias”) is why CNNs worked when data was scarce.

For scale: a first conv layer with 64 kernels of size 3×3 on RGB input has 64 × 27 = 1,728 weights. The dense layer above has about 87,000 times more.

Stride, padding, pooling and the receptive field

Three knobs control how the image's width and height shrink from layer to layer. Stride is how many pixels the kernel jumps each move. Padding adds a border of zeros so edges aren't lost. Pooling shrinks the map by summarising small blocks (for example, keeping the max).

Together they decide the receptive field: how much of the original image one deep feature can “see”.

Why this matters: to tell a dog from a cat, some feature near the end of the network must see most of the animal. If the dog fills 150 pixels but your deepest features only see 30×30 patches, the network can spot fur but not “dog”. So you need to grow the receptive field, and shrink the map to keep compute affordable.

Worked numbers, using the formula below the calculator:

  • Kernel 3, stride 1, padding 1 on a 224 input: (224 + 2 − 3) ÷ 1 + 1 = 224. The size is unchanged.
  • Same, but stride 2: ⌊(224 + 2 − 3) ÷ 2⌋ + 1 = ⌊111.5⌋ + 1 = 112. The size halves.
  • Receptive field of stacked 3×3, stride-1 layers: each layer adds 2 pixels. One layer sees 3×3, two see 5×5, three see 7×7. That growth is slow, so networks also use strides and pooling: after each halving, every later 3×3 layer covers twice as much of the original image.
  • 2×2 max pooling: the block [[1, 3], [2, 0]] becomes the single value 3. Four numbers in, one out.

The architecture lineage

Each generation fixed one specific problem. Knowing which problem is far more useful than memorising layer counts.

LeNet (1998) · AlexNet (2012)

Convolution + pooling + ReLU, trained on GPUs, with dropout and augmentation. AlexNet's win on the ImageNet contest is the moment deep learning became the default.

VGG (2014)

Showed that many small 3×3 kernels stacked up beat a few large ones. They see the same area, use fewer parameters and add more nonlinearity (more bends in the function). Very deep, very heavy.

ResNet (2015)

Residual connections (“skip connections”): each block adds its input straight to its output: output = x + F(x). If a block has nothing useful to add, it only has to learn F ≈ 0, and the signal passes through untouched. Without the shortcut it would have to learn an exact copy, which is surprisingly hard. Suddenly 50–150 layers trained reliably, because gradients have a direct shortcut back to early layers. Still the default backbone in production a decade later.

MobileNet / EfficientNet (2017–19)

Depthwise-separable convolutions (a cheaper convolution split into two steps) and compound scaling (growing depth, width and resolution together). The goal became accuracy per FLOP, which made vision on phones practical.

Vision Transformer (2020)

Cut the image into 16×16 patches and treat each patch like a word token (Chapter 14). It has little built-in sense of “nearby pixels matter”, so it needs more data or strong augmentation. But it scales better, and uses the same design as language models.

ConvNeXt, hybrids, SAM, CLIP (2022–)

Modernised CNNs now match ViTs. CLIP trains on matching images with their captions, so it can recognise things described in any words (“open vocabulary”). Segmentation you can prompt (SAM) and vision-language models turn seeing into a general-purpose tool.

🎁
Start from pretrained weights. Always.

For nearly every real vision task, start from a pretrained backbone (a network already trained on millions of images). Fine-tuning it on a few thousand labelled images beats training from scratch on a hundred thousand.

  • Very little data: freeze (don't update) the early layers.
  • More data: fine-tune everything with a low learning rate.
  • Chasing the last 1%: use a discriminative learning rate — lower for early layers, higher for later ones.

Why this works: early layers learn edges, colours and textures, which look much the same in almost any photo. Later layers learn task-specific shapes. So the early layers need little change, and freezing them protects them from being overwritten by a small, noisy dataset.

The four task shapes

The same backbone can serve very different products. What changes is the “head” on top and the shape of the answer: one label, a list of boxes, a label for every pixel, or a set of points. Pick the simplest shape that answers the product question — per-pixel labels cost far more to annotate than one label per image.

Classification

One label per image. Metric: accuracy, top-5, macro-F1.

Detection

A box and a label for each object. Metric: mAP over IoU thresholds. Needs NMS (both explained below).

Segmentation

A label for every pixel. Metric: mIoU, Dice. Comes in three kinds: semantic (by class), instance (by object) and panoptic (both).

Keypoints / pose

The position of each body joint. Metric: PCK, OKS. Feeds tracking and AR.

Detection mechanics: IoU and NMS

Detectors guess far more boxes than there are objects — often several boxes around the same cat. Two tools clean this up.

IoU (intersection over union) measures how much two boxes overlap: the shared area divided by the total area they cover. 1 means identical, 0 means no overlap. Non-maximum suppression (NMS) keeps the highest-scoring box and deletes any other box that overlaps it by more than a set IoU threshold.

IoU with numbers: two 10×10 boxes, one shifted 5 pixels to the right. They share a 5×10 strip, so the intersection is 50. The union is 100 + 100 − 50 = 150 (subtract the shared part so it isn't counted twice). IoU = 50 ÷ 150 ≈ 0.33 — below the usual 0.5 bar, so the shifted box would not count as a correct detection.

NMS as a dry run, threshold 0.5. The detector outputs three “cat” boxes: A (score 0.9), B (score 0.8, IoU 0.7 with A) and C (score 0.6, IoU 0.1 with A).

  1. Sort by score and keep the top box, A.
  2. B overlaps A with IoU 0.7, above 0.5, so it is a duplicate of A: delete it.
  3. C overlaps A by only 0.1, so it is probably a second cat: keep it.

The result is two cats. NMS is normally run separately for each class, so a dog box overlapping a cat box is not deleted.

mAP (mean average precision) turns all this into one score. A predicted box counts as correct if its IoU with a real box is above the threshold. Sweep the confidence threshold, draw the precision–recall curve (Chapter 7), and take the area under it: that is the class's average precision. Average over all classes and you have mAP. For segmentation, mIoU computes IoU between the predicted and true pixel masks for each class, then averages over classes.

mAP@[.5:.95] averages precision over IoU thresholds from 0.5 to 0.95. It is stricter, rewards tight boxes, and is the standard COCO metric.

Augmentation: the cheapest accuracy you'll ever buy

Augmentation means randomly changing each training image — cropping, flipping, recolouring — every time it is loaded, while keeping its label. The model never sees the exact same picture twice, so it can't memorise pixels and must learn what actually makes a cat a cat. On small datasets this often adds several accuracy points at no extra labelling cost.

The rule for choosing: only apply a change if the true label survives it. A flipped cat is still a cat; a flipped “b” becomes a “d”. For detection and segmentation the labels must move too: flip the image and you must flip its boxes or masks the same way.

The systems half of vision

At 224×224, a ResNet-50 forward pass takes a few milliseconds on a modern GPU. But decoding a 4 MB JPEG and running five augmentations takes tens of milliseconds of CPU.

So unless you add enough loader workers, decode on the GPU, pre-resize your data, or use a sequential file format, your expensive GPU sits waiting on libjpeg. Always profile the data loader before profiling the model (Chapter 11).

Deploying vision models

☁️ Server-side

Batch requests, use fp16/int8, and export to a fast runtime like TensorRT or ONNX Runtime. Image resolution is your biggest cost lever. Cost grows with the number of pixels, yet 320² is often within one accuracy point of 640². Since 640² has 4× the pixels of 320², halving the resolution cuts compute roughly 4×.

📱 On-device

Quantized MobileNet/EfficientNet-style models, run on the phone's NPU (its AI chip), within a strict memory budget. You win on privacy and latency. But updating the model now means shipping a new app release.

🎥 Streaming video

Don't run the model on every frame. Detect every k frames and track objects in between, or only run when something moves (motion gating). That cuts cost 10×, more than any model change could (Chapter 50).

⚠️
Common mistakes
  • Augmenting the validation set. Evaluation must give the same result every time — only resize and centre-crop.
  • Different preprocessing in training and serving. A different resize method or normalization constant quietly costs accuracy points.
  • Flipping images where orientation matters. Left vs right matters in medical imaging, driving, and any task with text.
  • Ignoring class imbalance in detection. Background boxes outnumber real objects thousands to one. That is why focal loss and hard-negative mining exist.
  • Training at a resolution you can't afford to serve. Decide the serving resolution first, then train for it.
  • Leaking near-duplicate frames across splits. Frames next to each other in a video are almost identical. Split train/test by clip or scene, never by single frame.

Interview drill

Warm-up: Why do two stacked 3×3 convolutions often beat one 5×5?

How a strong answer sounds
Two 3×3 layers see the same 5×5 area, but with fewer parameters (2·9·C² vs 25·C²). They also add an extra nonlinearity, so they can express more per parameter. And hardware kernels are better tuned for 3×3. That insight, from VGG, is why nearly every CNN since uses many small kernels stacked deep, not a few large ones.

Deeper: Your defect detector gets 0.91 mAP offline but misses obvious defects in the factory. What do you check?

How a strong answer sounds
First, distribution shift (the real data differs from the training data). The test set was probably shot in the same session as the training set, while the factory has a different line, lighting, camera or lens. I'd collect a few hundred factory images, label them, and evaluate on those. Second, preprocessing must match: resize, normalization and colour space must be identical in training and on the factory device, and quantization can also change behaviour. Third, the operating point: mAP averages over many thresholds, but the line runs at one confidence threshold. So I'd measure recall at that exact threshold, for the defect types that matter. The fix is usually a data engine — keep collecting factory failures, label them, retrain — not a better architecture.

🧠 Key takeaways

  • Convolution reuses one small kernel across the whole image. You get translation equivariance and far fewer parameters.
  • Stride, padding and depth set the output size and receptive field. Compute them — don't guess.
  • ResNet's skip connections made very deep networks trainable. ViTs give up built-in image assumptions in exchange for scaling better.
  • Detection needs IoU, NMS and mAP. Segmentation needs per-pixel metrics like mIoU.
  • Augmentation is the cheapest way to fight overfitting. The data pipeline is usually the real bottleneck.

Check your understanding

Input 64×64, kernel 3, stride 2, padding 1. What is the output size?

⌊(64 + 2 − 3)/2⌋ + 1 = ⌊31.5⌋ + 1 = 32. Stride 2 with “same” padding halves the width and height. It is the standard way to shrink a feature map.

What problem do residual connections solve?

The shortcut path passes its input through unchanged, so its derivative is 1. Gradients reach the early layers without shrinking. That is what made 50–1,000-layer networks trainable.

You have 4,000 labelled images of a specialised industrial part. Best approach?

Features learned on a big dataset carry over remarkably well to new tasks. A data-hungry model trained from scratch on only 4,000 images will do far worse than a fine-tuned ResNet or ConvNeXt.

Why does a detector need non-maximum suppression?

Detectors predict clusters of near-identical boxes around each object. NMS keeps the highest-scoring box in each cluster, using an IoU threshold. Set it too high and duplicates survive. Set it too low and you delete real objects that sit close together.

Your GPU sits at 35% utilization while training an image classifier. Most likely fix?

JPEG decoding plus augmentation on the CPU usually can't keep up with the GPU. More augmentation would make it worse. The answer is a faster pipeline or decoding on the GPU.
