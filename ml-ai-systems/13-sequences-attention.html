Sequences & Attention

Text, audio, clickstreams and sensor readings share one problem: meaning depends on order, and on things that happened long before. Recurrence (reading one step at a time while carrying a memory) was the first answer. Attention (letting each step look back at any earlier step directly) was the better one. Understanding why is the shortest path to understanding transformers.

Why sequences are different

A row in a table stands on its own. A sequence does not. Take “the trophy didn't fit in the suitcase because it was too big”. To understand “it”, you must link it to a noun several words back. Three properties define the problem:

📏

Variable length

Sentences, sessions and audio clips vary hugely in length. A model that expects a fixed-size input doesn't fit.

🔀

Order matters

“Dog bites man” ≠ “man bites dog”. Bag-of-words (just counting which words appear) throws that difference away.

🔭

Long-range dependencies

The context you need may be 5 tokens back, or 5,000. Both have to work.

Recurrent networks: carry a state forward

A recurrent neural network (RNN) reads one element at a time. It keeps a hidden state — a fixed-size vector that acts as a running summary of everything so far. Like reading a book and keeping notes on one index card, it updates that card at every word: hₜ = tanh(Wₓxₜ + Wₕhₜ₋₁ + b).

The same weights are reused at every step. This is weight sharing across time, just as convolution shares weights across space.

Watch the memory fade with a one-number example. Make the hidden state a single number, set Wx = 1 and Wh = 0.5, and feed the inputs 1, 0, 0 (no bias). Then:

  • h₁ = tanh(1×1 + 0.5×0) = tanh(1) ≈ 0.76
  • h₂ = tanh(0 + 0.5×0.76) = tanh(0.38) ≈ 0.36
  • h₃ = tanh(0 + 0.5×0.36) = tanh(0.18) ≈ 0.18

The only input that mattered was the first one, and its trace roughly halves every step. After ten steps it is almost gone. Real RNNs use vectors and learned matrices, but the same squeeze happens: old information must keep surviving the same multiplication.

An RNN, unrolledStep-through
  1. The first token is turned into a vector (embedded) and combined with a starting hidden state, usually all zeros. The result is h₁: a fixed-size vector meant to summarise “the”.
  2. h₁ is fed in along with the next token's vector. Notice the sequential dependency: step 2 cannot start until step 1 finishes. On a GPU this is the fatal flaw — during training, you can't work on different time steps in parallel.
  3. Each step overwrites the state with a new mix. Information about “trophy” must survive being re-mixed ten times to still be there when “it” arrives.
  4. To work out what “it” means, the model needs the subject from ten steps ago. That information has had to squeeze through a fixed-size vector, multiplied by the same matrix ten times.
  5. During training, gradients flow backwards through every step, multiplied by the same weight matrix each time. Multiply by something a bit below 1 many times and it shrinks to nothing (vanishing gradients). A bit above 1 and it blows up (exploding gradients). For example, 0.9 multiplied 50 times is about 0.005. This is the main limit of plain RNNs.
🧠
LSTM and GRU: gates that protect memory

An LSTM adds a second memory track, the “cell state”. Learned gates — forget, input and output — act like valves that decide what is kept, written and read. Crucially, the cell state is updated by adding to it, not by re-mixing it.

That additive path is the key. Like a residual connection, it gives gradients a route with derivative ≈1, so information survives hundreds of steps instead of dozens. A GRU is a lighter version with two gates and similar results. Both stretched the useful memory range a lot — but neither fixed the one-step-at-a-time training problem.

The encoder–decoder bottleneck

Early neural translation worked in two halves. An encoder RNN read the source sentence and kept only its final hidden state. A decoder RNN then wrote the translated sentence from that one vector.

So a single vector had to carry the whole sentence. Quality collapsed as sentences got longer — the model was being asked to memorise a paragraph in 512 numbers.

💡
The idea that fixed it

Don't squash the source into one vector. Keep all the encoder states, and let each decoding step choose which source words to look at. That choice is a set of weights that add up to one. Computing those weights from similarity is attention.

Bahdanau's 2014 paper introduced it for translation. “Attention Is All You Need” (2017) then removed the recurrence entirely.

Attention from first principles

Think of a library search. You type a query (what you need). Each book has a key — its title and tags (what it is about). And each book has a value — its actual content (what it contributes).

A normal dictionary returns one exact match. Attention is a “soft” lookup instead. It scores the query against every key, turns the scores into weights with softmax (a function that makes positive weights summing to 1), and returns a weighted average of all the values. Close matches count a lot; poor matches count a little.

🔍 Query (Q)What this token is looking for. Made from the current token: q = Wq·x.
🏷️ Key (K)What each token advertises about itself: k = Wk·x. The score is q·k.
📦 Value (V)What actually gets fetched and blended: v = Wv·x. The output is Σ weightᵢ · vᵢ.

Why three separate matrices instead of using the word vector for everything? Because a word plays different roles. The word “it” is looking for a noun (its query), advertises itself as a pronoun (its key), and passes on whatever it has picked up (its value). Learned projections let the model shape each role separately.

In matrix form, all queries, keys and values are stacked into Q, K and V (one row per token), so the whole lookup is three lines:

scores  = Q @ K.T / sqrt(d)      # similarity, scaled so softmax doesn't saturate
weights = softmax(scores)         # each row sums to 1
out     = weights @ V             # weighted average of values

A worked example with d = 2 and three tokens. The query is q = [1, 0]. The keys are k₁ = [1, 0], k₂ = [0, 1] and k₃ = [1, 1]. The values are v₁ = [10, 0], v₂ = [0, 10] and v₃ = [5, 5].

  1. Score: q·k₁ = 1, q·k₂ = 0, q·k₃ = 1.
  2. Scale by √2 ≈ 1.41: the scores become 0.71, 0 and 0.71.
  3. Softmax: e0.71 ≈ 2.03 and e0 = 1. The total is 2.03 + 1 + 2.03 = 5.06, so the weights are 0.40, 0.20 and 0.40. They add up to 1.
  4. Blend the values: 0.40×[10, 0] + 0.20×[0, 10] + 0.40×[5, 5] = [6.0, 4.0].

Tokens 1 and 3 matched the query, so their values dominate the output. Token 2 didn't match, but still contributes a little — that is the “soft” in soft lookup, and it is what makes the whole thing differentiable, so the model can learn Wq, Wk and Wv by gradient descent.

The weights here are made up for illustration, but the mechanism is exact: a softmax over dot products, giving a weight for each position. Real models learn dozens of these patterns side by side, each in its own “head”. One head tracks grammar, another tracks what pronouns refer to (coreference), another tracks position (Chapter 14).

➗
Why divide by √d?

The dot product of two random vectors with d numbers each has a spread (standard deviation) that grows like √d. Without scaling, scores at d=128 get so large that softmax saturates: it puts nearly all the weight on one position (almost “one-hot”). Then gradients vanish and training stalls.

With numbers: if each entry of q and k has variance 1, then at d = 128 the dot product has a standard deviation of √128 ≈ 11.3. Scores of 20 and 5 are then ordinary. But softmax of those two gives the first e15 ≈ 3 million times the weight of the second — effectively all of it.

Dividing by √d keeps the scores' variance around 1. It is a one-line fix for a real failure.

Self-attention vs cross-attention, and masking

Self-attention

Q, K and V all come from the same sequence. Every token looks at the other tokens around it. This is how each word's vector comes to reflect its context.

Cross-attention

Q comes from one sequence; K and V come from another. Examples: a decoder looking at an encoder's output, or a language model looking at retrieved documents or image patches.

Attention masksInteractive
📘

Rows are queries, columns are keys. A filled cell means “this query may look at this key”. A mask blocks the others: their scores are set to −∞ before the softmax, so their weight becomes exactly zero.

A tiny masking example. Token 2 in a GPT-style model has raw scores [2, 1, 3] against tokens 1, 2 and 3. Token 3 is in the future, so its score becomes −∞. Softmax then uses e², e¹ and e−∞ = 0, giving weights of about 0.73, 0.27 and exactly 0. The future token has no influence at all.

When to use which mask: bidirectional when the whole input is known up front and you want to understand it (classification, search embeddings). Causal when the model generates text left to right. Padding masks whenever sequences of different lengths share a batch. Sliding window when sequences are long and most useful context is nearby.

Cost and parallelism: the actual trade

Attention is not cheaper than recurrence. Its cost is quadratic in sequence length (T tokens → T² pairs to score), while an RNN's is linear (T steps).

It won because of parallelism. During training, every position can be computed at the same time, which suits a GPU perfectly. An RNN must walk through the sequence one step at a time.

Numbers make the trade concrete. At T = 1,000 tokens, attention scores 1,000 × 1,000 = 1 million pairs, but all in one parallel matmul. An RNN does only 1,000 updates, yet each must wait for the one before. At T = 4,000 attention jumps to 16 million pairs, while the RNN chain grows to 4,000 waiting steps.

More total arithmetic, but it all happens at once. A GPU with 10,000 lanes would rather do 10× the work in one parallel sweep than 1× the work in 1,000 steps that wait on each other. (At inference, generating text one token at a time is sequential again — which is why Chapter 26 exists.)

📈
The quadratic wall

Double the context and attention cost and memory go up 4×. That's why long context is a research area of its own. Main approaches:

  • FlashAttention — same maths, far fewer trips to memory.
  • Sliding-window and sparse patterns — each token looks at only some others.
  • Linear-attention approximations — reorder the maths so the T×T score matrix is never built, trading some quality for cost that grows linearly.
  • State-space models like Mamba — a recurrent design again, but with a way to train it in parallel.
⚠️
Common mistakes
  • Forgetting the causal mask (the rule that a token can't see later tokens) in a generative model. It trains beautifully and then generates nonsense — because during training it was peeking at the answer.
  • Not masking padding. The model pays attention to filler tokens, so results silently change depending on what else is in the batch.
  • Leaving out the √d scaling. Softmax saturates, gradients vanish, and the model looks like it is “too small”.
  • Treating attention weights as explanations. They show where information was mixed in from, not why the output came out as it did. This caveat is well studied.
  • Assuming longer context is free. Cost and memory grow quadratically. Retrieval is often cheaper and more accurate than stuffing everything in (Chapter 21).

Interview drill

Warm-up: Attention costs O(T²) and an RNN costs O(T). Why did attention win?

How a strong answer sounds
Because what matters is real (wall-clock) time on parallel hardware, not FLOPs. An RNN has O(T) sequential steps — each waits for the last — so a GPU's thousands of lanes sit idle. Attention has O(1) sequential depth: all positions are computed in one batched matmul. It also gives every position a direct path to every other, so the gradient between distant tokens doesn't have to survive T multiplications. More arithmetic, but far better hardware use and far easier training.

Deeper: You need to model 100,000-token documents. Options?

How a strong answer sounds
First, ask whether the whole document really must be in context. Retrieving just the relevant chunks is usually cheaper and often more accurate, because attention spread over 100k tokens gets diluted. If you truly need the full context: use FlashAttention so memory grows linearly (compute still grows quadratically). Use sparse or sliding-window attention with a few global tokens that see everything. Consider a state-space or linear-attention hybrid. And if the same document is queried again and again, reuse the KV cache and use prompt caching. I'd also measure quality at different positions in the document. Many long-context models get worse in the middle, so the solution has to be tested, not assumed.

🧠 Key takeaways

  • RNNs carry a fixed-size hidden state. Gradients through time vanish or explode, and training can't run in parallel.
  • LSTM/GRU gates add a memory path updated by addition. It extends the useful range, but training is still one step at a time.
  • Attention is a soft lookup: score the query against every key, softmax, then average the values.
  • Dividing by √d keeps softmax from saturating. Masks stop tokens seeing the future and make the model ignore padding.
  • Attention costs more FLOPs but needs only one sequential step. That parallelism is why it replaced recurrence.

Check your understanding

What is the main reason plain RNNs struggle with long-range dependencies?

Backpropagation through time multiplies by the same matrix of derivatives (the Jacobian) again and again. The product shrinks or grows exponentially with distance. Gates and additive paths were invented to get around exactly this.

In attention, what do the values (V) represent?

Keys decide how much attention each position gets. Values are what actually gets fetched and averaged.

Why are attention scores divided by √d?

The size of a dot product grows with √d. Without scaling, softmax puts nearly all its weight on one position, its gradient drops to zero, and training stalls.

A GPT-style model must not attend to future tokens. How is that enforced?

A score of −∞ becomes exactly zero weight after softmax. Zeroing the values instead would still leave future tokens in the softmax's denominator, which quietly leaks information about them.

Doubling sequence length from 2k to 4k affects self-attention compute how?

The score matrix is T×T, so cost grows with T². Twice the length means 4× the work. This quadratic growth is the reason for FlashAttention, sparse patterns and retrieval-based alternatives.
